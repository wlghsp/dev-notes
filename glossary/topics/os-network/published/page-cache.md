# page-cache

**"OS 커널이 디스크 파일 내용을 메모리에 캐싱해두는 영역"**

디스크는 느리다. OS는 파일을 읽거나 쓸 때마다 디스크에 직접 접근하지 않고, 한 번 읽은 내용을 메모리(페이지 캐시)에 올려둔다. 이후 같은 파일을 읽으면 디스크 대신 페이지 캐시에서 바로 가져온다.

---

## 읽기 경로

```
read() 호출
  → 페이지 캐시에 해당 페이지가 있으면? → 바로 반환 (빠름)
  → 없으면? → 디스크에서 읽어 페이지 캐시에 올린 후 반환 (느림)
```

두 번째 read()부터는 디스크를 건드리지 않는다.

---

## 쓰기 경로

```
write() 호출
  → 페이지 캐시에 데이터 기록 (dirty 상태로 표시)
  → 즉시 반환
  → OS가 나중에 dirty 페이지를 디스크에 flush (백그라운드)
```

페이지 캐시에 쓴 페이지를 "dirty page"라고 한다. 아직 디스크에 반영되지 않은 상태다.

---

## dirty page와 fsync

dirty page는 OS가 알아서 flush하지만, 시점을 보장하지 않는다. OS가 갑자기 죽으면 dirty page는 사라진다.

fsync()를 호출하면 해당 파일의 dirty page를 즉시 디스크에 강제 기록한다. "지금 당장 디스크에 써라"는 명령이다.

---

## 한 줄 요약

> 페이지 캐시 = 디스크 파일의 메모리 복사본. write()는 여기까지만, fsync()는 여기서 디스크까지.
