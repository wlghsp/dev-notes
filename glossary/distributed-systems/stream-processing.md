# Stream Processing (스트림 처리)

**한 줄 정의**: 데이터가 생성되는 즉시 처리하는 방식. 모아두지 않는다.

---

## 배치 처리와의 차이

데이터를 처리하는 방식은 크게 두 가지다.

**배치 처리**는 데이터를 일정 기간 쌓아뒀다가 한꺼번에 처리한다. 자정에 하루치 주문을 집계하거나, 매시간 로그를 분석하는 식이다. 처리 시점이 늦어지는 대신 구현이 단순하다.

**스트림 처리**는 데이터가 들어오는 순간 처리한다. 결제가 발생하면 즉시 이상 거래를 탐지하거나, 클릭이 발생하는 즉시 추천 모델에 반영하는 식이다.

```
배치:
  데이터 → 저장 → 저장 → 저장 → [처리] → 결과
                              ↑
                           자정, 매시간 등

스트림:
  데이터 → [처리] → 결과
  데이터 → [처리] → 결과
  데이터 → [처리] → 결과
```

---

## 스트림 처리의 핵심 개념

**이벤트(Event)**: 스트림을 구성하는 개별 데이터 단위. "사용자 A가 상품 B를 클릭했다", "온도 센서가 32도를 측정했다" 같은 것.

**윈도우(Window)**: 스트림에서 일정 범위를 잘라내는 단위. 무한히 흐르는 데이터를 집계하려면 범위가 필요하다. "최근 5분간 클릭 수", "10개 이벤트마다 평균" 같은 식으로 쓴다.

**상태(State)**: 이전 이벤트의 결과를 기억하는 것. "이 사용자가 오늘 몇 번 로그인했는가"를 알려면 이전 이벤트를 기억해야 한다. 상태가 없으면 각 이벤트를 독립적으로만 처리할 수 있다.

---

## Kafka와의 관계

Kafka는 이벤트를 저장하고 전달하는 역할이다. 스트림 처리는 그 이벤트를 받아서 무언가를 하는 역할이다.

```
이벤트 발생 → Kafka (저장/전달) → 스트림 처리 시스템 → 결과
```

Kafka 없이 스트림 처리를 할 수도 있지만, 실무에서는 Kafka를 소스로 쓰는 구조가 가장 흔하다.
