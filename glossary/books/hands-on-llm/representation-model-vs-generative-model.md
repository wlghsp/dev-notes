# Representation Model vs Generative Model

LLM은 아키텍처와 목적에 따라 두 가지 타입으로 나뉜다.

## Representation Model (표현 모델)

텍스트를 숫자 벡터(임베딩)로 변환하는 데 특화된 모델이다.
텍스트를 생성하지 않는다. 입력을 받아 의미를 압축한 벡터를 출력한다.

주로 분류, 검색, 클러스터링처럼 "이 텍스트가 무엇을 의미하는가"를 파악하는 태스크에 쓰인다.
Encoder-only 아키텍처를 사용하며, BERT가 대표적이다.

## Generative Model (생성 모델)

텍스트를 생성하는 데 특화된 모델이다.
주어진 입력(프롬프트)에 이어지는 텍스트를 토큰 단위로 예측해 출력한다.

번역, 요약, 대화, 코드 생성처럼 "텍스트를 만들어내는" 태스크에 쓰인다.
Decoder-only 아키텍처를 사용하며, GPT 계열이 대표적이다.

## 왜 구분이 중요한가

두 타입은 같은 "LLM"이라는 이름을 쓰지만 용도와 동작 방식이 다르다.
RAG 파이프라인을 예로 들면, 문서를 검색하는 쪽은 Representation Model(임베딩 생성),
검색 결과를 바탕으로 답을 생성하는 쪽은 Generative Model이 담당한다.
두 모델을 혼동하면 시스템 설계에서 잘못된 모델을 선택하게 된다.
