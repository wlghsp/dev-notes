# 테넌트 (Tenant)

테넌트는 원래 "임차인, 세입자"라는 뜻인데, IT에서는 같은 시스템(인프라, 서비스)을 나눠 쓰는 각각의 독립된 사용자 단위(회사, 부서, 팀, 고객)를 가리킨다.

## 건물 비유

하나의 건물(공유 인프라)에 여러 회사가 각자 층을 빌려 쓴다고 하면, 그 회사 하나하나가 테넌트다. 각 회사는 자기 사무실 안에서는 독립적으로 운영하지만, 건물 자체(엘리베이터, 전기, 배관)는 공유한다. 다른 회사가 내 사무실 문을 열고 들어올 수 없다는 게 중요한 지점이다.

## 클라우드에서의 테넌트

하나의 OpenStack 클러스터(공유 인프라) 위에 여러 팀이나 고객사가 각자의 "프로젝트"(테넌트)를 갖고 VM을 띄운다. 참고: openstack.md

A팀의 테넌트와 B팀의 테넌트는 같은 물리 서버 위에서 돌 수도 있지만, 격리된 상태로 운영된다.

- 네트워크가 분리되어 있어서 서로의 트래픽을 볼 수 없다
- 각자 정해진 쿼터(CPU/메모리/스토리지 할당량)만큼만 쓸 수 있다
- 각자 자기 프로젝트 안에서만 VM을 만들거나 지울 수 있는 권한을 갖는다

## 멀티테넌트라는 표현

멀티테넌트는 그냥 "테넌트가 여러 개"라는 뜻이다. "멀티테넌트 IaaS"는 여러 팀/고객에게 독립된 가상 네트워크·스토리지 쿼터·프로비저닝 API를 셀프서비스로 제공하는 클라우드 인프라를 가리킨다. 참고: provisioning.md

반대로 그냥 "VM 몇 대를 한 팀만 쓴다"는 상황은 테넌트를 여러 개로 나눌 필요가 없으니 멀티테넌트 개념이 필요 없는 경우다. RHOV가 이 범위(단일 사용 주체를 위한 VM 실행)에 가깝고, 여러 테넌트를 셀프서비스로 분리해줘야 하는 요구가 있을 때 OpenStack(RHOSP/RHOSO)이 필요해지는 이유가 이 지점이다. 참고: rhov.md, rhosp-osp.md
