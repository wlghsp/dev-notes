# process

실행 중인 프로그램. OS가 관리하는 동시성의 기본 격리 단위.

프로그램은 디스크에 있는 정적인 명령어 집합이다. 프로세스는 그 프로그램이 실행되는 동안의 동적인 인스턴스다. OS가 실행 환경(추상화)을 제공하고, 프로세스는 그 위에서 동작한다.

## 프로세스의 구성 요소

1. PID(Process ID) — 프로세스를 식별하는 고유 번호
2. Process State — 현재 실행 상태
3. Executable — 실행 중인 명령어 집합
4. Files — 열린 파일, 네트워크 연결 등 OS 리소스 목록
5. Address Space — 프로세스가 접근할 수 있는 메모리 영역 (코드, 데이터, 스택, 힙)

모든 프로세스는 최소 하나의 스레드를 가진다. 스레드는 이 컨테이너 안에서 실행되는 명령어 흐름이다. 즉 프로세스는 자원의 단위, 스레드는 실행의 단위다.

## 프로세스 상태

프로세스는 네 가지 상태를 거친다.

1. Created — OS가 프로세스를 생성하고 초기화한 상태. 메모리에 존재하지만 아직 실행 대기 중이 아니다
2. Ready — CPU를 기다리는 상태. 스케줄러가 선택하면 Running으로 전환된다
3. Running — CPU를 점유하고 실제로 실행 중인 상태
4. Terminated — 실행이 완료되거나 실패한 상태. OS가 자원을 회수한다

## 자식 프로세스

프로세스는 fork()나 spawn() 시스템 콜로 자식 프로세스를 만들 수 있다. 자식 프로세스는 부모의 주소 공간을 복사한 독립적인 인스턴스다. 부모와 자식은 각자 독립적으로 실행된다.

이 방식은 NGINX, Apache, Gunicorn 같은 서버에서 prefork 모드로 활용된다. 시작 시 여러 자식 프로세스를 미리 만들어두고 요청을 처리한다.

## 동시성에서 프로세스의 위치

프로세스 간 격리는 강력하다. 한 프로세스가 죽어도 다른 프로세스에 영향이 없다. 반면 프로세스 간 통신(IPC)은 비용이 크다. 주소 공간이 분리되어 있어 데이터를 주고받으려면 OS의 개입이 필요하다.
