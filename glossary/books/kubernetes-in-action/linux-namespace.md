# linux-namespace (리눅스 네임스페이스)
참고: cgroup.md, container-image.md

---

컨테이너 격리의 핵심 메커니즘이다. 각 프로세스가 시스템 자원의 어떤 부분을 볼 수 있는지를 제어한다. 프로세스는 자신이 속한 네임스페이스 안의 자원만 보고 사용할 수 있다.

VM은 하드웨어 가상화를 통해 격리하지만, 컨테이너는 이 네임스페이스로 격리한다. 그래서 컨테이너는 VM보다 훨씬 가볍다 — 별도의 OS 프로세스 없이, 호스트 OS의 커널 위에서 격리된 프로세스로 동작할 뿐이다.

## 네임스페이스 타입

리소스 종류별로 네임스페이스가 나뉜다. 하나의 프로세스는 각 타입마다 하나씩 네임스페이스를 가진다.

- Mount (mnt) — 파일시스템 마운트 포인트 격리
- Process ID (pid) — 프로세스 ID 격리. 컨테이너 안에서는 자신의 프로세스만 보인다
- Network (net) — 네트워크 인터페이스, 포트, 라우팅 테이블 격리
- IPC (ipc) — 프로세스 간 통신(메시지 큐, 공유 메모리 등) 격리
- UTS — 호스트명과 도메인명 격리. 컨테이너가 자신만의 hostname을 가질 수 있다
- User — 사용자 ID와 그룹 ID 격리
- Time — 시스템 클럭 오프셋 격리
- Cgroup — cgroup 루트 디렉토리 격리

## 네임스페이스 공유

컨테이너들이 모든 네임스페이스를 분리할 필요는 없다. 연관된 컨테이너가 network 네임스페이스를 공유하면 같은 네트워크 인터페이스와 IP를 사용한다. 파일시스템(mount)은 분리하면서 네트워크는 공유하는 식의 선택적 조합이 가능하다. Kubernetes의 Pod이 이 방식을 사용한다 — Pod 내 컨테이너들은 network, UTS 네임스페이스를 공유한다.

## 컨테이너는 사실 프로세스다

컨테이너는 특별한 격리 공간이 아니다. 여러 종류의 네임스페이스가 할당된 일반 OS 프로세스다. 호스트에서 `ps aux`를 실행하면 컨테이너 안의 프로세스도 보인다. 단, PID가 다르다 — 컨테이너는 자체 PID 네임스페이스를 가지므로 내부에서는 PID 1번으로 보이는 프로세스가 호스트에서는 다른 번호로 존재한다.
