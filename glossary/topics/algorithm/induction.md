# induction (수학적 귀납법)

"모든 자연수 n에 대해 이 명제가 참이다"를 증명할 때 쓰는 방법. 무한히 많은 경우를 하나씩 다 확인할 수 없으니, 대신 두 가지만 보인다.

1. **기저 사례(base case)**: 가장 작은 경우(`n = 1` 등)일 때 명제가 참이다. (필요에 따라 초깃값 여러 개를 확인)
2. **귀납 단계(inductive step)**: `P(k)`가 참이라고 가정하면(또는 `k` 이하가 모두 참이라고 가정하면), `P(k+1)`도 참이다. (`P(k) ⟹ P(k+1)`)

이 두 개만 보이면 도미노처럼 모든 n에 대해 참이 된다. 1이 참이고, 1이 참이면 2도 참이고, 2가 참이면 3도 참이고... 무한히 이어진다.

---

## 일상 비유 — 도미노

도미노를 일렬로 세워놓고 두 가지만 확인하면 전부 쓰러진다는 걸 안다.
- 첫 번째 도미노가 쓰러진다. (기저 사례)
- 어떤 도미노가 쓰러지면 바로 다음 도미노도 반드시 쓰러진다. (귀납 단계)

이 두 개를 확인했다면 두 번째, 세 번째 도미노를 직접 밀어볼 필요가 없다. 논리적으로 전부 쓰러진다.

---

## 알고리즘에서 왜 필요한가

재귀 함수나 DP 점화식이 "항상 맞는 값을 낸다"는 걸 증명할 때 귀납법을 쓴다. 코드가 정답을 낸다는 확신 없이 그냥 실행해보고 맞으면 넘어가는 경우가 많은데, 왜 맞는지는 귀납법으로 설명된다.

- **재귀 / DP**: 수학적 귀납법의 구조를 코드 형태로 옮겨놓은 것
- **루프 불변량(Loop Invariant)**: 반복문(for/while)의 정확성을 귀납법으로 증명하는 도구

---

## 예시 — 피보나치 DP가 맞다는 증명 (강한 귀납법)

`dp[i] = dp[i-1] + dp[i-2]`로 피보나치 수를 구하는 코드가 항상 올바른 피보나치 값을 낸다는 걸 귀납법으로 보인다.

- **기저 사례**: `dp[0] = 0`, `dp[1] = 1`은 정의 그대로이므로 참. (점화식이 이전 2개 항을 참조하므로 기저 사례도 2개 필요)
- **귀납 가정**: `0 ≤ i ≤ k`인 모든 `i`에 대해 `dp[i] = F(i)`(진짜 피보나치 값)라고 가정한다.
- **귀납 단계**: `dp[k+1] = dp[k] + dp[k-1]` 계산 시, 가정에 의해 `dp[k] = F(k)`, `dp[k-1] = F(k-1)`이다. 피보나치 수의 정의가 `F(k+1) = F(k) + F(k-1)`이므로 `dp[k+1] = F(k+1)`이 성립한다.
- **결론**: 모든 `i`에 대해 `dp[i] = F(i)`이다.

이 증명이 있어야 "예제 몇 개 돌려보니 맞더라"가 아니라 "모든 입력에 대해 반드시 맞다"고 정당성을 부여할 수 있다.

---

## 기억할 것 한 가지

귀납 단계에서 "k일 때 참이라고 가정"하는 걸 이상하게 느낄 수 있는데, 이건 순환 논리가 아니다. "가정이 참이면 다음도 참이다"라는 **조건문(`A ⟹ B`) 자체를 증명**하는 것이지, k일 때 이미 참이라고 확정 짓고 시작하는 것이 아니다.
