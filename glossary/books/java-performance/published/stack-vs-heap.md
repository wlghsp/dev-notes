# stack-vs-heap
참고: Java Performance: The Definitive Guide Ch.7

---

Java에서 데이터가 저장되는 두 가지 핵심 공간이다. 무엇이 어디에 저장되는지, 각각의 수명이 어떻게 다른지 이해하면 GC와 메모리 누수를 이해하는 기반이 된다.

---

## 스택 — 메서드 호출의 공간

스레드마다 하나씩 존재한다. 메서드를 호출할 때마다 스택 프레임(stack frame)이 하나 쌓이고, 메서드가 반환되면 자동으로 사라진다.

스택 프레임 안에 들어 있는 것들:
- 지역 변수(primitive 타입 값, 객체 참조)
- 메서드 파라미터
- 현재 실행 중인 바이트코드 위치

중요한 점: 스택에는 객체 자체가 저장되지 않는다. 객체를 가리키는 참조(주소값)가 저장된다. 객체 본체는 항상 힙에 있다.

```
void process() {
    int count = 0;           // count(primitive): 스택에 값 저장
    String name = "hello";   // name: 스택에 참조 저장, "hello" 객체는 힙에
    List<String> list = new ArrayList<>();  // list: 스택에 참조, ArrayList 객체는 힙에
}
// process() 반환 → 스택 프레임 사라짐 → count, name, list 참조 모두 사라짐
// 힙의 ArrayList 객체는 아직 남아 있다가 GC가 회수
```

---

## 힙 — 객체의 공간

모든 스레드가 공유하는 공간이다. `new` 키워드로 생성된 모든 객체가 여기에 올라온다.

힙에 있는 객체의 수명은 참조에 의해 결정된다. 어떤 곳에서도 참조되지 않게 되면 GC의 수집 대상이 된다. 반대로, 참조가 하나라도 살아 있으면 GC가 회수하지 않는다.

---

## 수명 차이가 핵심이다

스택의 데이터는 메서드가 끝나면 즉시 사라진다. 자동이고 결정적이다.

힙의 데이터는 참조가 사라진 뒤 GC가 실행될 때 회수된다. 시점을 예측하기 어렵다.

메모리 누수는 항상 힙에서 발생한다. 더 이상 사용하지 않는 객체인데 어딘가에서 참조를 붙들고 있어서 GC가 회수하지 못하는 상황이다. 스택은 메서드 종료와 함께 자동으로 정리되므로 누수가 생기지 않는다.
