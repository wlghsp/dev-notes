# multitasking

여러 작업을 일정 시간 동안 번갈아 실행함으로써 동시에 실행되는 것처럼 보이게 하는 런타임 시스템 수준의 기능.

멀티태스킹은 하드웨어 레벨의 개념이 아니다. 하드웨어는 물리적으로 한 번에 하나의 명령만 실행한다. 멀티태스킹은 런타임 시스템이 작업 전환을 제어해서 만들어내는 환상이다.

## 왜 필요한가

단일 CPU 코어는 한 번에 하나의 작업만 처리할 수 있다. 그러나 실용적인 프로그램은 여러 작업이 동시에 진행되는 것처럼 동작해야 한다. 멀티태스킹은 작업들을 빠르게 번갈아 실행함으로써 이 요구를 충족한다.

작업을 너무 많이 만들면 역효과가 난다. 컨텍스트 스위치 자체에 비용이 있기 때문에, 작업 전환이 너무 잦아지면 실제 연산보다 전환에 더 많은 시간을 쓰게 된다.

## preemptive multitasking

현대 OS가 사용하는 방식. 스케줄러가 타이머 인터럽트를 이용해 실행 중인 작업을 강제로 중단시키고 다른 작업에 제어권을 넘긴다. 작업이 스스로 제어권을 넘기지 않아도 된다.

time slice(타임 슬라이스) — 작업 하나에 할당되는 CPU 실행 시간. 이 시간이 끝나면 인터럽트가 발생하고 스케줄러가 다음 작업을 선택한다.

인터럽트의 종류:
1. 하드웨어 인터럽트 — 키보드, 마우스, 네트워크 카드 같은 장치에서 발생
2. 소프트웨어 인터럽트(시스템 콜) — 프로그램이 OS 서비스를 요청할 때 발생
3. 타이머/오류 인터럽트 — 타임 슬라이스 만료, 0으로 나누기 같은 오류

## context switching

한 작업에서 다른 작업으로 전환할 때, 현재 작업의 실행 상태(레지스터, 프로그램 카운터 등)를 저장하고 다음 작업의 상태를 복원하는 과정.

전환 시 저장하는 상태:
1. 프로그램 카운터 — 어디까지 실행했는지
2. 레지스터 값들 — 연산 중이던 데이터
3. 스택 포인터 — 현재 호출 스택 위치

작업 입장에서는 자기가 멈췄는지도 모른다. 재개될 때 저장된 상태를 그대로 복원받기 때문이다.

컨텍스트 스위치 한 번에 약 800~1300ns가 소요되며, 이는 CPU 명령 약 9000~15000개에 해당하는 비용이다.

## 멀티코어와의 차이

멀티코어 CPU는 진짜 물리적 병렬 실행이 가능하다. 코어 4개면 진짜로 4개 명령이 동시에 실행된다. 이건 환상이 아니다.

그러나 실행 중인 프로세스/스레드 수는 코어 수보다 항상 많다. 그래서 멀티코어 환경에서도 코어당 context switch 기반 멀티태스킹은 여전히 발생한다.

## task isolation

작업들을 서로 격리해서 하나의 작업이 다른 작업의 메모리나 상태에 영향을 주지 않게 하는 것.

격리 방식은 두 가지다.
- 단일 프로세스 + 스레드: 스레드 간 주소 공간을 공유한다. 메모리 효율이 좋지만 한 스레드가 공유 상태를 잘못 건드리면 전체에 영향이 생긴다.
- 복수 프로세스: 각 프로세스가 독립된 주소 공간을 가진다. 격리가 강하지만 IPC 오버헤드가 있다.

단일 멀티스레드 프로세스가 일반적으로 더 효율적이다.
