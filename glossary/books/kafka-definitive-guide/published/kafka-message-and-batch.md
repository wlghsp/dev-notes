# Kafka Message와 Batch

Kafka 안에서 다뤄지는 데이터의 최소 단위와, 그 단위를 묶어서 전송하는 방식.

## Message

Kafka에서 데이터를 주고받는 기본 단위다. 데이터베이스로 치면 하나의 row(레코드)에 해당한다.

메시지는 Kafka 입장에서 그냥 바이트 배열이다. 안에 어떤 내용이 들어있는지, 어떤 형식인지는 Kafka가 신경 쓰지 않는다.

메시지에는 key라는 선택적인 메타데이터가 붙을 수 있다. key도 바이트 배열이고, Kafka는 그 의미를 해석하지 않는다.

## Key가 하는 역할

key는 메시지가 어느 파티션에 쓰일지를 정하는 데 쓰인다. key의 해시값을 파티션 개수로 나눈 나머지로 파티션 번호를 정하는 방식이 가장 단순하다.

이 방식을 쓰면 같은 key를 가진 메시지는 항상 같은 파티션에 쓰인다(파티션 개수가 바뀌지 않는 한). 같은 key의 메시지끼리 순서를 보장하고 싶을 때 이 성질을 이용한다.

## Batch

같은 토픽, 같은 파티션으로 가는 메시지 여러 개를 묶은 것.

메시지 하나마다 네트워크 왕복을 하면 오버헤드가 너무 커진다. 여러 메시지를 배치로 묶어서 한 번에 보내면 이 오버헤드를 줄일 수 있다.

배치를 크게 잡을수록 단위 시간당 처리할 수 있는 메시지 수(처리량)는 늘어나지만, 메시지 하나가 실제로 전달되기까지 걸리는 시간(지연 시간)은 늘어난다. 이 둘은 서로 트레이드오프 관계다.

배치는 보통 압축된 상태로 전송된다. 압축은 네트워크 전송량과 저장 공간을 줄여주지만, 압축/해제에 CPU 자원을 쓴다는 비용이 있다.
