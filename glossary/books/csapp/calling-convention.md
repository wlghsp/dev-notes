# calling-convention (함수 호출 규약)

함수를 호출할 때 인자를 어떻게 전달하고, 레지스터를 누가 보존하고, 반환값을 어디에 두는지에 대한 규칙. 컴파일러와 OS가 약속한 표준이라 서로 다른 코드가 맞물려 동작할 수 있다.

## x86-64 인자 전달 순서

정수·포인터 인자는 레지스터로 전달한다. 순서는 고정이다.

```
1번째: %rdi
2번째: %rsi
3번째: %rdx
4번째: %rcx
5번째: %r8
6번째: %r9
7번째 이후: 스택 (caller의 스택 프레임에 push)
```

32비트 인자면 %edi, %esi... 16비트면 %di, %si... 식으로 같은 레지스터의 하위 부분을 쓴다.

부동소수점 인자는 별도로 %xmm0~%xmm7 레지스터를 사용한다.

## 반환값

정수·포인터 반환값은 `%rax`에 담는다. 부동소수점 반환값은 `%xmm0`에 담는다.

## callee-saved vs caller-saved

레지스터를 누가 보존해야 하는지에 따라 두 종류로 나뉜다.

callee-saved (피호출자 보존):
- `%rbx`, `%rbp`, `%r12`~`%r15`
- 이 레지스터를 쓰려면 함수 진입 시 스택에 백업하고, 반환 전에 복원해야 한다
- caller 입장에서는 함수를 호출해도 이 레지스터 값이 바뀌지 않는다고 보장된다

caller-saved (호출자 보존):
- `%rax`, `%rdi`, `%rsi`, `%rdx`, `%rcx`, `%r8`, `%r9`, `%r10`, `%r11`
- 함수가 마음대로 덮어쓸 수 있다
- caller가 이 값을 함수 호출 후에도 쓸 계획이면 호출 전에 직접 저장해야 한다

## 왜 이 구분이 필요한가

레지스터는 모든 함수가 공유하는 자원이다. 함수 A가 %rbx에 값을 저장한 뒤 함수 B를 호출했을 때 B가 %rbx를 써버리면 A가 복귀했을 때 값이 사라진다. 이를 막기 위해 어떤 레지스터는 callee가, 어떤 레지스터는 caller가 책임지도록 역할을 나눈다.

## 실제 예시

```c
long P(long x, long y) {
    long u = Q(y);   // Q 호출 전 x를 보존해야 함
    long v = Q(x);
    return u + v;
}
```

컴파일된 코드는 첫 번째 Q 호출 전에 x를 callee-saved 레지스터(%rbp)에 저장하고, Q(y)의 결과도 또 다른 callee-saved 레지스터(%rbx)에 저장한다. Q가 caller-saved 레지스터를 덮어써도 안전하게 보존된다.
