# 토큰 (Token)

NLP에서 텍스트를 처리하는 최소 단위다.
단어와 비슷하지만 정확히 같지는 않다.

## 단어와의 차이

토큰은 단어보다 작을 수도 있고, 클 수도 있다.
LLM은 텍스트를 단어 단위가 아니라 자주 등장하는 패턴 단위로 쪼갠다.

```
"unhappiness" → ["un", "happiness"]  (2개 토큰)
"cat"         → ["cat"]              (1개 토큰)
"나는"         → ["나", "는"]          (2개 토큰, 모델에 따라 다름)
```

영어는 평균적으로 단어 하나가 약 1.3개 토큰이다.
한국어는 조사·어미가 붙는 구조라 영어보다 토큰 수가 많아지는 경향이 있다.
"안녕하세요"는 영어 화자 입장에서 한 단어처럼 보이지만, 토크나이저에 따라 3~5개 토큰으로 분리될 수 있다.
이 차이는 한국어 API 호출 비용이 영어보다 높게 나오는 이유 중 하나다.

## 왜 단어 단위로 안 쪼개나

단어 단위로 쪼개면 어휘 목록이 너무 커진다.
"run", "runs", "running", "runner"를 각각 다른 단어로 보면 모델이 학습해야 할 항목이 폭발적으로 늘어난다.
공통 패턴("run")을 하나의 토큰으로 공유하면 어휘 목록을 줄이면서도 의미 관계를 포착할 수 있다.

반대로 문자 단위로 쪼개면 어휘 목록은 최소화되지만 시퀀스가 너무 길어진다.
"happiness"를 9개 문자로 처리하면 셀프 어텐션이 더 많은 관계를 계산해야 한다.
서브워드 방식은 이 두 극단 사이의 균형점이다.

## 토큰의 종류

**서브워드 토큰** — BPE, WordPiece 같은 알고리즘이 만드는 단위. 현재 대부분의 LLM이 사용한다.

**바이트 토큰** — 텍스트를 UTF-8 바이트 단위로 처리한다. GPT-4o가 채택한 방식이다.
어떤 언어든, 어떤 특수문자든 256개 바이트 어휘만으로 표현할 수 있어 OOV(Out-Of-Vocabulary, 어휘 목록에 없는 단어)가 원천 차단된다.

**특수 토큰** — 모델 구조를 위한 제어 토큰이다. 실제 텍스트가 아니라 신호를 전달한다.
- `[BOS]` / `<|startoftext|>` — 시퀀스 시작
- `[EOS]` / `<|endoftext|>` — 시퀀스 종료, 생성 멈춤 신호
- `[PAD]` — 배치 처리 시 길이 맞추기용
- `[MASK]` — BERT의 사전학습에서 예측 대상 토큰 표시

## LLM에서의 역할

LLM은 텍스트를 입력받으면 먼저 토큰으로 분리(토크나이징)한다.
각 토큰을 벡터로 변환한 뒤, 다음 토큰을 예측하는 방식으로 텍스트를 생성한다.

토큰 수는 세 가지에 직접 영향을 준다.
- **비용** — API 과금은 입력+출력 토큰 합산 기준이다.
- **속도** — 토큰이 많을수록 생성 시간이 길어진다.
- **컨텍스트 한도** — 모델의 컨텍스트 윈도우를 초과하면 오래된 내용이 잘려나간다.
