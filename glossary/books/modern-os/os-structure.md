# os-structure

OS 커널을 어떻게 구조화하느냐에 따른 설계 방식.

커널은 OS의 핵심이다. 메모리 관리, 프로세스 스케줄링, 장치 드라이버, 파일 시스템, 네트워킹 등 특권이 필요한 기능을 담당한다. 이 기능들을 어디에 두느냐에 따라 구조가 나뉜다.

모놀리식 커널 (Monolithic):
- 위의 모든 기능이 커널 공간에 존재
- 컴포넌트 간 함수 호출로 통신 → 빠름
- 한 컴포넌트의 버그가 커널 전체를 죽일 수 있음
- Linux, BSD가 이 방식

마이크로커널 (Microkernel):
- 커널에는 최소한만 (IPC, 기본 메모리 관리, 스케줄링)
- 파일 시스템, 드라이버 등은 유저 공간 프로세스로 실행
- 컴포넌트 간 통신이 메시지 패싱 → 느림 (모드 전환 비용)
- 안정성 높음 (드라이버 크래시가 커널을 죽이지 않음)
- Mach, MINIX, L4가 이 방식

하이브리드 커널:
- 마이크로커널 구조를 기반으로, 성능이 중요한 일부 서비스는 커널 공간에 배치
- Windows NT, macOS(XNU)가 이 방식

Tanenbaum은 마이크로커널 구조의 지지자였고, 이를 두고 Linux를 만든 Linus Torvalds와 1992년 유즈넷에서 유명한 논쟁을 벌였다 (Tanenbaum-Torvalds debate). Linux는 모놀리식이지만 모듈 시스템으로 어느 정도 유연성을 확보했다.
