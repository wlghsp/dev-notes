## Part A. 개념 학습

### A-1. 근거형 질문 직결 개념

- 그래프를 인접 행렬로 표현할 때 `computers[i][j]`가 1이라는 것은 정확히 무엇을 뜻하는가? 대각선(`computers[i][i]`)은 왜 항상 1인가?
컴퓨터 i와 컴퓨터 j가 서로 직접 연결되어 있다는 뜻이고, computer[i][i]가 항상 1인 이유는 자기 자신은 항상
자기 자신과 연결되어 있기 때문입니다.
- "연결 요소(connected component)"의 정의는 무엇인가? 네트워크 개수 = 연결 요소 개수라는 대응이 성립하는 이유는?
연결 요소(Connected Component)란 그래프에서 서로 경로를 통해 오갈 수 있는 정점들의 모임이며, 네트워크 개수와 연결 요소 개수가 일치하는 이유는 독립된 통신망 하나가 수학적으로 하나의 연결 요소와 정확히 1대 1로 대응하기 때문입니다.
- DFS가 한 번의 호출로 방문 가능한 노드 집합은 정확히 무엇과 일치하는가? (힌트: 시작 노드에서 도달 가능한 모든 노드)
시작노드에서 간선을 따라 도달할 수 있는 모든 노드의 집합과 정확히 일치

- 바깥 for문에서 `if not visited[i]`가 참일 때만 `dfs(i)`를 호출하고 `answer += 1`을 하는 것 — 이 두 동작이 항상 같은 조건에 묶여 있어야 하는 이유는?
새로운 연결 요소(그룹)를 처음 발견한 순간을 의미하므로, 전체 그룹 수를 정확히 세기 위해 dfs(i) 호출과 answer += 1이 항상 함께 실행되어야 합니다.
- 재귀 함수 안에서 `visited[node] = True`를 호출 시작 시점에 하는 것과, 재귀 호출 직전(이웃을 방문하기 전)에 하는 것의 차이는? 방문 표시를 아예 누락하면 어떤 문제가 생기는가?
함수 시작 시점 표시
장점: 시작 노드를 따로 처리할 필요가 없어 코드가 간결하고 직관적입니다.
이유: 예외 케이스가 발생할 확률이 가장 적습니다.
재귀호출 직전 표시
장점: 이미 방문한 노드는 함수 호출 자체를 안 하므로 미세하게 메모리와 속도가 절약됩니다.
단점: 탐색의 첫 시작 노드를 함수 밖에서 수동으로 방문 처리해야 하므로 실수가 자주 발생됩니다.

방문표시를 아예 누락하면 
무한 루프로 스택 오버플로우 메모리 초과로 프로그램이 강제 종료됨
시간 및 자원 방비: 사이클이 없는 트리나 그래프라도 여러 경로가 하나의 노드를 가리키고 있다면 같은 노드를 수없이 중복해서 방문합니다. 
이로 인해 연산 횟수가 기하급수적으로 늘어나 시간 초과가 발생합니다.

- 인접 행렬 기반 DFS의 시간 복잡도가 O(n²)인 이유는? (힌트: 각 노드마다 몇 개의 원소를 순회하는가, 그리고 그것이 몇 번 반복되는가)
방문하지 않은 노드마다 모두 방문하게 되는데 O(n^2) 방문한 노드는 다음에는 그보다 적게 방문하게 되므로 그보다 시간은 더욱 단축된다. 

이 6가지는 근거형 질문 1~4와 대응한다.

### A-2. 제출물 문항 직결 개념

- "탐색 시작 횟수와 연결 요소 수가 같다"를 증명하려면 무엇을 보여야 하는가?
  - (1) 서로 다른 시작 노드에서 시작한 DFS는 서로 다른 연결 요소를 방문한다 (겹치지 않음)
  - (2) 모든 노드는 어떤 시작 노드의 DFS에 의해 반드시 한 번은 방문된다 (빠짐없음)
  - 이 두 성질을 각각 무엇이라고 부르는가? (힌트: 분할의 정의 — 서로소, 전체를 덮음)
- `visited` 배열이 알고리즘 실행 내내 유지해야 하는 "불변식(invariant)"은 무엇인가? 예: "`visited[i] = True`이면 반드시 그 시점에 이미 어떤 연결 요소에 속하는 것으로 확정되었다" 같은 문장을 스스로 만들어볼 것
- 재귀 DFS를 스택을 이용한 반복(iterative) DFS로 바꾸면 무엇이 명시적으로 드러나는가? 재귀 호출이 암묵적으로 사용하는 자원은 무엇인가?
- 노드 수 n이 매우 클 때 재귀 DFS에서 발생할 수 있는 문제는? (힌트: 파이썬 재귀 깊이 제한, 콜 스택)

## Part B. 실험 힌트

이름은 예시다. 의미가 통하면 바꿔도 된다.

### B-1. visited 표시 위치를 바꿔서 관찰

- 현재 코드는 `dfs(node)` 진입 시 `visited[node] = True`를 먼저 하고 이웃을 순회한다
- 만약 `visited[node] = True`를 아예 지우고 실행하면 무슨 일이 나는가? 직접 실행해서 관찰할 것 (무한 재귀 또는 RecursionError 예상)
- 방문 표시를 재귀 호출 직전(`if not visited[i] and computers[node][i]: visited[i] = True; dfs(i)`)으로 옮기면 결과가 같은가, 다른가? 같다면 왜 같은지, 다르다면 어떤 입력에서 갈리는지 찾아본다

### B-2. 시작 노드를 바꿔서 답이 불변임을 확인

- 같은 그래프에서 바깥 for문의 순회 순서를 바꿔도(예: 역순으로 순회) 최종 `answer` 값이 같은지 확인
- 같은지 다른지, 같다면 그 이유를 "연결 요소는 그래프의 구조로 결정되지 정점을 순회하는 순서로 결정되지 않는다"는 문장과 연결해서 설명

### B-3. 반복(iterative) DFS로 재작성

- 스택(리스트)을 직접 써서 재귀 없이 같은 결과를 내는 버전을 작성
- 재귀 버전과 반복 버전이 모든 테스트 케이스에서 동일한 answer를 내는지 확인
- 두 버전의 차이를 "무엇을 스택에 넣는가", "언제 visited 표시를 하는가" 기준으로 비교

### B-4. n이 큰 경우 재귀 깊이 실험 (선택)

- 노드를 일렬로 연결한 사슬 그래프(1-2-3-...-n)를 생성해서 n을 키워가며 재귀 DFS 실행
- 어느 시점에 RecursionError가 나는지 확인하고, 반복 DFS는 같은 입력에서 문제없이 동작하는지 대조

## Part C. 반례/증명 구조화

- 근거형 질문 3번(방문 표시 위치 차이를 반례로 설명)은 B-1의 관찰 결과를 반례 형태로 정리하면 된다: "이런 입력에서, 방문 표시를 이 위치에 하지 않으면 이런 잘못된 동작이 나온다"
- 제출물 1번(탐색 시작 횟수 = 연결 요소 수)은 A-2에서 정리한 두 성질(서로소, 전체를 덮음)을 각각 코드의 어느 부분이 보장하는지 짚어서 서술
  - 서로소를 보장하는 부분: `if not visited[i]`
  - 전체를 덮음을 보장하는 부분: 바깥 for문이 0부터 n-1까지 모든 노드를 순회
- 제출물 2번(visited 불변식)은 A-2에서 만든 불변식 문장을 알고리즘 진행 단계별로(시작 전 / DFS 진입 시 / DFS 종료 후) 검증
- 증명은 관찰(실행해보니 이렇더라)이 아니라 코드 구조에서 논리적으로 도출해야 한다. B 파트의 실험은 증명을 확인하는 보조 수단이지, 증명 자체를 대체하지 않는다

## 막히면

- 근거형 질문 4번(시간 복잡도)은 dfs 함수 안 for문이 n번 돌고, dfs 자체가 최대 n번 호출된다는 사실에서 시작해봐라. 단, 각 노드는 한 번만 방문되므로 실제 dfs 함수 몸체가 "실행되는" 횟수와 "호출 시도되는" 횟수를 구분해야 한다.
- B-3이 막히면 재귀 호출이 일어나는 시점에 콜 스택에 무엇이 쌓이는지부터 손으로 그려봐라. 그 스택을 리스트로 흉내내면 된다.
