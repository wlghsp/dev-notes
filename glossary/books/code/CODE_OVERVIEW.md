# CODE — 전체 흐름 맥락

참고: Code — Charles Petzold (2000)

이 책은 컴퓨터가 어떻게 동작하는지를 밑바닥부터 쌓아올린다. 19세기 전신기에서 시작해 현대 GUI 운영체제까지, 한 계층이 그 아래 계층 위에서 만들어진다는 것을 보여준다.

---

## 1단계 — 신호와 전기 (Ch.1~6)

출발점은 단순한 질문이다. "어떻게 정보를 멀리 보낼 수 있을까?"

모스 부호가 핵심 통찰을 준다. 점과 대시, 두 가지 상태만으로 알파벳 전체를 표현할 수 있다. 두 상태면 충분하다.

전기는 이 두 상태를 물리적으로 구현한다. 전류가 흐른다/안 흐른다. 전선, 스위치, 배터리로 이루어진 회로가 신호를 만든다.

릴레이(relay)가 핵심 장치다. 약한 전류로 강한 전류를 제어한다. 신호를 멀리 보낼 때 중간에 릴레이를 놓으면 신호가 죽지 않는다. 그리고 릴레이 여러 개를 직렬/병렬로 연결하면 AND, OR 논리 연산이 된다.

```
전신기(먼 거리 신호) → 릴레이(신호 증폭) → 릴레이로 논리 연산 가능
```

---

## 2단계 — 수와 비트 (Ch.7~9)

전기 신호가 두 상태를 가진다는 것과 이진수가 0과 1 두 값을 가진다는 것은 같은 구조다.

10진수는 위치마다 10의 거듭제곱 값이 부여된다. 같은 방식으로 2진수는 위치마다 2의 거듭제곱이 부여된다. 8진수와 16진수는 이진수를 읽기 쉽게 묶은 것이다.

비트(bit)는 정보의 최소 단위다. n개 비트로 2ⁿ가지 상태를 표현할 수 있다. 불확실성이 클수록 정보량이 크다 — 섀넌(Shannon)의 통찰이다.

```
물리 신호(두 상태) = 수학 이진수(0과 1) → 비트로 정보를 측정
```

---

## 3단계 — 논리에서 연산으로 (Ch.10~13)

불 논리(Boolean logic)는 AND, OR, NOT 세 연산으로 이루어진다. 릴레이를 연결하는 방식이 이 연산들을 구현한다.

논리 게이트(logic gate)는 릴레이를 추상화한 것이다. NAND와 NOR만으로 모든 게이트를 만들 수 있다 — 이것이 범용성의 핵심이다.

게이트를 조합하면 덧셈이 된다. 반가산기(half adder)가 1비트 덧셈을 한다. 전가산기(full adder)가 올림수를 처리한다. 이것들을 이어 붙이면 여러 비트 덧셈기가 된다.

2의 보수(two's complement)로 음수를 표현하면 뺄셈이 덧셈과 같아진다. 회로 하나로 덧셈과 뺄셈을 모두 처리한다.

```
논리(AND/OR/NOT) → 게이트 → 반가산기 → 전가산기 → N비트 덧셈기
                                                   2의 보수로 뺄셈까지
```

## 4단계 — 기억 (Ch.14~17)

피드백(feedback)이 새로운 가능성을 연다. 출력을 입력으로 되돌리면 상태가 고정된다. 이것이 래치(latch)와 플립플롭(flip-flop)이다. 플립플롭은 1비트를 기억한다.

플립플롭 8개 → 1바이트 저장. 주소 버스로 원하는 위치를 선택하면 RAM이 된다.

클럭 신호(clock signal)는 회로의 박자다. 플립플롭들이 클럭에 맞춰 동작하면 예측 가능하게 움직인다. 클럭이 빠를수록 연산이 빠르다.

클럭에 맞춰 값이 증가하는 카운터(counter)는 자동화의 씨앗이다. 카운터가 주소를 자동으로 증가시키면 메모리를 순서대로 읽을 수 있다.

```
피드백 → 플립플롭(1비트 기억) → RAM → 클럭 → 카운터 → 자동 순회
```

## 5단계 — 하드웨어 압축 (Ch.18~19)

릴레이는 크고 느리고 전기를 많이 먹는다. 진공관(vacuum tube)이 릴레이를 전자적으로 대체했다. 더 빠르고 작았지만 발열이 심하고 자주 탔다.

트랜지스터(transistor)가 진공관을 대체했다. 반도체로 만든 스위치다. 작고 빠르고 오래간다.

집적회로(integrated circuit, IC)는 수천, 수백만 개의 트랜지스터를 하나의 칩 위에 올린 것이다. 마이크로프로세서(microprocessor)는 CPU 전체를 칩 하나에 구현했다.

마이크로프로세서는 명령어 집합(instruction set)을 가진다. 기계어 바이트들이 이 명령어들이다. 프로세서는 메모리에서 명령어를 읽고 → 해석하고 → 실행하는 사이클을 반복한다.

```
릴레이 → 진공관 → 트랜지스터 → 집적회로 → 마이크로프로세서
                                            명령어 집합으로 프로그래밍 가능
```

## 6단계 — 문자와 연결 (Ch.20~21)

숫자만 다루던 컴퓨터가 문자를 다루려면 약속이 필요하다. ASCII는 문자를 7비트 숫자로 매핑한 표준이다. A=65, a=97, 스페이스=32.

하지만 ASCII는 영어 기반이다. 다른 언어와 문자 체계를 다루기 위해 다양한 인코딩이 등장했다. 이것이 문자 인코딩 혼란의 시작이다.

버스(bus)는 CPU, 메모리, I/O 장치를 연결하는 공유 통로다. 주소 버스, 데이터 버스, 제어 버스로 나뉜다. 메모리 맵 I/O는 I/O 장치를 메모리 주소처럼 다루는 방법이다. 키보드 포트나 화면 메모리에 일반 메모리 읽기/쓰기 명령으로 접근한다.

```
숫자 → ASCII(문자 인코딩) → 버스(장치 연결) → 키보드/화면이 메모리처럼 동작
```

## 7단계 — 소프트웨어 계층 (Ch.22~25)

하드웨어가 갖춰졌다. 이제 소프트웨어가 그 위에 쌓인다.

운영체제(OS)는 하드웨어 추상화 계층이다. 프로그램이 디스크 섹터 번호를 몰라도 파일 이름으로 접근하게 해준다. API를 통해 키보드, 화면, 디스크에 표준 방법으로 접근한다. CP/M → MS-DOS → UNIX 순으로 발전했다.

수 표현의 확장. 정수와 2의 보수로는 충분하지 않다. 고정소수점은 소수점 위치를 약속으로 정한다. 부동소수점은 과학적 표기법의 이진 버전이다. IEEE 754 표준이 단정밀도(32비트)와 배정밀도(64비트)를 정의한다.

언어의 진화. 기계어 → 어셈블리(니모닉) → 고수준 언어(FORTRAN, ALGOL, C). 컴파일러가 고수준 언어를 기계어로 번역한다. 이식성과 생산성을 얻는 대신 어셈블리보다 실행 파일이 크고 느려진다.

그래픽 혁명. 텍스트 인터페이스에서 GUI로. 화면은 픽셀 배열이고, 픽셀 값이 비디오 메모리에 저장된다. 래스터 그래픽(비트맵)과 벡터 그래픽. GUI 운영체제는 수백 개의 그래픽 API 함수를 제공한다. 마우스, 아이콘, 창이 이 계층에서 등장한다.

```
OS(하드웨어 추상화)
   + 부동소수점(수 표현 확장)
   + 컴파일러(고수준 언어)
   + 그래픽 API(GUI)
→ 현대 컴퓨터의 소프트웨어 스택
```

## 전체 계층 요약

```
사용자
  ↕ GUI / 텍스트 인터페이스
응용 프로그램 (C, Java, Python...)
  ↕ 컴파일러 / 런타임
운영체제 (API, 파일시스템, 드라이버)
  ↕ 명령어 집합 (ISA)
마이크로프로세서
  ↕ 주소/데이터/제어 버스
RAM / ROM / I/O 장치
  ↕ 트랜지스터 → 논리 게이트
물리 전기 신호 (0과 1)
```

각 계층은 아래 계층의 복잡성을 숨기고 위 계층에 단순한 인터페이스를 제공한다. 이 책 전체가 이 한 문장을 25개 챕터에 걸쳐 구체적으로 보여주는 것이다.
