# interrupt

외부 하드웨어 이벤트가 CPU를 중단시키고 커널 핸들러를 실행시키는 메커니즘.

프로그램이 실행 중일 때 디스크 I/O가 완료됐거나, 키보드 입력이 들어오거나, 타이머가 만료됐을 때 — CPU가 그걸 어떻게 아는가? 폴링(polling)으로 계속 확인하는 방법도 있지만, 그러면 CPU를 낭비한다. 인터럽트는 하드웨어가 CPU에게 직접 신호를 보내는 방식이다.

인터럽트 처리 흐름:
1. 하드웨어 장치가 인터럽트 컨트롤러(PIC/APIC)에 신호 전송
2. 인터럽트 컨트롤러가 CPU에 인터럽트 라인 활성화
3. CPU가 현재 명령어 완료 후 실행을 중단
4. 현재 레지스터 상태를 스택에 저장
5. IDT(Interrupt Descriptor Table)에서 해당 인터럽트 벡터의 핸들러 주소 조회
6. 커널 모드로 전환 후 핸들러 실행
7. 핸들러 완료 후 원래 실행 흐름으로 복귀

인터럽트는 비동기적이다. 프로그램 실행 중 어느 시점에서든 발생할 수 있다. 이 점이 시스템 콜(trap)과의 차이다. trap은 프로그램이 명시적으로 요청한 동기적 이벤트다.

OS의 선점형 스케줄링은 타이머 인터럽트를 기반으로 동작한다. 타이머가 일정 주기로 인터럽트를 발생시키면, 커널이 현재 프로세스를 중단하고 다음 프로세스로 전환할 기회를 얻는다.
