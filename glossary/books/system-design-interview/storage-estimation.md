# storage-estimation (스토리지 용량 추정 방법)

시스템이 하루에 또는 일정 기간 동안 얼마나 많은 데이터를 저장해야 하는지 추정하는 계산. QPS 추정과 마찬가지로 활성 사용자 수에서 출발하되, 사용자 한 명이 만드는 데이터 크기를 곱해서 저장 공간을 구한다.

## 계산 흐름

1. 데이터를 만들어내는 일간 활성 사용자 수와 사용자당 평균 생성 건수를 구한다 (qps-estimation.md와 동일한 출발점)
2. 건당 평균 데이터 크기를 구한다 — 텍스트, 미디어 등 항목별로 나눠서 계산하면 정확도가 올라간다
3. 하루 저장량을 구한 뒤, 데이터 보존 기간(예: 5년)을 곱해서 전체 저장 용량을 추정한다

## 예시: Twitter 미디어 스토리지 추정

가정: DAU 1.5억, 사용자는 하루 평균 트윗 2개 작성, 트윗의 10%에 미디어 포함, 데이터는 5년 보관.

트윗 하나의 평균 구성: tweet_id 64바이트, 텍스트 140바이트, 미디어 1MB. 텍스트는 미디어에 비해 무시할 수 있는 크기이므로, 미디어 저장량만 추정하면 충분하다.

1. 하루 미디어 저장량 = 1.5억 × 2 × 10% × 1MB = 30TB
2. 5년 저장량 = 30TB × 365 × 5 ≈ 55PB

## 팁

정밀한 계산기 아니라 사고 과정을 보여주는 게 목적이다.

1. **반올림과 근사** — "99987 / 9.1" 같은 계산에 시간 쓰지 말고 "100,000 / 10"처럼 단순화한다
2. **가정을 먼저 적어둔다** — 나중에 다시 참조할 수 있도록 화이트보드나 종이에 남긴다
3. **단위를 명시한다** — "5"라고만 쓰면 5KB인지 5MB인지 헷갈린다. 단위를 붙이면 모호함이 사라진다
4. QPS, Peak QPS, 스토리지, 캐시 용량, 필요 서버 대수는 인터뷰에서 자주 나오는 추정 항목이니 미리 연습해둔다
