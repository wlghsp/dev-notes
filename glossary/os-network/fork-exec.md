# fork / exec (프로세스 모델)

**한 줄 정의**: 유닉스에서 새 프로세스를 만드는 두 가지 시스템 콜. fork는 복제, exec는 교체다.

---

## 왜 두 단계인가

유닉스에서 새 프로세스를 만드는 방법은 "기존 프로세스를 복사한 뒤, 원하는 프로그램으로 덮어쓰는" 두 단계다.

```
부모 프로세스
    ↓ fork()
자식 프로세스 (부모의 복사본)
    ↓ exec()
자식 프로세스 (새 프로그램으로 교체됨)
```

---

## fork()

현재 프로세스를 그대로 복제해서 자식 프로세스를 만든다. 메모리, 열린 파일 디스크립터, 환경 변수가 전부 복사된다.

fork() 호출 이후부터 부모와 자식은 독립적으로 실행된다. 반환값으로 둘을 구분한다.

```c
pid_t pid = fork();

if (pid == 0) {
    // 자식 프로세스: pid가 0
} else {
    // 부모 프로세스: pid는 자식의 PID
}
```

---

## exec()

현재 프로세스의 메모리를 새 프로그램으로 완전히 덮어쓴다. PID는 그대로 유지되지만, 실행 중인 코드와 데이터는 새 프로그램으로 교체된다. exec() 이후의 코드는 실행되지 않는다.

```c
execvp("ls", args);
// 이 줄은 실행되지 않음 — 위에서 이미 프로세스가 교체됨
```

---

## 둘을 합치면

터미널에서 명령어를 실행하는 과정이 정확히 이 두 단계다.

```
bash (쉘 프로세스)
    ↓ fork()
bash 복사본 (자식)
    ↓ exec("ls")
ls 프로세스 (bash 복사본이 ls로 교체됨)
```

쉘이 명령어를 실행할 때마다 이 과정이 반복된다. 부모 bash는 자식이 끝날 때까지 기다리고(wait), 자식은 명령어 실행 후 종료된다.

---

## macOS / Linux에서 동일하게 동작하는 이유

둘 다 유닉스 계보에서 나왔기 때문에 이 프로세스 모델을 그대로 계승한다. 터미널에서 명령어를 치거나, 서버에서 새 프로세스를 띄우거나, Java에서 `Runtime.exec()`를 호출할 때도 결국 내부에서 fork/exec가 일어난다.
