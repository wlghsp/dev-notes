# fork-exec (프로세스 생성)

유닉스에서 새 프로세스를 만드는 두 시스템 콜. CSAPP 1장과 8장에서 OS가 프로세스를 어떻게 추상화하는지 설명하는 맥락으로 등장한다.

## fork()

현재 프로세스를 복제해서 자식 프로세스를 만든다. 메모리 이미지, 열린 파일, 환경 변수가 전부 복사된다. 반환값으로 부모와 자식을 구분한다.

```c
pid_t pid = fork();
if (pid == 0) {
    // 자식: 반환값 0
} else {
    // 부모: 반환값은 자식의 PID
}
```

fork 이후 부모와 자식은 독립적인 주소 공간을 갖는다. 한쪽이 메모리를 바꿔도 다른 쪽에 영향 없다.

## exec()

현재 프로세스의 메모리를 새 프로그램으로 완전히 교체한다. PID는 유지되고 코드/데이터/스택이 새 프로그램으로 덮어씌워진다. exec 이후의 코드는 실행되지 않는다.

```c
execvp("ls", args);
// 여기는 실행되지 않음
```

## CSAPP 관점에서의 의미

CSAPP은 fork/exec를 OS의 프로세스 추상화를 설명하는 핵심 예시로 사용한다.

프로세스 추상화가 주는 두 가지 환상:
1. 독점적인 CPU 사용 — 실제로는 여러 프로세스가 번갈아 실행되지만 각 프로세스는 CPU를 혼자 쓰는 것처럼 느낀다
2. 독점적인 메모리 사용 — 가상 메모리 덕분에 각 프로세스는 자신만의 주소 공간을 갖는 것처럼 느낀다

fork는 이 추상화를 그대로 복제한다. 자식은 부모와 동일한 가상 주소 공간을 갖는 새로운 독립 프로세스로 시작한다.

## 셸에서의 동작

터미널에서 명령어를 실행할 때마다 이 과정이 반복된다.

```
bash (부모)
  ↓ fork()
bash 복사본 (자식)
  ↓ exec("ls")
ls 프로세스
  ↓ 종료
bash (부모가 wait()으로 기다렸다가 프롬프트 출력)
```
