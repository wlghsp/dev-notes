# counterexample (반례)

알고리즘이 틀렸음을 보여주는 구체적인 입력 인스턴스. 하나의 반례만으로 알고리즘의 올바름을 반증하기에 충분하다.

좋은 반례의 두 가지 조건:
1. verifiability(검증 가능성) — 해당 인스턴스에서 알고리즘이 내놓는 답과 더 나은 답 둘 다 계산할 수 있어야 한다
2. simplicity(단순함) — 불필요한 세부사항이 없어야 한다. 반례는 머릿속에서 다룰 수 있을 만큼 작아야 한다

반례를 찾는 전략:
- Think small — 알고리즘이 실패하는 경우는 보통 아주 작은 인스턴스에서 나타난다
- Think exhaustively — 작은 n에서 가능한 모든 구조를 따져본다
- Hunt for the weakness — greedy 알고리즘이면 "항상 가장 큰 것을 선택"하는 방식이 왜 틀릴 수 있는지 생각한다
- Go for a tie — 알고리즘의 판단 기준을 동률로 만들면 잘못된 선택을 유도할 수 있다
- Seek extremes — 매우 크거나 작은 값, 매우 가깝거나 먼 값의 혼합으로 구성된 인스턴스를 만든다
