# System Call (시스템 콜)

프로세스가 커널에 뭔가를 요청하는 유일한 창구다. 프로세스는 하드웨어에 직접 접근할 수 없기 때문에, 파일 읽기/소켓 열기/메모리 할당 같은 작업은 전부 시스템 콜을 통해 커널에 위임한다.

## 흐름

```
프로세스 (유저 모드)
  │
  │  write(fd, data, len)   ← 시스템 콜 호출
  │
  ▼
커널 모드 전환
  │
  │  실제 네트워크 전송 / 디스크 쓰기 처리
  │
  ▼
유저 모드 복귀
  │
  ▼
프로세스 계속 실행
```

시스템 콜을 호출하는 순간 CPU가 유저 모드에서 커널 모드로 전환된다. 커널이 작업을 마치면 결과를 돌려주고 다시 유저 모드로 돌아온다.

## 자주 보이는 시스템 콜

- `open` / `close` — 파일이나 소켓 열고 닫기
- `read` / `write` — 파일 디스크립터에서 읽고 쓰기
- `fork` — 현재 프로세스를 복제해서 자식 프로세스 생성
- `exec` — 현재 프로세스를 새 프로그램으로 교체
- `socket` / `connect` / `accept` — 네트워크 연결
- `mmap` — 메모리 매핑 (파일을 메모리처럼 접근)

## 왜 비용이 있나

유저 모드 ↔ 커널 모드 전환이 공짜가 아니다. CPU 레지스터 저장, 컨텍스트 전환, 권한 검사 등이 일어난다. 시스템 콜 한 번에 수백 ns 수준의 오버헤드가 생긴다.

그래서 고성능 I/O 라이브러리들은 시스템 콜 횟수를 줄이는 방향으로 설계한다. 예를 들어 한 번에 1바이트씩 `write()`를 1000번 호출하는 것보다 버퍼에 모아서 한 번에 `write()`하는 게 훨씬 빠르다.

## strace로 시스템 콜 확인

리눅스에서 `strace` 명령어로 프로세스가 어떤 시스템 콜을 호출하는지 볼 수 있다.

```bash
strace ls
```

`ls` 명령어 하나가 내부적으로 `openat`, `read`, `write`, `close` 등을 수십 번 호출하는 걸 볼 수 있다.
