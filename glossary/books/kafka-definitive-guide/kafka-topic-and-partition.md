# Kafka Topic과 Partition

Kafka에서 메시지를 분류하고 저장하는 논리적 단위와 물리적 단위.

## Topic

메시지를 카테고리별로 묶는 논리적 단위다. 데이터베이스의 테이블이나 파일시스템의 폴더에 가장 가깝다.

## Partition

토픽을 물리적으로 쪼갠 단위다. 커밋 로그 관점에서 보면 파티션 하나가 로그 하나에 해당한다.

메시지는 파티션 끝에만 추가되고(append-only), 파티션 안에서는 쓰인 순서대로 읽힌다(참고: append-only.md). 다만 토픽 전체로 보면 여러 파티션에 걸친 순서 보장은 없다 — 순서는 파티션 하나 안에서만 보장된다.

## 왜 파티션으로 쪼개는가

파티션 각각을 서로 다른 서버에 둘 수 있다. 그러면 토픽 하나를 여러 서버로 분산시켜서, 서버 한 대의 처리 능력을 넘어서는 규모로 확장할 수 있다.

또한 파티션은 복제(replicate)될 수 있어서, 서버 한 대에 장애가 나도 다른 서버에 있는 복제본으로 데이터를 지킬 수 있다(참고: kafka-broker-and-cluster.md).

## Stream이라는 용어와의 관계

파티션 개수와 상관없이 토픽 하나를 하나의 데이터 흐름으로 볼 때 stream이라는 용어를 쓴다. 프로듀서에서 컨슈머로 흘러가는 하나의 데이터 흐름이라는 의미다.

이 표현은 실시간으로 메시지를 처리하는 스트림 처리 프레임워크를 이야기할 때 특히 자주 쓰인다. 반면 오프라인 배치 처리 프레임워크는 데이터를 나중에 한꺼번에 처리한다는 점에서 대비된다.
