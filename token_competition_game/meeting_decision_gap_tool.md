# 회의 결정사항 전파 갭 해소 도구 (기획안)

## 문제 정의

회의에서 결정된 정책/방침이 참석자 밖으로 전파되지 않는 문제.
회의록은 존재하지만(텍스트 형태), 결정사항이 "누가 읽어야 하는지"와 연결되지 않아
관련 없는 사람은 놓치고, 관련 있는 사람도 스스로 찾아보지 않으면 모른다.

챗봇(질문하면 답하는 pull 방식)은 이 문제를 풀지 못한다.
애초에 결정이 있었는지 모르는 사람은 질문 자체를 하지 않기 때문.
→ 필요한 것은 push 방식: 지식이 사용자를 찾아가는 구조.

## 해결 방향

RAG cloud(rag.cloud.go.kr)에 이미 적재된 회의록을 활용해,
"결정사항 추출 → 기존 지식과 비교 → 관련자에게 이메일 발송"까지의 파이프라인을 구성.

### 파이프라인

1. **입력**: 텍스트 회의록을 Markdown으로 변환 후 RAG cloud에 업로드 (기존 가이드 절차 그대로, 참고: tool_for_ragcloud.md)
2. **결정사항 추출**: LLM이 회의록에서 일반 논의와 "결정사항/정책 변경"을 구분해 추출
   - 예: "앞으로 배포는 화요일에만 진행한다", "OO 요청 창구를 A팀에서 B팀으로 변경"
3. **기존 지식과 비교**: 추출된 결정사항을 RAG에 이미 있는 문서와 대조해 신규/변경/충돌 항목만 선별
   - 단순 재공지가 아니라 "무엇이 달라졌는지"를 판별하는 것이 핵심 부가가치
4. **관련자 판별**: 변경된 주제와 관련된 사람 후보 추출 (예: 과거 관련 문서를 조회했거나 관련 키워드로 질문한 이력이 있는 사람)
5. **출력**: 이메일로 변경사항 요약 발송

## 확정된 설계 범위

- 알림 출력 채널: 이메일로 확정
  - amaranth(사내 채팅 앱) 연동은 webhook/봇 API 지원 여부가 불확실해 이번 사례에서는 제외
  - 이메일은 구현 난이도가 낮아 바로 프로토타입 가능한 단계까지 설계

## 열린 질문 (다음 단계에서 결정 필요)

- 결정사항 추출 프롬프트/기준을 어떻게 검증할 것인가 (오탐/누락 방지)
- 관련자 판별 로직의 정확도를 어떻게 확보할 것인가 (열람 이력이 없는 신규 관련자는 어떻게 포함시킬지)
- 이메일 발송 주기 (회의록 업로드 즉시 vs 배치)

## RAG cloud만으로 이 파이프라인이 가능한가

RAG cloud(가이드 기준)는 "Dataset 업로드 → Chunk → Chat/Search"만 제공하는 저장 + 검색 + 생성 서비스.
파이프라인 단계별로 RAG cloud가 감당 가능한 범위를 나누면:

| 단계 | RAG cloud로 가능한가 |
|---|---|
| 회의록 저장 | 가능 (Dataset 업로드) |
| 결정사항 추출 | 부분 가능 — Chat으로 프롬프트 질의는 되지만, 업로드 시점에 자동 트리거하려면 API 필요 |
| 기존 지식과 비교 | 검색 기능은 활용 가능하나 "신규/변경/충돌 판별" 로직은 RAG cloud 바깥에서 구현해야 함 |
| 관련자 판별 | RAG cloud가 열람 이력 데이터를 제공하지 않으면 불가능 — 별도 사용 로그 시스템 필요 |
| 이메일 발송 | RAG cloud 기능이 아님, 무조건 외부 구현 |

**결론**: RAG cloud는 이 도구의 "지식 저장 + 검색 엔진" 역할만 가능하다.
파이프라인의 오케스트레이션(자동 트리거, 비교 로직, 발송)은 RAG cloud API 유무에 따라 설계가 완전히 갈린다.

- API가 있다면: RAG cloud를 지식 저장/검색 백엔드로 두고, 그 위에 트리거·비교·발송 파이프라인을 얹는 구조
- API가 없다면: RAG cloud는 사람이 직접 쓰는 창구로만 남기고, 이 파이프라인은 RAG cloud를 거치지 않고 별도 LLM 호출로 독립 구축해야 함

### Bitbucket의 역할

Bitbucket은 이 파이프라인에서 "회의록 저장소"가 아니라 **파이프라인 실행 위치(스케줄러/CI)** 후보로 검토.
예: Bitbucket Pipelines가 주기적으로 RAG cloud API를 호출해 신규 문서를 확인하고 처리하는 러너 역할.
→ RAG cloud API 존재 여부가 확인되기 전까지는 Bitbucket 활용 여부도 확정할 수 없음.
