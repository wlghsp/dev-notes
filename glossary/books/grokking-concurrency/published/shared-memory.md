# shared-memory

여러 태스크(스레드 또는 프로세스)가 같은 메모리 영역에 직접 접근하는 IPC 방식.

태스크들이 공통 메모리를 마치 자신의 로컬 변수처럼 읽고 쓴다. 한 태스크가 값을 바꾸면 즉시 다른 태스크에도 반영된다. OS가 할당만 해줄 뿐, 이후 통신에는 개입하지 않는다.

## 빠른 이유

데이터 복사가 없다. 메시지 패싱은 데이터를 유저 공간 → 커널 공간 → 유저 공간으로 복사하지만, 공유 메모리는 같은 메모리를 직접 읽고 쓰기 때문에 IPC 방식 중 가장 빠르다.

## 위험한 이유

OS가 접근 순서를 보장하지 않는다. 두 태스크가 같은 메모리에 동시에 쓰면 race-condition이 발생한다. 동기화를 직접 구현해야 하고, 잘못하면 데이터가 깨진다.

## SMP와의 관계

공유 메모리는 SMP(Symmetric Multiprocessing) 시스템에 특히 잘 맞는다. SMP에서는 모든 CPU가 하나의 논리적 주소 공간을 공유하므로, 공유 메모리 IPC가 자연스럽게 동작한다. 스레드는 원래부터 같은 프로세스 주소 공간을 공유하기 때문에, SMP에서 스레드 기반 공유 메모리가 가장 효율적이다.

## 단점

단일 머신을 넘어 확장할 수 없다. 분산 시스템에서는 사용할 수 없고, 그 경우엔 메시지 패싱으로 전환해야 한다.
