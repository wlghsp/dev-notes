# Apache Flink

**한 줄 정의**: 대규모 스트림 처리를 위한 별도 분산 처리 클러스터. Kafka Streams보다 복잡하고 강력하다.

---

## 무엇인가

Flink는 독립적인 분산 처리 시스템이다. Kafka와 별개로 자체 클러스터를 운영하고, Kafka를 데이터 소스로 연결해서 쓰는 구조가 흔하다.

```
Kafka (이벤트 저장/전달)
     ↓
Flink 클러스터 (복잡한 스트림 처리)
     ↓
결과 저장소 (DB, 다른 Kafka 토픽, S3 등)
```

---

## Kafka Streams와의 차이

Kafka Streams는 Kafka에 종속된 라이브러리다. Java 앱 안에서 돌아가고, Kafka 토픽을 입출력으로만 쓴다.

Flink는 독립 시스템이다. Kafka 외에 다양한 소스(데이터베이스, 파일 시스템 등)에서 읽을 수 있고, 훨씬 복잡한 연산을 대규모로 처리할 수 있다.

```
규모와 복잡도 기준:

단순한 토픽 간 변환/필터  →  Kafka Streams
복잡한 집계, 대규모 조인  →  Flink
```

---

## Flink가 잘하는 것

복잡한 윈도우 집계가 핵심이다. "지난 1시간 동안 특정 사용자의 이벤트 패턴"처럼 시간 기반 집계를 정교하게 처리한다.

스트림과 배치를 같은 API로 처리할 수 있다. 실시간 처리와 과거 데이터 재처리를 동일한 코드로 다룬다.

장애가 발생해도 처리 상태를 체크포인트로 저장해두기 때문에 재시작 후 이어서 처리할 수 있다.

---

## 언제 쓰는가

Kafka Streams로 감당이 안 되는 규모나 복잡도가 생겼을 때다. 별도 클러스터를 운영해야 하는 비용이 있어서, 단순한 파이프라인에는 오버스펙이다.

실시간 이상 탐지, 대규모 추천 시스템, 실시간 집계 대시보드 같은 사례에서 자주 등장한다.
