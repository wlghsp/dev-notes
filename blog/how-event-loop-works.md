# 싱글스레드 이벤트루프는 어떻게 비동기로 처리하는가

> "싱글스레드면 하나씩 순서대로 처리하는 거 아닌가?" — 흔한 오해다. 핵심은 **누가 I/O를 실제로 처리하는가**다.

---

## JS 스레드는 I/O를 직접 하지 않는다

Node.js 싱글스레드는 I/O를 직접 기다리지 않는다. OS에 시키고 돌아온다.

```
┌─────────────────────────────────────────┐
│            Node.js Process              │
│                                         │
│  ┌──────────────┐   ┌────────────────┐  │
│  │  이벤트루프   │   │  libuv 스레드풀 │  │
│  │  (JS 스레드) │   │  (4개 기본)    │  │
│  │  싱글스레드  │   │  파일 I/O 등   │  │
│  └──────┬───────┘   └───────┬────────┘  │
│         │                   │           │
└─────────┼───────────────────┼───────────┘
          │                   │
          ▼                   ▼
      OS 커널 (네트워크 I/O는 OS가 직접 — epoll/kqueue)
```

- **네트워크 I/O** (DB 쿼리, HTTP 호출): OS 커널이 처리
- **파일 I/O 등 일부**: libuv 스레드풀이 처리
- **JS 스레드**: 요청만 날리고, 콜백 큐에서 결과를 받아 실행

---

## 타임라인으로 보면

```
시간 →

JS 스레드:  [요청A 접수]→[DB 쿼리 등록]→[요청B 접수]→[API 호출 등록]→[요청C 처리]→[A콜백 실행]→[B콜백 실행]
                              ↓                              ↓
OS 커널:              [DB 쿼리 처리 중................................응답]
OS 커널:                                         [API 호출 중...................응답]
```

JS 스레드는 I/O 응답을 기다리며 멈추지 않는다. OS가 응답을 가져오면 **콜백 큐에 쌓이고**, 이벤트루프가 JS 스레드가 한가할 때 꺼내서 실행한다.

---

## 이벤트루프가 하는 일

이벤트루프는 무한 루프다. 각 반복(tick)마다 순서대로 체크한다:

```
while (할 일이 있다) {
  1. 타이머 체크          → setTimeout, setInterval 만료된 것 실행
  2. I/O 콜백 체크        → OS에서 완료 신호 온 것 실행
  3. 대기 (이 단계가 핵심) → OS에게 "뭐라도 완료되면 깨워줘" 하고 블로킹
  4. setImmediate 체크
  5. close 콜백 체크
}
```

3단계에서 OS의 `epoll`(Linux) / `kqueue`(macOS)를 사용한다. OS가 여러 소켓을 동시에 감시하다가 하나라도 응답이 오면 Node.js를 깨운다. 이게 **I/O 멀티플렉싱**이다.

> "감시"만 하고 있다가 응답이 오는 순간 이벤트루프를 깨운다. JS 스레드는 그 순간에만 깨어나서 콜백을 실행하고 다시 대기한다.

---

## 역할 분담 정리

| 역할 | 누가 하는가 |
|---|---|
| JS 코드 실행 | 이벤트루프 (싱글스레드) |
| 네트워크 I/O 대기/감시 | OS 커널 (epoll/kqueue) |
| 파일 I/O | libuv 스레드풀 |
| 완료 신호 전달 | OS → libuv → 콜백 큐 → 이벤트루프 |

---

## 그럼 진짜 싱글스레드인가

엄밀히는 아니다. **JS 코드가 실행되는 스레드**가 하나다.

libuv는 내부적으로 스레드풀(기본 4개)을 갖는다. 파일 I/O처럼 OS가 논블로킹으로 지원하지 않는 작업은 여기서 처리된다. 단, 이 스레드들은 JS 코드를 실행하지 않는다. I/O 작업만 담당하고 완료 시 이벤트루프에 알릴 뿐이다.

```
"Node.js는 싱글스레드다" = JS 코드는 항상 하나의 스레드에서만 실행된다
                          (동시에 두 JS 코드가 실행되는 일은 없다)
```

## 왜 CPU 집약 작업에 약한가

이 구조의 약점이 여기서 드러난다.

```javascript
app.get('/heavy', (req, res) => {
  // 이미지 리사이즈, 암호화, 복잡한 계산...
  const result = heavyCpuWork(); // JS 스레드가 2초 동안 여기 묶임
  res.json(result);
});
```

JS 스레드가 CPU 계산에 묶여 있으면 이벤트루프가 돌지 못한다. 그 2초 동안 다른 모든 요청이 멈춘다.

```
JS 스레드: [요청A — CPU 계산 중 2초........] [요청B] [요청C]
                   ↑
           이 2초 동안 B, C는 아무것도 못 함
```

I/O는 OS에 위임하니까 괜찮지만, CPU 작업은 위임할 곳이 없다. 싱글스레드의 구조적 한계다.

> 해결책: `worker_threads`로 별도 스레드에서 실행하거나, CPU 집약 작업은 별도 서비스로 분리한다.

---

## 요약

싱글스레드가 빠른 이유는 **"I/O는 OS한테 전부 위임하고, 자기는 코드 실행에만 집중"** 하기 때문이다. 스레드가 블로킹되는 게 아니라 OS가 논블로킹으로 감시하는 구조다.

멀티스레드처럼 스레드 수십 개를 만들어 메모리를 쓰는 게 아니라, OS의 I/O 멀티플렉싱 기능을 그대로 활용한다.
