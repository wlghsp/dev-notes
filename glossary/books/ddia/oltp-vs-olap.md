# oltp-vs-olap
참고: column-oriented-storage.md, data-warehouse.md

---

데이터베이스를 사용하는 패턴이 두 갈래로 나뉜다는 관찰에서 출발한다. 같은 DB 기술을 쓰더라도 어떤 종류의 쿼리를 날리느냐에 따라 최적화 방향이 완전히 달라진다.

## OLTP — Online Transaction Processing

사용자와 직접 상호작용하는 애플리케이션이 날리는 쿼리다. 특징은 소수의 레코드를 키로 찾아서 읽거나 삽입/갱신하는 것이다. 쿼리 하나가 처리하는 데이터 양은 적지만, 동시에 매우 많은 쿼리가 들어온다.

예를 들어 쇼핑몰에서 특정 유저의 주문 내역을 조회하거나, 결제 시 재고 수량을 1 줄이는 것이 OLTP 쿼리다. 레이턴시가 낮아야 하고 동시성을 잘 처리해야 한다.

## OLAP — Online Analytical Processing

데이터 분석가나 BI 도구가 날리는 쿼리다. 수백만~수억 개의 레코드를 스캔해서 집계한다. 쿼리 하나가 처리하는 데이터 양이 막대하지만, 동시에 실행되는 쿼리 수는 적다.

예를 들어 "지난 분기 지역별 매출 합계"나 "특정 캠페인 이후 구매 전환율 변화"가 OLAP 쿼리다. 레이턴시보다 처리량이 중요하고, 쿼리 패턴을 미리 예측하기 어렵다.

## 왜 분리하는가

OLTP DB에서 OLAP 쿼리를 돌리면 전체 테이블을 스캔하느라 운영 쿼리까지 느려진다. 두 워크로드의 요구사항 자체가 다르다. OLTP는 레코드 단위 접근에 최적화된 row-oriented 저장이 유리하고, OLAP는 특정 컬럼만 빠르게 집계하는 column-oriented 저장이 유리하다. 이 이유로 OLAP 워크로드는 별도의 data-warehouse.md로 분리한다.
