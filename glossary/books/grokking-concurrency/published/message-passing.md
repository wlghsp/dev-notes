# message-passing

태스크가 OS가 관리하는 채널을 통해 메시지를 주고받는 IPC 방식.

각 태스크는 고유한 이름(식별자)을 가지며, 이름을 지정해 메시지를 보내고 받는다. OS가 채널을 만들고, 데이터를 유저 공간에서 커널 채널로, 다시 수신자의 유저 공간으로 복사한다. 공유 메모리보다 비용이 크지만, OS가 전달을 보장하고 동기화를 관리해준다.

## 구현 방법 1: pipe

단방향 바이트 스트림. 한쪽에서 write(), 다른 쪽에서 read()한다.

unnamed pipe는 부모-자식처럼 관련 태스크끼리만 쓸 수 있다. 파일 디스크립터를 공유해야 하기 때문이다. named pipe(FIFO)는 파일시스템에 실체로 존재하기 때문에 무관한 태스크도 접근할 수 있다. FIFO 원칙(먼저 들어온 것이 먼저 나감)으로 처리된다.

Go 채널은 개념적으로 pipe와 유사하다. 고루틴 간 통신을 위한 채널이다.

## 구현 방법 2: message queue

FIFO 원칙으로 메시지를 보관하는 큐. pipe와 달리 여러 태스크가 동시에 쓰고 읽을 수 있다.

생산자는 큐에 넣고 바로 다음 작업을 계속한다. 소비자는 큐에서 꺼내 처리한다. 이 구조 덕분에 생산자와 소비자가 서로를 직접 알 필요가 없는 느슨하게 결합된(loosely coupled) 시스템을 만들 수 있다. OS 스케줄러, 라우터, 마이크로서비스 시스템에서 널리 사용된다.

## 구현 방법 3: socket(UDS)

같은 머신의 태스크 간 양방향 통신. UNIX domain socket(UDS)을 사용한다. send()/recv() 인터페이스로 동작하며, 나중에 코드 변경 없이 네트워크 소켓으로 확장할 수 있다.

직렬화(serialization)가 필요하기 때문에 가장 구현 비용이 크다. 그러나 가장 유연하고 분산 시스템으로 확장하기 쉽다.

## Go와 Erlang의 철학

Go: "공유해서 통신하지 말고, 통신해서 공유하라(Do not communicate by sharing memory; instead, share memory by communicating)."

Erlang: 프로세스가 어떤 데이터도 공유하지 않고 오직 메시지 패싱으로만 통신한다.
