# JIT (Just In Time) 컴파일

자바 소스코드는 먼저 바이트 코드라는 중간 언어로 컴파일된다. JVM은 이 바이트 코드를 한 줄씩 읽어 기계어로 번역하며 실행하는데, 이 방식을 인터프리트라고 부른다.

인터프리트 방식은 이미 최적화된 기계어를 바로 읽는 컴파일 언어보다 실행 속도가 느리다. JIT 컴파일러는 이 문제를 완화하기 위해, 애플리케이션 실행 중에 자주 쓰이는 코드만 동적으로 기계어로 컴파일한다.

## Hotspot과 프로파일링

JIT 컴파일러가 자주 실행된다고 판단한 코드 부분을 Hotspot이라고 부른다. JIT 컴파일러는 코드 실행 횟수, 루프 반복 횟수, 메소드 호출 횟수 등을 측정해 기록하는데, 이를 프로파일링이라고 한다. 이 프로파일링 결과로 Hotspot을 식별하고, 식별된 메소드 단위로 기계어 번역을 수행한다.

번역된 기계어는 코드 캐시(Code Cache)라는 별도 캐시 공간에 저장된다. 이후 같은 코드가 다시 호출되면 재컴파일 없이 코드 캐시에서 꺼내 쓰므로 성능이 향상된다. 오라클은 이 JIT 컴파일 방식 전체를 Hotspot이라고 부르기도 한다.

## C1 컴파일러와 C2 컴파일러

JIT 컴파일러는 최적화 수준이 다른 C1과 C2 두 컴파일러로 구성된다.

C1 컴파일러는 빠른 실행 속도를 위해 코드를 빠르게, 하지만 제한된 수준으로 최적화하고 컴파일한다. 특정 메서드가 C1의 호출 임계치를 넘으면 C1이 컴파일을 수행하고, 결과를 코드 캐시에 저장한다.

C2 컴파일러는 C1보다 더 높은 수준의 최적화를 수행한다. 메서드 호출이 C2의 임계치를 넘으면 C2가 다시 최적화와 컴파일을 수행하고, 마찬가지로 코드 캐시에 저장한다. 기본 임계치는 C1이 1,500회, C2가 10,000회다.

## Tiered Compilation

인터프리터, C1, C2를 조합해 컴파일 과정을 5개 Level로 나눈 것을 Tiered Compilation이라고 부른다.

Level 0(Interpreted Code)은 인터프리터가 모든 코드를 실행하는 초기 단계다. Level 1(Simple C1 Compiled Code)은 C1이 복잡도가 낮다고 판단한 메서드를 컴파일하는 단계로, 추가 최적화 여지가 없어 프로파일링도 수집하지 않는다. Level 2(Limited C1 Compiled Code)는 C2 컴파일러 큐가 꽉 찼을 때 제한된 수준으로 프로파일링과 최적화를 수행하는 단계다. Level 3(Full C1 Compiled Code)은 일반적인 상황에서 C1이 최대 수준으로 프로파일링과 최적화를 수행하는 단계다. Level 4(C2 Compiled Code)는 C2가 장기적인 성능을 위해 최적화를 수행하는 최종 단계로, 완전히 최적화된 것으로 간주해 더 이상 프로파일링하지 않는다.

배포 직후에는 코드 캐시가 비어 있어 코드가 인터프리터로 실행되거나 C1·C2의 컴파일 과정을 거쳐야 하므로, 이 구간에서 필연적으로 성능 저하가 발생한다. 참고: jvm-warm-up.md
