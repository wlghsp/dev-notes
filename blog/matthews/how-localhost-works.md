# localhost의 동작 원리

## 네트워크 인터페이스(NI)와 라우팅 테이블

OS는 네트워크로 데이터를 보낼 때 어떤 네트워크 인터페이스(NI)를 사용할지 정해야 한다. IP 주소만 보면 어떤 NI를 써야 할지 OS가 판단하기 때문에, 사용자는 평소 이를 신경 쓸 필요가 없다.

예를 들어 다음과 같은 규칙으로 목적지 IP 대역에 따라 사용할 NI가 정해진다.

- `192.168.0.0/16` 대역 → NI2
- `127.0.0.0/8` 대역 → NI0
- `0.0.0.0/0`(그 외 모든 대역) → NI1

이렇게 목적지 IP 대역에 따라 어떤 NI를 쓸지 관리하는 것을 네트워크 라우팅 테이블이라고 한다. 하나의 PC에 여러 통신 장비가 있어도, 대역으로 망을 구분할 수 있기 때문에 로컬 네트워크와 인터넷을 나누는 등 다양한 조합이 가능해진다.

## Loopback NI

여러 NI 중 `127.0.0.0/8` 대역을 담당하는 것이 Loopback NI다. 이는 OS만 설치하면 기본으로 제공되는 가상의 장치로, 실제 WIFI나 LAN이 없어도 존재한다.

`127.0.0.0/8`은 애초에 로컬용으로 예약된 대역이고, 그중 `127.0.0.1`은 첫 번째 IP로 자기 자신을 가리킨다. 즉 Loopback NI는 내가 보낸 요청을 받아 다시 나에게 응답을 돌려주는 장치, 말하자면 내 입이자 귀다.

가상 장치이기 때문에 물리적인 통신 과정이 생략되어 매우 빠르게 동작한다. 우리가 `localhost`를 쓸 수 있는 것은 바로 이 Loopback NI 덕분이다.

## localhost의 패킷 흐름

1. **앱에서 데이터 전송**: 웹 브라우저가 `http://127.0.0.1`로 요청을 보낸다. 이 요청은 TCP/IP 스택을 통해 패킷으로 나가려 한다.
2. **라우팅 판단**: TCP/IP 스택이 목적지 IP `127.0.0.1`을 확인하고 Loopback NI로 보낸다. 패킷을 외부로 내보내지 않고 로컬로 되돌린다.
3. **로컬로 패킷 전달**: 패킷이 다시 TCP/IP 스택 계층으로 전달되고, 올바른 포트로 전달된다.
4. **서버 앱 요청 수신**: 로컬 서버 앱(예: Node.js 앱)이 요청을 수신하고 응답을 생성해 다시 Loopback 인터페이스로 보낸다.
5. **응답 패킷의 루프백 경로**: 응답 패킷도 같은 과정을 거쳐 최종적으로 요청했던 로컬 브라우저에 전달된다.

## 마무리

매일 사용하지만 원리는 몰라도 되는 기술이 많다. 그러나 원리를 알면 트러블슈팅이 쉬워지는 경우가 있는데, Loopback NI가 그런 사례다.

참고로 Loopback에는 `127.0.0.1`뿐 아니라 다른 IP도 할당할 수 있다. 지금은 거의 쓰이지 않지만, 과거에는 소프트웨어로 구현한 L4 라우터를 만들 때 이런 방식이 활용되곤 했다.
