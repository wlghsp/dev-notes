# cpu-architecture (CPU 아키텍처)

CPU가 명령어를 어떤 형식으로 처리하는지에 대한 설계 규격. 아키텍처가 다르면 같은 프로그램을 실행할 수 없다.

## 왜 아키텍처가 다르면 실행이 안 되나

컴파일된 프로그램은 특정 아키텍처의 기계어로 변환된다. x86-64용 기계어는 ARM CPU가 해석할 수 없다. 명령어 형식 자체가 다르기 때문이다.

그래서 패키지를 받을 때 자기 CPU 아키텍처에 맞는 바이너리를 받아야 한다.

## 주요 아키텍처

x86-64 (= amd64)
- Intel과 AMD가 만든 데스크탑/서버용 아키텍처
- x86은 32비트, x86-64는 64비트 확장 버전
- AMD가 64비트 확장을 먼저 만들었기 때문에 amd64라고도 부름. Intel CPU에서도 동일하게 동작
- 대부분의 리눅스 서버, 윈도우 PC가 여기 해당

ARM (aarch64 / arm64)
- 모바일, 임베디드에서 시작해서 지금은 Mac, 서버까지 확장
- RISC 기반 설계 — 명령어를 단순하고 고정 길이로 유지해서 저전력·고효율이 가능했다. x86은 CISC로 명령어가 복잡하고 가변 길이다
- Apple Silicon(M1, M2, M3)이 ARM 기반. aarch64가 ARM 64비트를 가리키는 공식 명칭
- AWS Graviton, Raspberry Pi도 ARM

## x86-64 vs amd64 — 같은 건가?

같은 거임. amd64는 AMD가 설계했지만 Intel도 채택해서 지금은 동일한 아키텍처를 가리키는 두 가지 이름이다. 패키지 저장소에서 `amd64`라고 써있어도 Intel CPU에서 설치하면 됨.

## 패키지 받을 때 헷갈리는 이유

이름이 통일되어 있지 않음.

- x86-64 = amd64 = x64 — 전부 같은 것
- arm64 = aarch64 — 전부 같은 것
- armv7, armhf — 32비트 ARM. Raspberry Pi 구형 모델 등

Mac M1/M2/M3 쓰면 arm64, 일반 Intel/AMD PC 쓰면 amd64(x86-64) 받으면 됨.

## Rosetta 2 (참고)

Apple Silicon Mac에서 x86-64 바이너리를 실행할 수 있는 이유. Apple이 만든 변환 레이어로 x86-64 명령어를 실시간으로 ARM으로 변환해서 실행한다. 네이티브보다는 느리지만 대부분 체감하기 어려운 수준.
