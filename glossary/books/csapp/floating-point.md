# floating point (부동소수점)

실수를 비트로 표현하는 방식. IEEE 754 표준을 따른다.

## 왜 부동소수점인가

정수는 비트로 표현하기 쉽다. 근데 3.14, 0.001 같은 실수는 어떻게 비트로 표현할까?

고정소수점(fixed point) 방식은 소수점 위치를 고정한다. 예를 들어 8비트 중 4비트는 정수부, 4비트는 소수부로 고정. 표현 범위가 너무 좁다.

부동소수점은 소수점 위치를 고정하지 않고 "떠다니게(floating)" 한다. 과학적 표기법과 같은 원리다.

```
3.14 = 3.14 × 10^0
0.001 = 1.0 × 10^-3
```

## IEEE 754 구조

32비트(float) 기준:

```
[부호: 1비트] [지수: 8비트] [가수: 23비트]
```

- 부호 비트 — 0이면 양수, 1이면 음수
- 지수(exponent) — 소수점 위치를 결정
- 가수(mantissa) — 실제 숫자 값

64비트(double)는 지수 11비트, 가수 52비트.

## 부동소수점의 한계 — 정밀도 문제

10진수 0.1을 2진수로 정확히 표현할 수 없다. 2진수로는 무한히 반복되는 소수가 된다. 비트 수가 유한하니까 어딘가에서 잘라야 하고, 그 순간 오차가 생긴다.

```java
0.1 + 0.2 = 0.30000000000000004  // Java, Python 등에서 공통
```

이게 버그가 아니라 부동소수점의 구조적 한계다.

## 돈 계산에 float를 쓰면 안 되는 이유

0.1 + 0.2가 0.3이 아닌 것처럼, 금액 계산에 부동소수점을 쓰면 오차가 쌓인다. 1원, 1센트 단위 오차가 수백만 건 쌓이면 큰 문제가 된다. 그래서 금융 시스템은 정수(원 단위)나 BigDecimal 같은 정밀도 보장 타입을 쓴다.

## FPU와의 관계

부동소수점 연산은 ALU가 아니라 FPU(Floating Point Unit)가 처리한다. 정수 연산보다 회로가 복잡해서 클럭이 더 걸린다. AI 학습에서 GPU를 쓰는 이유 중 하나가 GPU가 부동소수점 연산에 최적화된 FPU를 대량으로 가지고 있기 때문이다.
