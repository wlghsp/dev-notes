# container-image (컨테이너 이미지)
참고: dockerfile.md, container-registry.md, linux-namespace.md

---

애플리케이션과 그 실행 환경 전체를 하나로 묶은 패키지다. 파일시스템, 라이브러리, 설정 파일, 실행 명령까지 포함한다. 이미지로부터 컨테이너(실행 중인 프로세스)가 만들어진다.

## 레이어 구조

이미지는 여러 레이어가 쌓인 구조다. Dockerfile의 각 지시어(directive)마다 새 레이어가 생성된다. 레이어는 여러 이미지 간에 공유되며, 동일한 레이어는 한 번만 저장된다. 이미지 배포 시 이미 가진 레이어는 다운로드하지 않아도 된다.

## Copy-on-Write (CoW)

여러 컨테이너가 같은 이미지 레이어를 공유하더라도 서로 간섭하지 않는 이유다. 이미지 레이어는 읽기 전용이고, 각 컨테이너는 자신만의 읽기/쓰기 레이어를 하나 더 가진다. 컨테이너가 공유 레이어의 파일을 수정하면 해당 파일 전체가 자신의 읽기/쓰기 레이어로 복사된 뒤 수정된다. 원본 레이어는 그대로다.

파일을 삭제해도 실제로는 읽기/쓰기 레이어에 "삭제됨"으로 표시만 될 뿐, 아래 레이어에서는 사라지지 않는다. 그래서 이미지에서 파일을 삭제해도 이미지 크기는 줄지 않는다.

## 이식성의 한계

컨테이너는 자체 커널이 없고 호스트 OS의 커널을 그대로 사용한다. 따라서 특정 커널 버전이나 커널 모듈이 필요한 앱은 해당 모듈이 없는 호스트에서 실행이 안 된다. 또한 특정 CPU 아키텍처(x86)용으로 컴파일된 이미지는 다른 아키텍처(ARM)에서 실행할 수 없다.
