# Hypervisor (하이퍼바이저)

물리 서버 하나 위에서 여러 개의 가상 머신(VM)을 실행할 수 있게 해주는 소프트웨어다. 각 VM은 자기만의 OS와 커널을 가지고, 물리 하드웨어를 독립적으로 쓰는 것처럼 동작한다.

## 왜 필요한가

물리 서버를 하나씩 사면 비싸고, 대부분의 시간에 CPU/메모리를 다 쓰지도 않는다. 하이퍼바이저로 하나의 물리 서버를 여러 VM으로 쪼개면 자원을 효율적으로 쓸 수 있다. AWS EC2, GCP Compute Engine 같은 클라우드 인스턴스가 이 방식으로 동작한다.

## Type 1 vs Type 2

**Type 1 (베어메탈 하이퍼바이저)**
하드웨어 위에 하이퍼바이저가 직접 올라간다. OS 없이 하이퍼바이저가 하드웨어를 직접 제어한다.

```
하드웨어
└── 하이퍼바이저 (Type 1)
    ├── VM1 (OS + 앱)
    ├── VM2 (OS + 앱)
    └── VM3 (OS + 앱)
```

성능이 좋다. 서버 가상화에 쓰인다. VMware ESXi, Microsoft Hyper-V, KVM이 여기 속한다.

**Type 2 (호스트형 하이퍼바이저)**
기존 OS 위에서 하이퍼바이저가 애플리케이션처럼 실행된다.

```
하드웨어
└── 호스트 OS
    └── 하이퍼바이저 (Type 2)
        ├── VM1 (OS + 앱)
        └── VM2 (OS + 앱)
```

설치가 쉽다. 개발 환경에 쓰인다. VirtualBox, VMware Workstation, macOS의 Parallels가 여기 속한다.

## VM vs 컨테이너

하이퍼바이저 기반 VM과 Docker 같은 컨테이너는 다르다.

VM은 OS와 커널을 통째로 들고 다닌다. 완전히 격리되어 있고 무겁다.

컨테이너는 호스트 OS의 커널을 공유한다. 격리는 하되 OS를 따로 띄우지 않아서 가볍고 빠르다.

```
VM:         [앱 | OS | 커널]  ← 커널까지 각자
컨테이너:   [앱]              ← 호스트 커널 공유
```

보안 격리가 중요하면 VM, 빠르게 많이 띄워야 하면 컨테이너를 쓴다.
