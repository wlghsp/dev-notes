# CPU (Central Processing Unit)

명령어를 읽고, 해석하고, 실행하는 장치. 컴퓨터의 두뇌라고 불리지만 실제로는 여러 부품의 집합이다.

## 내부 구성

**ALU (Arithmetic Logic Unit)**

실제 연산을 처리하는 회로. 덧셈, 뺄셈, AND/OR 같은 산술/논리 연산을 담당한다. CPU의 계산기 부분이다.

**레지스터**

CPU 안에 있는 아주 작은 임시 저장 공간. ALU가 연산할 데이터를 여기서 꺼내고 결과를 여기에 넣는다. 접근 속도가 1 클럭 수준으로 가장 빠르다. 참고: register.md

**캐시 (L1 / L2 / L3)**

레지스터보다는 크고 느리지만, 메모리(RAM)보다는 훨씬 빠른 중간 저장소. 자주 쓰는 데이터를 여기에 올려둬서 메모리 접근을 줄인다. L1이 가장 빠르고 작고, L3가 가장 느리고 크다.

**제어 장치 (Control Unit)**

명령어를 해석하고 ALU, 레지스터, 메모리에 신호를 보내서 순서대로 실행시키는 지휘자. 직접 연산하지는 않는다.

**MMU (Memory Management Unit)**

가상 주소를 물리 주소로 변환하는 하드웨어. 프로세스 격리와 메모리 보호를 담당한다. 참고: virtual-memory.md

**TLB (Translation Lookaside Buffer)**

MMU 안에 붙어있는 주소 변환 캐시. 최근 변환 결과를 저장해서 페이지 테이블 조회를 생략한다. 참고: tlb.md

## 명령어 실행 흐름

```
1. Fetch  — PC(프로그램 카운터)가 가리키는 주소에서 명령어를 가져옴
2. Decode — 제어 장치가 명령어를 해석
3. Execute — ALU가 레지스터 데이터로 연산
4. Write  — 결과를 레지스터 또는 메모리에 저장 (MMU가 주소 변환)
```

이 사이클을 클럭마다 반복한다. 3GHz CPU는 초당 30억 번 이 사이클을 돈다.

## 속도 계층

CPU가 데이터를 어디서 가져오느냐에 따라 속도 차이가 극단적이다.

- 레지스터 — 1 클럭
- L1 캐시 — 4~5 클럭
- L2 캐시 — 10~20 클럭
- L3 캐시 — 40~50 클럭
- RAM — 200~300 클럭
- 디스크(SSD) — 수십만 클럭

레지스터와 디스크의 차이가 수십만 배다. CPU가 메모리 접근을 최대한 줄이고 캐시와 레지스터를 활용하는 이유다.

참고: register.md, virtual-memory.md, tlb.md
