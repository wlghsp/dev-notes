# Cohesion (응집도)

**한 줄 정의**: 하나의 모듈 안에서 요소들이 얼마나 하나의 책임에 집중되어 있는가를 나타내는 척도.

---

## 무엇을 측정하는가

모듈 안에 있는 코드들이 "같은 이유로 존재하는가"를 본다. 응집도가 높으면 모듈 안의 코드들이 하나의 목적을 위해 모여 있다. 응집도가 낮으면 관련 없는 것들이 한 곳에 섞여 있다.

```
낮은 응집도:
  UserService
  ├── 사용자 생성
  ├── 이메일 발송
  ├── PDF 생성
  └── 결제 처리
  (왜 이게 다 같이 있는가?)

높은 응집도:
  UserService    → 사용자 생성, 조회, 수정, 삭제
  EmailService   → 이메일 발송
  PdfService     → PDF 생성
  PaymentService → 결제 처리
```

---

## 왜 높은 응집도가 좋은가

응집도가 높으면 변경 이유가 하나다. 이메일 발송 방식이 바뀌어도 UserService는 건드릴 필요가 없다. EmailService만 수정하면 된다.

응집도가 낮으면 하나를 수정할 때 관련 없는 코드도 함께 읽어야 한다. 이해 비용이 올라가고, 실수로 다른 기능을 건드릴 가능성도 높아진다.

---

## Coupling과의 관계

Cohesion과 Coupling은 항상 함께 나온다. 방향은 반대다.

Cohesion은 모듈 안을 본다 — 안에서 얼마나 잘 뭉쳐 있는가.
Coupling은 모듈 밖을 본다 — 밖과 얼마나 덜 엮여 있는가.

좋은 설계는 둘을 동시에 만족한다.

```
High Cohesion: 모듈 안은 강하게 뭉친다
Low Coupling:  모듈 밖과는 느슨하게 연결한다
```

하나만 있으면 부족하다. 응집도가 높아도 다른 모듈에 잔뜩 의존하면 변경이 전파된다. 결합도가 낮아도 모듈 안이 뒤죽박죽이면 유지보수가 어렵다.
