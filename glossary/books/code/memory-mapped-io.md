# memory-mapped-io

메모리 맵 I/O(Memory-Mapped I/O)는 입출력 장치를 메모리 주소 공간의 일부로 취급하는 방식이다. CPU는 특별한 I/O 명령 없이 평범한 메모리 읽기/쓰기 명령으로 장치를 제어한다.

## 핵심 아이디어

CPU는 주소 버스로 주소를 내보내고 데이터를 읽거나 쓴다. 이때 그 주소에 RAM이 연결될 수도 있고, 키보드나 디스플레이 같은 장치가 연결될 수도 있다. CPU 입장에서는 그 주소에 뭐가 연결되어 있는지 상관없다. 그냥 주소를 내보내고 데이터를 주고받을 뿐이다.

예를 들어 64KB 주소 공간의 일부를 RAM이 아닌 비디오 보드에 할당하면, CPU가 그 주소에 값을 쓸 때마다 화면 내용이 바뀐다. 비디오 보드의 RAM이 해당 주소를 "소유"하고 있어서, CPU가 쓴 값이 화면으로 이어진다.

## 8080의 두 가지 방식

8080은 메모리 맵 I/O와 별도의 I/O 포트 방식을 모두 지원한다.

**I/O 포트 방식 (8080 전용)**
64KB 메모리 주소와 분리된 256개의 I/O 포트 주소를 따로 갖는다.
- `OUT pp` — 누산기 값을 포트 pp로 출력
- `IN pp` — 포트 pp에서 값을 읽어 누산기로

포트 주소는 메모리 주소와 완전히 분리되어 있다. 8228 System Controller 칩이 메모리 접근인지 I/O 접근인지를 제어 신호로 구분한다.

**메모리 맵 I/O 방식**
장치를 그냥 특정 메모리 주소 범위에 배치한다. CPU는 MOV, LDA, STA 같은 일반 메모리 명령으로 장치를 제어한다. 6800은 I/O 포트 방식이 없고 메모리 맵 I/O만 지원한다.

## 비디오 디스플레이가 메모리 맵 I/O의 대표 사례

320×200 해상도의 흑백 디스플레이는 64,000개의 픽셀을 가진다. 픽셀 하나에 1비트면 8,000바이트(≈8KB)가 필요하다. 이 8KB를 CPU 주소 공간의 특정 위치에 배치하면, CPU가 그 주소 영역에 쓰는 데이터가 곧바로 화면에 나타난다.

텍스트만 표시하는 경우는 더 적은 메모리로 가능하다. 25행 × 40열 = 1000개의 문자. 각 문자를 7비트 ASCII 코드로 저장하면 약 1KB면 된다. 화면에 글자를 그리는 건 비디오 보드 안의 문자 생성기(character generator, ROM)가 맡는다. CPU는 어떤 문자인지(ASCII 코드)만 써주면 된다.

## 인터럽트와 I/O

키보드처럼 비동기적으로 입력이 들어오는 장치는 CPU가 계속 확인하기 어렵다. CPU가 반복적으로 장치를 확인하는 방식(폴링)보다 효율적인 방법이 인터럽트다.

키를 누르면 키보드 하드웨어가 CPU의 INT 핀에 신호를 보낸다. CPU는 현재 실행 중이던 Program Counter를 스택에 저장하고, 인터럽트를 처리하는 코드 위치로 점프한다. 처리가 끝나면 스택에서 주소를 복원해 원래 자리로 돌아온다. 참고: instruction-set-code.md
