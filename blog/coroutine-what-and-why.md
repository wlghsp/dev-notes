# 고루틴(Goroutine)과 코루틴(Coroutine) — 개념부터 실제 사용까지

> Prometheus 발표에서 "Go는 고루틴으로 동시성을 처리한다"고 했을 때, 코루틴이 뭐냐는 질문이 나왔다. 이 문서는 코루틴의 정의부터 고루틴과의 차이, 실제 코드 예시까지 담았다.

---

## 1. 코루틴의 정의

**코루틴 = Co(함께, 서로) + Routine(규칙적 일의 순서)**

> "실행의 지연과 재개를 허용함으로써, 비선점적 멀티태스킹을 위한 서브루틴을 일반화한 컴퓨터 프로그램 구성요소"

간단히 말하면: **"함수의 실행을 중간에 멈췄다가 나중에 재개할 수 있는 기능"**

### 중요한 특징: 스레드에서 실행된다

코루틴은:
- 독립적으로 실행될 수 없음 (스레드 없이 불가능)
- **스레드 내에서** 실행됨
- 중단 지점에서 **스레드를 해방** → 다른 코루틴이 같은 스레드 사용

```
일반 스레드 (1개 스레드 = 1개 작업)
  스레드1 → 작업1 (계속 실행)
  스레드2 → 작업2 (계속 실행)

코루틴 (여러 코루틴 = 1개 스레드)
  스레드1 → 코루틴A (중단) → 코루틴B (중단) → 코루틴A (재개) → ...
```

### 서브루틴 vs 코루틴

```
서브루틴 (일반 함수)
  start → ... → end
  (처음부터 끝까지 한번에 실행)

코루틴
  start → ... → pause(중단, 스레드 해방) → ... → resume(재개) → ... → end
  (여러 지점에서 중단하고 재개, 스레드 재사용)
```

## 2. 코루틴의 역사

**1958년**: 코루틴 개념 탄생

**발전 과정**:
- 1960s-1970s: 어셈블리, LISP에서 사용
- 1980s-1990s: 주목도 낮음 (동시성 처리는 스레드와 프로세스로 충분했음)
- 2000s-2010s: **비동기 프로그래밍의 필요성 증가** → 코루틴 재조명
- 현재: **Python, JavaScript, Kotlin, C#, Rust** 등 대부분의 언어에서 지원

## 3. 왜 코루틴이 필요한가

### 문제: 쓰레드와 콜백의 한계

**쓰레드 방식** — 여러 쓰레드 생성
```java
// 3개의 작업을 처리하려면 3개의 쓰레드 필요
new Thread(() -> goToWork()).start();      // thread-1
new Thread(() -> leaveWork()).start();     // thread-2
new Thread(() -> playMusic()).start();     // thread-3
```

**문제점**:
1. Context switching 비용이 큼 (OS가 쓰레드 전환할 때마다 오버헤드)
2. 많은 쓰레드 생성 시 메모리 낭비
3. 동기화 (Lock, Mutex) 코드 복잡

**콜백 방식** — 콜백 지옥
```javascript
asyncGoToWork(() => {
  asyncLeaveWork(() => {
    asyncPlayMusic(() => {
      // ...
    });
  });
});
```

**문제점**:
1. 코드 가독성 최악 (들여쓰기 지옥)
2. 예외처리 어려움
3. 흐름 파악이 어려움

### 해결: 코루틴으로 경량 동시성 처리

```python
# Python 코루틴 — 순차적이지만 효율적
async def main():
    await goToWork()      # 1번 일시 중지
    await leaveWork()     # 2번 일시 중지
    await playMusic()     # 3번 일시 중지
```

**장점**:
1. **Context switching 없음**: 하나의 쓰레드에서 여러 작업 처리
2. **메모리 효율**: 쓰레드보다 훨씬 가벼움 (수천~수만 개 가능)
3. **가독성**: 동기 코드처럼 읽을 수 있음
4. **예외처리**: try-catch로 간단함

## 4. 핵심 개념: 비선점형 vs 선점형

### 비선점형 (코루틴)

```
코루틴 A: 작업 1 → [멈춤] → 작업 2 → [멈춤] → 완료
코루틴 B:           작업 1 → [멈춤] → 작업 2 → 완료
코루틴 C:                    작업 1 → [멈춤] → 작업 2 → 완료

특징: 자신이 멈춤 신호를 내릴 때까지 CPU를 절대 빼앗기지 않음
```

**"멈춘다"는 것은 프로그래머가 `await`/`yield`로 명시함**

### 선점형 (쓰레드)

```
쓰레드 1: 작업 1 → [강제로 멈춤] → 작업 2 → [강제로 멈춤] → 완료
쓰레드 2:         작업 1 → [강제로 멈춤] → 작업 2 → [강제로 멈춤] → 완료
쓰레드 3:                  작업 1 → [강제로 멈춤] → 작업 2 → 완료

특징: OS가 강제로 쓰레드를 멈추고 다른 쓰레드로 전환 (Context switching)
```

## 5. 병행성 vs 병렬성

### 병행성(동시성, Concurrency)

```
시간축 →

코루틴 1: ████░░░░░
코루틴 2: ░░░░████░░░░
코루틴 3: ░░░░░░░░████

한 쓰레드에서 빠르게 번갈아 실행되는 것처럼 보임
실제로는 한 번에 하나씩 실행 (논리적 병렬)
```

### 병렬성(Parallelism)

```
시간축 →

코어 1: ████████
코어 2: ░░░░░░░░████
코어 3: ░░░░░░░░░░░░████

여러 코어에서 **동시에** 물리적으로 실행됨
```

**코루틴은 병행성만 제공** (한 쓰레드에서)
**쓰레드/고루틴은 병렬성도 제공** (여러 코어에서)

## 6. "경량 스레드"라는 표현에 대해

코루틴을 "경량 스레드"라고 부르는 이유:
- 스레드처럼 **동시에** 여러 작업 처리 가능
- 스레드보다 **훨씬 가벼움** (메모리, CPU 비용)
- 같은 자원으로 **훨씬 많은** 작업 처리 (10,000개 코루틴 = 11개 스레드)

하지만 정확하게는:
- 스레드 **자체**가 아니라, 스레드를 **재사용**하는 메커니즘
- 스레드 **대신** 경량하게 동시성 처리하는 기능

> **결론**: "경량 스레드"는 개념적 표현이지, 실제로 스레드 새로 만드는 게 아니다. 스레드를 효율적으로 재사용할 뿐.

## 7. 고루틴(Goroutine)이란

**Go 언어의 경량 스레드. OS 스레드처럼 동작하지만 훨씬 가볍다.**

```go
go function()  // ← 이 한 줄로 고루틴 시작
```

특징:
- 여러 코어에서 **병렬로** 실행 (진정한 동시 실행)
- 경량이라 수천 개 만들어도 괜찮음
- Go 런타임이 OS 스레드에 자동으로 할당

```go
// Prometheus 메트릭 수집 예시
go scrapeMetrics("server1")  // 고루틴 1
go scrapeMetrics("server2")  // 고루틴 2
go scrapeMetrics("server3")  // 고루틴 3
// ← 3개가 여러 코어에서 동시에 실행됨
```

## 8. 고루틴 vs 코루틴

| 구분 | 고루틴 (Go) | 코루틴 (Python, Kotlin 등) |
|---|---|---|
| **정의** | 경량 스레드 | 함수 일시 중지/재개 기능 |
| **동시성 방식** | 병렬성 + 병행성 (여러 코어) | 병행성만 (한 스레드) |
| **제어** | Go 런타임이 자동 관리 | 프로그래머가 `await`로 명시 |
| **언어** | Go만 | Python, JavaScript, Kotlin, Rust 등 |
| **메모리** | 매우 가벼움 | 더욱 가벼움 |
| **용도** | CPU/I/O 작업 모두 | 주로 I/O 대기 시간 활용 |

### 실행 흐름 비교

**고루틴 (자동 관리)**
```
고루틴 1: [코어1] 작업 → 작업 → 작업 → 완료
고루틴 2: [코어2] 작업 → 작업 → 작업 → 완료
고루틴 3: [코어3] 작업 → 작업 → 작업 → 완료
(Go 런타임이 자동으로 코어에 할당, 언제 멈출지도 자동)
```

**코루틴 (명시적 제어)**
```
코루틴 1: await(멈춤) → [다른 코루틴 실행] → await(멈춤) → 완료
코루틴 2:                   await(멈춤) → [다른 코루틴 실행] → 완료
코루틴 3:                                       await(멈춤) → 완료
(프로그래머가 await로 "여기서 멈춘다"고 명시)
```

## 9. 코드로 비교하기

### Kotlin 코루틴 예시

#### launch() — 결과가 필요 없을 때
```kotlin
// 3개의 작업을 동시에 처리 (결과 불필요)
runBlocking {
    launch {
        println("출근")
        delay(1000)  // ← 스레드 블로킹 없이 일시 중단
        println("도착")
    }

    launch {
        println("퇴근")
        delay(2000)  // ← 스레드 블로킹 없이 일시 중단
        println("집 도착")
    }

    launch {
        println("음악 재생")
        delay(500)   // ← 스레드 블로킹 없이 일시 중단
        println("음악 종료")
    }

    // runBlocking은 모든 launch가 완료될 때까지 대기
}

// 실행 순서:
// "출근", "퇴근", "음악 재생" (동시 시작)
// → 0.5초 후 "음악 종료"
// → 1초 후 "도착"
// → 2초 후 "집 도착"
// (전체 2초만 소요, 스레드는 블로킹되지 않음)
```

#### async() — 결과가 필요할 때
```kotlin
// 여러 페이지를 비동기로 가져오고 결과 비교
suspend fun main() = coroutineScope {
    val firstPage = async {
        delay(50)    // API 대기
        "First page"
    }

    val secondPage = async {
        delay(100)   // API 대기
        "Second page"
    }

    // 두 결과 모두 준비될 때까지 대기
    val result = firstPage.await() == secondPage.await()
    println("Pages are equal: $result")
}

// launch vs async 차이:
// - launch: 결과 없음 (Job 반환)
// - async: 결과 있음 (Deferred<T> 반환, .await()로 얻음)
```

#### suspend 함수 — 일시 중단 가능한 함수
```kotlin
// suspend 키워드가 붙으면 코루틴 내에서만 호출 가능
suspend fun greet() {
    println("Hello")
    delay(1000)  // ← 스레드를 블로킹하지 않고 일시 중단
    println("World")
}

suspend fun main() {
    greet()  // suspend 함수는 suspend 함수에서만 호출
}
```

### Python 코루틴 예시

```python
import asyncio

async def goToWork():
    print("출근")
    await asyncio.sleep(1)  # ← 스레드 블로킹 없이 1초 대기
    print("도착")

async def leaveWork():
    print("퇴근")
    await asyncio.sleep(2)  # ← 스레드 블로킹 없이 2초 대기
    print("집 도착")

async def playMusic():
    print("음악 재생")
    await asyncio.sleep(0.5)  # ← 스레드 블로킹 없이 0.5초 대기
    print("음악 종료")

async def main():
    # 3개를 동시에 실행 (asyncio.gather 사용)
    await asyncio.gather(
        goToWork(),
        leaveWork(),
        playMusic()
    )

asyncio.run(main())
# 전체 2초만 소요 (순차면 3.5초)
# 한 스레드에서 3개가 번갈아가며 실행됨
```

## 10. Kotlin 코루틴의 주요 특징

### launch vs async 차이

| 구분 | `launch()` | `async()` |
|---|---|---|
| **반환값** | `Job` (값 없음) | `Deferred<T>` (값 있음) |
| **결과 조회** | 불가능 | `.await()` 사용 |
| **사용 시기** | 결과가 필요 없을 때 | 결과가 필요할 때 |
| **예** | 로그 기록, 알림 전송 | API 응답 수집, 계산 결과 |

### 구조화된 동시성 (Structured Concurrency)

```kotlin
suspend fun main() = coroutineScope {
    launch { /* 작업 1 */ }
    launch { /* 작업 2 */ }
    // 모든 launch가 완료될 때까지 대기
    // 부모 코루틴이 실패하면 자식들도 자동 취소됨
}
```

**장점**: 부모-자식 관계가 명확해서 메모리 누수 방지

### 스레드 vs 코루틴 리소스 비교 (실제 성능 측정)

**같은 작업 10,000개 처리:**
```
일반 스레드: 2,282개 스레드 생성 필요
코루틴:      약 11개 스레드만 필요 (재사용)

결과: 코루틴이 약 4배 더 빠르고 자원 효율적
```

**메모리 비교:**
```
스레드 1,000개 = ~500MB 메모리
코루틴 50,000개 = ~500MB 메모리

코루틴은 스레드의 50배를 같은 메모리로 처리!
```

**왜 이렇게 효율적인가?**
- 스택리스 코루틴(Stackless Coroutine): 별도 스택 메모리 불필요
- 컨텍스트 스위칭 비용 제거: 중단 지점에서 스레드 해방
- 스레드 재사용: 같은 스레드를 여러 코루틴이 공유

## 11. "경량 스레드"의 정확한 의미

결국 다음과 같이 정리할 수 있습니다:

```
고루틴 = 진정한 "경량 스레드"
  (OS 스레드를 감싼 래퍼, 여러 코어에서 병렬 실행)

코루틴 = "스레드를 재사용하는 경량한 메커니즘"
  (스레드가 아니라, 스레드 내에서 번갈아 실행)
```

**그래서 두 가지 표현 모두 맞습니다:**
- "코루틴은 경량 스레드다" = 스레드보다 가볍다 (맞음)
- "코루틴은 스레드가 아니다" = 스레드 자체는 아니다 (맞음)

둘 다 관점의 차이일 뿐, 모순이 아닙니다.

## 12. 정리

### 한 줄 요약

| 개념 | 설명 |
|---|---|
| **코루틴** | 함수를 일시 중지/재개할 수 있는 기능 — 스레드 블로킹 없이 경량 동시성 처리 |
| **고루틴** | Go의 경량 스레드 — 자동 병렬 실행 |
| **차이** | 제어 방식 (명시적 vs 자동) + 실행 위치 (한 스레드 vs 여러 코어) |

### 선택 기준

**코루틴 사용 시기**:
- I/O 대기가 많은 작업 (네트워크, DB, 파일)
- 수천 개의 가벼운 작업 처리
- 복잡한 비동기 로직을 순차적으로 작성하고 싶을 때

**고루틴 사용 시기**:
- Go 언어를 사용할 때 (코루틴이 필요 없을 정도로 간단)
- CPU와 I/O 작업을 모두 병렬로 처리해야 할 때
- 높은 처리량이 필요할 때

## 13. 발표 때 하지 못한 답변

> Q: "고루틴과 코루틴이 같은 건가요?"

**A**: "비슷하지만 다르다.
- **고루틴**: Go의 경량 스레드. Go 런타임이 자동으로 여러 코어에 할당해서 병렬 실행. 프로그래머는 `go` 키워드만 붙이면 끝.
- **코루틴**: 다른 언어의 기능. 프로그래머가 `await`로 '여기서 멈춰'라고 명시하면, 한 스레드에서 번갈아 실행. 경량이고 가독성이 좋음.

둘 다 효율적으로 동시성을 다루지만, **제어 방식이 다르다**. Go는 자동, 코루틴은 명시적."
