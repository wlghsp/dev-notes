# trap

소프트웨어에서 발생하는 동기적 인터럽트.

인터럽트가 하드웨어가 비동기적으로 발생시키는 것이라면, trap은 실행 중인 프로그램이 스스로 발생시키는 동기적 이벤트다. 현재 명령어의 직접적인 결과로 발생하기 때문에, 발생 위치가 명확하다.

trap이 발생하는 경우:
1. 시스템 콜 — 프로그램이 의도적으로 `syscall` 명령어 실행
2. 예외(exception) — 실행 중 오류 상황 (page fault, divide-by-zero, invalid opcode 등)
3. 브레이크포인트 — 디버거가 `int 3` 명령어를 삽입해 실행을 중단

시스템 콜의 관점에서 trap은 유저 모드에서 커널 모드로 진입하는 통로다. x86-64에서는 `syscall` 명령어가 이를 수행한다. 구형 x86에서는 `int 0x80`을 사용했다.

page fault도 trap의 일종이다. 프로세스가 물리 메모리에 없는 페이지에 접근하면 CPU가 page fault trap을 발생시키고, 커널이 핸들러에서 디스크에서 해당 페이지를 로드한 뒤 실행을 재개한다.

trap과 인터럽트의 공통점: 둘 다 커널 모드로 전환되고, IDT를 통해 핸들러가 실행된다.
trap과 인터럽트의 차이: 발생 시점이 동기적이냐 비동기적이냐.
