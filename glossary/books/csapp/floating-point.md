# floating point (부동소수점)

실수를 비트로 표현하는 방식. IEEE 754 표준을 따른다.

## 왜 부동소수점인가

정수는 비트로 표현하기 쉽다. 근데 3.14, 0.001 같은 실수는 어떻게 비트로 표현할까?

고정소수점(fixed point) 방식은 소수점 위치를 고정한다. 예를 들어 8비트 중 4비트는 정수부, 4비트는 소수부로 고정. 표현 범위가 너무 좁다.

부동소수점은 소수점 위치를 고정하지 않고 "떠다니게(floating)" 한다. 과학적 표기법과 같은 원리다.

```
3.14 = 3.14 × 10^0
0.001 = 1.0 × 10^-3
```

## 이진 분수

IEEE 754를 이해하려면 이진 분수부터 알아야 한다. 소수점 왼쪽 비트는 2의 양수 거듭제곱, 오른쪽 비트는 2의 음수 거듭제곱이다.

```
101.11(2진수) = 1×2² + 0×2¹ + 1×2⁰ + 1×2⁻¹ + 1×2⁻²
             = 4 + 0 + 1 + 0.5 + 0.25
             = 5.75
```

이진 분수로 표현 가능한 수는 `x × 2^y` 형태인 수뿐이다. 0.2(= 1/5) 같은 수는 이진 분수로 정확히 표현이 안 된다. 무한히 반복되는 이진 소수가 되기 때문이다.

## IEEE 754 구조

32비트(float) 기준:

```
[부호: 1비트] [지수(exp): 8비트] [가수(frac): 23비트]
```

- 부호 비트 — 0이면 양수, 1이면 음수
- 지수(exponent) — 소수점 위치를 결정. 바이어스 인코딩으로 저장
- 가수(fraction) — 실제 숫자의 소수 부분

64비트(double)는 지수 11비트, 가수 52비트.

## 바이어스 인코딩 (bias encoding)

지수 필드는 음수와 양수를 모두 표현해야 한다. 부호 비트를 쓰는 대신 바이어스(bias) 값을 빼는 방식을 쓴다.

- float(8비트 지수): bias = 127
- double(11비트 지수): bias = 1023

지수 필드에 저장된 값 e에서 bias를 빼서 실제 지수 E를 구한다. `E = e - bias`. 예를 들어 float에서 e = 130이면 E = 130 - 127 = 3, 즉 2³ = 8을 곱한다.

## 암묵적 선행 1비트 (implied leading 1)

정규화된 수(normalized)에서 가수는 항상 `1.xxxx` 형태다. 맨 앞의 1은 항상 고정이므로 비트에 저장하지 않는다. 23비트 가수 필드가 실질적으로 24비트 정밀도를 갖는 이유다.

## IEEE 754의 세 가지 값 범주

**정규화된 수 (normalized)** — 지수 필드가 전부 0도, 전부 1도 아닌 경우. 가장 일반적인 경우다. 가수는 `1.frac` 형태로 해석된다.

**비정규화된 수 (denormalized)** — 지수 필드가 전부 0인 경우. 0을 포함한 0에 매우 가까운 수를 표현한다. 가수는 `0.frac` 형태로 해석된다.

**특수값** — 지수 필드가 전부 1인 경우.
- frac이 전부 0 → Infinity (±∞). 아주 큰 수끼리 곱하거나 0으로 나눌 때
- frac이 0이 아님 → NaN (Not a Number). √-1, ∞-∞ 같이 실수로 표현할 수 없는 연산 결과

## 부동소수점의 한계 — 정밀도 문제

10진수 0.1을 2진수로 정확히 표현할 수 없다. 2진수로는 무한히 반복되는 소수가 된다. 비트 수가 유한하니까 어딘가에서 잘라야 하고, 그 순간 오차가 생긴다.

```java
0.1 + 0.2 = 0.30000000000000004  // Java, Python 등에서 공통
```

이게 버그가 아니라 부동소수점의 구조적 한계다.

## 돈 계산에 float를 쓰면 안 되는 이유

0.1 + 0.2가 0.3이 아닌 것처럼, 금액 계산에 부동소수점을 쓰면 오차가 쌓인다. 1원, 1센트 단위 오차가 수백만 건 쌓이면 큰 문제가 된다. 그래서 금융 시스템은 정수(원 단위)나 BigDecimal 같은 정밀도 보장 타입을 쓴다.

## FPU와의 관계

부동소수점 연산은 ALU가 아니라 FPU(Floating Point Unit)가 처리한다. 정수 연산보다 회로가 복잡해서 클럭이 더 걸린다. AI 학습에서 GPU를 쓰는 이유 중 하나가 GPU가 부동소수점 연산에 최적화된 FPU를 대량으로 가지고 있기 때문이다.
