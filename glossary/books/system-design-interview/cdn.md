# CDN (Content Delivery Network)

지리적으로 분산된 서버 네트워크로 정적 콘텐츠(이미지, CSS, JS, 비디오 등)를 사용자와 가까운 위치에서 빠르게 제공하는 서비스.

## 동작 방식

사용자가 웹사이트를 방문하면 가장 가까운 CDN 서버가 정적 콘텐츠를 전달한다. CDN 서버가 멀수록 로딩이 느려진다.

CDN 워크플로우:

1. User A가 image.png 요청 (CDN URL 사용)
2. CDN에 해당 이미지가 없으면 원본 서버(또는 S3)에서 가져온다
3. CDN이 이미지를 캐시하고 User A에게 반환, TTL이 포함된다
4. User B가 같은 이미지 요청 → TTL이 유효하면 CDN에서 바로 반환

## 고려사항

**비용** — CDN은 3rd party 제공자가 운영하며 데이터 전송량에 따라 비용이 발생한다. 자주 사용되지 않는 파일은 CDN 캐싱 이점이 없다.

**캐시 만료 시간 설정** — 시간에 민감한 콘텐츠는 적절한 TTL이 중요하다. 너무 길면 콘텐츠가 stale해지고 너무 짧으면 원본 서버 요청이 많아진다.

**CDN 장애 대응** — CDN이 일시 장애를 겪으면 클라이언트가 원본 서버에서 직접 가져올 수 있어야 한다.

**파일 무효화(Invalidation)** — TTL 만료 전에 CDN에서 파일을 제거하려면 CDN 벤더 API를 호출하거나 URL에 버전 파라미터를 추가한다 (예: image.png?v=2).
