# os-abstraction

복잡한 하드웨어를 감추고 프로그램에게 단순한 인터페이스만 보여주는 OS의 핵심 역할.

## 왜 추상화가 필요한가

프로그램이 하드웨어를 직접 다루면 CPU 스케줄링, 메모리 배치, 디스크 장치 드라이버를 모두 알아야 한다. 하드웨어가 바뀌면 프로그램도 바꿔야 한다. OS가 그 복잡함을 감추고 단순한 인터페이스를 제공하면 프로그램은 하드웨어를 몰라도 된다.

## OS가 제공하는 대표적인 추상화 3가지

**프로세스** — CPU의 추상화.

실제로는 CPU 하나를 여러 프로그램이 수백 밀리초마다 번갈아 쓴다. 하지만 각 프로세스는 CPU를 혼자 독점하는 것처럼 동작한다. OS가 context-switch로 그 복잡함을 감춘다. 자세한 내용은 process.md 참고.

**가상 메모리** — 물리 메모리의 추상화.

실제로는 물리 메모리를 여러 프로세스가 나눠 쓴다. 하지만 각 프로세스는 메모리 전체를 혼자 갖고 있는 것처럼 보이는 가상 주소 공간을 가진다. OS가 페이지 테이블로 그 복잡함을 감춘다. 자세한 내용은 virtual-memory.md 참고.

**파일** — 디스크 장치의 추상화.

실제로는 디스크마다 제어 방식이 다르고 섹터, 트랙 같은 물리적 구조가 있다. 하지만 프로그램은 그걸 몰라도 된다. OS가 모든 입출력 장치를 단순한 바이트 스트림(파일)처럼 보이게 만든다.

## 추상화가 주는 것

- **복잡성 은닉** — 프로그램은 하드웨어 세부사항을 몰라도 된다
- **이식성** — 하드웨어가 바뀌어도 프로그램을 다시 짜지 않아도 된다
- **격리** — 각 프로세스는 서로의 존재를 모르고 독립적으로 동작한다
