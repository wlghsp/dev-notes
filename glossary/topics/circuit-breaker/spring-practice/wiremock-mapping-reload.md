# WireMock 매핑 파일 리로드 — 자동 감지 안 됨

WireMock을 Docker 컨테이너로 띄우고 매핑 JSON 파일을 볼륨 마운트해서 쓸 때 흔히 하는 오해가 있다. 파일만 고쳐서 저장하면 WireMock이 알아서 다시 읽어줄 거라는 오해인데, 실제로는 그렇지 않다.

## 실제 동작

WireMock은 매핑 파일을 컨테이너 시작 시점에 한 번 메모리로 읽어들인다. 이후 파일시스템 변경을 자동으로 감지해서 다시 로드하지 않는다. `--verbose` 옵션은 요청/응답 상세 로깅 옵션일 뿐 리로드와는 무관하다.

실행 중인 컨테이너의 매핑 파일을 고쳐도, 컨테이너 안에는 변경 사항이 정확히 반영돼 있는데도 실제 HTTP 응답은 예전 매핑 그대로 나간다.

## 반영시키는 방법

컨테이너를 재시작해야 한다.

```bash
docker restart <wiremock-container-name>
```

## 확인하는 방법

응답 시간이나 응답 값으로 실제 반영 여부를 확인한다. 예를 들어 지연(`fixedDelayMilliseconds`)을 추가했다면 다음처럼 확인한다.

```bash
time curl -s "http://localhost:<port>/<path>" > /dev/null
```

재시작 전에는 `real`이 즉시(수십 ms)로 나오고, 재시작 후에는 설정한 지연 시간만큼 걸린다.

## 장애 재현 실습에서 자주 걸리는 함정

방화벽 차단 같은 장애를 재현하려고 WireMock 매핑에 지연(`fixedDelayMilliseconds`)을 추가하고 저장한 뒤 바로 확인하면, 예상과 다르게 응답이 즉시 온다. 컨테이너 내부 파일은 이미 변경돼 있는데도 그렇다. 컨테이너를 재기동하고 나서야 설정한 지연이 실제로 걸린다.
