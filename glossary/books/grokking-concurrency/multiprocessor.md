# Multiprocessor

2개 이상의 프로세서를 가진 컴퓨터 시스템. 각 프로세서가 독립적으로 명령어를 실행할 수 있어 물리적 병렬 실행이 가능하다.

## 멀티프로세서 vs 멀티코어

- **멀티프로세서(multiprocessor)** — 물리적으로 별개인 칩을 여러 개 설치한 구성.
- **멀티코어(multicore)** — 하나의 칩 안에 여러 코어를 넣은 구성. 각 코어가 독립적인 CU와 ALU를 가진다. OS는 각 코어를 별도의 프로세서로 인식한다.

두 방식은 코어 간 통신 속도와 메모리 접근 방식에서 차이가 있지만, 이 책에서는 동일하게 취급한다.

## SMP (Symmetric Multiprocessing)

대부분의 멀티프로세서 시스템이 채택하는 아키텍처. 동일한 프로세서 여러 개가 하나의 공유 메모리(RAM)에 연결되고, 단일 OS 아래서 동작한다.

OS가 프로세서들에 프로세스를 스케줄링하고 동기화하는 일을 투명하게 처리한다. 사용자 입장에서 프로세서가 몇 개든 신경 쓰지 않아도 된다.

프로세서 수가 늘어날수록 시스템 버스가 병목이 된다. 프로세서들이 모두 같은 버스를 통해 RAM에 접근하기 때문이다.

## 캐시 일관성(Cache Coherence)

멀티코어에서 생기는 고전적인 문제. 코어마다 자신의 L1 캐시가 있는데, 한 코어가 메모리 값을 수정하면 다른 코어의 캐시에는 아직 이전 값이 남아있을 수 있다. 이 불일치 상태가 캐시 불일관성이다.

이를 해결하기 위해 1980년대 MESI 프로토콜이 개발됐다. 각 캐시 라인의 상태(Modified, Exclusive, Shared, Invalid)를 추적해서 모든 코어가 동일한 데이터를 보도록 보장한다. 오늘날 현대 컴퓨팅의 필수 요소다.
