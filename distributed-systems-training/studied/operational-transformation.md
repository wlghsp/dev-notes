# Operational Transformation (OT)

여러 사용자가 동시에 같은 문서를 편집할 때, 편집 순서가 뒤섞여도 모든 클라이언트가 같은 최종 결과에 도달하도록 만드는 알고리즘.

구글독스, 구글시트가 실시간 협업 편집에 쓰는 방식으로 알려져 있다 (내부 구현은 비공개, 다수의 논문과 특허를 통해 원리가 공개되어 있음).

## 핵심 문제

두 사용자가 동시에 같은 문서를 고치면, 한쪽의 편집이 다른 쪽 편집을 무효화하거나 위치를 어긋나게 만들 수 있다.

예를 들어 "ABC"라는 문서에서:
- 사용자1: 위치 1에 "X" 삽입 → "AXBC"
- 사용자2(동시에, 사용자1의 편집을 못 본 상태): 위치 2에 "Y" 삽입 → "ABYC"

두 편집을 순서대로 그대로 적용하면 서버와 클라이언트마다 결과가 달라질 수 있다. 이걸 그대로 이어붙이면 안 되고, 뒤에 적용되는 연산의 위치를 앞선 연산에 맞게 "변환(transform)"해야 한다.

## 동작 방식

**연산(Operation)으로 표현**
편집을 "3번째 위치에 'A' 삽입", "5~7번째 삭제"처럼 연산 단위로 표현한다. 문서 전체를 매번 전송하지 않고 변경분만 전송한다.

**Transform 함수**
동시에 발생한 두 연산 OP_A, OP_B가 있을 때, transform(OP_A, OP_B)는 OP_B가 이미 적용된 상태에도 OP_A가 의도한 결과를 내도록 위치를 보정한 연산을 만든다. 이 변환 규칙을 어떤 순서로 적용해도 모든 클라이언트가 같은 결과에 수렴하는 것이 알고리즘의 핵심 요구사항이다.

**중앙 서버의 역할**
OT는 보통 중앙 서버가 연산의 도착 순서를 정하고 transform을 수행하는 구조를 취한다. 클라이언트는 로컬 편집을 낙관적으로 즉시 반영하고, 서버가 확정한 연산을 받으면 다시 조정한다.

## 특징

- 서버가 순서를 중재하므로 중앙 서버 없이는 동작하기 어렵다
- transform 함수를 텍스트 외의 복잡한 데이터 구조(표, 트리)에 맞게 올바르게 구현하는 게 까다롭다 — edge case가 많다
- 오프라인 편집 후 재접속처럼 긴 시간 분기된 상태를 병합하는 데는 상대적으로 약하다
