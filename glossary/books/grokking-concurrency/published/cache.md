# Cache

CPU 칩 위에 올라간 고속 임시 메모리. CPU의 연산 속도가 RAM의 데이터 전송 속도보다 훨씬 빠르기 때문에, 그 속도 차이를 메우기 위해 존재한다.

## 왜 필요한가

프로그램이 실행되면 코드와 데이터가 RAM에 올라간다. CPU가 연산할 때마다 RAM에서 값을 가져오면 CPU는 데이터가 도착할 때까지 멈춰서 기다려야 한다. 캐시는 CPU 가까이에 자주 쓰는 데이터를 미리 올려놓아 이 대기 시간을 줄인다.

## 3단계 계층 구조

캐시는 3단계로 나뉜다.

1. **L1** — CPU 코어 내부. 수십 KB. 접근 속도가 가장 빠르다. 현재 실행 중인 명령어와 데이터를 담는다.
2. **L2** — 수백 KB. L1보다 크고 느리다.
3. **L3** — 여러 코어가 공유. 수 MB. 가장 크고 느리다. L2와 L3는 다음에 필요할 데이터를 RAM에서 미리 L1으로 옮겨놓는 역할을 한다.

L1이 가장 CPU에 가깝고, 레벨이 높아질수록 느리지만 용량이 커진다.

## 캐시 컨트롤러

CPU가 데이터를 필요로 할 때, 캐시 컨트롤러가 해당 데이터가 캐시에 있는지 확인한다. 있으면 바로 제공하고(캐시 히트), 없으면 RAM에서 가져와 캐시에 올린다(캐시 미스). 또한 앞으로 필요할 데이터를 예측해서 미리 RAM에서 캐시로 로드해둔다.

## Scaled Latency — 속도 차이의 실감

접근 속도를 체감 단위로 환산하면 격차가 얼마나 큰지 알 수 있다. CPU 사이클 1회를 1초라고 할 때:

- L1 캐시 접근 — 2초
- L2 캐시 접근 — 7초
- L3 캐시 접근 — 1분
- RAM 접근 — 4분
- SSD I/O — 1.5~4일
- HDD I/O — 1~9개월
- 네트워크 요청(SF~NYC) — 5년

이 차이가 캐시 히트율이 성능에 결정적인 영향을 미치는 이유다.
