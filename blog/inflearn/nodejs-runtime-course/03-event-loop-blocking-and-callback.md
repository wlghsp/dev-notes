# [강의 노트] 3강: 식당 웨이터 비유로 통찰하는 비동기 논블로킹 아키텍처 (2/2)

앞선 내용(멀티 스레드의 한계, 싱글 스레드 비동기 논블로킹, CPU 집약적 작업의 정의)은 03-sync-vs-async-basics.md에서 다뤘습니다. 이어서 이벤트 루프를 막는 안티 패턴과 코드 레벨의 콜백 동작 원리를 다룹니다.

## 1. 치명적 안티 패턴: 이벤트 루프 블로킹 (양파 썰기)

비동기 환경에서 가장 경계해야 할 것은 메인 스레드가 직접 앞서 다룬 'CPU 집약적 작업'을 수행하는 것입니다.

- **문제 상황**: 주방에 맡길 수 없는 복잡한 연산(예: 웨이터가 직접 양파 100개 썰기)을 메인 스레드에 지시하면, 웨이터가 그 자리에 멈춰 서게 됩니다.
- **결과**: 유일한 웨이터가 멈췄으므로, 이벤트 루프 전체가 멈추고 새로운 접속자의 로그인, 클릭 등 모든 API 요청 처리가 마비(Blocking)됩니다.

> 💡 **[CS 실무 Point: CPU 집중 작업의 격리(Isolation)]**
> 현업 엔지니어는 이런 상황을 마주하면 Node.js의 worker_threads 모듈을 사용해 libuv의 스레드 풀과는 완전히 분리된 별도의 자바스크립트 실행 환경(워커)을 띄우거나, 메인 Node.js 서버는 API 게이트웨이 역할만 하고 무거운 연산은 AWS SQS 등 메시지 큐를 통해 Python 기반의 독립된 마이크로서비스로 넘겨버리는 아키텍처를 설계합니다.

> 🌱 **[직관적 비유]**
> 손님이 "웨이터님, 여기서 양파 100개만 다져주세요"라고 무리한 요구를 했을 때, 웨이터가 그걸 직접 썰고 있으면 식당 전체가 마비됩니다. 훌륭한 식당 사장(엔지니어)이라면 메인 웨이터를 멈춰 세우는 대신, '양파만 전문으로 써는 알바생(Worker Thread)'을 주방 구석에 따로 고용하거나, 아예 옆 건물에 있는 파트너 식당(Python 마이크로서비스)에 양파 썰기를 외주 주는 방식으로 문제를 해결합니다.

## 2. 코드 레벨에서의 동작 원리와 콜백(Callback)의 본질

이러한 아키텍처의 차이는 실제 코드를 작성하는 방식에 명확히 드러납니다.

```javascript
// [안티 패턴] 동기(Synchronous) 블로킹 방식
// 웨이터가 주방 앞에서 요리가 나올 때까지 멈춰버립니다.
const data = db.querySync('SELECT * FROM users');
console.log('데이터 조회가 끝났습니다.', data); // DB 조회가 끝나기 전까지 절대 실행되지 않음

// [권장 패턴] 비동기(Asynchronous) 논블로킹 방식
// 웨이터가 주방에 주문과 함께 '진동벨(콜백 함수)'을 남기고 즉시 다음 일로 넘어갑니다.
db.query('SELECT * FROM users', (error, data) => {
  // 훗날 요리가 완성되어 주방에서 진동벨을 울리면, 그때 돌아와서 이 서빙(함수)을 실행합니다.
  console.log('요청하신 데이터가 준비되었습니다.', data);
});
console.log('주문을 주방에 넣었고, 저는 곧바로 다음 테이블로 이동합니다!'); // 즉시 실행됨!
```

> 💡 **[CS 실무 Point: Next.js 기반 환경에서의 비동기 처리]**
> 최신 React와 Next.js 환경에서 서버 컴포넌트(Server Components)를 다룰 때 async/await를 사용하는 이유도 이 근본 원리에 닿아 있습니다. 내부 엔진(V8)은 이것을 완벽한 비동기 논블로킹으로 처리하는 것을 넘어, 일반 작업보다 우선순위가 높은 '마이크로태스크(Microtask)'로 분류하여 가장 빠르게 처리함으로써 서버 자원의 낭비를 막아줍니다.

## 3. 학습 포인트: 머릿속으로 그려보는 사고 실험

여러분이 만든 Node.js 서버에 두 가지 요청이 들어왔습니다.

- A 요청: 데이터베이스에서 유저 프로필 가져오기 (비동기 I/O 작업)
- B 요청: 4K 동영상을 압축하기 (동기적 CPU 집약적 작업)

만약 단일 스레드가 B 요청을 메인 로직에서 그대로 처리하게 둔다면, B 요청의 압축이 끝나는 10분 동안 A 요청을 보낸 유저는 프로필 하나를 보기 위해 하염없이 흰 화면만 쳐다보고 있어야 합니다. 이것이 바로 우리가 비동기 아키텍처의 특성을 이해하고 코드를 짜야 하는 이유입니다.

이 강의에서 등장한 용어는 03-glossary.md 파일에 정리했습니다.
