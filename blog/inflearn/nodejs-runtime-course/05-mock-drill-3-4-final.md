# [강의 노트] 5강. 이벤트 루프 실전 모의연습과 6단계 페이즈 완벽 마스터 (2/2)

앞선 내용(우선순위 계급도, 모의연습 1~2)은 05-mock-drill-1-2.md에서 다뤘습니다. 이어서 정거장 내부의 새치기, 기아 현상, 그리고 모든 것이 얽힌 최종 보스 모의연습을 다룹니다.

## 1. 실전 모의연습 3: 정거장 내에서의 아찔한 새치기 (Phase Interruptions)

순찰 반장(이벤트 루프)은 1번(Timer) 정거장에 쌓인 알람 서류를 한 번에 다 쳐내는 것이 아닙니다. 서류를 딱 한 장 결재할 때마다, 즉시 뒤를 돌아보고 VIP 결재함에 서류가 생겼는지 확인합니다.

```javascript
setTimeout(() => {
    console.log('1: 타이머 첫 번째 알람');
    Promise.resolve().then(() => console.log('2: [새치기] 알람 도중 생성된 VIP 서류'));
}, 0);

setTimeout(() => {
    console.log('3: 타이머 두 번째 알람');
}, 0);
```

> 💡 **[CS 실무 Point: Node 11+의 마이크로태스크 체크 단위]**
> 최신 Node.js는 성능과 예측 가능성을 높이기 위해, 1번 정거장에 서류가 수백 장 있어도 콜백 함수가 딱 1개 실행되고 끝나는 그 찰나의 틈(틱, Tick)마다 무조건 마이크로태스크 큐(VIP 결재함)를 열어보고 새치기를 허용합니다.

**[시각화] 콜백과 콜백 사이, 그 찰나의 새치기**

```
[Step 1] 대기 상태
[ 일반 1번 정거장 (Timer Phase) ] : [ 첫 번째 알람 ] -> [ 두 번째 알람 ]
[ VIP 결재함 ] : (비어 있음)

[Step 2] 첫 번째 알람 실행 & VIP 기습 생성!
▶ 화면 출력: 1
[ 일반 1번 정거장 ] : [ 두 번째 알람 ]
[ VIP 결재함 ] : [ 2 (새치기 VIP 서류) ] <-- 기습 접수!

[Step 3] 이벤트 루프 급브레이크!
▶ 화면 출력: 2
[ VIP 결재함 ] : (다시 텅 빔!)

[Step 4] 정거장 업무 재개
▶ 화면 출력: 3
```

**📝 [스텝별 실행 흐름 및 6단계 심층 해부]**

1. **알람 동시 대기 (Timer Phase 진입)**: 콜 스택이 비워지고 VIP 결재함에도 아무것도 없음을 확인한 이벤트 루프가 버스 시동을 켜고 첫 번째 정거장인 Timer Phase에 도착합니다. 이곳에는 0초 뒤 실행될 두 개의 알람 서류가 나란히 줄을 서 있습니다.
2. **첫 번째 알람 처리 및 기습 VIP 생성 (1 출력)**: 순찰 반장이 Timer Phase의 맨 앞 서류를 꺼내 소장님(콜 스택) 책상에 올립니다. 1이 출력됩니다. 그런데 이 콜백 함수가 실행되는 내부 로직에서 뜻밖의 일이 벌어집니다. 내부의 Promise가 작동하면서, 텅 비어있던 VIP 결재함(Microtask Queue)에 기습적으로 '2번 서류'를 던져 넣은 것입니다.
3. **이벤트 루프의 급브레이크 (Tick Level Microtask Check)**: 과거 버전의 Node.js였다면 순찰 반장은 Timer Phase에 남은 '두 번째 알람'까지 마저 결재했을 것입니다. 하지만 최신 Node.js의 순찰 반장은 서류를 딱 한 장 결재할 때마다 무조건 습관적으로 VIP 결재함을 뒤돌아봅니다. 방금 들어온 2번 서류의 불빛을 본 순찰 반장은, Timer Phase에 아직 서류가 남아있음에도 불구하고 그 자리에 급브레이크를 밟고 업무를 중단합니다!
4. **새치기 VIP 절대 우선 처리 (2 출력)**: 정거장(Phase) 내부의 남은 업무를 모두 멈춘 반장님은 VIP 결재함으로 달려가 기습 접수된 2번 서류를 먼저 소장님께 밀어 올립니다. 2가 출력됩니다.
5. **정거장 업무 재개 및 마무리 (3 출력)**: 다시 VIP 함이 비워진 것을 철저히 확인한 뒤에야, 반장님은 브레이크를 풀고 원래 있던 Timer Phase 정거장으로 돌아갑니다. 그리고 얌전히 대기하고 있던 3번 두 번째 알람 서류를 마저 처리합니다. 3이 출력됩니다.
6. **결과**: 이벤트 루프의 6단계 Phase 진행 중이라도 단일 콜백 처리 직후라면 언제든 VIP의 아찔한 새치기가 틱(Tick) 단위로 허용되어 1 -> 2 -> 3 순으로 흐름이 절단되어 실행됩니다.

## 2. 실전 모의연습 4: 절대 권력의 부작용, 기아 현상 (Starvation)

VVIP 서류(nextTick)가 무분별하게 쏟아지면, 순환 버스가 일반 정거장으로 평생 출발하지 못하는 참사가 벌어집니다.

```javascript
setTimeout(() => console.log('일반 알람: 영원히 실행되지 못합니다.'), 0);

function 무한_VIP_생성기() {
    process.nextTick(() => {
        console.log('VVIP 서류 무한 처리 중...');
        무한_VIP_생성기(); // 재귀 호출: 자기 자신을 또 VVIP 큐에 밀어 넣음
    });
}
무한_VIP_생성기();
```

**[시각화] 이벤트 루프 버스의 발이 묶이는 기아 현상**

```
[ 일반 1번 정거장 (Timer Phase) ] : [ 일반 알람 ] (간절히 기다리는 중...)

[ VVIP 결재함 (nextTick Queue) ] : [ 무한_VIP_생성 ] -> [ 무한_VIP_생성 ] -> ... (끝없이 증식)
```

**📝 [스텝별 실행 흐름 및 6단계 심층 해부]**

1. **초기 접수 및 배정**: 스크립트가 실행되면서 setTimeout의 일반 알람은 Timer Phase 정거장 큐에 배정되고, 무한_VIP_생성기() 함수가 호출되며 최초의 VVIP 서류가 nextTick Queue에 접수됩니다.
2. **이벤트 루프의 최우선 검문 시작**: 콜 스택이 비워지자 이벤트 루프가 움직입니다. 1번 정거장(Timer Phase)으로 가기 전, 규칙에 따라 무조건 VVIP 결재함(nextTick Queue)부터 엽니다.
3. **VVIP 무한 증식과 재귀의 함정**: 순찰 반장이 첫 번째 VVIP 서류를 꺼내 소장님께 올립니다. 그런데 이 서류가 처리되면서(재귀 호출로 인해) 정확히 똑같은 VVIP 서류 한 장이 또다시 VVIP 결재함에 기습 접수됩니다.
4. **이벤트 루프의 딜레마 (Phase Starvation 발생)**: 순찰 반장의 룰은 단순합니다. "VVIP 결재함이 완전히 텅 빌 때까지 절대 정거장으로 출발하지 마라." 순찰 반장은 땀을 뻘뻘 흘리며 새로 생긴 VVIP 서류를 올리고, 올리고, 또 올리지만 서류는 복사하듯 끊임없이 생성됩니다.
5. **결과**: 1번 정거장(Timer Phase)에서 대기하던 일반 알람은 단 0.001초면 끝날 간단한 작업임에도 불구하고, 이벤트 루프 버스가 영원히 정거장에 도착하지 못해 평생을 대기하게 됩니다. 이벤트 루프가 Phase 순회를 하지 못하고 마이크로태스크 큐에 발이 묶인 이 절망적인 상태, 이것이 바로 백엔드 시스템 전체의 응답을 먹통으로 만드는 무서운 '기아 현상(Starvation)'입니다.

## 3. 최종 보스 모의연습: 모든 것이 얽힌 종합 세트

모든 계급과 새치기 원리, 정거장 시스템이 총동원된 최종 몬스터 코드입니다.

```javascript
console.log('1 현장 출근 (동기)');

setTimeout(() => console.log('6 예약된 알람 (Timer)'), 0);

Promise.resolve().then(() => {
    console.log('4 VIP 긴급 서류 (Promise)');
    process.nextTick(() => console.log('5 [새치기] VIP 내부의 VVIP (nextTick)'));
});

process.nextTick(() => console.log('3 VVIP 절대 우선 서류 (nextTick)'));

console.log('2 현장 퇴근 (동기)');
```

**[시각화] 최종 아키텍처 흐름 완벽 해부**

```
[Step 1] 동기 코드 실행
▶ 화면 출력: 1 -> 2
[ VVIP 결재함 (nextTick) ] : [ 3 ]
[ VIP 결재함 (Promise) ] : [ 4 ]
[ 일반 1번 정거장 (Timer) ] : [ 6 ]

[Step 2] 0순위 VVIP 결재함 오픈
▶ 화면 출력: 3

[Step 3] 1순위 VIP 결재함 오픈 (그리고 꼬리물기 발생!)
▶ 화면 출력: 4
[ VVIP 결재함 (nextTick) ] : [ 5 ([새치기]) ] <-- 기습 접수!

[Step 4] 정거장 이동 전 검문 (급브레이크!)
▶ 화면 출력: 5

[Step 5] 일반 정거장(Timer Phase) 처리
▶ 화면 출력: 6
```

**📝 [스텝별 실행 흐름 및 6단계 심층 해부]**

1. **[Phase 0: 동기 코드 최우선 처리 (콜 스택)]**: 프로그램이 시작되면 이벤트 루프는 대기 상태입니다. 소장님(콜 스택)이 코드를 위에서 아래로 스캔하며 즉시 처리합니다. 가장 먼저 1이 출력됩니다. 이후 비동기 작업들이 스캐닝되며 각자의 대기열로 배정됩니다. (setTimeout은 1번 정거장인 Timer Phase 큐로, 첫 번째 Promise는 VIP 결재함으로, 첫 번째 nextTick은 VVIP 결재함으로 배정). 그리고 맨 밑의 동기 코드인 2가 출력된 후, 소장님이 퇴근하며 콜 스택이 완전히 비워집니다.
2. **[정거장 이동 전 0순위 VVIP 결재함 오픈]**: 콜 스택이 비워진 찰나, 드디어 이벤트 루프가 가동을 준비합니다. 1번 정거장(Timer Phase)으로 출발하기 전, 가장 높은 계급인 VVIP 함(nextTick Queue)으로 달려갑니다. 대기 중이던 3번 서류를 올려 실행시킵니다. (3 출력)
3. **[1순위 VIP 큐 오픈 및 내부 꼬리물기 기습 발생!]**: VVIP 함이 비워진 것을 확인한 이벤트 루프는 다음 계급인 VIP 함(Microtask Queue)을 엽니다. 4번 서류를 집어 콜 스택에 올립니다. (4 출력). 그런데 아찔한 순간이 발생합니다. 4번 코드가 실행되는 도중, 그 내부에 숨어있던 nextTick이 발동하여 방금 비웠던 최고 계급의 0순위 VVIP 함에 '5번 새치기 서류'를 몰래 밀어 넣은 것입니다!
4. **[정거장 이동 전 엄격한 재검문 (급브레이크!)]**: 4번 서류 처리를 마친 이벤트 루프는 "이제 드디어 1번 정거장(Timer Phase)으로 출발할까?" 하다가 원칙에 따라 다시 한번 VVIP/VIP 함을 뒤돌아봅니다. 맙소사, 비어있어야 할 0순위 VVIP 함에 5번 서류가 들어와 깜빡이고 있습니다. 이벤트 루프는 정거장 출발을 즉시 보류(급브레이크)하고 다시 달려가 5번 서류를 처리합니다. (5 출력)
5. **[최종 정거장 진입 (Timer Phase)]**: 다시 뒤를 돌아 VVIP와 VIP 결재함에 먼지 하나 없이 모든 결재 서류가 사라진 것을 최종 확인합니다. 이제야 마음 놓고 버스 시동을 켠 이벤트 루프는 1번 정거장(Timer Phase)에 무사히 도달합니다. 프로그램 시작부터 조용히 대기하던 6번 알람 서류를 비로소 집어 듭니다. (6 출력)
6. **[결과]**: 철저한 계급, 찰나의 기습 새치기, 그리고 깐깐한 정거장 이동 전 재검문의 원칙이 완벽하게 맞물리며 최종 정답은 1 -> 2 -> 3 -> 4 -> 5 -> 6 이 도출됩니다.

여러분, 진심으로 축하드립니다. 오늘 배운 이 톱니바퀴의 스텝들은 Node.js의 가장 깊은 심장부입니다. 이 튼튼한 기초 체력이 훗날 여러분이 설계할 거대한 백엔드 아키텍처의 가장 단단한 기둥이 될 것입니다.
