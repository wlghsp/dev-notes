# RFC 5737 — 문서·테스트 전용 IP 대역

`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24` 세 대역은 RFC 5737에서 문서화·테스트 목적으로 예약해둔 IP 대역이다. 실제 인터넷 어디에도 라우팅되지 않는다.

## 왜 필요한가

장애 재현 실습에서 "방화벽이 SYN 패킷 자체를 버리는" 상황(connect timeout)을 만들고 싶을 때, 존재하지 않는 목적지로 요청을 보내야 한다. 아무 사설 IP나 임의로 쓰면 실제로 그 IP를 쓰는 네트워크와 우연히 충돌할 위험이 있다.

RFC 5737 대역은 표준으로 예약되어 있어 절대 실제 서비스가 쓰지 않는다는 게 보장된다. 이 대역으로 요청을 보내면 패킷이 라우팅 과정에서 사라지고, 클라이언트는 응답도 거부도 받지 못한 채 connect timeout까지 그대로 대기하게 된다.

## connect timeout과의 관계

이 대역으로 URL을 바꿔 요청을 보내면, TCP 연결 자체가 성립되지 않는 상황을 재현할 수 있다. read timeout(연결은 됐지만 응답이 없는 상황)과는 재현 방법이 다르다는 점이 핵심이다.
