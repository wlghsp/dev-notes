# twos-complement-why (2의 보수, 왜 쓰는가)

## 문제: 음수를 비트로 어떻게 저장할까

8비트로 -1을 어떻게 저장할까?

가장 단순한 생각: 맨 앞 비트를 부호 비트로 쓰자.
- `0_0000001` = +1
- `1_0000001` = -1

이걸 부호-크기 방식(sign-magnitude)이라고 한다. 직관적이지만 문제가 있다.

`+1 + (-1)`을 계산해보면:

```
  0_0000001
+ 1_0000001
----------
  1_0000010  →  -2가 나온다. 틀렸다.
```

CPU가 덧셈 회로 하나로 양수/음수를 같이 처리할 수 없다. 음수용 별도 회로가 필요해진다.

## 아이디어: "더했을 때 0이 되는 수"를 음수로 정의하자

1 + (-1) = 0이 되려면, 8비트에서 (-1)은 뭐여야 할까?

```
  0_0000001
+ ???????
---------
  0_0000000  (올림 비트는 버림)
```

답: `11111111`

`00000001 + 11111111 = 100000000` → 9번째 비트(올림)는 버리면 `00000000`. 0이 나온다.

그래서 -1 = `11111111`로 정의한다.

## 패턴

8비트 기준으로 음수들:

```
11111111 = -1
11111110 = -2
11111101 = -3
...
10000001 = -127
10000000 = -128
```

`10000000`에서 하나 더 빼면 `01111111` = +127로 넘어간다. 그래서 -128이 최솟값.

양수는 `00000000`(0) ~ `01111111`(127).

## 왜 -128~127 비대칭인가

0이 `00000000` 하나만 존재하기 때문.

부호-크기 방식은 `+0`(`00000000`)과 `-0`(`10000000`)이 따로 있어서 자리 낭비가 생긴다. 2의 보수는 0이 하나라 음수가 하나 더 들어갈 자리가 생긴다. 그래서 양수 최대(127)보다 음수 최솟값(-128)이 하나 더 크다.

## 핵심 이유

2의 보수를 쓰는 이유는 단 하나: 덧셈 회로 하나로 양수/음수 계산을 동시에 처리할 수 있어서. CPU 설계가 단순해진다.
