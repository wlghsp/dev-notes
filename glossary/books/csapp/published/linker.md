# linker

여러 오브젝트 파일을 합쳐 실행 가능한 바이너리를 만드는 단계.

## 핵심 아이디어

어셈블러가 만든 오브젝트 파일(.o)은 혼자서는 실행이 안 된다. 다른 파일의 함수나 변수를 참조하는 부분의 주소가 비어있기 때문이다. 링커는 여러 오브젝트 파일과 라이브러리를 합치고, 비어있던 주소를 확정해서 실행 가능한 파일을 만든다.

## 하는 일

**심볼 해소** — 오브젝트 파일 A에서 참조한 함수가 오브젝트 파일 B에 정의되어 있으면, A의 빈 주소 자리에 B의 실제 주소를 채운다.

**주소 확정** — 각 오브젝트 파일의 코드와 데이터를 최종 실행 파일의 어느 주소에 배치할지 결정한다.

**라이브러리 연결** — 표준 라이브러리(libc 등)나 외부 라이브러리의 코드를 연결한다.

## 정적 링킹 vs 동적 링킹

**정적 링킹** — 라이브러리 코드를 실행 파일 안에 직접 포함시킨다. 실행 파일이 커지지만 외부 의존성이 없다.

**동적 링킹** — 라이브러리를 실행 파일에 포함하지 않고, 실행 시점에 연결한다. 실행 파일이 작고 라이브러리를 여러 프로세스가 공유할 수 있다. `.so`(Linux), `.dylib`(Mac), `.dll`(Windows) 파일이 동적 라이브러리다.

## 결과

실행 가능한 바이너리. 이 파일을 OS에 넘기면 프로세스가 생성된다.
