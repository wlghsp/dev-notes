# ipc

Inter-Process Communication. OS가 프로세스와 스레드가 서로 통신하고 조율할 수 있도록 제공하는 메커니즘.

이름은 "프로세스 간 통신"이지만, 실제로는 스레드 간 통신도 포함한다. 모든 프로세스는 최소 하나의 스레드를 가지므로, 통신은 사실상 스레드 사이에서 일어난다. 스레드든 프로세스든 실행 단위를 task로 통칭할 수 있다.

## 두 가지 기본 모델

IPC의 가장 널리 쓰이는 두 방식은 공유 메모리와 메시지 패싱이다.

1. 공유 메모리(shared memory) — 여러 태스크가 공통 메모리 영역을 직접 읽고 쓴다. OS가 할당만 해주고 이후 통신에는 개입하지 않는다. 빠르지만 동시 접근 제어를 직접 해야 한다.

2. 메시지 패싱(message passing) — 태스크가 OS가 관리하는 채널을 통해 메시지를 주고받는다. OS가 복사와 전달을 처리한다. 비용은 크지만 안전하고 네트워크를 넘어 분산 시스템으로 확장할 수 있다.

## 메시지 패싱 구현 방법

책에서 다루는 세 가지 구현체:

1. pipe — 단방향 바이트 스트림. 한쪽에서 쓰면 다른 쪽에서 읽는다. unnamed pipe는 관련 태스크 간에만 사용. named pipe(FIFO)는 파일시스템에 존재해 무관한 태스크도 사용 가능

2. message queue — FIFO 원칙으로 메시지를 보관한다. 여러 태스크가 동시에 쓰고 읽을 수 있어 느슨하게 결합된 시스템을 만들 수 있다

3. socket(UDS) — 같은 머신의 태스크 간 양방향 통신. send()/recv() 인터페이스로 동작하며, 나중에 네트워크 소켓으로 확장할 수 있다

## 선택 기준

같은 머신, 성능 우선 → 공유 메모리. 안전성, 단순성, 분산 확장성 → 메시지 패싱.
