# thread

하나의 프로세스 안에서 독립적으로 실행되는 논리적 흐름. 프로세스가 실행 환경의 단위라면, 스레드는 그 환경 안에서의 실행 단위다.

## 프로세스와의 차이

프로세스는 독립적인 주소 공간을 가진다. 스레드는 같은 프로세스 안의 다른 스레드들과 주소 공간을 공유한다.

- **공유하는 것** — 코드 세그먼트, 데이터 세그먼트(전역 변수), 힙, 파일 디스크립터
- **각자 가지는 것** — 스택, 레지스터 상태, 프로그램 카운터(PC)

스레드는 같은 메모리를 공유하기 때문에 프로세스보다 생성 비용이 낮고 통신이 쉽다. 반면 하나의 스레드가 공유 데이터를 잘못 수정하면 같은 프로세스의 다른 스레드 전체에 영향을 준다.

## 왜 스레드를 쓰는가

1. **병렬 처리** — 멀티코어 CPU에서 여러 스레드가 동시에 실행되어 CPU 연산을 병렬화한다.
2. **I/O 대기 중 다른 작업** — 하나의 스레드가 네트워크 응답을 기다리는 동안 다른 스레드가 CPU를 쓸 수 있다.
3. **응답성** — UI 스레드가 블로킹되지 않도록 무거운 작업을 별도 스레드로 분리한다.

## 스레드와 동기화

공유 데이터에 여러 스레드가 동시에 접근하면 race-condition이 발생한다. 이를 막기 위해 mutex, semaphore 같은 동기화 도구를 쓴다.
