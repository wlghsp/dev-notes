# database-sharding (데이터베이스 샤딩)

대규모 데이터베이스를 더 작고 관리하기 쉬운 단위로 분리하는 수평 파티셔닝 기법. 각 파티션을 샤드(Shard)라 부른다.

## 동작 방식

각 샤드는 같은 스키마를 공유하지만 실제 데이터는 서로 겹치지 않는다. 샤드 키(Sharding Key, 파티션 키)가 데이터를 어느 샤드에 저장할지 결정한다. 예를 들어 user_id % 4로 4개의 샤드에 데이터를 균등 분배한다.

샤드 키 선택의 핵심 기준은 데이터를 고르게 분배할 수 있는 컬럼을 고르는 것이다.

## 샤딩의 복잡성과 문제점

샤딩은 확장성을 높이지만 새로운 문제를 만든다.

**Resharding(리샤딩)** — 단일 샤드가 더 이상 데이터를 담을 수 없거나 데이터 분포가 불균형해질 때 샤드 함수를 업데이트하고 데이터를 이동해야 한다. Consistent Hashing(Ch05)이 이를 해결하는 기법이다.

**Celebrity Problem(핫스팟 키 문제)** — 특정 샤드에 접근이 집중되는 문제. 예를 들어 유명인 수백 명이 같은 샤드에 몰리면 그 샤드가 과부하된다. 유명인 한 명당 별도 샤드를 할당하거나 추가 파티션이 필요할 수 있다.

**Join과 비정규화** — 여러 샤드에 걸친 JOIN은 어렵다. 단일 테이블에서 쿼리할 수 있도록 DB를 비정규화하는 게 일반적인 해결책이다.
