# induction (수학적 귀납법)

"모든 자연수 n에 대해 이 명제가 참이다"를 증명할 때 쓰는 방법. 무한히 많은 경우를 하나씩 다 확인할 수 없으니, 대신 두 가지만 보인다.

1. 기저 사례(base case): `n = 1`(또는 가장 작은 경우)일 때 명제가 참이다
2. 귀납 단계(inductive step): `P(k)`가 참이라고 가정하면, `P(k+1)`도 참이다 (`P(k) ⟹ P(k+1)`)

이 두 개만 보이면 도미노처럼 모든 n에 대해 참이 된다. 1이 참이고, 1이 참이면 2도 참이고, 2가 참이면 3도 참이고... 무한히 이어진다.

## 일상 비유 — 도미노

도미노를 일렬로 세워놓고 두 가지만 확인하면 전부 쓰러진다는 걸 안다.
- 첫 번째 도미노가 쓰러진다(기저 사례)
- 어떤 도미노가 쓰러지면 바로 다음 도미노도 반드시 쓰러진다(귀납 단계)

이 두 개를 확인했다고 해서 두 번째, 세 번째 도미노를 직접 밀어볼 필요는 없다. 논리적으로 전부 쓰러진다.

## 알고리즘에서 왜 필요한가

재귀 함수나 DP 점화식이 "항상 맞는 값을 낸다"는 걸 증명할 때 귀납법을 쓴다. 코드가 정답을 낸다는 확신 없이 그냥 실행해보고 맞으면 넘어가는 경우가 많은데, 왜 맞는지는 귀납법으로 설명된다.

## 예시 — 피보나치 DP가 맞다는 증명

`dp[i] = dp[i-1] + dp[i-2]`로 피보나치 수를 구하는 코드가 있다고 하자. 이 점화식이 항상 올바른 피보나치 값을 낸다는 걸 귀납법으로 보인다.

- 기저 사례: `dp[0] = 0`, `dp[1] = 1`은 정의 그대로이므로 참
- 귀납 가정: `0 ≤ i ≤ k`인 모든 i에 대해 `dp[i] = F(i)`(진짜 피보나치 값)라고 가정한다
- 귀납 단계: `dp[k+1] = dp[k] + dp[k-1]`인데, 가정에 의해 `dp[k] = F(k)`, `dp[k-1] = F(k-1)`이다. 피보나치 수의 정의가 `F(k+1) = F(k) + F(k-1)`이므로 `dp[k+1] = F(k+1)`
- 따라서 모든 i에 대해 `dp[i] = F(i)`

이 증명이 있어야 "예제 몇 개 돌려보니 맞더라"가 아니라 "모든 입력에 대해 반드시 맞다"고 말할 수 있다.

## 알고리즘 문제에서 마주치는 형태

재귀 함수의 정확성을 증명할 때는 "더 작은 입력에서 재귀 호출이 올바른 값을 반환한다"고 가정(귀납 가정)하고, 그 값으로 현재 입력의 답을 올바르게 조립할 수 있는지만 보이면 된다. 이게 loop-invariant.md(불변량)와도 이어지는데, 반복문에 귀납법을 적용한 것이 불변량이다.

## 기억할 것 한 가지

귀납 단계에서 "k일 때 참이라고 가정"하는 걸 이상하게 느낄 수 있는데, 이건 순환 논리가 아니다. "가정이 참이면 다음도 참"이라는 조건문 자체를 증명하는 것이지, k일 때 참이라고 확정 짓고 쓰는 게 아니다.
