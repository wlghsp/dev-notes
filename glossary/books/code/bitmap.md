# bitmap (비트맵)

비트맵은 이미지를 픽셀의 2차원 배열로 표현한 것이다. 각 픽셀의 색 값을 메모리에 순서대로 저장한다. 첫 번째 행의 픽셀들, 이어서 두 번째 행, 그 다음 행 순으로 이어지는 단순한 바이트 스트림이다.

## 비트맵이 필요한 이유

텍스트 기반 인터페이스에서는 ASCII 코드 하나로 화면에 문자 하나를 표시한다. 이미지를 표시하려면 픽셀 하나하나의 색을 지정해야 한다. 비트맵이 그 역할을 한다.

비디오 디스플레이 메모리 자체가 비트맵이다. 그 메모리 주소에 픽셀 값을 쓰는 것이 화면에 그림을 그리는 것이다.

## 래스터 그래픽과 벡터 그래픽

그래픽은 두 가지로 나뉜다.

래스터 그래픽(raster graphics) = 비트맵 그래픽. 픽셀 배열로 이미지를 저장한다. 사진처럼 복잡한 실제 이미지를 표현하기에 적합하다. 해상도가 고정되어 있어 확대하면 계단 현상이 생긴다.

벡터 그래픽(vector graphics)은 선, 곡선, 도형을 수학적 명령어로 저장한다. 확대해도 품질이 유지된다. 설계 도면이나 로고처럼 기하학적 이미지에 적합하다. 실제 다리 사진은 벡터로 표현할 수 없다.

## 비트맵 압축

비트맵은 크다. 640×480 풀컬러 이미지가 약 1MB다. 압축이 필요하다.

무손실 압축(lossless)은 원본을 완벽하게 복원할 수 있다. 런길이 인코딩(RLE, Run-Length Encoding)은 "파란 픽셀이 72개 연속"을 짧게 표현한다. GIF 파일 형식이 LZW라는 무손실 압축을 사용한다.

손실 압축(lossy)은 일부 데이터를 버리며 파일을 훨씬 작게 만든다. 사람 눈이 인식하지 못하는 부분을 버린다. JPEG가 대표적이다. 사진에 적합하지만 스프레드시트에는 쓰면 안 된다.

## 비트맵 파일 형식

- BMP: Windows 기본 비트맵 형식
- GIF: CompuServe가 1987년 개발. LZW 무손실 압축
- JPEG: 사진용 손실 압축. 품질 설정 가능

## GUI와 비트맵

GUI(그래픽 사용자 인터페이스) 운영체제는 비트맵 기반이다. 버튼, 아이콘, 창의 테두리가 모두 픽셀로 그려진다. 운영체제의 그래픽 API가 선, 사각형, 타원을 그리는 함수를 제공하며, 그 함수들이 결국 픽셀을 비디오 메모리에 쓴다. WYSIWYG(What You See Is What You Get)은 화면과 프린터가 같은 그래픽 API를 쓰기 때문에 가능하다.
