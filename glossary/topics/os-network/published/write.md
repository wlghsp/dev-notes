# write

**"데이터를 OS 커널의 페이지 캐시(Page Cache)에 쓰는 시스템 콜"**

프로세스가 write()를 호출하면 데이터는 디스크가 아니라 OS가 관리하는 메모리 영역(페이지 캐시)에 저장된다. 디스크 기록은 OS가 나중에 알아서 처리한다. write()는 그 시점을 기다리지 않고 즉시 반환한다.

---

## 데이터 경로

```
프로세스 유저 버퍼 (byte[], ByteBuffer 등)
  → write() 호출
  → OS 페이지 캐시 (커널 메모리)  ← write() 완료
  → 디스크                         ← fsync() 또는 OS 백그라운드 flush
```

write()가 완료됐다고 디스크에 쓰인 게 아니다. 커널이 들고 있는 상태다.

---

## 프로세스가 죽어도 데이터는 살아있다

write()가 완료된 데이터는 커널 페이지 캐시에 있다. 프로세스(JVM, mysqld 등)가 죽어도 OS는 살아있으므로 캐시의 데이터는 유지된다. 이 점에서 "프로세스 메모리에 저장"과 다르다.

단, OS(머신) 자체가 죽으면 페이지 캐시도 사라진다.

---

## fsync와의 관계

write()는 빠르다 — 메모리 복사만 하고 반환하기 때문이다. 하지만 OS가 죽으면 날아간다.

fsync()는 느리다 — 실제 디스크 기록이 끝날 때까지 블로킹한다. 하지만 이후엔 OS가 죽어도 데이터가 남는다.

"커밋된 데이터는 반드시 살아야 한다"는 보장이 필요할 때 fsync가 필요한 이유가 이것이다.

---
