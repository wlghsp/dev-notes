# CGLIB 프록시

CGLIB은 Code Generation Library의 줄임말이다. 자바 런타임에 새로운 클래스를 동적으로 만들어주는 바이트코드 조작 라이브러리이고, 스프링은 이 라이브러리를 빌려 써서 프록시를 만든다.

## 만드는 방식

대상 클래스 자체를 상속해서 프록시를 만드는 방식이다.

프록시 객체는 대상 클래스를 상속한 하위 클래스로 런타임에 생성되고, 오버라이드된 메서드 안에서 부가 로직을 수행한 뒤 `super`로 원본 로직을 호출한다.

## 가로챌 수 있는 범위

인터페이스가 없어도 동작하고, 클래스에 선언된 public/protected 메서드 대부분을 가로챌 수 있다.

## 만들 수 없는 경우

`final` 클래스나 `final` 메서드는 상속으로 오버라이드할 수 없어서 프록시를 만들 수 없다. 대상 클래스나 가로채려는 메서드에 `final`이 붙어 있으면 CGLIB 방식 자체가 실패한다.

## 스프링 부트가 기본으로 고르는 이유

스프링 부트는 기본값(`spring.aop.proxy-target-class=true`)으로 CGLIB을 우선 사용한다.

인터페이스 유무와 무관하게 항상 같은 방식으로 프록시가 만들어지는 게 예측하기 쉽기 때문이다. 인터페이스 없이 클래스만 있는 컴포넌트에 `@Transactional`이나 `@CircuitBreaker`를 붙여도 문제없이 동작하는 이유가 이것이다 — JDK 동적 프록시였다면 인터페이스가 없는 순간 프록시 자체를 못 만들었을 것이다. 인터페이스 기반 방식은 jdk-dynamic-proxy.md, 프록시 전반의 개념은 spring-aop-proxy.md에 정리했다.
