# granularity

문제를 분해할 때 작업의 크기와 수를 어떻게 결정할 것인지에 관한 개념. 분해의 세분화 정도를 의미한다.

작업 하나에서 실행되는 명령어 수로 측정한다.

## fine-grained vs coarse-grained

fine-grained(세밀한 분해) — 문제를 많은 수의 작은 작업으로 쪼갠다. 더 많은 병렬성을 얻을 수 있고 처리 자원 간에 작업을 고르게 분산할 수 있다. 그러나 작업 수가 늘수록 작업 간 통신 비용과 스레드/프로세스 생성 비용이 증가한다. 작업이 100만 개가 되면 OS 스케줄러 부하가 극심해진다.

coarse-grained(굵은 분해) — 문제를 적은 수의 큰 작업으로 쪼갠다. 통신과 조율 오버헤드가 낮다. 그러나 작업 크기가 불균등하면 일부 처리 자원은 바쁘고 나머지는 노는 load imbalance가 생긴다. 이는 프로그램의 동시성을 제한한다.

최적 성능은 두 극단의 중간 어딘가에 있다.

## 이상적인 작업 수

분해된 작업 수는 최소한 사용 가능한 처리 자원(코어, 스레드) 수 이상이어야 한다. 가능하면 더 많은 것이 좋다. 런타임 시스템이 스케줄링 유연성을 가질 수 있기 때문이다.

예를 들어 시스템에 4개 코어가 있을 때 4개 스레드로 딱 나눠버리면, 4코어 시스템에서는 최적이지만 8코어 시스템에서는 절반이 논다. 작업 수를 코어 수보다 많게 만들면 런타임 시스템이 남는 코어를 활용할 수 있다.

## agglomeration

fine-grained 분해 후 성능 향상을 위해 작은 작업들을 더 큰 단위로 묶는 과정. 통신 오버헤드를 줄이기 위해 같은 프로세서에 배정될 작업들을 하나로 합친다. 이 과정은 Foster's Methodology(Chapter 13)에서 체계적으로 다룬다.

data decomposition에서는 가능한 한 작은 단위로 먼저 쪼개고, 필요한 경우 agglomeration으로 합치는 전략이 권장된다. 처음부터 크게 쪼개면 병렬화 기회를 놓친다.
