# file-system-basics (파일 시스템 기초)

파일 시스템은 디스크에 데이터를 파일 단위로 저장하고 이름으로 찾을 수 있게 조직하는 방법이다. 운영체제의 일부로 동작하며, 프로그램이 섹터 번호 대신 파일 이름만으로 데이터를 읽고 쓸 수 있게 해준다.

## 파일 시스템이 필요한 이유

디스크는 섹터(sector) 단위로 데이터를 읽고 쓴다. 섹터는 보통 512바이트다. 프로그램을 직접 저장하면 어느 트랙 몇 번 섹터에 있는지 직접 기억해야 하고, 긴 프로그램이 연속된 섹터에 있지 않으면 관리가 불가능해진다. 파일 시스템이 이 복잡성을 숨긴다.

## CP/M 파일 시스템

CP/M 디스크(8인치 단면 77트랙)의 구조를 예로 들면, 처음 두 트랙은 CP/M 자체가 저장된다. 나머지 75트랙이 파일 저장 공간이다.

파일 저장 공간은 할당 블록(allocation block) 단위로 나뉜다. 할당 블록 하나는 8개 섹터, 즉 1024바이트다. 디스크에 할당 블록이 243개 있다(0번~242번).

첫 두 할당 블록(2048바이트)은 디렉터리(directory) 전용이다. 디렉터리는 디스크에 저장된 모든 파일의 목록이다. 각 파일은 32바이트짜리 디렉터리 엔트리 하나를 차지한다. 총 디렉터리 크기가 2048바이트이므로 최대 64개 파일을 저장할 수 있다.

디렉터리 엔트리에 담긴 정보는 다음과 같다.

- 파일명: 최대 8자 (bytes 1~8)
- 파일 타입: 최대 3자 (bytes 9~11) — TXT는 텍스트, COM은 실행 파일
- 디스크 맵: 이 파일이 어느 할당 블록들에 저장되어 있는지 (bytes 16~31)

파일 이름과 타입을 합쳐 `MYLETTER.TXT`, `CALC.COM` 형태로 쓴다. 이 8.3 명명 규칙은 MS-DOS까지 이어졌다.

## 텍스트 파일과 바이너리 파일

텍스트 파일(text file)은 ASCII 코드만으로 이루어진 파일이다. 사람이 읽을 수 있다. 숫자도 ASCII 문자로 저장하므로, 숫자 42를 저장하면 `34h 32h` (문자 '4'와 '2')가 된다.

바이너리 파일(binary file)은 기계가 해석하는 형태로 저장한다. 숫자 42를 저장하면 `2Ah`(16진수 42) 하나가 된다. 실행 파일(COM)이 바이너리 파일이다.

## 계층적 파일 시스템

CP/M과 초기 MS-DOS의 파일 시스템은 디렉터리가 하나였다. 파일이 많아지면 혼란스러워진다.

MS-DOS 2.0에서 계층적 파일 시스템(hierarchical file system)이 도입됐다. 디렉터리 안에 디렉터리(서브디렉터리, 폴더)를 만들 수 있게 됐다. 최상위 디렉터리를 루트 디렉터리(root directory)라 한다. 이 구조는 UNIX에서 먼저 만들어진 것을 MS-DOS가 가져온 것이다.
