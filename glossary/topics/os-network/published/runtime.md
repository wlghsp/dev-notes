# runtime (런타임)

"무언가를 실제로 실행시켜주는 주체"라는 뜻이다. 문맥마다 가리키는 대상이 다르지만 의미는 같다.

## 문맥별 런타임

**Java 런타임 (JRE / JVM)**
Java 바이트코드를 실제로 실행하는 환경이다. `.java` 파일을 컴파일하면 `.class` 파일(바이트코드)이 나오고, JVM이 그걸 읽어서 실행한다. Java 코드는 JVM 없이는 돌아가지 않는다.

**컨테이너 런타임 (containerd, runc)**
컨테이너를 실제로 켜고 끄는 프로그램이다. namespace/cgroup 시스템 콜을 호출해서 격리된 프로세스를 띄운다. Kubernetes는 스케줄링만 결정하고, 실제로 컨테이너를 실행하는 일은 컨테이너 런타임에 위임한다.
참고: kubernetes-container-runtime.md

**JavaScript 런타임 (Node.js, 브라우저)**
JavaScript는 원래 브라우저 안에서만 돌아가는 언어였다. Node.js는 브라우저 밖에서 JS를 실행할 수 있게 해주는 런타임이다. V8 엔진을 꺼내서 서버에서 돌린 것이다.

## 공통 패턴

런타임이 필요한 이유는 코드나 이미지 자체가 "실행 가능한 상태"가 아니기 때문이다.

- Java 바이트코드는 JVM이 해석해줘야 실행된다
- 컨테이너 이미지는 런타임이 namespace/cgroup을 설정해줘야 프로세스가 뜬다
- JS 코드는 엔진이 파싱하고 실행해줘야 동작한다

런타임은 항상 "중간에서 실행을 책임지는 레이어"다.
