# 인프라 대시보드 표출 항목과 시각화 예시

이 문서는 대시보드에 무엇을 표시하고, 각 항목을 어떤 형태로 보여줄지 정리한다. 모든 수치·대상명·임계선은 화면 설명용 예시다. 막대와 그래프는 표현 방식을 보여주는 개략도다.

> `[신규 제안]`은 이번 문서에서 추가한 기능·가공을 뜻한다. 기존 지표의 시각화 변경은 표시하지 않는다. 표시가 없는 항목도 현재 구현이 모두 확인됐다는 뜻은 아니다.

## 1. 자원풀 잔여 용량

**보여줄 값:** CPU·메모리·스토리지별 할당 가능 총량, 할당량, 잔여량, 할당률.

**표시 방식:** 자원별 요약 카드 3개. 잔여량을 가장 큰 숫자로 표시하고, 아래에 할당량 / 총량과 가로 막대를 배치한다. 세 막대는 같은 길이와 0~100% 기준을 사용한다. 잔여가 적은 카드에만 주의 색상과 상태 문구를 넣는다.

```text
CPU                         메모리                      스토리지  [주의]

380 vCore 남음              1.1 TiB 남음                50 TiB 남음
████████████░░░░░░░░        ███████████████░░░░░        ██████████████████░░
할당 620 / 1,000            할당 2.9 / 4.0              할당 450 / 500
할당률 62%                  할당률 72.5%                할당률 90%

█ 할당   ░ 잔여
```

숫자는 신규 수요를 얼마나 받을 수 있는지, 막대는 어떤 자원이 상대적으로 부족한지 보여준다. 예약분이 별도로 존재하면 막대를 할당·예약·잔여로 나눈다. 물리 용량과 할당 가능 용량은 명칭을 구분한다.

## 2. 자원 용량 추이와 소진 전망 [신규 제안: 소진 예측]

**보여줄 값:** 기간별 할당량 변화, 현재 잔여량, 주간 순증가량, 예상 소진까지 남은 기간.

**표시 방식:** 장기 라인차트와 전망 숫자 카드. 관측 구간은 실선, 미래 추정 구간은 점선으로 그리고, 총량을 가로 기준선으로 표시한다. 현재 시점에 세로선을 넣어 관측과 예측을 구분한다.

```text
스토리지 할당 추이                         [최근 6주 ▾]

500 TiB ────────────────────────────────────● 총량
        │                              · ·  │
450 TiB │                       ━━━● ·      │
        │                  ━━━━━   ┊        │
400 TiB │          ━━━━━━━━         ┊        │
        │   ━━━━━━━                ┊        │
        └──────────────────────────┴────────┴────
             과거                 현재    약 4주 후

잔여 50 TiB       주간 증가 +12.5 TiB       약 4주 후 소진 예상
관측 ━━━          추정 · · ·
```

“약 4주 후” 옆에는 “현재 증가 속도 유지 시”를 붙인다. 관측이 부족하거나 증가 추세가 없으면 날짜 대신 “소진 시점 산정 불가”와 이유를 표시한다. CPU·메모리·스토리지는 탭으로 전환하며, 서로 다른 단위를 한 축에 겹치지 않는다.

## 3. CPU·메모리 실사용 추이

**보여줄 값:** 선택한 호스트 또는 VM의 CPU·메모리 사용률, 현재값, 조회 기간 최고값, 임계값 초과 구간.

**표시 방식:** 같은 시간축을 사용하는 작은 라인차트 2개를 위아래로 배치한다. 두 차트 모두 세로축을 0~100%로 고정하고, 차트 제목 옆에 현재값과 최고값을 표시한다. 초과 구간만 옅은 경고색으로 강조한다.

```text
node-07 · 실사용                         [최근 1시간 ▾]

CPU      현재 82% · 기간 최고 96%
100% │                       ╭╮
 85% ├ · · · · · · · · · · ·││· · · ·  예시 임계선
     │       ╭──────╮    ╭──╯╰────
  0% └──────────────────────────────────
     13:30             14:00       14:30

메모리   현재 68% · 기간 최고 74%
100% │
     │           ╭─────────────────
     │ ──────────╯
  0% └──────────────────────────────────
     13:30             14:00       14:30
```

호스트 전체 평균을 표시할 때는 “호스트 평균”이라는 집계 범위를 명시하고, 아래의 상위 사용 대상과 함께 보여준다. 할당률은 이 그래프에 섞지 않는다.

## 4. 사용률이 높은 호스트·VM

**보여줄 값:** 자원별 사용률 상위 대상, 현재 사용률, 임계값 초과 지속 시간.

**표시 방식:** 내림차순 가로 막대 순위. 대상 이름을 왼쪽에, 수치와 지속 시간을 오른쪽에 둔다. 상위 5개를 기본으로 보여주고 전체 목록으로 연결한다.

```text
사용률 상위 대상                  [CPU] [메모리] [파일시스템]

01  node-07   ███████████████████░   96%  위험 · 15분 지속
02  node-12   ██████████████████░░   91%  주의 ·  6분 지속
03  node-03   ████████████████░░░░   80%
04  node-18   ██████████████░░░░░░   72%
05  node-02   █████████████░░░░░░░   65%

                                         전체 대상 보기 →
```

CPU·메모리는 호스트 또는 VM 단위로, 파일시스템은 `node-07 /data`처럼 마운트 경로까지 표시한다. 같은 호스트에 파일시스템이 여러 개 있어도 어느 곳이 부족한지 구분할 수 있어야 한다.

## 5. 기관·프로젝트별 자원 점유

**보여줄 값:** 기관 또는 프로젝트별 할당량, 선택 범위의 전체 할당량 대비 점유율, 순위.

**표시 방식:** 가로 막대 랭킹. CPU·메모리·스토리지를 탭으로 전환하고, 기관과 프로젝트도 별도 선택으로 구분한다. 상위 5개와 기타를 표시한다.

```text
스토리지 점유                         [기관 ▾] [스토리지 ▾]
전체 할당량 450 TiB 기준

기관 A   ████████████████████    180 TiB   40%
기관 B   ██████████████          126 TiB   28%
기관 C   █████████                81 TiB   18%
기타     ███████                 63 TiB   14%
```

순위를 빠르게 비교할 수 있도록 도넛보다 막대를 사용한다. 기관 선택 시 해당 기관의 프로젝트 순위로 내려가며, 현재 조회 범위와 점유율의 분모를 제목 아래에 표시한다.

## 6. 할당 대비 실사용과 저사용 검토 후보 [신규 제안: 비교·후보 선정]

**보여줄 값:** 프로젝트별 할당량, 같은 단위로 환산한 평균 실사용량, 할당량 대비 평균·P95 사용률, 관측 기간. P95 비교도 `[신규 제안]`에 포함한다.

**표시 방식:** 할당량은 연한 배경 막대, 실사용량은 진한 내부 막대로 겹쳐 보여준다. 공통 눈금으로 절대량을 비교하고, 오른쪽에 사용률을 병기한다.

```text
CPU 할당 대비 평균 실사용 · 최근 14일
공통 눈금: 0 ───────────────────────────── 100 vCore

sandbox   ██░░░░░░░░░░░░░░       평균 6.4 / 할당 80 vCore
                                   평균 8% · P95 18%  [검토 후보]

portal    ████████████░░░░░░░░    평균 60 / 할당 100 vCore
                                   평균 60% · P95 88%

batch     █████░░░░░░░░░░        평균 24 / 할당 72 vCore
                                   평균 33% · P95 92%

█ 평균 실사용   ░ 할당 중 평균 미사용 부분
```

평균이 낮아도 피크가 높은 배치 작업을 구분할 수 있도록 P95를 함께 보여준다. “평균 미사용” 부분을 곧바로 회수 가능량으로 표시하지 않는다. 후보 선택 시 관측 기간, 수집률, 피크 추이를 펼친다.

## 7. Kubernetes Pod 상태

**보여줄 값:** Running·Pending·Failed·Succeeded·Unknown 상태별 Pod 수, 전체 Pod 수, 재시작 반복 대상 수.

**표시 방식:** 상태 분포는 하나의 누적 가로 막대와 상태별 숫자로 표시한다. 재시작 반복은 분포와 분리한 강조 배지로 둔다. 아래에는 확인이 필요한 Pod만 목록으로 보여준다.

```text
Pod 상태                                           전체 120개

████████████████████████████████████████▓▓▒▒░
Running 110   Pending 4   Failed 2   Succeeded 3   Unknown 1

[재시작 반복 2개]   조회 기간: 최근 1시간

billing-api-7d9   billing   CrashLoopBackOff   재시작 +12회
report-job-2a1    reports   Pending           8분 지속
```

CrashLoopBackOff는 Pod 상태 분포와 별개인 컨테이너 대기 사유로 표시한다. 재시작 반복 2개를 전체 120개에 추가하지 않는다. 상태는 색과 이름을 함께 쓰고, 소수의 실패 대상은 막대 비율이 작아도 숫자로 확인할 수 있게 한다.

## 8. 주요 이벤트 타임라인

**보여줄 값:** 발생 시각, 대상, 이벤트 유형, 요약, 반복 횟수.

**표시 방식:** 최신 항목이 위에 오는 세로 타임라인. 이벤트 종류마다 아이콘과 짧은 이름을 붙인다. 같은 대상에서 반복되는 동일 이벤트는 한 항목에 횟수를 모아 표시한다.

```text
주요 이벤트                              [전체 유형 ▾]

14:32  ●  Pod 재시작 반복
       │  billing-api-7d9 · 최근 10분 12회
       │
14:25  ◆  스케일 변경
       │  portal-api · replica 3 → 5
       │
14:18  ▲  사용률 임계값 초과
       │  node-07 /data · 95% 도달
       │
14:10  ✓  알람 해제
          node-03 · CPU 사용률 회복
```

차트의 이벤트 마커를 선택하면 같은 항목을 보여준다. 시간상 인접한 이벤트는 함께 확인할 수 있게 하되, 원인으로 단정하는 연결선은 붙이지 않는다. 스케일 변경처럼 이력이 필요한 항목은 실제 이력이 있을 때 표시한다.

## 9. 네트워크 In/Out 트래픽

**보여줄 값:** 선택 인터페이스의 수신·송신 처리량, 조회 기간 최대 처리량, 트래픽 상위 인터페이스.

**표시 방식:** 같은 시간축에 In/Out 두 선을 표시하고 색상과 선 모양을 다르게 한다. 현재 수치는 차트 위에, 상위 대상은 차트 아래 짧은 랭킹으로 둔다.

```text
네트워크 · gateway-01 / eth0                   [최근 1시간 ▾]

수신 In  320 Mbps                 송신 Out  180 Mbps

Mbps │                 ╭────╮
     │   ━━━━━━━━━━━━━━╯    ╰━━━━━━     ━ 수신
     │       · · · · · · · · · · ·     · 송신
   0 └────────────────────────────────
     13:30          14:00         14:30

트래픽 상위 · 현재 In + Out
01 gateway-01 / eth0   ███████████████   500 Mbps
02 gateway-02 / eth0   █████████         300 Mbps
```

전송된 누적 바이트와 초당 처리량을 구분해 `Mbps` 또는 `MiB/s`를 일관되게 사용한다. 링크 용량을 아는 경우에만 별도로 대역폭 사용률을 표시한다.

## 10. 스토리지 사용 현황

**보여줄 값:** 스토리지 풀별 실제 사용량·실사용 기준 총량·잔여량, 호스트 파일시스템별 사용률.

**표시 방식:** 풀별 실제 사용량은 가로 막대 목록, 파일시스템은 사용률 높은 순으로 별도 목록을 둔다. 할당 현황과 실제 저장된 데이터의 양은 제목부터 구분한다.

```text
스토리지 풀 · 실제 사용량

pool-a   ████████████████░░░░  400 / 500 TiB   잔여 100 TiB
pool-b   ██████████░░░░░░░░░░  100 / 200 TiB   잔여 100 TiB

파일시스템 · 확인 필요 대상

node-07 /data   ███████████████████░   96%  [위험]
node-12 /var    ██████████████████░░   91%  [주의]
```

pool-a의 할당량이 450 TiB이고 실제 사용량이 400 TiB일 수 있다. 이때 실제 빈 공간 100 TiB를 신규 할당 가능량이라고 표시하지 않는다. 풀의 실사용 데이터가 없다면 파일시스템 수치를 풀 수치로 대체하지 않는다.

## 11. 하드웨어 상태

**보여줄 값:** 서버별 정상·주의·장애·미확인 상태와 해당 부품. 온도·전원·팬 등 세부 값은 수집되는 항목만 표시한다.

**표시 방식:** 서버 한 대를 하나의 칸으로 표현한 상태 격자. 문제가 있는 서버는 상태 문구를 함께 표시하고 선택 시 부품 정보를 펼친다. 서버가 많으면 랙 또는 클러스터로 묶는다.

```text
하드웨어 상태 · Rack A

[정상 srv-01]  [정상 srv-02]  [주의 srv-03]  [정상 srv-04]
[정상 srv-05]  [장애 srv-06]  [정상 srv-07]  [미확인 srv-08]

선택: srv-06
전원 PSU-2 장애 · 마지막 관측 14:32
```

정상은 옅은 청록색, 주의는 황색, 장애는 적색, 미확인은 회색으로 구분한다. 미수집 장비가 정상 장비와 같은 색으로 보이지 않게 한다.

## 12. 활성 알람과 확인 대상

**보여줄 값:** 심각도별 활성 알람 수, 대상, 발생 원인, 현재값, 지속 시간, 발생·해제 상태.

**표시 방식:** 상단에 심각도별 숫자를 작게 요약하고, 아래에는 대상별 목록을 둔다. 심각도 분류와 확인 우선순위 구성은 `[신규 제안]`이다. 각 행 왼쪽에 상태 색상선을 넣어 우선순위를 구분한다.

```text
활성 알람                           위험 1 · 주의 2

┃ 위험  node-07 /data
┃       파일시스템 사용률 96% · 15분 지속       [상세 →]

┃ 주의  billing-api-7d9
┃       재시작 반복 · 최근 10분 12회            [상세 →]

┃ 주의  pool-a
┃       할당 가능 잔여 10%                     [상세 →]

[활성 3]  [해제 이력]
```

알람 건수와 영향을 받는 자원 수는 구분한다. 같은 자원의 반복 알람은 묶어서 보여주고 발생 횟수를 병기한다. 소진 전망은 “예측 주의”처럼 관측 알람과 구분하며, 실제 알람 체계에 심각도가 없다면 화면 분류임을 표시한다.

## 13. 데이터 수집 상태 [신규 제안: 수집 상태 종합 표시]

**보여줄 값:** 정상 수집·지연·미수집 대상 수, 대상별 마지막 관측 시각, 지연 시간.

**표시 방식:** 화면 상단의 작은 상태 표시와 지연 대상 목록. 기본 상태에서는 공간을 적게 쓰고, 지연이 발생하면 대상과 시각을 펼쳐 보여준다.

```text
데이터 상태   정상 수집 47 / 48개 · 지연 1개   [펼치기 ▾]

cluster-b   [수집 지연]
마지막 관측 14:24 · 기준 시각 14:32 · 8분 경과
```

로그 수집 대상에는 마지막 수신 시각과 수신 이후 경과 시간을 표시한다. 로그가 없다는 이유만으로 수집 장애로 확정하지 않으며, 폐쇄망 로그 확인 화면의 예시는 18번에 정리한다.

지연 대상의 카드에는 “마지막 관측값”을 붙인다. 그래프는 누락 구간을 끊어서 표시하며, 값이 0인 것처럼 바닥으로 떨어뜨리지 않는다.

## 14. 운영 관리 화면에 추가할 항목

다음 항목은 별도 운영 관리 탭에 모아 보여준다. 각 항목도 숫자만 나열하기보다 실패·지연·미처리 대상을 바로 식별할 수 있게 구성한다.

### 외부 연동 처리 현황

**보여줄 값:** 연동 채널별 성공·실패 건수와 처리 지연.

**표시 방식:** 성공·실패 누적 막대와 지연 추이. 건수와 시간은 서로 다른 그래프로 표시한다.

```text
연동 A   ███████████████████▒   성공 980 · 실패 20
연동 B   ████████████████▒▒▒▒   성공 800 · 실패 200

█ 성공   ▒ 실패
처리 지연 · P95    ▁▂▂▃▂▅▇▅    현재 2.4초
```

### 스케줄러 실행 현황

**보여줄 값:** 작업별 최근 실행 결과, 소요 시간, 마지막 성공 시각.

**표시 방식:** 최근 실행 회차를 칸으로 나열한 이력 격자. 실패한 칸을 선택하면 오류 요약을 표시한다.

```text
최근 6회 실행                  과거 → 최근
자원 집계                      ✓ ✓ ✓ ✓ × ✓    최근 12초
알람 평가                      ✓ ✓ ✓ × × ×    최근 실패

✓ 성공 · × 실패 · — 미실행
```

### 관리자 활동

**보여줄 값:** 시간대별 활동 건수와 생성·수정·삭제 등 활동 유형.

**표시 방식:** 시간대별 누적 막대와 최근 변경 목록.

```text
활동 건수   ▁▂▅▃▇▂▁
            09시 → 15시

14:30  관리자 A · 프로젝트 설정 수정
14:22  관리자 B · 자원 할당 변경
```

### 고객지원 처리 현황

**보여줄 값:** 미답변·처리 중·완료 건수, 오래 대기한 문의.

**표시 방식:** 상태별 숫자 카드와 대기 시간 순 목록.

```text
미답변 8건       처리 중 12건       오늘 완료 23건

오래 대기한 문의
#1042  자원 증설 문의    2일 대기
#1051  접근 권한 문의    1일 대기
```

### 서비스 브로커·카탈로그와 보안 정책

**보여줄 값:** 브로커별 연결 상태, 등록 카탈로그 수, 접속 허용 IP의 활성·비활성 수.

**표시 방식:** 브로커는 상태 목록, 카탈로그와 IP 정책은 숫자 카드.

```text
broker-a  [정상]       broker-b  [연결 오류]
등록 카탈로그 24개     허용 IP 활성 18개 · 비활성 3개
```

등록 수와 활성 수는 구성 현황으로 표시한다. 등록 건수가 많다는 이유만으로 서비스나 보안 상태를 정상이라고 표현하지 않는다.

## 15. 로그 발생량 추이 [신규 제안: 시간대별 로그 집계]

**보여줄 값:** 선택 기간의 수집 로그 건수, 시간 구간별 건수, 시스템·컨테이너 로그별 발생량, 발생량 상위 대상.

**표시 방식:** 시간대별 막대그래프. 시스템 로그와 컨테이너 로그를 탭으로 구분하고, 클러스터·호스트·네임스페이스·Pod로 범위를 좁힌다. 막대 구간 선택 시 해당 시간의 메시지 목록을 아래에 표시한다.

```text
로그 발생량                     [시스템] [컨테이너] [최근 1시간 ▾]
대상: billing 네임스페이스       총 24,810건 · 5분 구간별 건수

건수 │                       █
     │                    █  █  █
     │        █     █     █  █  █
     │  █  █  █  █  █  █  █  █  █  █  █  █
   0 └────────────────────────────────────────
      13:30              14:00           14:30
                         └─ 구간 선택 ─┘

선택 구간 14:00–14:15 · 발생량 상위 대상
billing-api   ███████████████   4,200건
payment-api   ██████            1,680건
```

로그 증가를 곧바로 장애로 표시하지 않는다. 트래픽 증가나 로그 설정 변경으로도 건수가 달라질 수 있으므로 원문과 자원 지표로 연결한다. 건수는 현재 저장·조회 가능한 로그 기준이며, 중복 수집이나 누락 여부에 따라 실제 발생량과 다를 수 있다.

## 16. 반복 메시지 상위 목록 [신규 제안: 메시지 패턴 집계]

**보여줄 값:** 유사 메시지 패턴, 검출 건수, 영향 대상 수, 최초·최근 관측 시각, 대표 원문.

**표시 방식:** 검출 건수 내림차순 목록. 시간·요청 ID처럼 매번 바뀌는 부분을 제외한 패턴을 제목으로 표시하고, 항목 선택 시 대표 원문과 발생 대상 목록을 펼친다.

```text
반복 메시지 · 최근 1시간                       [호스트 / Pod ▾]

128건  connection refused        대상 3개   최근 14:32  [펼치기]
 42건  request timeout           대상 2개   최근 14:30  [펼치기]
 18건  no space left on device   대상 1개   최근 14:28  [펼치기]

선택: connection refused
최초 14:02 · 최근 14:32 · billing-api 외 2개 대상
대표 원문: connect to internal-service:8080 failed: connection refused
                                              [관련 로그 보기 →]
```

이 목록은 전체 로그 중 반복 패턴을 보여준다. 실패 문구를 찾는 별도 필터는 “오류 의심 패턴”으로 표시하며, 표준 로그 레벨이 확인되기 전에는 검출 건수를 “에러율”로 표현하지 않는다. 서로 다른 문제를 같은 패턴으로 묶지 않았는지 원문을 확인할 수 있게 한다.

## 17. 자원 지표와 관련 로그 [신규 제안: 대상·시간 연계 조회]

**보여줄 값:** 선택 대상의 자원 사용률 또는 이벤트, 선택 시점 전후의 로그, 로그 발생 시각과 출처.

**표시 방식:** 위쪽에 자원 추이, 아래쪽에 같은 대상의 로그를 배치한다. 그래프의 구간이나 이벤트 마커를 선택하면 관련 시간 범위가 강조되고 로그 목록이 함께 바뀐다. 앞뒤 시간 범위는 사용자가 조정한다.

```text
node-07 · CPU 사용률

100% │                  ╭──╮
     │          ╭───────╯  ╰────
     │ ─────────╯       ┊
  0% └──────────────────┼──────────────
       14:00          14:18          14:30
                        ▲ 선택 시점

관련 로그 · node-07 · 14:13–14:23             [전후 5분 ▾]
14:17:42  system   worker process started
14:18:03  system   retrying connection to internal-service
14:18:05  system   retrying connection to internal-service

[이전 로그 더 보기]                     [선택 원문의 앞뒤 로그]
```

“관련”은 같은 대상과 시간 범위라는 뜻이다. 화면에서 해당 로그를 CPU 급등의 원인이라고 단정하지 않는다. Pod 이벤트에서는 클러스터·네임스페이스·Pod를 함께 식별하고, 같은 이름의 다른 대상 로그가 섞이지 않게 한다.

## 18. 폐쇄망 로그 확인 화면 [신규 제안: 내부 통합 조회 화면]

**보여줄 값:** 내부 수집 대상의 로그 수신 상태, 발생량, 반복 패턴, 선택 구간의 원문.

**표시 방식:** 로그 전용 상세 탭에 위 세 항목과 13번 수집 상태를 함께 배치한다. 상단에서 범위와 기간을 선택하고, 발생량에서 구간을 고른 뒤 반복 메시지와 원문으로 내려간다. 검색·집계·원문 조회는 외부 서비스 호출 없이 내부에서 수행하는 화면으로 제안한다.

```text
로그 확인        [시스템 / 컨테이너 ▾] [대상 ▾] [최근 1시간 ▾]

수집 로그 24,810건      반복 패턴 3종      수신 상태 확인 1개

[시간대별 발생량 그래프                                    ]

[반복 메시지 상위 목록              ] [대상별 마지막 수신   ]
[패턴 · 건수 · 대상 수              ] [node-07  14:32       ]
[                                  ] [node-12  14:24 확인  ]

[선택 대상·구간의 로그 원문                                ]
[시각 · 출처 · 메시지 · 앞뒤 로그 펼치기                    ]
```

로그가 들어오지 않는 대상에는 “마지막 수신 이후 8분 경과”처럼 관측 사실을 표시한다. 로그 무발생과 수집 장애를 구분하려면 수집기 상태 또는 주기적인 상태 신호도 함께 확인하며, 근거가 없으면 “수신 상태 확인 필요”로 표현한다.

원문 조회는 사용자에게 허용된 대상 범위에서 제공하고, 자격 증명 등 민감한 값은 마스킹한다. 기존 로그 조회 기반에 집계·패턴 분류·연계 화면을 추가하는 제안이며, 실제 폐쇄망에서 수집되는 로그 종류와 필드는 확인이 필요하다.

## 한 화면에 배치하는 예시

첫 화면은 아래 구성을 기본으로 하고, 나머지 항목은 자원별 상세 탭에서 확인한다.

```text
[플랫폼 / 자원풀 / 기관 선택]                         [데이터 수집 상태]

[CPU 잔여 용량]           [메모리 잔여 용량]           [스토리지 잔여 용량]

[용량 추이 / 실사용 추이                       ]      [활성 알람        ]
[선택 자원의 시간 변화                         ]      [확인 대상        ]

[기관·프로젝트 점유                            ]      [할당 대비 실사용 ]

상세 탭: 호스트·VM | Kubernetes | 네트워크 | 스토리지 | 하드웨어 | 로그 | 운영 관리
```

표현은 숫자 카드·가로 막대·라인차트·상태 목록을 중심으로 통일한다. 모든 지표에는 대상 범위와 단위를 붙이고, 기간 집계에는 조회 기간을 표시한다. 정상은 청록색, 주의는 황색, 위험은 적색, 미확인은 회색을 쓰되 상태 문구를 항상 함께 표시한다.
