# system-call

유저 프로그램이 커널 서비스를 요청하는 메커니즘.

유저 프로세스는 직접 하드웨어에 접근하거나, 다른 프로세스의 메모리를 건드리거나, 파일을 마음대로 열 수 없다. 이런 특권 작업은 반드시 커널을 통해야 한다. 시스템 콜은 유저 모드에서 커널 모드로 전환하는 공식 진입점이다.

시스템 콜의 흐름:
1. 유저 프로그램이 시스템 콜 번호와 인자를 레지스터에 세팅
2. `syscall` 명령어(x86-64) 실행 → trap 발생
3. CPU가 커널 모드로 전환, 커널의 시스템 콜 핸들러로 점프
4. 커널이 요청 처리
5. 결과를 레지스터에 담아 유저 모드로 복귀

자주 쓰이는 시스템 콜: `read`, `write`, `open`, `close`, `fork`, `exec`, `exit`, `wait`, `mmap`

C 표준 라이브러리(`libc`)의 함수들은 대부분 내부에서 시스템 콜을 감싼 래퍼다. `printf`는 결국 `write` 시스템 콜을 호출한다.

시스템 콜은 일반 함수 호출보다 훨씬 비싸다. 모드 전환, 레지스터 저장/복원, 커널 스택 전환이 모두 포함되기 때문이다.
