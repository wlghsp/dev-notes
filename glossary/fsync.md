# fsync

**"OS 버퍼에 있는 데이터를 실제 디스크에 강제로 기록하는 시스템 콜"**

OS는 디스크 쓰기를 즉시 처리하지 않는다. 성능을 위해 메모리(페이지 캐시)에 모아뒀다가 나중에 한꺼번에 쓴다. `fsync`는 이 캐시를 즉시 디스크에 내려보내라고 OS에게 강제하는 명령이다.

---

## 왜 필요한가

```
write() 호출
  → OS 페이지 캐시에 저장 (메모리)
  → 함수는 즉시 반환 (빠름)
  → 실제 디스크 기록은 OS가 알아서 나중에

fsync() 호출
  → OS 캐시 → 디스크 강제 기록
  → 디스크에 완전히 쓰일 때까지 블로킹 (느림)
  → 완료 후 반환
```

`write()`만 하고 OS가 죽으면 캐시에 있던 데이터는 사라진다. `fsync()`까지 해야 디스크에 있다고 보장할 수 있다.

---

## DB에서의 역할

InnoDB가 COMMIT 시 Redo Log에 `fsync`를 호출하는 이유가 이것이다. "이 트랜잭션은 서버가 죽어도 반드시 복구 가능해야 한다"는 보장을 디스크 수준에서 확보하는 것이다.

`fsync` 없이 write()만 하면 빠르지만, OS가 죽는 순간 커밋한 데이터가 사라질 수 있다.

---

## 성능 트레이드오프

`fsync`는 느리다. 디스크가 실제로 기록을 완료할 때까지 기다려야 하기 때문이다. 그래서 DB는 `innodb_flush_log_at_trx_commit` 같은 설정으로 얼마나 자주 fsync할지 조절한다. 안전성과 성능의 트레이드오프다.
