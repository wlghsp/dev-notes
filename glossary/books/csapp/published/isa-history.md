# isa-history (ISA 설계 철학의 역사)

ISA(Instruction Set Architecture)는 CPU가 이해하는 명령어 집합의 규격이다. 어떤 명령어를 제공하고 어떻게 설계하느냐에 따라 성능, 전력, 구현 복잡도가 완전히 달라진다. 이 설계 철학을 둘러싼 논쟁이 수십 년에 걸쳐 아키텍처의 역사를 만들었다.

## 1970년대 — CISC 등장, "명령어가 많을수록 좋다"

당시 메모리는 극도로 비쌌다. 프로그램을 작게 만들려면 한 명령어로 많은 일을 해야 했다. 그래서 "복잡한 작업을 단일 명령어로 처리하자"는 CISC(Complex Instruction Set Computer) 철학이 나왔다.

x86이 대표적이다. `MOVSB` 하나로 메모리 블록 복사를 처리하고, 곱셈·나눗셈도 단일 명령어로 제공했다. 명령어 수백 개, 명령어 길이도 제각각이었다.

문제는 회로가 폭발적으로 복잡해진다는 것이었다. 명령어가 복잡할수록 디코딩 회로가 커지고, 클럭을 올리기 어려워진다. 그리고 실제 프로그램을 분석해보니 전체 명령어 중 20%만 90%의 시간을 차지했다. 복잡한 명령어 대부분은 거의 쓰이지 않았다.

## 1980년대 — RISC 등장, "단순할수록 빠르다"

스탠퍼드와 버클리에서 각각 MIPS와 RISC-I 프로젝트가 나왔다. 핵심 주장은 명령어를 단순하게 고정 길이로 만들면, 디코딩이 빠르고 파이프라이닝이 쉬워진다는 것이었다.

RISC(Reduced Instruction Set Computer)의 원칙:
- 명령어를 고정 길이(32비트)로
- 메모리 접근은 Load/Store만. 연산은 레지스터끼리만
- 명령어 수를 줄이고 클럭당 처리량을 높인다

실제로 같은 클럭에서 RISC가 훨씬 빨랐다. 단순한 명령어를 파이프라인에 빽빽하게 채울 수 있었기 때문이다.

## 1990년대 — x86의 생존, 내부적으로 RISC가 되다

RISC가 이론적으로 우월했지만 x86이 죽지 않았다. 이유는 소프트웨어 자산이었다. 수십 년치 x86 소프트웨어가 쌓여 있었고, 기업들은 아키텍처를 바꿀 수 없었다.

Intel과 AMD의 선택은 타협이었다. 겉으로는 x86 명령어를 받아들이되, CPU 내부에서 그 명령어를 더 단순한 마이크로-op(micro-operation)으로 쪼개서 RISC처럼 처리한다. 외부 인터페이스는 CISC, 내부 실행 엔진은 RISC가 된 것이다.

Pentium Pro(1995)부터 이 구조가 본격적으로 적용됐다. 오늘날 x86-64 CPU도 동일한 원리로 동작한다.

## 2000년대 — ARM의 조용한 확장

ARM은 1985년 영국 Acorn 컴퓨터에서 나왔다. 처음부터 RISC 설계였고, 저전력을 목표로 했다. 데스크탑 시장에서는 x86에 밀렸지만, 배터리로 동작하는 임베디드·모바일 시장에서 독점적 위치를 차지했다.

스마트폰 시대가 열리면서 ARM이 폭발적으로 퍼졌다. 2007년 아이폰부터 사실상 모든 스마트폰이 ARM이다. 저전력이 핵심 경쟁력이었다.

## 2020년대 — ARM이 서버와 데스크탑까지

Apple Silicon(M1, 2020)이 ARM이 데스크탑에서도 x86을 이길 수 있다는 걸 증명했다. 단순히 저전력이 아니라 성능도 앞섰다. CPU·GPU·메모리를 하나의 SoC로 통합한 구조가 핵심이었다.

서버 시장에서도 AWS Graviton(ARM 기반)이 x86 대비 가격 대비 성능으로 점유율을 늘리고 있다.

RISC가 옳았지만 x86이 소프트웨어 자산으로 버텼고, ARM이 모바일에서 축적한 생태계로 결국 서버와 데스크탑까지 올라온 흐름이다.

## CISC vs RISC — 지금도 유효한 구분인가

엄밀히 말하면 지금은 경계가 흐릿하다. x86은 내부적으로 RISC고, ARM도 점점 복잡한 명령어를 추가하고 있다(NEON, SVE 등 SIMD). 순수한 CISC나 순수한 RISC는 사실상 없다.

그래도 설계 철학의 차이는 남아있다. x86은 하위 호환성을 위해 복잡성을 안고 가고, ARM은 단순함을 유지하면서 확장을 선택적으로 추가한다.
