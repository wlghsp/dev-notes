# machine-code (기계어와 어셈블리)

CPU가 실제로 실행하는 것은 기계어(machine code)다. 어셈블리(assembly)는 그 기계어를 사람이 읽을 수 있는 텍스트로 표현한 것이다.

## 기계어란

기계어는 바이트의 나열이다. `53 48 89 d3 e8 00 00 00` 같은 형태. CPU는 이 바이트들을 명령어로 해석해서 실행한다. 소스코드에 대한 정보는 전혀 없다. 타입도 없고, 변수명도 없다. 바이트뿐이다.

## 어셈블리란

기계어와 1:1로 대응하는 텍스트 표현이다. `53`이라는 바이트가 `pushq %rbx`라는 어셈블리 명령어에 해당한다. 어셈블러(assembler)가 어셈블리를 기계어로 변환하고, 역방향은 디스어셈블러(disassembler)가 담당한다.

GCC로 어셈블리 파일을 생성하려면:
```
gcc -Og -S source.c
```

## 컴파일러가 숨기는 것들

C 코드를 작성할 때 보이지 않지만 기계어 수준에서 존재하는 것들:
- 프로그램 카운터(%rip) — 다음 실행할 명령어 주소
- 레지스터 파일 — 16개 범용 레지스터
- 조건 코드 레지스터 — 최근 연산 결과의 상태 플래그
- 가상 메모리 — 연속된 바이트 배열로 보이는 주소 공간

## ATT vs Intel 형식

같은 기계어를 두 가지 방식으로 표기한다.

ATT 형식(GCC/Linux 기본):
```
movq %rdx, %rbx    # 소스 먼저, 목적지 나중
```

Intel 형식(Microsoft/Intel 문서):
```
mov rbx, rdx       # 목적지 먼저, 소스 나중. % 없음
```

CSAPP은 ATT 형식을 사용한다.
