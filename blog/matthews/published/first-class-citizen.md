# 코드에서 1급 시민으로 다룬다는 것

## 문제의식

AI 덕분에 코드는 빠르게 만들 수 있게 됐지만, "좋은 코드"를 만드는 건 여전히 어렵다. 예를 들어 "사이트 만료되면 막아줘"라고 하면 AI는 바로 이런 코드를 준다.

```js
if (site.expired) {
  throw new Error('Site expired');
}
```

틀린 코드는 아니지만, 이런 조건문이 로그인·API·결제·관리자 화면 등 여기저기 생기기 시작하면, 원래는 단순한 개념 하나였던 것이 시스템 전체에 흩어진 규칙이 되어버린다.

## 1급 시민이란

원래 "1급 시민"은 프로그래밍 언어에서 함수 같은 대상을 다른 값처럼 변수에 담고, 인자로 넘기고, 반환할 수 있다는 뜻이다(예: TS의 함수). 여기서는 이 개념을 실무로 확장해서, 1급 시민을 **시스템이 이해하고 관리해야 하는 하나의 공식 개념**으로 정의한다.

## 예시: 만료 상태

`site.expired` 같은 boolean 조건으로 시작했던 것이, 서비스가 커지면서 로그인 정책·화면 표시·API 응답·결제 안내·로그/통계까지 다 얽히게 된다. 이 시점에서 boolean을 enum으로 승격시킨다.

```ts
enum SiteStatus {
  ACTIVE = 'ACTIVE',
  EXPIRED = 'EXPIRED',
  SUSPENDED = 'SUSPENDED',
}
```

이렇게 하면 "만료"가 흩어진 if문이 아니라, 화면·API·로그·통계·알림이 공통으로 참조할 수 있는 이름 있는 상태가 된다. 즉 시스템 안에서 시민권을 얻는 것.

## AI에게 어떻게 말해야 하는가

- "사이트가 만료되면 접근을 막아줘" → 기능이 생김 (조건문 하나 추가)
- "사이트 만료 상태를 1급 시민으로 다뤄줘" → 설계가 생김 (타입/도메인 모델/API/로그/테스트 전반에 반영)

AI는 요구사항을 코드로 빠르게 바꾸는 데 강하지만, 그냥 기능만 요청하면 가장 가까운 곳에 조건문을 붙이는 쪽으로 간다. "1급 시민으로 다뤄달라"는 요청이 AI로 하여금 임시방편이 아니라 정식 개념으로 설계하게 만드는 트리거가 된다.

## 결론

좋은 설계란 예외를 계속 추가하는 게 아니라, 반복해서 등장하는 개념을 발견해서 1급 시민으로 승격시키는 과정이다. if문 → 상태 → 이벤트 → 정책으로 진화한다. AI 시대에는 코드를 쓰는 능력보다, **어떤 개념을 시스템의 중심에 올려야 하는지 말해주는 능력**이 더 중요해질 수 있다.
