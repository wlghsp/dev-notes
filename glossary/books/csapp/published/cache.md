# cache

CPU가 메모리에서 데이터를 가져오는 데 걸리는 시간을 줄이기 위해, 자주 쓰는 데이터를 CPU 가까이에 복사해두는 고속 저장소.

## 왜 캐시가 필요한가

CPU는 1 clock에 연산을 처리할 수 있지만, 메인 메모리(DRAM)에서 데이터를 읽어오려면 수백 clock이 걸린다. 이 속도 차이를 "메모리 갭(memory gap)"이라 부르고, 캐시는 이 갭을 메우기 위해 존재한다.

## 계층 구조

CPU 안에 여러 레벨의 캐시가 있다.

1. **L1 캐시** — CPU 코어(연산 처리 단위) 바로 옆. 수 KB. 접근 시간 ~4 cycle(clock 신호 횟수). 가장 빠르고 가장 작다.
2. **L2 캐시** — L1보다 크고 느리다. 수십 ~ 수백 KB. ~10 cycle.
3. **L3 캐시** — 여러 코어가 공유. 수 MB. ~30~40 cycle.

캐시에 없으면 DRAM까지 내려가고, DRAM에도 없으면 디스크까지 내려간다. 계층이 내려갈수록 크기는 크고 속도는 느리다.

## 지역성(Locality)

캐시가 효과적인 이유는 프로그램이 지역성을 가지기 때문이다.

- **시간적 지역성(Temporal Locality)** — 방금 접근한 데이터는 곧 다시 접근할 가능성이 높다. 루프 안의 카운터 변수가 대표적이다.
- **공간적 지역성(Spatial Locality)** — 방금 접근한 주소 근처의 데이터도 곧 접근할 가능성이 높다. 배열을 순서대로 읽는 게 대표적이다.

캐시는 데이터를 한 바이트씩이 아니라 "캐시 라인(cache line)" 단위(보통 64바이트)로 가져온다. 공간적 지역성 덕분에 이 전략이 유효하다.
