# integer overflow (정수 오버플로우)

정수 연산 결과가 해당 타입이 표현할 수 있는 범위를 벗어나는 현상.

## 왜 발생하는가

비트 수가 고정되어 있기 때문이다. 8비트 부호 있는 정수는 -128 ~ 127까지만 표현할 수 있다. 127에 1을 더하면 128이 되어야 하는데, 128은 표현 범위를 벗어난다.

```
01111111  = 127
+ 00000001
----------
10000000  = -128  (오버플로우 발생)
```

최상위 비트가 1이 되면서 음수로 해석된다. 결과가 완전히 뒤집힌다.

## 부호 없는 정수의 오버플로우

8비트 부호 없는 정수(0~255) 기준:

```
11111111  = 255
+ 00000001
----------
100000000 → 올림수 버림 → 00000000 = 0
```

255에 1을 더하면 0이 된다. 시계처럼 한 바퀴 돌아온다. 이걸 wrap-around라고 한다.

## ALU와의 관계

ALU가 연산 후 오버플로우가 발생하면 플래그 레지스터의 Overflow 플래그를 1로 세팅한다. 소프트웨어가 이 플래그를 확인해서 오버플로우 여부를 알 수 있다.

언어마다 처리 방식이 다르다.

- C — 부호 있는 정수 오버플로우는 undefined behavior. 컴파일러가 최적화 과정에서 예측 불가능한 동작을 할 수 있다.
- Java — 오버플로우가 발생해도 예외를 던지지 않고 wrap-around된 값을 반환한다.
- Rust — debug 모드에서는 패닉, release 모드에서는 wrap-around.

## 실제 버그 사례

Boeing 787 소프트웨어에서 248일 연속 가동 시 정수 오버플로우로 전력 시스템이 꺼지는 버그가 발견됐다. 카운터가 32비트 한계를 넘어서 0으로 리셋됐기 때문이다.
