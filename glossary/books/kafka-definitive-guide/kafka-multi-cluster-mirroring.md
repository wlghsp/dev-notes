# Kafka 멀티 클러스터와 MirrorMaker

하나의 Kafka 클러스터로는 부족해서 여러 클러스터를 두고, 그 사이에 데이터를 복사하는 방식.

## 왜 클러스터를 여러 개 두는가

데이터 종류별로 클러스터를 분리하거나, 보안 요구사항 때문에 격리가 필요하거나, 데이터센터가 여러 곳이라 재해 복구(disaster recovery)를 대비해야 할 때 클러스터를 나눈다.

## 클러스터 간 복제는 별도로 필요하다

Kafka 클러스터 내부의 리더-팔로워 복제 메커니즘은 하나의 클러스터 안에서만 동작한다(참고: kafka-broker-and-cluster.md). 데이터센터를 여러 개 두고 서로 다른 클러스터를 쓴다면, 클러스터 사이의 복제는 이 메커니즘으로 처리되지 않는다.

예를 들어 사용자가 한 데이터센터에서 프로필을 바꾸면, 다른 데이터센터의 검색 결과에도 그 변경이 반영돼야 한다. 이런 경우에 클러스터 간 복제가 필요해진다.

## MirrorMaker

Kafka 프로젝트가 제공하는 클러스터 간 복제 도구다. 특별한 게 아니라 컨슈머와 프로듀서를 큐로 연결해놓은 것에 가깝다 — 한 클러스터에서 메시지를 소비해서 다른 클러스터에 그대로 생산한다.

이 단순한 구조로도, 로컬 클러스터 여러 개를 하나의 집계(aggregate) 클러스터로 모으고 그 집계 클러스터를 다시 다른 데이터센터로 복사하는 식의 복잡한 데이터 파이프라인을 구성할 수 있다.
