# bytecode
참고: Java Performance: The Definitive Guide Ch.1

---

Java 소스코드(.java)를 javac로 컴파일하면 생성되는 중간 표현(.class 파일)이다.

특정 CPU 아키텍처의 기계어가 아니라, JVM이 이해하는 가상 명령어 집합(instruction set)으로 구성된다. 바이트코드라는 이름은 각 명령어의 opcode가 1바이트이기 때문이다.

---

## 왜 중간 단계가 필요한가

직접 기계어로 컴파일하면 플랫폼마다 다른 바이너리가 필요하다. 바이트코드는 플랫폼 독립적인 공통 언어 역할을 한다. JVM이 각 플랫폼에서 바이트코드를 해석하거나 그 플랫폼의 기계어로 변환(JIT)한다.

---

## 소스코드 → 바이트코드 → 실행까지의 흐름

```
Hello.java
  ↓ javac (컴파일)
Hello.class  (바이트코드)
  ↓ JVM 실행
  ├── 인터프리터: 바이트코드를 한 줄씩 해석해 실행 (느리지만 즉시 시작)
  └── JIT 컴파일러: 자주 실행되는 코드를 기계어로 변환 (빠르지만 컴파일 시간 필요)
```

---

## 바이트코드와 성능의 관계

바이트코드 자체는 성능 병목이 아니다. 문제는 그 바이트코드를 JVM이 어떻게 처리하는가다.

JIT 컴파일러는 바이트코드를 분석해 최적화한다. 소스코드 수준에서 "비효율적으로" 보이는 코드도 JIT가 최적화해 빠르게 만들 수 있고, 반대로 소스코드가 깔끔해도 JIT 최적화를 방해하는 패턴이 있으면 느려진다.

`javap -c Hello.class` 명령으로 바이트코드를 직접 볼 수 있다.
