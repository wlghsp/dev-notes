# Column vs Row-Oriented DBMS

데이터를 디스크에 물리적으로 어떻게 배치하는가에 따라 DB를 로우 지향과 컬럼 지향으로 나눈다. 이 선택은 접근 패턴에 따라 성능에 큰 영향을 미친다.

## 로우 지향 (Row-Oriented)

같은 로우에 속하는 값들을 디스크에 연속으로 저장한다. 테이블을 수평으로 파티셔닝하는 방식이다.

```
| ID | Name  | Birth Date  | Phone Number  |
| 10 | John  | 01 Aug 1981 | +1 111 222 333|
| 20 | Sam   | 14 Sep 1988 | +1 555 888 999|
```

디스크에서 한 블록을 읽으면 그 로우에 속한 모든 컬럼이 함께 딸려온다. 특정 사용자 전체 정보를 읽거나 쓸 때 효율적이다. 하지만 전화번호만 조회하고 싶을 때도 이름, 생년월일이 모두 페이징되어 들어온다.

로우 지향이 적합한 경우: 전체 레코드를 읽고 쓰는 OLTP 워크로드. 포인트 쿼리와 범위 스캔.

## 컬럼 지향 (Column-Oriented)

같은 컬럼에 속하는 값들을 디스크에 연속으로 저장한다. 테이블을 수직으로 파티셔닝하는 방식이다.

```
Symbol: 1:DOW; 2:DOW; 3:S&P; 4:S&P
Date:   1:08 Aug 2018; 2:09 Aug 2018; ...
Price:  1:24,314.65; 2:24,136.16; ...
```

컬럼 단위로 파일을 분리해서 저장하므로, 특정 컬럼만 조회할 때 다른 컬럼을 읽지 않아도 된다. 같은 타입의 값이 연속으로 저장되므로 압축 효율도 높다. 또한 현대 CPU의 벡터 명령어(SIMD)를 이용해 여러 데이터를 한 번에 처리할 수 있다.

컬럼 지향이 적합한 경우: 많은 로우에 걸쳐 특정 컬럼의 집계를 계산하는 OLAP 워크로드. 분석 쿼리.

## Wide Column Stores

컬럼 지향과 혼동하지 말아야 할 개념이다. BigTable, HBase 같은 와이드 컬럼 스토어는 데이터를 다차원 맵으로 표현한다. 컬럼들이 column family로 묶이고, 각 column family 내부에서는 데이터가 로우 단위로 저장된다. 키나 키 시퀀스로 데이터를 검색하는 구조에 적합하다.

## 선택 기준

워크로드의 접근 패턴이 결정한다.

- 대부분의 컬럼을 요청하는 포인트 쿼리나 범위 스캔이 주 워크로드 → 로우 지향
- 일부 컬럼에 대한 집계나 분석이 주 워크로드 → 컬럼 지향
