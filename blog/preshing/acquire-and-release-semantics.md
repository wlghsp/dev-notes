# Acquire와 Release 시맨틱

원문: "Acquire and Release Semantics" — Preshing on Programming (2012)

## 먼저, 왜 이런 개념이 필요한가

컴파일러와 CPU는 성능을 위해 코드에 적힌 순서와 다르게 명령어를 실행할 때가 있다. 예를 들어 다음 코드가 있다고 하자.

```cpp
A = 1;
B = 2;
```

한 스레드 안에서만 보면 `A`를 먼저 쓰든 `B`를 먼저 쓰든 결과가 똑같기 때문에, 컴파일러나 CPU가 순서를 바꿔서 `B`를 먼저 써도 아무 문제가 없다. 이런 순서 바꾸기를 재배치(reordering)라고 한다.

문제는 스레드가 여러 개일 때 생긴다. 스레드 1이 `A`와 `B`를 쓰는 동안, 스레드 2가 그 값을 읽고 있다면? 스레드 2 입장에서는 스레드 1이 어떤 순서로 값을 썼는지가 매우 중요해질 수 있다. 그런데 재배치는 "한 스레드 안에서 결과가 같으면 순서를 바꿔도 된다"는 규칙으로 일어나기 때문에, 다른 스레드가 그 순서에 의존하고 있다는 사실은 고려하지 않는다.

Acquire/Release 시맨틱은 바로 이 지점, 즉 "여기서부터 여기까지는 순서를 바꾸면 안 된다"는 경계선을 정하는 방법이다. 저자는 이 경계선을 잘못 긋거나 아예 빠뜨리는 것이 락 없이 동시성 코드를 짤 때(lock-free programming) 가장 흔한 실수라고 말한다.

## 두 개의 방향이 있는 장벽

경계선은 한 방향만 막는다. 그래서 두 가지로 나뉜다.

**Release**: 쓰기 연산에 붙는다. "이 쓰기보다 코드상 앞에 있던 연산들은, 이 쓰기보다 늦게 실행되면 안 된다"는 규칙이다. 즉 앞의 작업들을 이 지점 뒤로 넘어가지 못하게 붙잡아 두는 것이다.

**Acquire**: 읽기 연산에 붙는다. "이 읽기보다 코드상 뒤에 있는 연산들은, 이 읽기보다 먼저 실행되면 안 된다"는 규칙이다. 즉 뒤의 작업들을 이 지점 앞으로 끌어오지 못하게 막는 것이다.

둘 다 "이 지점을 넘어서 재배치되지 마라"는 같은 발상이지만, release는 앞쪽을, acquire는 뒤쪽을 지킨다는 점에서 방향이 반대다.

## 실제로 쓰이는 예: 신호 주고받기

스레드 1과 스레드 2가 있다고 하자.

1. 스레드 1이 값 `A`에 데이터를 쓴다.
2. 스레드 1이 `Ready`라는 플래그를 `true`로 쓴다. 이때 이 쓰기에 release를 붙인다.
3. 스레드 2가 `Ready`를 읽는다. 이때 이 읽기에 acquire를 붙인다.
4. 스레드 2가 `Ready == true`를 확인하면, 그다음 `A`를 읽는다.

release 덕분에 "`A`에 값을 쓰는 것"이 "`Ready`를 쓰는 것"보다 뒤로 밀려나지 않는다. acquire 덕분에 "`A`를 읽는 것"이 "`Ready`를 읽는 것"보다 앞으로 당겨지지 않는다. 두 규칙이 합쳐지면, 스레드 2가 `Ready == true`를 봤을 때는 스레드 1이 `A`에 쓴 값도 반드시 함께 보인다는 것이 보장된다. `Ready` 하나가 두 스레드 사이의 신호등 역할을 하는 셈이다.

## 코드로는 어떻게 표현하는가

C++에서는 이 개념을 다음 세 가지 방식 중 하나로 표현한다.

1. 프로세서별 명령어를 직접 쓰는 방법 (예: PowerPC의 `lwsync`).
2. C++11에서 이식 가능한 방법으로, `atomic_thread_fence(memory_order_release)` / `atomic_thread_fence(memory_order_acquire)`처럼 별도의 장벽을 세우는 방법.
3. 장벽을 따로 세우지 않고, 값을 읽고 쓰는 연산 자체에 표시하는 방법: `store(value, memory_order_release)`, `load(memory_order_acquire)`.

## Mutex(락)도 결국 같은 원리

락을 잡을 때(acquire)와 락을 풀 때(release)도 똑같은 장벽이 쓰인다. 락 안에서 이루어지는 모든 메모리 연산이 락의 시작과 끝이라는 두 장벽 사이에 갇혀서, 락 바깥으로 새어나가지 못하게 되는 것이다. 그래서 이 둘을 묶어 "장벽 샌드위치"라고 부른다.
