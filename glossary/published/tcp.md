# TCP (Transmission Control Protocol)

인터넷에서 데이터를 **끊기지 않게, 순서대로, 빠짐없이** 전달하는 전송 계층 프로토콜.

HTTP, MySQL, Kafka, gRPC 등 대부분의 애플리케이션 프로토콜이 TCP 위에서 동작한다.

## 계층 구조

데이터를 보낼 때 위 계층에서 아래 계층으로 내려가면서 각 계층이 자기 헤더를 붙인다.
받을 때는 반대로 아래서 위로 올라가면서 헤더를 벗겨낸다.

```
HTTP 메시지 전송 시:

HTTP    [HTTP 헤더 | 본문]
TCP     [TCP 헤더 | HTTP 헤더 | 본문]
IP      [IP 헤더  | TCP 헤더 | HTTP 헤더 | 본문]
이더넷  [이더넷 헤더 | IP 헤더 | TCP 헤더 | HTTP 헤더 | 본문]
```

각 계층은 자기 아래 계층에 데이터를 넘길 뿐, 위 계층의 내용이 뭔지 모른다.
TCP 입장에서 HTTP 본문은 그냥 전달할 바이트 덩어리다.

```
애플리케이션 계층   HTTP, MySQL 프로토콜, Kafka 프로토콜 등
전송 계층          TCP  ← 여기
네트워크 계층      IP
물리/링크 계층     이더넷, Wi-Fi 등
```

## 3-way handshake

TCP 연결을 맺는 과정. 데이터를 주고받기 전에 반드시 거쳐야 한다.

```
클라이언트         서버
    |               |
    |--- SYN ------>|   "연결할게"
    |               |
    |<-- SYN+ACK ---|   "OK, 나도 연결할게"
    |               |
    |--- ACK ------>|   "확인"
    |               |
    |  연결 수립됨  |
```

SYN과 ACK는 TCP 헤더에 있는 플래그 비트 이름이다.

- SYN (Synchronize): "나 시퀀스 번호 X로 시작할게, 연결하자"는 신호. 연결 시작 의사를 표현한다.
- ACK (Acknowledgment): "그거 받았어, 다음은 Y 번호 줘"라는 신호. 상대방이 보낸 패킷을 정상 수신했음을 확인한다.
- SYN+ACK: 두 플래그를 동시에 켠 것. 서버가 클라이언트의 SYN을 확인(ACK)하면서, 동시에 서버 측 연결도 시작(SYN)한다. 패킷 하나로 두 역할을 동시에 수행한다.

세 번 주고받는 이유는 양방향 통신이 가능한지 서로 확인해야 하기 때문이다.
클라이언트 → 서버 방향, 서버 → 클라이언트 방향 둘 다 확인하고 나서야 연결이 수립된다.

## TCP가 보장하는 것

신뢰성이 핵심이다.

- 순서 보장 — 패킷이 뒤섞여 도착해도 원래 순서대로 재조립한다
- 유실 감지 — ACK가 안 오면 재전송한다
- 흐름 제어 — 수신 측이 처리할 수 있는 만큼만 보낸다
- 혼잡 제어 — 네트워크 상태에 따라 전송 속도를 조절한다

이 보장 때문에 TCP는 UDP보다 느리다. 대신 데이터가 반드시 도착한다는 걸 믿을 수 있다.

## 연결 종료: 4-way handshake

연결을 끊을 때는 4번 주고받는다.

FIN (Finish): "나는 더 보낼 데이터가 없어"라는 신호. SYN이 연결 시작이라면 FIN은 연결 종료 의사 표현이다. FIN을 보낸 쪽은 더 이상 데이터를 보내지 않지만, 상대방이 FIN을 보내기 전까지는 여전히 받을 수 있다.

```
클라이언트         서버
    |               |
    |--- FIN ------>|   "나는 다 보냈어"
    |<-- ACK -------|   "확인"
    |<-- FIN -------|   "나도 다 보냈어"
    |--- ACK ------>|   "확인"
    |               |
    |  연결 종료됨  |
```

연결 수립(3번)보다 한 번 더 많은 이유는 양쪽이 독립적으로 종료 신호를 보내야 하기 때문이다.

## 운영에서 보이는 TCP 흔적

MySQL 접속 시 `ERROR 2003: Can't connect` 는 TCP 연결 자체가 안 된 것이다. 방화벽이나 포트 문제다.

`TIME_WAIT` 상태는 연결 종료 후 잠시 대기하는 상태다. 포트를 재사용하기 전에 남은 패킷이 있을 수 있어서 기다린다.

```bash
# 현재 TCP 연결 상태 확인
ss -tn
netstat -tn
```
