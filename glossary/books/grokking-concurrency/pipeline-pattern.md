# pipeline-pattern

task decomposition에서 가장 흔하게 사용되는 패턴. 알고리즘을 여러 개의 순차적 단계로 나누고, 각 단계를 서로 다른 처리 자원(코어, 스레드)에 분산해서 실행한다.

각 처리 자원은 조립 라인의 작업자처럼 자신의 단계를 완료하면 결과를 다음 단계에 넘기면서, 새로운 데이터를 받아 처리한다. 이로 인해 여러 데이터 청크가 동시에 파이프라인의 서로 다른 단계에서 처리된다.

## 왜 효율적인가

파이프라인 없이 세탁을 한다면: 세탁기 → (세탁기 끝날 때까지 건조기 대기) → 건조기 → (건조기 끝날 때까지 폴더 대기) → 접기. 세탁기와 건조기가 번갈아 쉰다.

파이프라인을 쓰면: 1번 빨래가 건조기로 넘어가는 순간, 세탁기는 곧바로 2번 빨래를 시작한다. 세탁기·건조기·폴더가 동시에 각자의 데이터를 처리한다.

## 구현 방식

각 단계를 독립적인 스레드로 만들고, 단계 사이를 큐(queue)로 연결한다. 한 단계가 완료한 데이터를 큐에 넣으면, 다음 단계 스레드가 꺼내서 처리한다.

```
DATA → [Stage 1 Thread] --queue--> [Stage 2 Thread] --queue--> [Stage 3 Thread] → RESULT
```

## 언제 유용한가

공유 자원의 수가 제한되어 있을 때 특히 효과적이다. 파이프라인은 특정 단계의 스레드 수를 제한해서, 공유 자원이 과부하되지 않게 유지한다. 예를 들어 파일시스템은 동시 read/write 요청이 일정 수를 넘으면 성능이 떨어지므로, 파일 I/O 단계의 스레드 수를 제한하는 용도로 파이프라인이 적합하다.

## ETL과의 연결

빅데이터 세계의 ETL(Extract-Transform-Load)이 파이프라인 패턴의 대표적 응용이다. 소스에서 데이터를 추출하고(Extract), 정제하고(Transform), 데이터 웨어하우스에 적재한다(Load).
