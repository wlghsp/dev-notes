# process

실행 중인 프로그램에 대한 OS의 추상화. 프로그램 자체는 디스크에 있는 정적인 파일이지만, 프로세스는 그 프로그램이 실행되는 순간 OS가 만들어주는 동적인 실행 환경이다.

## 프로세스가 제공하는 두 가지 핵심 추상화

1. **독립적인 논리 제어 흐름** — 각 프로세스는 CPU를 독점하는 것처럼 동작한다. 실제로는 OS가 여러 프로세스를 번갈아 실행하지만(context-switch), 각 프로세스는 그걸 알지 못한다.

2. **독립적인 주소 공간** — 각 프로세스는 메모리 전체를 혼자 쓰는 것처럼 보는 가상 주소 공간을 가진다. 다른 프로세스의 메모리를 직접 볼 수 없다.

## 프로세스의 주소 공간 구성

각 영역이 실행 중에 어떻게 쓰이는지가 핵심이다. 가상→물리 변환 메커니즘은 virtual-memory.md 참고.

**텍스트 세그먼트** — 컴파일된 기계어 코드가 올라간다. read-only로 보호되어 있어서 실행 중에 코드를 덮어쓸 수 없다.

**데이터 세그먼트** — 전역 변수, 정적 변수가 여기 있다. 프로그램 시작 시 이미 할당되어 있고, 프로세스가 살아있는 동안 유지된다.

**힙** — `malloc`/`free`로 프로그래머가 직접 관리하는 영역. 낮은 주소에서 높은 주소 방향(↑)으로 자란다. free 없이 계속 할당하면 메모리 누수가 여기서 발생한다.

**스택** — 함수가 호출될 때마다 스택 프레임이 쌓인다. 프레임에는 지역 변수, 리턴 주소, 인자가 들어간다. 함수가 반환되면 프레임이 자동으로 사라진다. 높은 주소에서 낮은 주소 방향(↓)으로 자란다. 재귀가 너무 깊어지면 힙과 충돌해서 stack overflow가 된다.

**커널 공간** — 모든 프로세스의 주소 공간 상단에 공유되지만, 유저 모드에서는 접근하면 segfault가 난다 (segfault.md 참고). 시스템 콜로만 진입 가능하다.

## 커널 모드 vs 유저 모드

프로세스는 두 가지 모드로 실행된다.

- **유저 모드** — 제한된 명령어만 실행 가능. 하드웨어 직접 접근 불가. 일반 코드는 여기서 실행된다.
- **커널 모드** — 모든 명령어와 하드웨어에 접근 가능. 시스템 콜이 발생하면 커널 모드로 전환된다.

이 구분이 있기 때문에 한 프로세스의 버그가 다른 프로세스나 OS 자체를 망가뜨리지 않는다.

## 프로세스 생성

Unix에서 새 프로세스는 `fork()`로 만든다. 부모 프로세스의 복사본이 생기고, 이후 `exec()`으로 다른 프로그램을 로드할 수 있다. 자세한 내용은 fork-exec.md 참고.
