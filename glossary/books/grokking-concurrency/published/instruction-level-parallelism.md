# Instruction-Level Parallelism

CPU가 명령어를 순서대로 하나씩 처리하지 않고, 서로 독립적인 명령어들을 동시에 처리하는 것. 프로그래머가 병렬 코드를 따로 작성하지 않아도 하드웨어가 알아서 한다.

## 어떻게 가능한가

CPU 내부에는 ALU(연산 유닛)가 여러 개 있다. 서로 영향을 주지 않는 명령어들은 각각 다른 ALU에서 동시에 실행될 수 있다.

```
a = 1 + 2;   // 명령어 A
b = 3 + 4;   // 명령어 B  ← A와 무관, 동시에 실행 가능
c = a + b;   // 명령어 C  ← A, B 둘 다 끝나야 실행 가능
```

A와 B는 독립적이라 CPU가 동시에 처리한다. C는 A, B 결과에 의존하니까 기다린다. 어떤 명령어를 동시에 실행할 수 있는지 판단하고 순서를 재배치하는 건 컴파일러가 담당한다.

## 멀티스레드와 뭐가 다른가

멀티스레드는 개발자가 직접 병렬 구조를 설계해야 한다. ILP는 그럴 필요 없다. 순차 코드를 짜도 CPU와 컴파일러가 내부적으로 병렬 실행한다. 개발자 입장에서는 보이지 않는 병렬성이다.

## 동시성 계층에서의 위치

ILP는 하드웨어 계층에서 일어나는 가장 낮은 수준의 병렬성이다. 이 위로 멀티코어/멀티프로세서, 그 위로 OS가 제공하는 프로세스와 스레드 추상화가 올라간다.
