# tlb (Translation Lookaside Buffer)

가상 주소 → 물리 주소 변환 결과를 캐싱하는 하드웨어. CPU 안에 내장된 소형 캐시다.

## 왜 필요한가

프로그램은 가상 주소를 사용한다. 실제 메모리 접근 시 OS의 페이지 테이블을 통해 물리 주소로 변환해야 한다. 페이지 테이블은 메모리에 있기 때문에, 변환할 때마다 메모리를 한 번 더 읽어야 한다. 메모리 접근이 두 배로 느려진다.

TLB는 최근에 변환한 (가상 주소 → 물리 주소) 쌍을 CPU 내부에 캐싱해서 이 오버헤드를 없앤다.

## TLB hit vs miss

- TLB hit — 캐시에 변환 결과가 있음. 페이지 테이블 조회 없이 바로 물리 주소 획득
- TLB miss — 캐시에 없음. 페이지 테이블을 메모리에서 읽어서 변환 후 TLB에 등록

TLB는 용량이 매우 작아서 (수십~수백 엔트리) miss가 잦으면 성능이 급격히 떨어진다.

## context-switch와 TLB flush

프로세스가 전환되면 페이지 테이블 자체가 바뀐다. TLB에 캐싱된 변환 정보는 이전 프로세스 기준이기 때문에 전부 무효화(flush)해야 한다.

TLB flush 이후 새 프로세스가 처음 실행될 때 TLB miss가 집중적으로 발생한다. 이게 context-switch 비용에서 큰 부분을 차지한다.

스레드 전환은 같은 프로세스 내에서 일어나기 때문에 페이지 테이블이 바뀌지 않아 TLB flush가 필요 없다. 이 차이가 프로세스 전환보다 스레드 전환이 싼 주된 이유다.
