# stack-frame (스택 프레임)

함수가 호출될 때 스택에 생성되는 함수 전용 메모리 영역. 함수의 실행에 필요한 모든 상태를 담는다.

## 왜 필요한가

함수 A가 함수 B를 호출하면 B가 실행되는 동안 A는 일시 중단된다. B가 끝나면 A로 돌아와야 하는데, 이때 필요한 정보들을 어딘가에 저장해야 한다. 스택이 그 역할을 한다. 함수 호출이 중첩될수록 스택에 프레임이 쌓이고, 함수가 반환될 때마다 프레임이 제거된다.

x86-64는 스택이 높은 주소에서 낮은 주소 방향으로 자란다. `%rsp`(스택 포인터)가 항상 스택의 최상단(가장 낮은 주소)을 가리킨다.

## 스택 프레임의 구성

함수 Q가 실행 중일 때 스택 구조 (위에서 아래 방향으로):

```
[ 이전 프레임들 (caller의 caller...) ]
[ 함수 P의 프레임                     ]
  - Argument 7~n (7번째 이후 인자)
  - Return address ← P가 call 시 push
  ─────────────────────────────────────  ← 여기서부터 Q의 프레임
  - Saved registers (callee-saved)
  - Local variables
  - Argument build area (Q가 다른 함수 호출 시)
  ← %rsp (스택 탑)
```

구성 요소:
- 반환 주소(return address) — call 명령어가 자동으로 push. Q가 ret하면 여기로 돌아옴
- 저장된 레지스터(saved registers) — callee-saved 레지스터를 사용하기 전에 백업
- 지역 변수(local variables) — 레지스터에 다 못 담는 경우 스택에 저장
- 인자 빌드 영역(argument build area) — Q가 또 다른 함수를 호출할 때 7번째 이후 인자 전달용

## 프레임이 없는 경우도 있다

인자가 6개 이하이고, 지역 변수를 전부 레지스터에 담을 수 있고, 다른 함수를 호출하지 않는 함수는 스택 프레임이 필요 없다. 이런 함수를 리프 함수(leaf procedure)라고 한다.

## call / ret 동작

```
call Q:
  1. 다음 명령어 주소(return address)를 스택에 push
  2. PC를 Q의 시작 주소로 설정

ret:
  1. 스택 최상단에서 return address를 pop
  2. PC를 그 주소로 설정 → caller로 복귀
```

## 프레임 할당과 해제

함수 진입 시 `subq $N, %rsp` 로 스택 포인터를 낮춰서 프레임 공간을 확보하고, 반환 전 `addq $N, %rsp` 로 복원한다.

가변 크기 배열처럼 컴파일 타임에 크기를 알 수 없는 경우 `%rbp`(프레임 포인터)를 사용해서 프레임 기준점을 고정하고, `leave` 명령어로 한 번에 해제한다.
