# File Descriptor (파일 디스크립터)

OS가 "열린 것"을 관리하는 번호표다. 프로세스가 파일, 소켓, 파이프 등을 열면 OS가 정수 하나를 돌려준다. 프로세스는 이 번호로 해당 자원을 읽고 쓴다.

## 기본 번호

프로세스가 시작될 때 기본으로 3개가 열려 있다.

- 0 — 표준 입력 (키보드)
- 1 — 표준 출력 (터미널 화면)
- 2 — 표준 에러

그 이후로 파일이나 소켓을 열면 3, 4, 5... 순서로 번호가 붙는다.

## 왜 번호로 다루냐

유닉스의 "모든 것이 파일" 철학 때문이다. OS 입장에서 파일이든 소켓이든 파이프든 전부 "열린 자원"으로 동일하게 취급한다.

프로세스는 fd에 `read(fd, ...)` / `write(fd, ...)` 하면 되고, 그게 디스크로 가는지 네트워크로 가는지는 OS 커널이 처리한다. 프로세스는 신경 안 써도 된다.

```c
int fd = open("file.txt", O_RDONLY);   // 파일 열기 → fd = 3
int fd = socket(AF_INET, SOCK_STREAM); // 소켓 열기 → fd = 3
// 둘 다 똑같이 번호를 받는다
```

## 실용적인 의미

`cat`, `echo` 같은 명령어가 파일에도, 소켓에도, 터미널에도 동일하게 동작하는 게 이 덕분이다. 다 fd로 동일하게 다루니까.

fd를 닫지 않으면 자원이 해제되지 않는다. 서버 프로세스에서 연결을 받을 때마다 소켓 fd가 생기는데, 닫지 않고 쌓이면 fd가 고갈된다. 이게 "too many open files" 에러의 원인이다.
