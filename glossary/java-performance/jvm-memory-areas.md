# jvm-memory-areas
참고: Java Performance: The Definitive Guide Ch.7, 8

---

JVM이 사용하는 메모리는 크게 두 범주로 나뉜다. JVM이 관리하는 영역과, OS로부터 직접 받아 JVM이 관리하는 네이티브 메모리다.

---

## JVM 관리 메모리 (스펙 기준 5가지 영역)

1. 힙(Heap)
   - 객체 인스턴스와 배열이 할당되는 공간
   - 모든 스레드가 공유한다
   - GC가 관리한다. JVM에서 가장 중심이 되는 메모리 영역
   - `-Xmx`, `-Xms` 플래그로 최대/초기 크기를 지정한다

2. 스택(JVM Stack)
   - 각 스레드마다 독립적으로 존재한다
   - 메서드 호출마다 스택 프레임이 하나씩 쌓인다
   - 스택 프레임에는 지역 변수, 피연산자 스택, 현재 실행 위치(PC)가 들어 있다
   - 스레드가 종료되면 자동으로 사라진다. GC 대상이 아니다

3. 메서드 영역(Method Area) / Metaspace
   - 로드된 클래스의 메타데이터(클래스 이름, 필드, 메서드, 상수 풀)가 저장된다
   - Java 8 이전: PermGen(힙의 일부). Java 8 이후: Metaspace(네이티브 메모리)
   - 클래스 언로딩이 발생하면 회수된다

4. PC 레지스터
   - 각 스레드가 현재 실행 중인 바이트코드 명령어의 주소를 저장한다
   - 스레드마다 독립적으로 존재한다

5. 네이티브 메서드 스택
   - JNI(Java Native Interface)로 호출되는 C/C++ 네이티브 코드를 위한 스택

---

## 네이티브 메모리 (JVM이 직접 OS에서 확보)

- 코드 캐시(Code Cache) — JIT 컴파일된 기계어 코드가 저장되는 공간
- GC 관련 데이터 구조 — GC 알고리즘이 사용하는 카드 테이블, remembered set 등
- 클래스 로더 자체 — 클래스 로더 구현체가 사용하는 메모리

---

## 왜 구분해서 알아야 하는가

OutOfMemoryError가 발생했을 때 어떤 영역이 부족한지 모르면 엉뚱한 곳을 튜닝하게 된다.

- `Java heap space` 에러 → 힙 부족
- `Metaspace` 에러 → 클래스 메타데이터 영역 부족 (클래스가 너무 많이 로드됨)
- `unable to create new native thread` 에러 → 스레드 스택 공간 부족

각 영역이 어디 있고 무엇을 담는지 알아야 문제의 원인을 찾을 수 있다.
