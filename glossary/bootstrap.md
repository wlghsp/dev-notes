# bootstrap

**"스스로 시작하기 위한 최소한의 진입점"**

어원은 "신발 끈을 잡아당겨 스스로 일어선다(pull yourself up by your bootstraps)"는 표현에서 왔다.
외부 도움 없이 스스로 구동을 시작한다는 개념.

IT에서는 **전체 시스템을 알기 전에, 시작에 필요한 최소한의 정보만 주어지는 것**을 bootstrap이라고 부른다.

## Kafka에서의 bootstrap.servers

```
bootstrap.servers=172.30.1.223:19092
```

클라이언트가 Kafka 클러스터에 처음 접속할 때 쓰는 브로커 주소다.
클라이언트는 이 주소로 연결한 뒤, 해당 브로커에서 클러스터 전체의 메타데이터(다른 브로커 정보, 토픽 파티션 배치 등)를 받아온다.

기술적으로는 1대만 적어도 동작하지만, 실제 운영에서는 브로커 전체를 명시하는 게 관례다.
명시한 브로커가 모두 죽으면 클라이언트가 클러스터에 진입 자체를 못 하기 때문에 가용성을 위해 전부 넣는다.

## 다른 곳에서 bootstrap이 쓰이는 패턴

컴퓨터 부팅도 bootstrapping이다. OS가 메모리에 올라가는 과정 자체가 "최소한의 코드로 나머지를 불러오는" 구조다.

Spring Boot의 "Boot"도 같은 맥락. 앱 구동에 필요한 설정을 자동으로 시작(bootstrap)해준다는 의미.

## 핵심

bootstrap은 항상 "전부"가 아니라 "시작을 위한 최소"다.
나머지는 그 시작점에서 스스로 찾아간다.
