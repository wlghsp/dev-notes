# b-tree
참고: lsm-tree.md, write-amplification.md

---

대부분의 관계형 DB(MySQL InnoDB, PostgreSQL)와 많은 비관계형 DB의 기본 인덱스 구조다. 1970년대에 등장했고 수십 년간 검증된 구조다.

## 구조

데이터를 고정 크기 페이지(전통적으로 4KB, 실제로는 더 클 수 있음) 단위로 읽고 쓴다. 각 페이지는 키 범위를 담당하는 자식 페이지에 대한 참조를 포함한다. 루트 페이지에서 시작해 내려가면서 범위를 좁히고, 리프 페이지에서 실제 값(또는 row가 저장된 위치의 참조)을 얻는다.

## 쓰기 동작

새 키-값을 삽입하거나 기존 값을 갱신할 때 해당 리프 페이지를 찾아서 수정한다. 페이지를 수정하면 디스크의 해당 위치에 덮어쓴다(overwrite). 이것이 LSM-tree의 append와 근본적으로 다른 점이다.

페이지가 꽉 차면 두 개의 페이지로 분할(split)하고, 부모 페이지에 새 범위를 추가한다. 이 과정에서 여러 페이지를 수정해야 할 수 있고, 중간에 충돌이 나면 인덱스가 깨질 수 있다. 이를 방지하기 위해 WAL(Write-Ahead Log, redo log라고도 부름)에 먼저 기록한다.

## 높이가 낮다

대부분의 데이터베이스에서 B-tree의 높이는 3~4 수준이다. 분기 수(branching factor)가 보통 수백 개이기 때문에, 4단계 트리로 256TB 이상의 데이터를 인덱싱할 수 있다. 루트에서 리프까지 4번의 페이지 접근으로 임의의 키를 찾을 수 있다는 의미다.

## LSM-tree와의 차이

B-tree는 각 키가 트리 내 정확히 한 위치에만 존재한다. LSM-tree는 같은 키가 여러 SSTable에 존재할 수 있고 compaction으로 정리된다. B-tree는 읽기 성능이 더 예측 가능하고, LSM-tree는 쓰기 throughput이 더 높다.
