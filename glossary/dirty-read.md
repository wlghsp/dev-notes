# dirty-read

**"커밋되지 않은 데이터를 다른 트랜잭션이 읽는 현상"**

---

## 언제 발생하나

트랜잭션 A가 데이터를 변경했지만 아직 커밋하지 않은 상태에서, 트랜잭션 B가 그 변경된 값을 읽을 수 있을 때 발생한다.

```
트랜잭션 A: UPDATE balance = 0  (아직 COMMIT 안 함)
트랜잭션 B: SELECT balance      → 0 읽음
트랜잭션 A: ROLLBACK
→ B가 읽은 0은 실제로 존재한 적 없는 값
```

B 입장에서는 없던 일이 된 데이터를 기반으로 로직을 수행한 셈이다.

---

## 왜 위험한가

존재한 적 없는 상태를 기반으로 판단하게 된다. 잔액 계산, 재고 차감 등 금액/수량이 오가는 로직에서 치명적인 오류로 이어질 수 있다.

---

## 어느 격리 수준에서 발생하나

READ UNCOMMITTED에서만 발생한다. 이 수준은 undo log를 타지 않고 현재 변경 중인 row를 그대로 읽기 때문이다.

READ COMMITTED부터는 커밋된 데이터만 읽으므로 dirty read가 원천 차단된다.

---

## 한 줄 요약

> 커밋 전 데이터를 읽었다가, 상대방이 롤백하면 내가 읽은 데이터가 유령이 되는 현상.
