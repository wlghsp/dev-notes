# substitution-method (치환법)

recurrence-relation.md(재귀 관계)를 푸는 방법 중 하나. 두 단계로 이루어진다.

1. 답의 형태를 추측한다 (예: T(n) = O(n log n)일 것 같다)
2. 그 추측이 맞는지 induction.md(수학적 귀납법)로 증명한다

이름이 "치환"인 이유는, 증명 단계에서 "더 작은 값에서는 추측이 맞다"고 가정한 걸 재귀식에 대입(치환)해서 원래 크기에서도 맞는지 확인하기 때문이다.

## 예시 — T(n) = 2T(⌊n/2⌋) + n

병합 정렬과 같은 형태의 재귀식이다. T(n) = O(n lg n)이라고 추측하고, T(n) ≤ cn lg n을 증명한다.

- 귀납 가정: n보다 작은 모든 m에 대해 T(m) ≤ cm lg m이 성립한다고 가정한다. 특히 m = ⌊n/2⌋일 때도 성립하므로 T(⌊n/2⌋) ≤ c⌊n/2⌋lg(⌊n/2⌋)
- 이걸 재귀식에 대입한다: T(n) ≤ 2(c⌊n/2⌋lg(⌊n/2⌋)) + n
- 정리하면 T(n) ≤ cn lg n − cn + n ≤ cn lg n (단, c ≥ 1일 때)
- 이제 경계 조건(n이 아주 작을 때)도 이 부등식을 만족하는 c를 고를 수 있는지 확인하면 증명이 끝난다

## 좋은 추측을 만드는 법

이 방법의 약점은 "추측"이 처음부터 있어야 한다는 점이다. 추측을 만드는 대표적인 방법 두 가지가 있다.

- 비슷한 형태의 재귀식을 본 적이 있다면 같은 답을 추측해본다. 예를 들어 `T(n) = 2T(⌊n/2⌋ + 17) + n`처럼 항이 살짝 지저분해도, n이 커지면 17은 무시할 수 있는 수준이라 `T(n) = 2T(n/2) + n`과 같은 답(O(n lg n))을 추측할 수 있다
- recursion-tree-method.md(재귀 트리 방법)로 대략적인 형태를 먼저 그려보고, 그 결과를 치환법으로 정확히 증명한다

## 막힐 때 — 더 낮은 차수 항을 빼본다

가끔 추측이 거의 맞는데 증명이 아슬아슬하게 안 풀릴 때가 있다. 예를 들어 `T(n) = T(⌊n/2⌋) + T(⌈n/2⌉) + 1`에서 T(n) ≤ cn을 증명하려고 대입하면 `T(n) ≤ cn + 1`이 나와서 cn 이하라는 걸 보일 수 없다. 이때 추측을 `T(n) ≤ cn − d` (d는 상수)로 살짝 낮춰서 다시 대입하면, 두 번 빼는 효과(재귀 호출이 두 번이라)로 증명이 성립한다. 답을 더 크게 잡는 게 아니라 더 작게 잡아야 증명이 풀리는 경우가 있다는 게 이 방법의 반직관적인 지점이다.

## 흔한 실수

`T(n) = 2T(⌊n/2⌋) + n`에서 T(n) = O(n)이라고 잘못 증명하는 경우가 있다. `T(n) ≤ 2(cn/2) + n = cn + n`까지 계산하고 "O(n)이다"라고 결론짓는데, 이건 틀렸다. 증명해야 하는 건 정확히 `T(n) ≤ cn`인데 `cn + n`은 `cn`보다 크므로 증명이 안 된 것이다. 점근 표기법의 상수 c는 미리 정해서 끝까지 지켜야 하는 값이지, 뒤에서 마음대로 늘어나면 안 된다.
