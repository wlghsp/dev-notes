# Redis Lua Script

Redis 명령 여러 개를 하나의 원자적 단위로 묶어 실행하기 위해 쓰는 스크립트.

`EVAL` 명령으로 실행하며, 스크립트가 끝날 때까지 다른 클라이언트의 명령이 끼어들 수 없다.

## 왜 필요한가

Redis는 싱글 스레드로 명령을 처리한다. 명령 하나는 원자적이지만, 명령 여러 개를 순서대로 보내면 그 사이에 다른 클라이언트의 명령이 끼어들 수 있다.

예를 들어 "값을 읽고, 조건을 확인하고, 갱신한다"를 세 번의 개별 명령으로 나누면, 읽기와 갱신 사이에 다른 클라이언트가 같은 값을 바꿔버릴 수 있다. Lua 스크립트로 이 세 단계를 하나로 묶으면 중간에 끼어들 여지가 없어진다.

## MULTI/EXEC와의 차이

Redis 트랜잭션(`MULTI`/`EXEC`)도 여러 명령을 원자적으로 묶지만, 스크립트 실행 중 조건 분기를 할 수 없다. 즉 "이전 명령의 결과를 보고 다음 명령을 결정한다"가 불가능하다.

Lua 스크립트는 스크립트 안에서 `if` 같은 조건 분기가 가능하다. 그래서 "조건부로 갱신한다" 같은 로직은 MULTI/EXEC로는 표현이 안 되고 Lua로만 가능하다.

## 대표적으로 쓰이는 자리

분산 락 해제가 대표적이다. 락을 걸 때는 `SET key value NX` 한 번으로 끝나지만, 해제할 때는 "이 락이 내가 건 게 맞는지 확인 후 지운다"는 GET-then-DEL 두 단계가 필요하다. 이 두 단계를 개별 명령으로 보내면 확인과 삭제 사이에 다른 프로세스가 끼어들어 남의 락을 지우는 문제가 생긴다. Lua로 묶으면 이 문제가 없어진다.

Rate limiting도 비슷한 이유로 쓰인다. "카운터를 읽고, 한도를 넘었는지 확인하고, 증가시킨다"를 개별 명령으로 처리하면 두 클라이언트가 동시에 읽어서 둘 다 한도를 통과해버리는 레이스가 생긴다.

## 주의할 점

스크립트 실행 중에는 Redis 전체가 블록된다. 싱글 스레드이기 때문에 스크립트가 길거나 무거우면 그 시간만큼 다른 모든 클라이언트의 명령이 대기한다.

그래서 Lua 스크립트는 "원자성이 꼭 필요한 짧은 로직"에 국한해서 쓰는 것이 일반적인 관행이다. 무거운 연산을 Lua 안에 넣는 것은 권장되지 않는다.
