# Kiro IDE

## 한 줄 요약

AWS가 2025년 7월에 출시한 AI 에이전트 IDE. VS Code 포크 기반. **"코드보다 스펙을 먼저 쓴다"** 는 접근이 핵심이다.

---

## 기존 AI 코딩 도구와 뭐가 다른가

Cursor, GitHub Copilot, Claude Code 같은 기존 도구들은 **채팅 기반**이다. 뭔가 만들고 싶으면 AI한테 말하고, AI가 코드를 제안하고, 사람이 받아서 수정한다.

문제는 맥락이 대화 단위로 사라진다는 것이다. 오늘 A 기능 만들고 내일 B 기능 만들 때, AI는 어제 어떤 설계 결정을 했는지 모른다. 팀원이 바뀌어도 마찬가지다.

Kiro는 **Spec(명세)을 중심**에 놓는다. 대화로 시작하더라도, 그 결과가 구조화된 문서로 저장된다. AI가 그 문서를 보고 일한다.

---

## 핵심 개념 세 가지

### 1. Spec-Driven Development

기능 하나를 만들 때 Kiro는 세 파일을 자동 생성한다.

```
.kiro/specs/order-feature/
  ├── requirements.md   ← 무엇을 만드는가 (유저 스토리, 인수 조건)
  ├── design.md         ← 어떻게 만드는가 (컴포넌트, 데이터 모델, API)
  └── tasks.md          ← 실제 구현 태스크 체크리스트
```

"주문 기능 만들어줘" 라고 말하면 Kiro가 먼저 이 세 파일을 채운다. 사람이 검토하고 승인하면, 그때 코드를 생성한다.

코드보다 설계가 먼저다. 이 방식을 "Vibe Coding"의 반대 개념으로 포지셔닝한다.

### 2. Steering Files

프로젝트 전반에 걸쳐 AI가 항상 지켜야 할 규칙을 정의하는 마크다운 파일이다.

```
.kiro/steering/
  ├── tech-stack.md     ← 사용 라이브러리, 금지된 패턴
  ├── conventions.md    ← 네이밍 규칙, 코드 스타일
  └── security.md       ← 보안 요구사항
```

매번 채팅에서 "우리는 Lombok 안 써요", "테스트는 JUnit5 써요" 같은 말을 반복하지 않아도 된다. Steering File에 한 번 써두면 Kiro가 모든 작업에서 참고한다.

CLAUDE.md와 비슷한 개념이다.

### 3. Agent Hooks

파일 저장, 생성, 삭제 같은 **이벤트에 AI 작업을 자동으로 연결**하는 기능이다.

예시:
- `.java` 파일 저장할 때마다 → 테스트 파일 자동 생성
- `*.sql` 파일 생성될 때마다 → 마이그레이션 가이드 문서 자동 업데이트
- PR 올리기 전 → 보안 취약점 스캔 자동 실행

트리거 조건과 실행할 작업을 자연어로 정의한다. 별도 스크립트 없이 이벤트 기반 자동화가 된다.

## Cursor, Claude Code와 비교

세 도구의 포지셔닝이 다르다.

**Cursor**
- 인라인 자동완성, 탭 완성에 강함
- 대화 기반으로 빠르게 반복
- 다양한 모델 선택 가능
- 가장 넓은 커뮤니티, 플러그인 생태계

**Claude Code**
- 터미널 에이전트, IDE를 대체하지 않음
- 열린 탐색형 작업, 대규모 리팩터링에 강함
- 파일 저장 이벤트 같은 자동 트리거 없음
- 세션마다 사람이 시작해야 함

**Kiro**
- IDE 자체가 에이전트 레이어를 내장
- 스펙 → 설계 → 태스크 → 코드 흐름이 구조화됨
- Hooks로 파일 이벤트에 AI 작업 자동 연결
- AWS 서비스와 통합이 자연스러움
- 팀 단위 협업, 요구사항 추적에 적합

실무에서는 Kiro + Claude Code를 같이 쓰는 팀도 있다. Kiro로 구조화된 기능 개발하고, Claude Code로 열린 탐색이나 즉흥적인 리팩터링을 처리하는 식으로.

## 핵심 철학

Kiro가 내세우는 메시지는 **"Vibe Coding에서 Engineering Rigor로"** 다.

AI에게 막연히 말해서 코드 뽑아내는 방식 대신, 요구사항 → 설계 → 구현의 소프트웨어 공학 프로세스를 AI 에이전트가 따르도록 강제한다.

규모가 커질수록, 팀이 커질수록 그 차이가 나온다는 게 AWS의 주장이다.
