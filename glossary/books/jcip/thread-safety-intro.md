# Thread Safety (스레드 안전성)

순차 프로그래밍 모델은 "다음에 뭐가 실행될지"가 코드 순서로 정해진다.
스레드가 여러 개 돌아가는 환경에서는 이 전제가 깨진다.
서로 다른 스레드의 연산이 런타임에 임의로 인터리빙(interleaving)되기 때문이다.

스레드 안전성은 이 인터리빙이 어떤 순서로 일어나도 프로그램이 올바르게 동작하는 성질을 말한다.
여러 스레드가 별도의 동기화 없이 동시에 실행돼도, 호출하는 쪽에서 추가로 순서를 맞추거나 조율할 필요가 없어야 한다.

이게 왜 어려운가 하면, 스레드들이 프로세스의 메모리 주소 공간을 공유하기 때문이다.
힙에 있는 같은 변수를 여러 스레드가 동시에 읽고 쓸 수 있다는 뜻이다.
프로세스 간 통신(소켓, 파일 등)과 달리 이런 공유는 별도의 명시적 전달 없이 그냥 일어나므로 편리하지만, 그만큼 위험하다.
한 스레드가 다른 스레드가 한창 사용 중인 변수를 예고 없이 바꿔버릴 수 있다.

스레드 안전성이 깨지는 대표적인 현상이 race-condition.md 이다.
안전성을 지키는 기본 도구는 atomicity.md 와 intrinsic-lock.md 에서 다룬다.
