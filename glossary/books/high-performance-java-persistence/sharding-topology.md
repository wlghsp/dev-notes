# sharding-topology (샤딩 토폴로지)

복제(Multi-Master 포함)만으로 감당할 수 없을 만큼 데이터가 커졌을 때, 데이터를 여러 노드로 쪼개 각 노드가 전체의 일부만 갖게 하는 것.

## horizontal partitioning과의 차이

전통적인 relational DB는 같은 서버 안에서 여러 테이블로 데이터를 나누는 horizontal partitioning을 지원해 왔다. 샤딩은 이를 한 걸음 더 나아가, 데이터를 여러 대의 물리적 머신에 분산시키는 분산 시스템 토폴로지를 요구한다.

## 샤드 간 조인 금지 원칙

각 샤드는 자기 완결적(self-contained)이어야 한다. 하나의 사용자 트랜잭션은 단일 샤드 안의 데이터만 사용해야 하며, 샤드를 가로지르는 조인은 보통 금지된다. 분산 락과 네트워크 오버헤드 비용이 트랜잭션 응답 시간을 크게 늘리기 때문이다.

## 지리적 분산 샤딩

샤딩 토폴로지는 흔히 최소 두 개의 별도 데이터 센터로 구성된다. 각 데이터 센터가 하나의 지리적 리전을 전담하면 로드가 지역별로 분산된다. 모든 테이블이 파티션될 필요는 없다 — 크기가 작은 테이블은 각 샤드에 그대로 복제해 두고, 사용자 데이터처럼 큰 테이블만 파티션한다. 샤드끼리는 비동기 복제로 동기화 상태를 유지한다.

예: 사용자 테이블은 지역별로 샤딩하고(북미 샤드, 유럽 샤드), 국가 코드처럼 작고 거의 안 바뀌는 테이블은 모든 샤드에 그대로 복제한다. 사용자 관련 데이터는 전부 같은 데이터 센터 안에 두어, 샤드 간 처리가 필요 없게 만든다.

## 샤딩은 최후의 수단

시스템 용량을 늘리는 우선순위는 다음과 같다.

1. 데이터 접근 계층 자체를 최적화해서 응답 시간을 낮춘다
2. 복제된 각 노드를 비용 효율적인 구성으로 스케일 업한다
3. 동기화 지연이 허용 범위 안에 들어올 때까지 복제 노드를 늘린다
4. 그래도 부족하면 샤딩한다
