# NP-hard란?

## 한 줄 요약

**"빠르게 푸는 방법이 아직(어쩌면 영원히) 알려지지 않은, 어려운 문제들의 그룹"**에 속한다는 뜻.

## 배경: P vs NP

- **P (Polynomial time)**: 다항 시간에 풀 수 있는 문제들의 집합. `O(n)`, `O(n^2)`, `O(n^3)` 처럼 n이 커져도 감당할 만한 속도로 답을 구할 수 있음.
  - 예: 정렬(O(n log n)), 최단 경로(다익스트라, O(n^2)), 이 리포의 "숫자 게임" 문제(정렬+투포인터, O(n log n))
- **NP (Nondeterministic Polynomial time)**: 답이 주어지면 그게 맞는지 다항 시간에 **검증**은 할 수 있는 문제들의 집합. (답을 찾는 게 빠르다는 보장은 없음)
  - 예: "이 부분집합이 크기 k이고 서로 충돌 없이 점수 합이 X 이상인가?" → 이건 주어진 답을 O(n)~O(n^2)에 검증 가능.

핵심 질문 **P = NP?** 는 아직 아무도 증명 못 한 컴퓨터 과학의 최대 미해결 문제 중 하나.

## NP-hard의 정의

어떤 문제 X가 **NP-hard**라는 것은:

> NP에 속한 모든 문제를 X로 (다항 시간 안에) 변환할 수 있다.

즉 X는 "NP에 있는 문제들 중 가장 어려운 축에 속한다"는 뜻. X 자체가 NP에 속하는지는 상관없음(NP-hard는 NP보다 더 넓은 범위를 포괄).

- **NP-complete**: NP-hard이면서 동시에 NP에도 속하는 문제. (검증도 빠르고, 가장 어려운 문제이기도 한 것)
- 유명한 NP-complete 문제들: 외판원 문제(TSP), 배낭 문제(0/1 Knapsack), 그래프 색칠 문제, **최대 독립집합(Maximum Independent Set)**, SAT(논리식 충족 문제) 등.

## 실무적으로 의미하는 것

어떤 문제가 NP-hard로 밝혀지면:

1. **다항 시간 알고리즘이 존재하지 않을 가능성이 매우 높다** (P≠NP가 사실상 정설로 받아들여짐).
2. 그래서 정확한 답을 구하려면 보통 아래 중 하나를 택함:
   - **완전탐색 / 지수 시간 알고리즘** (n이 작을 때만 가능) — 이번 문제의 비트마스크 방식이 여기 해당
   - **근사 알고리즘** (정확한 최적해는 포기, 일정 비율 이내의 답만 보장)
   - **휴리스틱** (유전 알고리즘, 시뮬레이티드 어닐링 등 — 보장은 없지만 실용적으로 괜찮은 답)
   - **입력에 제약을 걸기** (그래프가 트리다, 값 범위가 작다 등 특수 구조를 가정하면 다항 시간 풀이가 가능해지는 경우가 많음)

## 리뷰 순서의 대비 최대화 문제와의 연결

- conflicts로 주어지는 충돌 관계 = 그래프의 간선
- "충돌 없이 k개를 골라 점수 합 최대화" = **최대 가중치 독립집합** 문제
- 이 문제는 일반 그래프에서 NP-hard로 알려져 있음 → 다항 시간 그리디/DP로는 정확한 답을 보장할 수 없음
- 그래서 solution.py는 n이 작다는 전제 하에 `O(2^n · n)`의 비트마스크 완전탐색을 사용함
- 만약 conflicts가 항상 **트리**나 **일렬(경로)** 구조라면, 그 특수한 구조를 이용한 다항 시간 DP가 가능해짐 (일반 그래프가 아니게 되므로)
