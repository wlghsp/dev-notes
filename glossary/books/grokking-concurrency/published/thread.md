# thread

프로세스 안에서 독립적으로 실행되는 흐름. 동시성을 구현하는 가장 기본적인 빌딩 블록이다.

## 프로세스와의 차이

프로세스는 독립적인 주소 공간을 가진다. 스레드는 같은 프로세스 안의 다른 스레드들과 주소 공간을 공유한다.

- 공유하는 것 — 코드, 힙, 전역 변수, 파일 디스크립터
- 각자 가지는 것 — 스택, 레지스터 상태, 프로그램 카운터(PC)

공유 덕분에 스레드 간 통신은 단순히 같은 메모리를 읽고 쓰는 것으로 끝난다. 반면 이 공유가 동시성 문제의 원인이기도 하다. 여러 스레드가 같은 데이터에 동시에 접근하면 race-condition이 생긴다.

## 왜 스레드인가

프로세스를 여러 개 띄우면 격리는 좋지만 통신 비용이 크다. 스레드는 같은 메모리를 쓰기 때문에 생성 비용이 낮고, 데이터 공유가 빠르다.

멀티코어 CPU에서 여러 스레드를 동시에 실행하면 물리적인 병렬 처리가 가능하다. 하나의 스레드가 I/O를 기다리는 동안 다른 스레드가 CPU를 사용할 수도 있다.

## 스레드 생성 비용

스레드는 프로세스보다 가볍지만 공짜는 아니다. 스레드마다 별도의 스택이 필요하고, 컨텍스트 스위치 시 레지스터 상태를 저장하고 복원해야 한다. 스레드를 무한정 늘리면 컨텍스트 스위치 오버헤드가 오히려 성능을 떨어뜨린다.

이 비용을 관리하기 위해 thread-pool 패턴을 쓴다. 스레드를 미리 만들어두고 재사용한다.

## 유저 스레드 vs 커널 스레드

OS 커널이 직접 관리하는 커널 스레드는 멀티코어에서 실제로 병렬 실행된다. 유저 스레드(그린 스레드, 코루틴)는 유저 공간에서 직접 스케줄링하며 커널 개입 없이 전환한다. 전환 비용은 낮지만 하나가 블로킹되면 전체가 블로킹될 수 있다.
