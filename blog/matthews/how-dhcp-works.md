# DHCP의 원리 - 인터넷이 저절로 되는 이유

## Why

카페에서 WIFI 목록을 보고 선택하고 비밀번호를 입력하면 바로 연결된다. 그런데 이 짧은 과정을 곱씹어보면 의문이 생긴다.

- 내 장치에 네트워크 설정을 무선으로 어떻게 해주는가?
- IP 주소가 다른 사람과 왜 겹치지 않는가?
- 누가 나에게 IP를 주는가?

## WIFI의 SSID가 있는 이유

유선은 물리적으로 연결된 장치를 알 수 있지만, 무선은 눈에 보이지 않기 때문에 어디에 연결하는지 구분할 필요가 있다. 그래서 SSID(Service Set Identifier)가 생겼다. 무선 신호로 "내가 누구인지 알릴 테니 보고 들어오라"고 광고하는 것이다.

SSID는 광고판처럼 퍼블릭한 특징을 가진다. 숨길 수는 있지만 완전히 숨겨지는 것은 아니고, 일반적으로 숨기지도 않는다.

## SSID를 선택하면 일어나는 일: DHCP

SSID를 고르고 비밀번호를 입력(또는 퍼블릭이면 바로 연결)하면 몇 초 후 인터넷이 연결된다. 이 짧은 시간 동안 DHCP(Dynamic Host Configuration Protocol)가 작동한다.

DHCP는 네트워크 라우터(공유기)가 지원하는 기능으로, 네트워크에 들어오려는 장치에게 IP를 동적으로 부여한다. CIDR로 정해진 IP 범위 안에서 겹치지 않게 미사용 IP를 관리하고 나눠준다.

물론 IP를 수동으로 직접 지정할 수도 있지만, 카페에 갈 때마다 IP를 받아 적고 네트워크 설정을 하는 것은 비현실적이다.

## DHCP의 동작 원리

여기서 브로드캐스트 IP(Broadcast IP)라는 개념이 사용된다. `255.255.255.255`처럼 주소의 모든 비트가 1로 채워진, 가용 범위 중 가장 마지막 IP다. 이 IP는 특수 목적으로 예약된 방송용 IP다.

네트워크에서 통신하려면 서로의 IP를 알아야 하는데, 브로드캐스트 IP로 보내면 네트워크에 연결된 모든 장치에게 전달된다. 의미가 있는 장치는 듣고, 아닌 장치는 그냥 버리는 방식이다(라디오 방송과 비슷하다).

이 방송에는 HTTP가 아니라 DHCP 프로토콜이 쓰인다(HTTP도 결국 프로토콜의 한 종류일 뿐이다).

## DHCP가 IP를 받는 과정

1. 연결하려는 장치가 SSID로 무선 연결을 시도한다. 이 단계는 TCP/IP가 아니라 IEEE 802.11 프로토콜을 사용하며, 아직 DHCP는 쓰이지 않는다.
2. 무선 연결이 설정되면 DHCP가 시작된다. 장치가 `255.255.255.255`로 "IP 주소 주실 분"이라는 메시지(DHCP Discover)를 보낸다.
3. 네트워크 안의 DHCP 서버가 이를 듣고 응답한다. 예를 들어 "192.168.0.101 이 있는데 빌려드릴까요?"
4. 장치가 그 IP를 쓰겠다고 응답하면, DHCP 서버는 IP를 임대하며 "반납 시간은 1시간 후"라고 안내한다.
5. 장치는 이렇게 빌린 IP로 인터넷에 접속한다.

1시간 후 반납이라는 게 이상하게 들릴 수 있지만, 계속 사용 중이면 OS가 알아서 임대를 연장한다. 사용자가 신경 쓸 필요는 없다.

## 실제로 확인해보기: dhclient

Linux에는 DHCP 요청을 수동으로 실행해볼 수 있는 `dhclient`라는 CLI 프로그램이 있다.

```
$ dhclient -v eth0
dhclient[1234]: DHCPDISCOVER on eth0 to 255.255.255.255 port 67 interval 5
dhclient[1234]: DHCPDISCOVER on eth0 to 255.255.255.255 port 67 interval 8
dhclient[1234]: DHCPOFFER from 192.168.1.1
dhclient[1234]: DHCPREQUEST on eth0 to 255.255.255.255 port 67
dhclient[1234]: DHCPACK from 192.168.1.1
dhclient[1234]: bound to 192.168.1.100 -- renewal in 3600 seconds.
```

`-v`(verbose) 옵션을 붙이면 위에서 설명한 Discover → Offer → Request → Ack 과정이 그대로 로그로 출력된다.

> 주의: 이 명령을 실제 서버에서 실행하면 안 된다. `eth0`의 실제 IP가 DHCP로 재할당될 수 있다.

## 마무리

WIFI를 통해 어디서든 쉽게 인터넷에 연결할 수 있는 것은 DHCP 덕분에 복잡한 네트워크 설정이 자동화되기 때문이다.

- 통신사의 유동 IP 서비스도 DHCP를 사용한다. 이 경우 브로드캐스트에 응답하는 DHCP 서버는 아파트 어딘가에 설치된 통신사 장비 안에 있다.
- 유선 LAN도 동일하다. 공유기에서 나온 LAN 선을 PC에 꽂는 순간 DHCP가 작동한다.
- AWS VPC의 서브넷도 DHCP 기능을 가지고 있어서, EC2 인스턴스를 만들면 IP가 자동으로 부여된다.
- 도커의 bridge 네트워크도 같은 역할을 한다(엄밀히는 DHCP가 아니라 자체 규격이지만, IP를 동적으로 부여하는 방식은 동일하다).
