# Week 3 핵심 정리

연관관계 주인, 편의 메서드, LAZY/N+1, cascade/orphanRemoval을 실제 테스트 코드로 검증하며 확인한 내용.

---

## 1. 연관관계 주인

- 외래 키(FK)를 물리적으로 가진 쪽이 주인이다. `Todo.user`(`@ManyToOne`)가 주인, `User.todos`(`mappedBy`)는 비주인.
- **주인 쪽만 SQL에 반영된다.** `mappedBy` 쪽 필드(컬렉션)를 아무리 바꿔도 flush해도 SQL이 안 나간다 — 직접 재현해서 확인함.

## 2. 연관관계 편의 메서드

- 주인 쪽만 세팅하면 **DB는 정상**(UPDATE 정상 반영)이지만 **메모리 상 반대쪽 컬렉션은 갱신 안 됨** — 같은 테스트 안에서 이 대비를 직접 확인함.
- 즉 편의 메서드는 SQL을 위한 게 아니라, 같은 영속성 컨텍스트 안에서 객체 그래프의 일관성을 지키기 위한 장치.

## 3. LAZY와 N+1

- LAZY는 "지금 안 가져온다"만 보장하지, "여러 개를 묶어서 가져온다"는 보장이 없다.
- `find()` 시점엔 SQL 없음 → 실제 필드 접근(`getUsername()` 등) 시점에 SELECT 발생 — 접근 전/후를 나눠 직접 확인함.
- N+1 재현: `Todo` N건 조회(쿼리 1) + 각각의 LAZY `user` 접근(쿼리 N) = 총 1+N. 여기서 "부모/자식"(도메인, User가 부모)과 "순회 대상"(이 실험에서는 Todo)은 다른 개념이라는 점에 주의.

## 4. cascade REMOVE vs orphanRemoval — 개념

- 둘 다 자식을 지울 수 있지만 트리거가 다르다.
  - cascade REMOVE: **부모의 생명주기**를 따라간다 (부모가 삭제될 때 자식도 삭제)
  - orphanRemoval: **관계의 생명주기**를 따라간다 (부모는 그대로여도, 컬렉션에서 자식이 빠지면 삭제)
- "부모는 안 지우고 컬렉션에서만 제거"하는 시나리오에서 두 옵션의 결과가 갈린다 — 이게 둘을 구분하는 핵심 실험.

## 5. 실전에서 겪은 함정: cascade REMOVE + orphanRemoval 조합 버그

- `cascade = CascadeType.REMOVE`(단독)와 `orphanRemoval = true`를 함께 쓰면, **컬렉션에서 자식을 제거하는 것만으로는 orphan 삭제가 트리거되지 않았다** — 실제로 테스트가 계속 실패하는 걸 직접 겪음.
- Hibernate 버전(6.2.13 / 6.4.10 / 6.5.3) 문제가 아님을 직접 낮춰서 확인. 완전히 새 엔티티로 재현한 결과 `cascade = CascadeType.ALL`로 바꾸면 정상 동작함을 확인.
- **결론: `orphanRemoval = true`를 쓸 때는 `cascade`를 `REMOVE` 단독이 아니라 `ALL`(또는 최소 PERSIST 포함)로 써야 한다.** (자세한 재현 과정은 cascade-remove-orphan-removal-issue.md)
- 이건 강의나 문서에 잘 안 나오는 실전 함정이라, 근거형 질문 3번 답변에 그대로 쓸 수 있는 강한 근거임.

---

## 근거형 질문 답변 방향 요약

1. **연관관계 주인이 필요한 이유**: 객체는 양방향 참조가 자유롭지만 테이블은 FK가 한쪽에만 있어서, SQL 반영 기준을 하나로 정해야 함 → 주인 개념 필요
2. **LAZY인데 N+1이 나는 이유**: LAZY는 "안 가져온다"만 보장, "묶어서 가져온다"는 별개 → 순회 중 접근이 반복되면 그만큼 SELECT 반복
3. **cascade REMOVE vs orphanRemoval 결과가 갈리는 상황**: "부모는 그대로, 컬렉션에서만 제거"할 때. 이때 REMOVE는 유지, orphanRemoval은 삭제. **추가로 실전에서는 REMOVE+orphanRemoval 조합 자체가 컬렉션 조작 시 씹히는 버그를 겪었고, ALL로 바꿔서 해결함**
4. **편의 메서드가 필요한 이유**: DB는 문제없지만(주인만 봄), 메모리 객체 그래프가 깨짐 — SQL 문제가 아니라 같은 컨텍스트 내 조회 일관성 문제
