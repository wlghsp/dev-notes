# UDP (User Datagram Protocol)

TCP와 같은 전송 계층 프로토콜이지만, 연결 없이 데이터를 그냥 던지는 방식이다.

소켓 비유로 하면 TCP가 전화 통화라면, UDP는 문자 메시지다. 보내고 나서 읽었는지 확인하지 않는다.

## TCP와의 차이

TCP는 보내기 전에 3-way handshake로 연결을 맺고, ACK로 수신을 확인하고, 유실되면 재전송한다.

UDP는 그런 것 없다.

- 연결 수립 없음 — SYN/ACK 없이 바로 전송
- 수신 확인 없음 — ACK 없음, 상대가 받았는지 모름
- 재전송 없음 — 유실되면 그냥 없어짐
- 순서 보장 없음 — 패킷이 뒤섞여도 그대로 전달

## 그럼 왜 쓰냐

신뢰성을 포기한 대신 **빠르다**.

TCP는 연결/확인/재전송 때문에 왕복 지연이 생긴다. UDP는 그냥 던지기 때문에 지연이 최소화된다.

유실보다 **지연이 더 나쁜 상황**에서 쓴다.

- 동영상 스트리밍 — 프레임 하나 유실되면 화면이 잠깐 깨지는 게 낫지, 멈추는 건 더 나쁨
- 온라인 게임 — 0.1초 전 위치 데이터가 유실되면 그냥 버리면 됨, 재전송 기다리면 더 이상함
- DNS 쿼리 — 짧은 요청/응답 한 번이라 연결 수립 오버헤드가 아까움

## 신뢰성이 필요하면 애플리케이션이 직접 구현

UDP 위에서 신뢰성이 필요하면 애플리케이션 레벨에서 직접 구현한다. QUIC(HTTP/3의 기반)이 대표적인 예다. UDP를 쓰면서 자체적으로 재전송, 순서 보장, 혼잡 제어를 구현했다. TCP의 문제(헤드오브라인 블로킹 등)를 피하면서 신뢰성도 갖추기 위해서다.
