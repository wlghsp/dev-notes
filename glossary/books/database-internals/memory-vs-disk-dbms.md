# Memory vs Disk-Based DBMS

데이터베이스 시스템은 데이터를 메모리와 디스크 모두에 저장한다. 어느 쪽을 주 저장소로 사용하는가에 따라 구조가 근본적으로 달라진다.

## 두 종류의 구분

**In-Memory DBMS (Main Memory DBMS)**
데이터를 주로 메모리에 저장한다. 디스크는 복구와 로깅 목적으로만 사용한다. 메모리 가격이 내려가면서 점점 실용적인 선택이 되고 있다.

**Disk-Based DBMS**
데이터를 주로 디스크에 저장한다. 메모리는 디스크 내용을 캐시하거나 임시 저장소로 사용한다. 두 방식 모두 디스크를 어느 정도는 사용하지만, 인메모리 DB는 데이터를 거의 전부 RAM에 유지한다.

## 왜 디스크 기반이 기본인가

메모리 접근이 디스크보다 몇 자릿수 빠른 것은 사실이다. 그럼에도 디스크 기반이 기본으로 자리 잡은 이유는 두 가지다.

첫째, RAM은 휘발성이다. 전원이 꺼지면 데이터가 사라진다. 소프트웨어 오류, 하드웨어 장애, 정전 모두 데이터 손실로 이어진다.

둘째, RAM 가격은 여전히 SSD나 HDD보다 훨씬 비싸다. 대용량 데이터를 전부 메모리에 올리는 비용이 현실적이지 않다.

## 인메모리 DB의 내구성 처리

인메모리 DB도 내구성을 포기하지 않는다. 다음 두 가지 메커니즘으로 해결한다.

**Write-Ahead Log (WAL)**
연산이 완료된 것으로 간주되기 전에 결과를 순차적 로그 파일에 기록한다. 재시작 시 이 로그를 재실행해 메모리 상태를 복원한다.

**Backup Copy (Checkpoint)**
로그 전체를 재실행하면 시간이 오래 걸리므로, 주기적으로 메모리 상태를 디스크에 스냅샷으로 기록한다. 이 스냅샷 이전의 로그는 버릴 수 있다. 이 과정을 checkpointing이라 한다. 체크포인팅은 클라이언트를 블로킹하지 않고 비동기로 처리된다.

## 디스크 기반 DB와의 구조적 차이

인메모리 DB는 단순히 디스크 기반 DB에 거대한 페이지 캐시를 얹은 것이 아니다. 두 방식은 사용하는 자료구조와 최적화 방법이 근본적으로 다르다.

디스크 기반 자료구조는 디스크 접근 패턴에 최적화돼 있다. 디스크에서는 랜덤 접근이 매우 느리기 때문에, 넓고 낮은 트리(B-Tree 등)를 선호한다. 한 번의 I/O로 많은 키를 읽을 수 있도록 노드를 크게 만들고, 탐색 깊이를 줄인다.

인메모리 자료구조는 포인터를 빠르게 따라갈 수 있기 때문에 더 다양한 선택지가 있다. 가변 길이 데이터 처리도 포인터 참조만으로 해결되는 경우가 많아 구현이 훨씬 간단하다.
