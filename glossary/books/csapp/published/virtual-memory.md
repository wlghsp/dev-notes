# virtual-memory

각 프로세스에게 메모리 전체를 혼자 쓰는 것처럼 보이게 만드는 OS의 추상화.

## 핵심 아이디어

프로그램이 메모리를 직접 접근할 때 쓰는 주소는 "가상 주소"다. 실제 DRAM의 물리 주소가 아니다. CPU가 메모리에 접근할 때마다 하드웨어(MMU)가 가상 주소를 물리 주소로 변환한다.

```
프로세스 A: 가상주소 0x1000 → 물리주소 0x4000
프로세스 B: 가상주소 0x1000 → 물리주소 0x9000
```

두 프로세스가 같은 가상 주소를 쓰더라도 실제로는 다른 물리 메모리를 가리킨다. 이게 프로세스 격리가 가능한 이유다.

## 왜 가상 주소를 쓰는가

물리 주소를 직접 쓰면 두 가지 문제가 생긴다.

**격리 불가** — 프로세스A가 프로세스B의 물리 주소를 직접 읽을 수 있다. 커널이 올라와 있는 물리 주소에 임의로 쓰면 커널 코드가 덮어써져 스케줄링, 인터럽트 처리 등 모든 것이 망가져 시스템 전체가 죽는다.

**주소 공간 제약** — 물리 주소를 직접 쓰면 프로그램이 물리 메모리 크기에 맞게 컴파일되어야 한다. 동시에 여러 프로세스를 띄우면 각 프로그램이 어느 물리 주소를 쓸지 컴파일 시점에 미리 정해야 하고, 서로 겹치지 않게 조정해야 한다. RAM을 증설하거나 줄이면 프로그램을 다시 컴파일해야 한다. 가상 메모리를 쓰면 프로그램은 항상 같은 가상 주소 기준으로 컴파일되고, 물리 메모리 크기와 무관하게 동작한다.

## 가상→물리 주소 변환 흐름

OS가 규칙(페이지 테이블)을 만들고, CPU MMU가 그 규칙대로 변환을 실행한다.

```
프로세스가 가상 주소로 접근
        ↓
CPU 안의 MMU가 가상 주소를 받음
        ↓
TLB에 변환 결과가 있으면? → 바로 물리 주소 반환 (TLB 히트)
        ↓ (TLB 미스)
페이지 테이블을 메모리에서 읽어서 물리 주소 계산
        ↓
변환 결과를 TLB에 등록 후 물리 주소로 실제 메모리 접근
```

MMU(Memory Management Unit)는 가상→물리 주소 변환을 하드웨어로 처리하는 장치로 CPU 안에 내장되어 있다. 소프트웨어만으로 모든 메모리 접근을 검사하면 너무 느리기 때문에 하드웨어가 담당한다. MMU가 없는 하드웨어(일부 임베디드)에서는 가상 주소를 쓸 수 없다.

## 가상 메모리가 제공하는 세 가지

1. **프로세스 격리** — 한 프로세스가 다른 프로세스의 메모리를 읽거나 쓸 수 없다.

2. **메모리 관리 단순화** — 각 프로세스는 자신이 연속된 큰 메모리를 가진 것처럼 볼 수 있다. 실제 물리 메모리는 단편화되어 있어도 상관없다.

3. **디스크를 메모리처럼** — 실제 DRAM보다 큰 메모리를 사용하는 것처럼 보일 수 있다. 자주 쓰지 않는 페이지는 디스크(스왑)에 내려두고, 필요할 때 다시 올린다. 접근했을 때 디스크에 있으면 page-fault가 발생한다.

## 가상 주소 공간 구조

```
높은 주소 (0xFFFF...)
  [커널 공간]       — OS가 사용, 유저 코드에서 직접 접근 불가
  [스택]            — 함수 호출마다 자람 (↓ 방향)
  [공백]
  [힙]              — 동적 할당 (↑ 방향)
  [BSS/데이터]      — 전역/정적 변수
  [텍스트]          — 실행 코드
낮은 주소 (0x0000...)
```
