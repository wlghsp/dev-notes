# schema-on-write-vs-read
참고: document-model.md

---

스키마를 언제 강제하느냐의 차이다.

**schema-on-write** — 데이터를 쓸 때 스키마를 검증한다. 관계형 DB의 방식이다. DB가 쓰기 시점에 모든 데이터가 선언된 스키마에 맞는지 확인한다. 컴파일 타임 타입 체킹과 유사하다. 스키마에 맞지 않으면 쓰기가 거부된다.

**schema-on-read** — 데이터를 읽을 때 구조를 해석한다. 문서 DB의 방식이다. DB는 어떤 데이터든 그냥 저장하고, 구조는 읽는 애플리케이션 코드가 가정한다. 런타임 타입 체킹과 유사하다. 스키마가 없는 게 아니라, 스키마가 암묵적으로 코드 안에 있는 것이다.

## 트레이드오프

schema-on-write는 스키마 변경이 번거롭다. 컬럼 추가는 `ALTER TABLE`로 되지만, 대용량 테이블에서 MySQL은 전체 테이블을 복사하기 때문에 수 시간의 다운타임이 생길 수 있다. 반면 데이터 일관성을 DB가 보장한다.

schema-on-read는 스키마 변경이 유연하다. 새 구조로 새 문서를 쓰기 시작하고, 읽는 코드에서 예전 문서와 새 문서를 구분해서 처리하면 된다. 대신 데이터 일관성은 애플리케이션이 책임져야 한다.

데이터 구조가 이질적이거나(각 레코드가 다른 구조를 가짐) 외부 시스템에 의해 결정되는 경우라면 schema-on-read가 더 자연스럽다. 모든 레코드가 동일한 구조를 가져야 한다면 schema-on-write가 더 안전하다.
