# Compressed Oops (압축 참조)

64비트 JVM에서 객체 참조를 8바이트 대신 4바이트로 저장하는 최적화 기법이다. Oop은 Ordinary Object Pointer의 줄임말로, JVM 내부에서 객체를 가리키는 포인터를 부르는 이름이다.

## 왜 필요한가

64비트 JVM은 주소 공간이 64비트라 참조 하나에 8바이트가 필요하다. 참조가 많은 애플리케이션에서는 이 8바이트가 그대로 메모리 사용량과 캐시 효율에 부담이 된다. 32비트 JVM처럼 참조를 4바이트로 줄이면 메모리도 아끼고 캐시 적중률도 올라가지만, 32비트 주소 공간은 최대 4GB까지만 가리킬 수 있어 힙을 키울 수 없다는 제약이 있다.

## 어떻게 4바이트로 8바이트 주소를 가리키는가

핵심은 객체 정렬이다. 자바 객체는 항상 8바이트 단위로 정렬되므로, 모든 객체 주소는 8의 배수다. 그래서 실제 주소를 그대로 저장하지 않고, **주소를 8로 나눈 값**을 4바이트에 저장한다.

참조를 사용할 때 JVM이 이 값에 8을 곱해(비트 시프트) 원래 주소로 복원한다. 4바이트로 표현 가능한 최댓값(약 43억)에 8을 곱하면 약 32GB까지의 주소 공간을 커버할 수 있다. 이 덕분에 참조는 4바이트로 유지하면서도 힙은 32GB까지 쓸 수 있다.

## 힙이 32GB를 넘으면

압축이 불가능해진다. 이 임계값을 넘는 순간 모든 참조 필드와 Class Word가 8바이트로 확장되고, 애플리케이션 전체 객체 크기가 한꺼번에 커진다. 참고: java-objects-inside-out.md
