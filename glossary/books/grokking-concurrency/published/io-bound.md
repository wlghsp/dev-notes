# io-bound

작업의 실행 속도가 I/O 서브시스템의 속도에 의해 결정되는 작업 유형.

CPU는 빠르게 준비되어 있지만, 디스크 읽기/쓰기나 네트워크 응답을 기다리느라 대부분의 시간을 보낸다. 병목이 연산 능력이 아니라 I/O 속도에 있다.

## 특징

작업 시간의 대부분이 대기(wait)로 채워진다. CPU 입장에서는 할 일이 없는 상태가 많다. 코어를 아무리 늘려도 I/O 대기 시간 자체는 줄어들지 않는다.

대표적인 예: 데이터베이스 쿼리, 파일 읽기/쓰기, 네트워크 API 호출, 사용자 입력 대기.

## 멀티코어와의 관계

I/O-bound 작업은 코어 수를 늘린다고 성능이 비례해서 향상되지 않는다. 코어가 대기 중인 상태이기 때문에 코어를 추가해봐야 대기 시간이 줄지 않는다.

대신 단일 코어에서 여러 I/O-bound 작업을 번갈아 실행하는 방식이 효과적이다. 하나가 I/O를 기다리는 동안 다른 작업이 CPU를 쓸 수 있다. 이것이 이벤트 루프나 비동기 I/O의 핵심 아이디어다.

## 스케줄러의 역할

스케줄러는 I/O-bound 작업이 I/O를 기다리는 순간 그 작업을 대기 상태로 전환하고, 다른 작업에 CPU를 넘긴다. I/O가 완료되면 해당 작업을 다시 Ready 상태로 올려 스케줄링 대상에 포함시킨다.
