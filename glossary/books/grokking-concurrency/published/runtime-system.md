# Runtime System

애플리케이션과 하드웨어 사이에 놓인 소프트웨어 추상화 계층. 가장 대표적인 예가 운영체제(OS)다.

## 왜 필요한가

CPU를 직접 다루는 것은 복잡하다. 하드웨어 자원 제어, 자원 접근 관리, 프로그램 격리, 공유 자원 접근 등 모든 것을 개발자가 직접 처리해야 한다면 프로그래밍이 불가능에 가까워진다. 런타임 시스템은 이 복잡한 저수준 작업을 대신 처리하고, 개발자에게 사용하기 쉬운 인터페이스를 제공한다.

## 컴퓨터 시스템 구성 요소

CPU, RAM 외에 컴퓨터를 구성하는 요소들:

- **주변 장치(peripheral devices)** — 프린터, 키보드, 하드 드라이브, 모니터 등
- **드라이버(drivers)** — 주변 장치가 CPU, RAM과 통신할 수 있게 해주는 소프트웨어
- **시스템 버스(system bus)** — CPU, RAM, 주변 장치를 연결하는 통신 채널

런타임 시스템이 조율한다는 것은 이 구성 요소들을 대상으로 한다. CPU는 어떤 프로그램이 언제 쓸지 스케줄링하고, RAM은 프로그램마다 공간을 할당해 격리하며, 주변 장치는 드라이버를 통해 I/O 요청을 처리한다. 여러 프로그램이 동시에 이 자원들을 쓰려 할 때 충돌 없이 중재하는 것이 런타임의 핵심 역할이다.

## OS 외의 런타임 시스템

OS가 가장 아래에 있는 런타임이고, 그 위로 더 특정 환경에 특화된 런타임들이 쌓인다.

- **언어 런타임** — JVM(Java), V8(JavaScript), CPython(Python). GC, 타입 시스템, 표준 라이브러리 실행 환경을 제공한다. OS 위에서 동작하지만 그 자체로 런타임 시스템이다.
- **언어 런타임 내 스케줄러** — Go의 goroutine 스케줄러, Erlang의 프로세스 스케줄러. OS 스케줄러와 별개로 경량 실행 단위를 자체적으로 스케줄링한다.
- **컨테이너 런타임** — containerd, runc. 컨테이너 프로세스를 생성·격리·관리한다.
- **WebAssembly 런타임** — Wasmtime, WasmEdge. Wasm 바이너리를 실행하는 추상화 계층.

공통점은 "어떤 실행 단위를 만들고 관리하는 계층"이라는 것이다. 관리 대상이 프로세스냐, 스레드냐, 코루틴이냐, 컨테이너냐에 따라 런타임의 종류가 달라진다.
