# OSI 모델은 왜 TCP/IP와 잘 안 맞을까

원문: "The OSI model doesn't map well to TCP/IP" — Julia Evans (jvns.ca, 2021)

## Why

누구나 네트워크를 배울 때 OSI 7계층 모델을 외운다. 그런데 실제 TCP/IP 네트워킹과 이 모델을 하나씩 대응시켜보면, 생각보다 잘 안 맞는 부분이 많다.

## 어디까지 맞고, 어디부터 안 맞는가

일부 계층은 실제 프로토콜과 대응된다.

- Layer 2 = Ethernet
- Layer 3 = IP
- Layer 4 = TCP/UDP
- Layer 7 = 애플리케이션 데이터(DNS 쿼리, HTTP 요청 등)

하지만 Layer 5, 6은 "모든 계층이 대응하는 헤더를 가진다"는 식의 명확한 대응 관계가 TCP/IP 프로토콜에 없다.

## 그런데도 업계에서 계속 쓰이는 이유

모델이 실제와 딱 맞지 않는데도, 실무에서는 여전히 "Layer 2, 3, 4, 7" 같은 표현을 로드밸런서나 라우팅 논의에서 자주 사용한다. 모델 자체가 완벽하지 않더라도, 이런 용어를 이해하는 것은 기술 문서를 읽을 때 여전히 필요하다.

## ARP가 보여주는 불일치

ARP 프로토콜이 이 불일치를 잘 보여주는 사례다. ARP는 IP 주소를 다루는 내용(Layer 3의 관심사)을 담고 있지만, IP 헤더 없이 Ethernet 프레임 위에 바로 얹혀 있다. 깔끔한 계층 구조로는 설명할 수 없는 형태다.

## 왜 이런 괴리가 생겼는가

OSI 모델은 1970~80년대 "프로토콜 전쟁(Protocol Wars)" 시기에 만들어진, 지금은 쓰이지 않는 프로토콜들을 그대로 기술한 모델이었다. 결국 TCP/IP가 OSI 진영의 프로토콜들을 이기고 살아남았기 때문에, 모델과 실제 구현 사이에 근본적인 괴리가 생겼다.

## 저자의 대안

계층 번호로 말하는 대신, 구체적인 프로토콜 이름을 쓰자는 것이 저자의 제안이다. "Layer 2"라고 하는 대신 "Ethernet"이라고, "Layer 7 로드밸런서"라고 하는 대신 "HTTP 로드밸런서"라고 말하는 식이다.
