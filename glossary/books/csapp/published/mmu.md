# MMU (Memory Management Unit)

가상 주소를 물리 주소로 변환하는 하드웨어. CPU 안에 내장되어 있다.

## 왜 하드웨어가 담당하는가

가상 메모리를 쓰면 모든 메모리 접근마다 가상→물리 주소 변환이 필요하다. 이걸 소프트웨어(OS)가 처리하면 명령어 하나 실행할 때마다 OS가 개입해야 한다. 너무 느려서 현실적으로 불가능하다.

MMU가 하드웨어로 변환을 처리하기 때문에 오버헤드 없이 매 클럭마다 변환이 가능하다.

## 변환 흐름

```
CPU가 가상 주소 생성
        ↓
MMU가 가상 주소를 받음
        ↓
TLB에 변환 결과가 있으면? → 바로 물리 주소 반환
        ↓ (TLB 미스)
페이지 테이블을 메모리에서 읽어서 물리 주소 계산
        ↓
결과를 TLB에 등록 후 물리 주소 반환
        ↓
물리 주소로 실제 메모리 접근
```

TLB는 MMU 안에 붙어있는 캐시다. 자주 쓰는 변환 결과를 저장해서 페이지 테이블 조회를 생략한다. 참고: tlb.md

## 페이지 테이블과의 관계

OS가 프로세스마다 페이지 테이블을 만들고 관리한다. MMU는 그 페이지 테이블을 읽어서 변환만 한다. 규칙은 OS가 만들고, 실행은 MMU가 한다.

프로세스가 전환될 때 OS가 페이지 테이블 포인터를 바꿔주면 MMU는 자동으로 새 프로세스의 주소 공간을 기준으로 변환한다.

## 접근 권한 검사

MMU는 주소 변환만 하지 않는다. 페이지 테이블에 기록된 권한도 같이 확인한다.

- 읽기 전용 페이지에 쓰기 시도 → 차단
- 실행 권한 없는 페이지에서 코드 실행 시도 → 차단 (NX bit)
- 커널 영역에 유저 프로세스가 접근 시도 → 차단

권한 위반이 발생하면 MMU가 CPU에 예외(exception)를 발생시키고, OS가 해당 프로세스를 종료한다. 이게 segmentation fault다.

## MMU가 없으면

가상 주소를 쓸 수 없다. 일부 임베디드 하드웨어처럼 MMU가 없는 환경에서는 프로그램이 물리 주소를 직접 쓴다. 프로세스 격리가 불가능하고, 프로그램 하나가 잘못되면 시스템 전체에 영향을 준다.
