# [강의 노트] 5강. 이벤트 루프 실전 모의연습과 6단계 페이즈 완벽 마스터 (1/2)

## 1. 개요 및 배경 (Overview & Background)

본 강의는 앞서 배운 Node.js의 핵심 부품(콜 스택, 이벤트 큐, 이벤트 루프 6단계)들이 실제 코드에서 어떻게 맞물려 돌아가는지 증명하는 실전 모의연습(Mock Drill)입니다. 외부 모듈(파일 시스템, 네트워크)을 사용하기 전, 순수 자바스크립트의 비동기 함수만으로 이벤트 루프의 '우선순위'와 '새치기(Interruption)' 메커니즘을 완벽하게 체화합니다.

> 💡 **[CS 및 실무 적용 Point: 비동기 실행 순서의 예측 가능성]**
> 현업에서 여러 개의 비동기 API 통신과 데이터베이스 조회가 동시에 일어날 때, 개발자가 실행 순서를 정확히 통제하지 못하면 이른바 '경쟁 상태(Race Condition)' 버그가 발생합니다. A 데이터가 오기도 전에 B 로직이 실행되어 undefined 에러를 뿜어내는 식입니다. 오늘 진행할 우선순위와 페이즈(Phase) 이동 원리를 마스터하면, 아무리 복잡하게 얽힌 콜백과 프로미스 지옥 속에서도 데이터의 흐름을 투명하게 꿰뚫어 보고 통제할 수 있는 시야를 갖추게 됩니다.

> 🌱 **[직관적 비유]**
> 오늘은 우리 머릿속에 '가상의 건축 현장 시뮬레이터'를 켜는 날입니다. 총괄 소장님(콜 스택)이 어떤 서류를 책상에 먼저 올리는지, 깐깐한 순찰 반장(이벤트 루프)이 서류 결재함 사이를 어떤 규칙으로 돌아다니며 새치기를 허용하는지 눈으로 직접 추적해 볼 것입니다.

## 2. 절대 법칙: 결재 우선순위 완벽 정리 (계급도)

코드를 보기 전, 시스템을 지배하는 절대적인 결재 우선순위 4계급을 반드시 머릿속에 각인해야 합니다. 순찰 반장(이벤트 루프)은 무조건 이 계급에 따라 대기함을 열어봅니다.

1. **[초월 계급] 동기 코드 (메인 실행 흐름)**: 소장님(콜 스택)이 대기함에 넣지 않고 그 자리에서 즉시 처리합니다.
2. **[0순위 VVIP] process.nextTick (nextTick Queue)**: 비동기 중의 황제입니다. 대기함에 들어온 모든 비동기 서류 중 무조건 가장 먼저 소장님 책상으로 올라갑니다.
3. **[1순위 VIP] Promise (Microtask Queue)**: VVIP(nextTick) 대기함이 완전히 텅 빌 때까지 기다려야 하지만, 여전히 강력한 권력을 가집니다. 일반 정거장 서류들보다 먼저 처리됩니다.
4. **[2순위 일반 시민] setTimeout, setInterval 등 (일반 정거장 큐)**: VVIP와 VIP 결재함이 모두 텅텅 비어야만, 비로소 순찰 반장이 1번 정거장(Timer)으로 버스를 몰고 가 결재를 시작합니다.

## 3. 실전 모의연습 1: 콜 스택과 블로킹 (Blocking)

자바스크립트는 단일 콜 스택(소장님 1명)을 가집니다. 비동기 하청업체(libuv)에 일을 넘기지 않고 소장님 혼자 무거운 연산을 처리하면 어떤 일이 벌어지는지 확인합니다.

**[시각화] 동기적 수학 연산으로 인한 현장 마비**

```javascript
console.log('가벼운 작업: 출력 완료');
for (let i = 0; i < 10000000000; i++) { /* 100억 번의 무거운 수학 연산 */ }
console.log('이 코드는 한참 뒤에야 실행됩니다.');
```

```
[ Call Stack (소장님 책상) ]
  |                                 |
  | for문 (100억 번 연산 중...)     | <-- 여기서 수 초간 멈춤! (블로킹)
  | 메인 실행 컨텍스트              |
  -----------------------------------
```

**📝 [스텝별 실행 흐름 및 6단계 심층 해부]**

1. **가벼운 작업 즉시 처리 (Phase 0 진입 전)**: 프로그램이 시작되자마자 소장님(콜 스택)은 맨 윗줄의 가벼운 출력 코드를 발견합니다. 이 시점에서는 이벤트 루프가 아예 작동할 필요도 없이 소장님이 즉시 스택에 올려 처리합니다.
2. **무거운 연산의 등장과 블로킹 (동기 지연)**: 이어서 100억 번의 수학 연산을 마주합니다. 이것은 비동기 API가 아니므로 소장님은 libuv 하청업체에 넘길 수 없습니다. 직접 계산기를 두드리기 시작하며 콜 스택이 점유당합니다.
3. **현장 마비 (Event Loop의 기립 대기)**: 콜 스택(소장님 책상)에 무거운 연산 서류가 꽉 들어차게 되면서 현장은 수 초간 꼼짝없이 멈춰 섭니다. 이벤트 루프는 "콜 스택이 완전히 비워졌을 때만" 6단계 Phase(정거장) 순회를 시작할 수 있다는 절대 규칙을 가집니다. 따라서 이벤트 루프는 출발선에서 멍하니 대기만 할 뿐 아무것도 하지 못합니다.
4. **결과**: 책상이 완전히 막혀 있으므로, 이 시간 동안 시스템 외부에서 네트워크 요청이 들어오거나 1번 정거장(Timer Phase)에 알람 서류가 생겨도 소장님 책상에 올릴 수가 없습니다. 무거운 연산이 다 끝나고 맨 마지막 줄 코드까지 처리되어 소장님이 퇴근(콜 스택 비워짐)을 해야만 비로소 이벤트 루프가 첫 Phase로 진입할 수 있는 마비 상태가 됩니다.

## 4. 실전 모의연습 2: VIP 결재함 내부의 계급 분쟁

코드가 작성된 순서에 속지 마십시오. 이벤트 루프는 작성된 순서가 아니라 시스템의 계급(우선순위)을 따릅니다.

```javascript
Promise.resolve().then(() => {
    console.log('A: 자재 주문 완료 보고서 [VIP 접수]');
});

process.nextTick(() => {
    console.log('B: 현장 붕괴 위험 긴급 안전 점검 [VVIP 접수]');
});

Promise.resolve().then(() => {
    console.log('C: 인부 출근부 확인 보고서 [VIP 접수]');
});
```

**[시각화] VVIP와 VIP의 새치기 경쟁**

```
[Step 1] 서류 접수 직후
[ VIP 결재함 (Microtask Queue) ] : [ A (Promise) ] -> [ C (Promise) ]
[ VVIP 결재함 (nextTick Queue) ] : [ B (nextTick) ]

[Step 2] 이벤트 루프의 개입 (B 새치기)
▶ 화면 출력: B (VVIP 접수)
[ VVIP 결재함 ] : (텅 빔!)

[Step 3] 다음 계급 처리 (A, C 처리)
▶ 화면 출력: A -> C
```

**📝 [스텝별 실행 흐름 및 6단계 심층 해부]**

1. **서류 접수 및 분류 (백그라운드 위임)**: 코드가 실행되면서 비동기 작업들이 메인 스레드를 스쳐 지나가며 각자의 대기함으로 즉시 빨려 들어갑니다. VIP 결재함(Microtask Queue)에는 작성된 순서에 따라 A와 C 서류가 나란히 쌓입니다. 반면, 중간에 작성되었던 절대 권력의 B 서류는 VVIP 결재함(nextTick Queue)이라는 별도의 프리미엄 창구에 홀로 접수됩니다.
2. **이벤트 루프 가동 및 정거장 이동 전 최우선 검문**: 코드를 끝까지 다 읽고 콜 스택이 텅 비워지는 순간, 이벤트 루프(순찰 반장)가 움직입니다. 순찰 반장은 1번 정거장(Timer Phase)으로 출발하기 전에 반드시 Microtask Check라는 최우선 검문 절차를 거칩니다.
3. **0순위 VVIP 최우선 결재 (B 실행)**: 순찰 반장은 코드가 적힌 물리적 순서(A -> B -> C)를 완전히 무시합니다. 가장 먼저 0순위 결재함인 VVIP(nextTick Queue)를 열어제낍니다. 그곳에서 대기 중이던 B 서류를 가장 먼저 콜 스택으로 밀어 올려 실행시킵니다. (B 가장 먼저 출력)
4. **1순위 VIP 순차 결재 (A, C 실행)**: B가 실행되고 나서 순찰 반장은 다시 한번 VVIP 결재함을 봅니다. 완전히 텅 빈 것을 확인한 후에야, 비로소 다음 계급인 VIP 결재함(Microtask Queue)을 엽니다. 이곳에서는 먼저 들어온 순서의 원칙(FIFO)을 지키며 A를 콜 스택에 올리고, 처리가 끝나면 연이어 C를 올립니다. (A 출력 후 C 출력)
5. **결과**: 작성 순서라는 함정에 빠지지 않고, 시스템이 하드코딩으로 정의해 둔 계급 체계에 따라 B -> A -> C 순으로 실행 흐름이 재배치됩니다. 이 결재함들이 다 비워진 후에야 이벤트 루프는 비로소 정규 6단계 Phase 버스를 운행하기 시작합니다.
