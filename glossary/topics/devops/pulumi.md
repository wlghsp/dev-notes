# Pulumi

## 한 줄 요약

IaC 도구인데, HCL 같은 전용 선언형 언어 대신 TypeScript, Python, Go 같은 범용 프로그래밍 언어로 인프라를 선언한다.

---

## terraform과 뭐가 다른가

terraform.md에서 정리했듯 terraform은 `.tf`라는 선언형 언어로 "인프라가 최종적으로 이런 상태여야 한다"를 적는다.
Pulumi도 목표는 같다 — 원하는 상태를 코드로 적으면 지금 상태와 비교해서 차이만 만든다.
다른 건 그 코드를 무엇으로 쓰느냐다. Pulumi는 이 선언을 TypeScript나 Python 같은 진짜 프로그래밍 언어로 쓴다.

이 차이가 실무에서 갈리는 지점은 로직이 복잡해질 때다.
"환경마다 서버 개수가 다르고, 이름 규칙도 조금씩 다르게" 같은 요구를 HCL의 `for_each`나 `count`로 표현하려면 우회가 필요하다.
Pulumi는 그냥 for loop, 조건문, 함수를 쓰면 된다 — 언어 자체가 범용이기 때문이다.

---

## 선언형 언어가 아니라서 얻는 것

Pulumi 코드는 일반 애플리케이션 코드와 같은 도구 체인을 그대로 쓸 수 있다.

IDE의 자동완성, 타입 체크, "정의로 이동" 같은 기능이 인프라 코드에도 그대로 적용된다.
HCL은 전용 언어라 이런 IDE 지원이 상대적으로 얕다.

TypeScript로 작성한 인프라 코드는 ESLint/Prettier로 스타일을 강제할 수 있고, 모노레포 구조로 여러 인프라 모듈을 묶어 관리할 수 있다.
Jest 같은 일반 단위 테스트 프레임워크로 인프라 코드 자체를 테스트할 수도 있다 — "이 함수가 만드는 리소스 이름이 규칙을 지키는가" 같은 걸 유닛 테스트로 검증하는 식이다.

---

## 트레이드오프

언어가 범용이라는 건 인프라 코드가 일반 애플리케이션 코드만큼 복잡해질 수 있다는 뜻이기도 하다.
terraform은 DSL이 제한적인 만큼 팀원 누가 짜도 형태가 비슷하게 수렴하는데, Pulumi는 같은 결과를 짜는 방식이 사람마다 크게 갈릴 수 있다.

생태계 크기도 terraform이 아직 앞선다.
Pulumi는 terraform 프로바이더를 자동 변환(bridging)해서 따라가는 구조라, 최신 클라우드 리소스 지원이 조금 늦게 반영되는 경우가 있다.

---

## 상태 관리는 어떻게 하나

terraform이 `.tfstate` 파일로 현재 상태를 기록하듯, Pulumi도 상태 파일이 필요하다.
차이는 기본값이 Pulumi Cloud라는 관리형 백엔드라는 점이다 — 직접 state 파일을 관리하고 싶다면 S3 같은 곳에 백엔드를 지정할 수도 있다.
