# swap

디스크의 일부를 RAM처럼 쓰는 OS의 메모리 확장 기법.

## 핵심 아이디어

RAM이 꽉 찼을 때 OS는 당장 안 쓰는 페이지를 디스크의 swap 영역으로 내린다. RAM에 빈 자리가 생기고 새 데이터를 올릴 수 있다. 나중에 그 페이지에 다시 접근하면 page fault가 발생하고 OS가 swap에서 RAM으로 다시 올린다.

```
RAM이 꽉 참
    ↓
OS가 오래 안 쓴 페이지를 골라 디스크(swap)에 씀
    ↓
RAM에 빈 자리 확보
    ↓
나중에 그 페이지에 접근 → page fault 발생
    ↓
OS가 swap에서 RAM으로 다시 올림
```

## 왜 성능이 떨어지는가

디스크는 RAM보다 수백~수천 배 느리다. swap이 발생하기 시작하면 메모리 접근이 디스크 I/O로 바뀌므로 성능이 급격히 떨어진다. 서버가 갑자기 느려졌을 때 swap 사용량이 올라가고 있다면 메모리 부족 신호다.

## 서버에서 확인하는 법

`free -h` 또는 `vmstat` 으로 swap 사용량을 확인할 수 있다. swap used가 계속 증가하고 있으면 메모리 부족 상태다.

## swap을 끄는 경우

Kubernetes 노드는 swap을 끄는 것이 기본이다. 이유는 예측 가능성 때문이다. swap이 켜져 있으면 메모리 limit을 초과한 Pod이 죽지 않고 디스크로 밀려나 살아있는 것처럼 보이지만 극도로 느린 상태가 된다. 이 상태가 퍼지면 노드 전체가 응답 불가에 빠진다. 느리게 살아있는 것보다 즉시 죽고 다른 노드에서 재시작하는 게 낫다. 그래서 swap을 끄고 OOM Killer가 즉시 처리하게 둔다.
