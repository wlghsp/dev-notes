## 객체 생성의 흐름

1. 클래스가 로드되어 있지 않으면 먼저 클래스 로딩이 발생한다
2. 힙의 Eden 영역에서 객체 크기만큼 공간을 확보한다
3. 헤더(mark word, class pointer)를 포함한 객체 구조를 초기화한다
4. 생성자 코드를 실행한다
5. 참조를 반환한다

---

## TLAB (Thread-Local Allocation Buffer)

힙은 모든 스레드가 공유하기 때문에, 여러 스레드가 동시에 객체를 생성하면 힙의 어느 위치에 할당할지를 놓고 경합이 생긴다.

이를 피하기 위해 JVM은 각 스레드에게 Eden 영역의 작은 구역을 미리 배타적으로 할당한다. 이것이 TLAB이다. 스레드는 자신의 TLAB 안에서 락 없이 빠르게 객체를 할당할 수 있다. TLAB이 가득 차면 새 TLAB을 요청한다.

---

## 객체 생성 비용

Java에서 객체 생성 자체의 비용은 매우 낮다. TLAB이 있기 때문에 포인터 하나를 이동하는 정도다.

진짜 비용은 GC 압력이다. 많은 객체를 생성할수록 GC가 더 자주 실행된다. 특히 short-lived 객체를 대량으로 만들면 minor GC가 자주 발생한다. minor GC 자체는 빠르지만, 아주 높은 빈도로 발생하면 전체 처리량에 영향을 준다.

객체 풀링(object pooling)은 생성/소멸 비용을 줄이기 위한 패턴이지만, 현대 JVM에서는 오히려 역효과가 나는 경우가 많다. 풀에서 객체를 꺼내고 반납하는 동기화 비용이 GC 비용보다 클 수 있기 때문이다. 생성 비용이 매우 높은 객체(DB 커넥션 등)에만 유효하다.
