# context-switch

OS가 현재 실행 중인 프로세스(또는 스레드)를 멈추고 다른 프로세스(또는 스레드)로 CPU를 넘겨주는 동작.

## 왜 필요한가

CPU 코어는 한 번에 하나의 흐름만 실행할 수 있다. 하지만 수십~수백 개의 프로세스가 동시에 실행되는 것처럼 보인다. OS가 아주 빠르게 context-switch를 반복해서 각 프로세스에게 CPU를 번갈아 주기 때문이다.

## 무엇을 저장하고 복원하는가

CPU를 넘겨주기 전에 현재 프로세스의 "문맥(context)"을 저장해야 한다. 다음에 다시 실행할 때 이어서 계속할 수 있게.

저장하는 것:
- 프로그램 카운터(PC) — 다음에 실행할 명령어 주소
- 레지스터 값 전체
- 메모리 매핑 정보 (어떤 가상 주소가 어떤 물리 주소인지)

이 정보를 PCB(Process Control Block)에 저장한다. 다음 프로세스의 PCB를 불러와서 CPU에 복원하면 전환 완료.

## 비용

context-switch는 공짜가 아니다.

- PCB 저장/복원 시간
- 캐시 오염 — 이전 프로세스가 채워둔 L1/L2 캐시가 새 프로세스에게는 쓸모없다. 새 프로세스가 처음 실행될 때 캐시 미스가 집중적으로 발생한다.
- TLB 플러시 — 가상→물리 주소 변환 캐시도 무효화된다.

스레드 간 전환은 같은 주소 공간을 공유하기 때문에 메모리 매핑 정보를 바꿀 필요가 없어서 프로세스 간 전환보다 비용이 낮다.

## 관련 개념

- 전환 대상 단위는 process.md, thread.md 참고
- 캐시 오염 비용은 cache.md 참고
- 가상 주소 변환 캐시는 tlb.md 참고
