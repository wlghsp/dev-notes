# memory fragmentation (메모리 단편화)

메모리를 할당하고 해제하다 보면 중간중간 쓸 수 없는 빈 구멍이 생기는 현상.

총 여유 공간은 있는데 연속된 공간이 없어서 새로운 할당 요청을 처리하지 못하는 상태가 된다.

## 외부 단편화 (external fragmentation)

빈 공간이 여러 조각으로 흩어져 있어서 연속된 큰 블록을 만들 수 없는 경우.

```
[A: 100MB] [빈: 50MB] [C: 200MB] [빈: 50MB] [D: 100MB]
```

총 빈 공간은 100MB인데, 80MB 연속 할당 요청이 오면 실패한다. 50MB짜리 구멍 두 개가 붙어있지 않기 때문이다.

세그멘테이션 방식에서 특히 심각하다. 세그먼트 크기가 제각각이라 해제 후 남는 구멍 크기도 제각각이고, 이 구멍들이 점점 쌓인다.

## 내부 단편화 (internal fragmentation)

할당된 블록 안에 실제로 쓰지 않는 공간이 생기는 경우.

메모리 할당기는 보통 요청 크기를 정해진 단위(예: 8바이트, 4KB)로 올림해서 준다. 13바이트를 요청하면 16바이트를 받고, 3바이트는 낭비된다.

페이징이 외부 단편화를 해결하지만, 페이지 단위(4KB) 할당 때문에 내부 단편화는 오히려 생긴다.

## 페이징이 외부 단편화를 해결하는 이유

페이징은 메모리를 고정 크기 페이지로 자른다. x86 기반 OS는 보통 4KB를 기본으로 쓰지만, Apple Silicon처럼 16KB를 쓰는 경우도 있다. 물리 메모리의 빈 페이지라면 어디든 가상 주소에 매핑할 수 있다. 물리적으로 흩어져 있어도 가상 주소 공간에서는 연속된 것처럼 보이게 만들 수 있다.

세그멘테이션은 물리 메모리에 연속된 공간이 실제로 있어야 하지만, 페이징은 그 제약이 없다.

## 힙에서의 단편화

`malloc` / `free`를 반복하면 힙도 단편화된다. 작은 블록들을 많이 할당하고 일부만 해제하면 힙 중간에 구멍이 생긴다. 이를 줄이기 위해 메모리 할당기(jemalloc, tcmalloc 등)는 크기별로 블록을 분류해서 관리하는 전략을 쓴다.
