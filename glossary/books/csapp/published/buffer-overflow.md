# buffer-overflow (버퍼 오버플로우)

스택에 할당된 버퍼(배열)에 경계를 초과해서 데이터를 쓰면, 그 옆에 있는 스택 상태(저장된 레지스터, 반환 주소 등)가 덮어씌워지는 현상.

## 왜 발생하는가

C는 배열 접근 시 경계 검사를 하지 않는다. 지역 배열은 스택 프레임 안에 있고, 그 바로 위에 반환 주소가 있다. 배열 크기를 초과해서 쓰면 반환 주소까지 덮어쓸 수 있다.

```c
void echo() {
    char buf[8];  // 스택에 8바이트
    gets(buf);    // 입력 길이를 제한하지 않음
}
```

8바이트를 초과한 입력이 들어오면:
- 0~7바이트: 정상 (buf 범위)
- 8~23바이트: 사용되지 않는 스택 공간 덮어씀
- 24~31바이트: 반환 주소 덮어씀
- 32바이트 이상: caller의 저장 상태까지 손상

반환 주소가 바뀌면 `ret` 실행 시 엉뚱한 주소로 점프한다.

## 공격 방식

공격자가 입력 문자열에 실행 가능한 기계어 코드(exploit code)를 포함시키고, 반환 주소를 그 코드의 주소로 덮어쓴다. 함수가 return하면 exploit code가 실행된다. 주로 쉘을 열거나 권한을 탈취하는 데 쓰인다.

1988년 인터넷 웜이 실제로 이 방식으로 수백 대의 머신을 마비시켰다.

## 방어 기법 세 가지

스택 랜덤화 (ASLR):
- 프로그램 실행마다 스택 주소를 무작위로 배치한다
- 공격자가 exploit code의 주소를 미리 알기 어렵게 만든다
- 완전한 방어는 아님 — nop sled 기법으로 우회 가능

스택 보호(Stack Canary):
- 지역 배열과 반환 주소 사이에 무작위 값(canary)을 삽입한다
- 함수 반환 직전에 canary 값이 바뀌었는지 확인한다
- 바뀌었으면 즉시 프로그램을 중단시킨다
- GCC가 char 배열이 있는 함수에 자동으로 삽입한다

실행 불가 스택 (NX bit):
- 스택 메모리 영역에 실행 권한을 부여하지 않는다
- 공격자가 스택에 코드를 올려도 실행할 수 없다
- AMD가 도입한 NX(No-eXecute) 비트, Intel은 XD(eXecute Disable)라고 부름

세 방어 기법을 함께 쓰면 각각 단독보다 훨씬 효과적이다.
