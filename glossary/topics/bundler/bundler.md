# Bundler (번들러)

여러 개의 모듈(JS, CSS, 이미지 등) 파일을 브라우저가 바로 실행할 수 있는 형태의 소수 파일로 묶어주는 도구.

## 왜 필요한가

브라우저는 원래 `<script>` 태그를 여러 개 나열해서 파일을 로드했다. 파일이 수백 개가 되면 다음 문제가 생긴다.

- 요청 수가 많아져서 네트워크 오버헤드가 커진다 (HTTP/1.1 환경에서 특히)
- 파일 로드 순서를 개발자가 직접 관리해야 한다 (의존성 순서)
- `import`/`export` 같은 모듈 문법을 오래된 브라우저는 지원하지 않는다

번들러는 이 문제를 해결하기 위해 다음을 수행한다.

1. **모듈 그래프 분석** — 진입점(entry)부터 시작해서 `import`로 연결된 모든 파일을 추적한다
2. **번들링** — 추적한 파일들을 하나 또는 소수의 파일로 합친다
3. **변환(transform)** — TypeScript, JSX, 최신 문법 등을 브라우저가 이해하는 코드로 변환한다 (보통 별도 트랜스파일러와 연동)
4. **최적화** — 사용하지 않는 코드 제거(tree shaking), 압축(minify), 코드 분할(code splitting) 등

## 번들링 방식의 차이

번들러마다 모듈 그래프를 언제, 어떻게 처리하는지가 다르다.

- **Bundle 기반 (Webpack, Rollup)** — 개발 서버를 켤 때도 전체 앱을 미리 번들링한다. 앱이 커질수록 초기 구동이 느려진다
- **Native ESM 기반 (Vite)** — 개발 중에는 번들링을 생략하고 브라우저의 native ES Module 로딩을 그대로 활용한다 (참고: vite-why-fast.md)

## 대표적인 번들러

- **Webpack** — 가장 오래되고 생태계가 넓다. 설정이 복잡한 편
- **Rollup** — 라이브러리 번들링에 특화, tree shaking이 강점
- **esbuild** — Go로 작성되어 빌드 속도가 매우 빠름. Vite가 내부적으로 사용
- **Vite** — 개발 서버는 native ESM, 프로덕션 빌드는 Rollup 기반

참고: esm.md, cjs.md, vite-why-fast.md
