# integer representation (정수 표현)

컴퓨터가 정수를 비트로 표현하는 방식. 부호 없는 정수와 부호 있는 정수(2의 보수) 두 가지가 있다.

## 부호 없는 정수 (unsigned)

모든 비트를 값으로 쓴다. 음수를 표현할 수 없다.

8비트 기준:
```
00000000 = 0
00000001 = 1
11111111 = 255
```

범위: 0 ~ 2^N - 1 (N은 비트 수)

## 부호 있는 정수 — 2의 보수 (two's complement)

음수를 표현하기 위해 2의 보수 방식을 쓴다. 최상위 비트(MSB)가 부호 비트다. 0이면 양수, 1이면 음수.

8비트 기준:
```
00000000 = 0
00000001 = 1
01111111 = 127   (양수 최대)
10000000 = -128  (음수 최소)
11111111 = -1
```

범위: -2^(N-1) ~ 2^(N-1) - 1

## 왜 2의 보수인가

음수를 표현하는 방법은 여러 가지가 있었다. 단순히 최상위 비트를 부호 비트로 쓰는 방법(부호-크기 표현)도 있었는데, 이 방식은 +0과 -0이 따로 존재하고 덧셈 회로를 따로 만들어야 했다.

2의 보수는 덧셈 회로 하나로 덧셈과 뺄셈을 모두 처리할 수 있다. ALU 설계가 단순해진다.

```
5 + (-3) = 5 + (2의 보수로 표현한 -3)
         = 00000101 + 11111101
         = 100000010
         = 00000010 (올림수 버림)
         = 2  ← 맞다
```

## 2의 보수 구하는 법

양수 → 음수로 변환할 때:
1. 비트를 전부 뒤집는다 (0→1, 1→0)
2. 1을 더한다

```
3  = 00000011
뒤집기 → 11111100
+1     → 11111101  = -3
```

## 범위의 비대칭

2의 보수는 음수 범위가 양수보다 하나 더 크다. 8비트 기준으로 -128 ~ 127이다. -128에 대응하는 양수(128)를 표현할 수 없다. 이 때문에 `abs(-128)`을 하면 여전히 -128이 나오는 언어도 있다.

## 부호 확장 (sign extension)

작은 타입을 큰 타입으로 변환할 때 비트 수를 늘려야 한다.

- unsigned → 큰 타입: 앞에 0을 채운다 (zero extension)
- signed → 큰 타입: 부호 비트(MSB)를 복사해서 앞에 채운다 (sign extension)

```
-3을 8비트에서 16비트로 확장:
11111101  →  1111111111111101   (부호 비트 1을 앞에 복사)
```

부호 비트를 복사하는 이유는 값을 유지하기 위해서다. 음수의 MSB는 1이므로 1로 채워야 같은 음수 값이 유지된다.

## 잘라내기 (truncation)

큰 타입을 작은 타입으로 변환할 때 상위 비트를 버린다. 값이 바뀔 수 있다.

```c
int x = 53191;
short sx = (short) x;  // -12345 — 상위 비트가 잘려나가면서 값이 바뀜
```

잘라내기는 일종의 오버플로우다. 표현 범위를 벗어난 값을 억지로 작은 타입에 넣는 것이기 때문이다.

## signed ↔ unsigned 변환의 함정

C에서 signed와 unsigned를 섞어 쓰면 암묵적 변환이 일어난다. 비트 패턴은 그대로인데 해석 방식이 바뀐다.

```c
int x = -1;
unsigned u = 2147483648;

printf("%u", x);   // 4294967295 — -1의 비트를 unsigned로 해석
printf("%d", u);   // -2147483648 — 큰 unsigned를 signed로 해석
```

더 위험한 경우는 비교 연산이다. signed와 unsigned를 비교하면 C가 signed를 unsigned로 암묵적 캐스팅한다.

```c
-1 < 0U   // -1이 unsigned로 캐스팅되어 4294967295가 됨 → false
```

이 동작은 보안 취약점으로 이어진 사례가 있다. FreeBSD의 `getpeername` 함수에서 음수 값이 unsigned로 해석되어 의도치 않게 커널 메모리를 읽을 수 있는 취약점이 발생했다.
