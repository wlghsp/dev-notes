# Kernel — 왜 존재하는가

커널은 프로세스가 하드웨어를 못 건드리게 막고, 대신 처리해주는 코드다.

## OS의 실체

"OS가 한다"는 말이 있으면, 그게 전부 커널이 하는 거다. 프로세스 스케줄링, 메모리 관리, 파일 읽기 — 전부 커널 코드가 실행된다.

"OS"라는 단어는 추상적인 개념이고, 커널은 그게 실제로 구현된 코드 덩어리다.

## 왜 커널이 필요한가

프로세스가 하드웨어에 직접 접근하면 안 된다.

- 프로세스 A가 프로세스 B의 메모리를 읽으면 안 된다
- 아무 프로세스나 디스크에 마음대로 쓰면 안 된다
- CPU를 한 프로세스가 독점하면 안 된다

그래서 하드웨어 접근은 커널만 할 수 있게 막아놨다. 프로세스는 "이거 해줘"하고 요청만 한다 - 그게 시스템 콜이다. 

## 비유

은행 창구랑 같다.

- 고객(프로세스)은 금고(하드웨어)에 직접 못 들어간다
- 창구 직원(커널)에게 요청하면, 직원이 금고에서 꺼내다 준다
- 직원은 권한 확인하고, 다른 고객 것 안 건드리게 보호한다
