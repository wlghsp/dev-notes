# KVM (Kernel-based Virtual Machine)

KVM은 리눅스 커널에 내장된 하이퍼바이저 기능이다. RHV, RHOSP, RHOV가 이름은 다 다르지만 결국 밑바닥에서는 이 KVM을 쓴다.

## 정체: 별도 프로그램이 아니라 커널 모듈

KVM은 독립된 하이퍼바이저 소프트웨어가 아니라, 일반 리눅스 커널에 들어 있는 커널 모듈이다. CPU의 하드웨어 가상화 기능(인텔 VT-x, AMD-V)을 커널이 직접 활용하도록 열어주는 역할을 한다. 그래서 "KVM을 설치한다"는 말은 새 프로그램을 까는 것이 아니라, 리눅스 커널에 이미 있는 가상화 기능을 켜는 것에 가깝다. `/dev/kvm` 디바이스 파일이 열려 있으면 이 기능이 활성화된 것이다.

이게 왜 하필 커널 모듈이어야 하냐면, CPU의 VT-x/AMD-V 같은 하드웨어 기능은 커널 모드(하드웨어를 직접 다룰 수 있는 CPU 실행 모드)에서만 켤 수 있기 때문이다. 일반 애플리케이션은 유저 모드에서 돌기 때문에 이 권한이 없다. KVM은 커널의 일부로 들어가서 이 커널 모드 권한을 그대로 물려받아 CPU 가상화 기능을 켠다. 커널과 유저 모드/커널 모드 개념 자체는 kernel.md 참고.

## KVM과 QEMU의 역할 분담

KVM 혼자서는 VM을 완전히 못 띄운다. KVM은 CPU/메모리 가상화만 담당하고, 디스크 이미지 처리, 네트워크 카드 에뮬레이션, VM 프로세스 실행 같은 나머지 작업은 QEMU라는 유저스페이스 프로그램이 맡는다. 그래서 실무에서는 항상 "KVM/QEMU" 조합으로 묶여 언급된다.

```
QEMU (유저스페이스 프로세스)
  ├── 디스크 이미지, 네트워크 카드 등 에뮬레이션
  └── /dev/kvm을 통해 KVM에 CPU 명령 실행을 위임
        └── KVM (커널 모듈) — 하드웨어 가속으로 실제 CPU 명령 실행
```

VM의 CPU 연산 자체는 KVM을 거쳐 하드웨어 가속으로 실행되기 때문에, 소프트웨어로만 흉내 내는 순수 에뮬레이션보다 훨씬 빠르다.

## RHV, RHOSP, RHOV와의 관계

- RHV — KVM 위에 VM 생명주기 관리(마이그레이션, 스케줄링)를 얹은 관리 툴
- RHOSP(Nova) — KVM 위에 멀티테넌트 IaaS(네트워크·스토리지·셀프서비스 API)를 얹은 계층
- RHOV — KVM을 그대로 쓰되, 관리를 OCP/쿠버네티스 오브젝트(KubeVirt)로 하는 방식. 자세한 내용은 kubevirt.md 참고

즉 RHV, RHOSP, RHOV는 이름과 관리 방식만 다를 뿐, VM을 실제로 실행하는 하드웨어 가속 엔진은 전부 KVM으로 같다.

## VMware ESXi와의 구조적 차이

VMware의 ESXi도 하이퍼바이저라는 역할은 같지만, ESXi는 그 자체가 하이퍼바이저 전용으로 만들어진 운영체제다. 반면 KVM은 범용 리눅스 커널에 가상화 기능을 얹은 것이다. 그래서 "가상화 전용 OS를 처음부터 만든" 것이 ESXi 방식이고, "리눅스라는 범용 OS 위에 가상화 기능을 얹은" 것이 KVM 방식이라는 근본적인 접근 차이가 있다.

## OCP 노드 자체는 무엇 위에서 도는가 (RHOV의 중첩 가상화)

"OCP 위에서 VM이 돈다"(RHOV)고 하면 OCP가 뭔가 신비한 기반인 것처럼 들리지만, OCP도 결국 리눅스 위에서 돈다. OCP 클러스터의 각 노드는 RHCOS(Red Hat CoreOS, OCP 전용으로 최소화된 리눅스 배포판)가 설치된 서버이고, 이 노드는 베어메탈이거나 다른 하이퍼바이저(vSphere/ESXi, RHV, 퍼블릭 클라우드의 자체 하이퍼바이저) 위의 VM이다. 참고: rhov.md

노드가 VM인 경우가 실무에서 흔한데, 이때 RHOV를 쓰면 이중 가상화 구조가 된다 — "VM(OCP 노드) 안에서 OCP가 돌고, 그 OCP가 다시 KVM으로 VM(RHOV가 만든 VM)을 돌린다"는 중첩 구조다. 이 경우 안쪽 VM이 하드웨어 가상화 명령어에 접근하려면 중첩 가상화(nested virtualization)를 노드 하이퍼바이저 쪽에서 지원해줘야 성능 손실 없이 동작한다. 그래서 RHOV를 실무에 적용할 때는 OCP 노드 자체가 베어메탈인지 VM인지가 성능에 실제로 영향을 준다.

참고: rhv.md, rhosp-osp.md, rhov.md, vsphere-vcenter.md, kubevirt.md
