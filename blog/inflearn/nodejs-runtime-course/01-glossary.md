# 1강 핵심 용어 사전 (Glossary in Context)

본문: 01-runtime-and-sandbox.md

### 샌드박스 (Sandbox)
- **단순 의미**: 외부의 접근이나 영향을 차단하여 보호된 격리 구역.
- **실무적 맥락**: 웹 서핑을 하다가 무심코 접속한 해킹 사이트의 자바스크립트 코드가 내 컴퓨터의 C드라이브를 포맷하거나 비밀번호 파일을 빼갈 수 없는 이유가 바로 이 '샌드박스' 때문입니다. 브라우저는 보안을 위해 자바스크립트를 철저히 모래성 안에 가두어 시스템(OS)에 접근하지 못하게 막습니다. Node.js는 자바스크립트를 이 샌드박스 밖으로 꺼내어, 서버의 하드웨어와 OS를 직접 만질 수 있는 '시스템 제어권'을 쥐여준 혁신적인 사건입니다.

### 런타임 환경 (Runtime Environment)
- **단순 의미**: 특정 프로그래밍 언어로 작성된 코드가 실행되는 환경.
- **실무적 맥락**: 언어(문법) 자체는 단순히 텍스트에 불과합니다. 이 텍스트를 읽고 컴퓨터가 알아듣게 번역해서 실행해 주는 토대가 런타임입니다. 프론트엔드 개발자가 쓰는 window나 document 같은 객체는 '브라우저 런타임'이 제공하는 도구이고, 백엔드 개발자가 쓰는 require('fs') 같은 파일 시스템 도구는 'Node.js 런타임'이 제공하는 도구입니다. 똑같은 한국어를 쓰더라도 방송국(런타임)에 가면 마이크가 있고, 주방(런타임)에 가면 칼이 있는 것과 같습니다.

### API (Application Programming Interface)
- **단순 의미**: 프로그램들이 서로 상호작용하기 위한 통신 인터페이스.
- **실무적 맥락**: 백엔드 개발 관점에서 API는 '식당의 메뉴판이자 점원'입니다. 스마트폰 앱(클라이언트)이 눈에 보이지 않는 백엔드 서버의 데이터베이스에 직접 접근하는 것은 불가능하고 매우 위험합니다. 따라서 Node.js 서버는 "주문(요청)을 주면, 데이터(음식)를 주겠다"는 명확한 창구(API)를 열어둡니다. 클라이언트가 데이터를 달라고 요청하면, 보이지 않는 곳에서 데이터를 조회하고 검증하여 결과를 반환하는 모든 시스템 설계가 바로 API 구축입니다.

### 병목 현상 (Bottleneck)
- **단순 의미**: 전체 시스템의 성능이 어떤 하나의 느린 요소 때문에 제한받는 현상.
- **실무적 맥락**: 도로의 차선이 4차선에서 1차선으로 줄어들 때 차가 막히는 것과 같습니다. Node.js 환경에서 병목 현상은 치명적입니다. 단 하나의 동영상 인코딩(무거운 CPU 작업)이 실행되면, 그 작업이 끝날 때까지 뒤에 줄 서 있는 1,000명의 로그인 요청이 멈춰버립니다. 따라서 아키텍트는 우리 서비스에 무거운 연산이 필요한지 파악하고, 필요하다면 그 작업만 Python 서버 등 다른 곳으로 분리(Microservice)하여 병목을 방지하는 설계를 해야 합니다.

### 스레드 (Thread)
- **단순 의미**: 프로세스(실행 중인 프로그램) 내에서 실제로 작업을 수행하는 가장 작은 흐름의 단위.
- **실무적 맥락**: 식당에서 일하는 '종업원'으로 이해하면 쉽습니다. Java나 C++ 기반의 서버는 손님이 올 때마다 종업원(스레드)을 새로 고용하여 1:1로 응대하게 합니다(Multi-thread). 반면, Node.js는 아주 빠르고 기억력이 좋은 단 한 명의 종업원(Single-thread)이 주문만 재빠르게 받고 요리는 주방(OS)으로 넘긴 뒤, 요리가 완성되면 알림(Event)을 받고 다시 손님에게 서빙하는 방식을 취합니다. 이 때문에 Node.js는 수만 명의 가벼운 주문(I/O)을 처리하는 데는 폭발적인 성능을 자랑하지만, 종업원 본인이 직접 오래 걸리는 요리(CPU 연산)를 시작해 버리면 다른 손님들의 주문을 아예 받지 못하는 치명적인 약점을 동시에 갖게 됩니다.
