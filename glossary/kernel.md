# Kernel (커널)

OS의 핵심 부분. 하드웨어와 프로세스 사이에서 중재자 역할을 한다.

프로세스는 하드웨어에 직접 접근할 수 없다. CPU, 메모리, 디스크, 네트워크 카드 — 전부 커널을 통해서만 쓸 수 있다. 프로세스가 뭔가 하고 싶으면 커널에 요청(시스템 콜)을 보내고, 커널이 대신 처리해준다.

리눅스 커널은 커널의 대표적인 구현체다. 리눅스 = 커널이고, Ubuntu/CentOS/Debian 같은 배포판은 리눅스 커널 위에 패키지, 도구, 설정을 얹은 것이다.

## 커널이 하는 일

**프로세스 관리**
어떤 프로세스가 CPU를 얼마나 쓸지 스케줄링한다. CPU 코어는 한 번에 하나의 작업만 처리하는데, 커널이 수십 ms 단위로 프로세스를 번갈아가며 실행시켜서 동시에 돌아가는 것처럼 보이게 만든다.

**메모리 관리**
프로세스마다 독립된 가상 메모리 공간을 준다. 프로세스 A가 프로세스 B의 메모리를 직접 읽을 수 없다. 커널이 실제 물리 메모리와 가상 주소를 매핑하고 보호한다.

**파일 시스템**
디스크에 파일을 읽고 쓰는 것을 처리한다. 프로세스는 `read(fd, ...)`만 하면 되고, 커널이 실제 디스크 블록을 찾아서 읽어온다.

**네트워크**
TCP/IP 스택이 커널 안에 있다. 프로세스가 소켓에 `write()`하면 커널이 TCP 세그먼트 포장, IP 라우팅, 네트워크 카드 전송까지 전부 처리한다.

**시스템 콜 인터페이스**
프로세스가 커널에 요청하는 창구다. `read`, `write`, `open`, `close`, `fork`, `exec` 등이 시스템 콜이다. 프로세스는 시스템 콜을 통해서만 커널 기능을 쓸 수 있다.

## 유저 모드 vs 커널 모드

CPU에는 두 가지 실행 모드가 있다.

- 유저 모드 — 프로세스가 실행되는 모드. 하드웨어 직접 접근 불가
- 커널 모드 — 커널이 실행되는 모드. 하드웨어 직접 접근 가능

프로세스가 시스템 콜을 호출하면 CPU가 유저 모드에서 커널 모드로 전환된다. 커널이 작업을 마치면 다시 유저 모드로 돌아온다. 이 전환 비용이 있어서 시스템 콜은 가능하면 줄이는 게 성능에 좋다.
