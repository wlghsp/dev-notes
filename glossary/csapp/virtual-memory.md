# virtual-memory

각 프로세스에게 메모리 전체를 혼자 쓰는 것처럼 보이게 만드는 OS의 추상화.

## 핵심 아이디어

프로그램이 메모리를 직접 접근할 때 쓰는 주소는 "가상 주소"다. 실제 DRAM의 물리 주소가 아니다. CPU가 메모리에 접근할 때마다 하드웨어(MMU)가 가상 주소를 물리 주소로 변환한다.

```
프로세스 A: 가상주소 0x1000 → 물리주소 0x4000
프로세스 B: 가상주소 0x1000 → 물리주소 0x9000
```

두 프로세스가 같은 가상 주소를 쓰더라도 실제로는 다른 물리 메모리를 가리킨다. 이게 프로세스 격리의 근거다.

## 가상 메모리가 제공하는 세 가지

1. **프로세스 격리** — 한 프로세스가 다른 프로세스의 메모리를 읽거나 쓸 수 없다.

2. **메모리 관리 단순화** — 각 프로세스는 자신이 연속된 큰 메모리를 가진 것처럼 볼 수 있다. 실제 물리 메모리는 단편화되어 있어도 상관없다.

3. **디스크를 메모리처럼** — 실제 DRAM보다 큰 메모리를 사용하는 것처럼 보일 수 있다. 자주 쓰지 않는 페이지는 디스크(스왑)에 내려두고, 필요할 때 다시 올린다. 접근했을 때 디스크에 있으면 page-fault가 발생한다.

## 가상 주소 공간 구조

```
높은 주소 (0xFFFF...)
  [커널 공간]       — OS가 사용, 유저 코드에서 직접 접근 불가
  [스택]            — 함수 호출마다 자람 (↓ 방향)
  [공백]
  [힙]              — 동적 할당 (↑ 방향)
  [BSS/데이터]      — 전역/정적 변수
  [텍스트]          — 실행 코드
낮은 주소 (0x0000...)
```
