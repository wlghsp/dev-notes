# Offset

어떤 기준점으로부터의 **위치**를 나타내는 값. 0부터 시작하는 정수다.

맥락마다 의미가 조금 다르지만 핵심은 같다. "어디서부터 읽을 것인가"를 가리키는 포인터.

## Kafka에서의 Offset

Kafka에서 offset은 파티션 내 메시지의 위치를 가리킨다.

파티션은 메시지가 순서대로 쌓이는 append-only 로그다. 새 메시지가 들어오면 맨 뒤에 붙고, 그 메시지의 offset은 직전 메시지 offset + 1이다.

컨슈머는 자신이 어디까지 읽었는지 offset으로 기억한다. 다음 번에 읽을 때는 마지막으로 읽은 offset + 1부터 시작한다.

컨슈머가 offset을 언제 커밋하느냐에 따라 전달 보장 방식이 결정된다.

- 처리 전에 offset 커밋 → At-Most-Once. 처리 실패해도 다시 읽지 않음
- 처리 후에 offset 커밋 → At-Least-Once. 커밋 전에 죽으면 같은 메시지를 다시 읽음

## Offset 커밋의 의미

Kafka에서 offset을 커밋한다는 것은 "나는 이 번호까지 읽고 처리했다"고 브로커에 알리는 것이다.

컨슈머가 재시작되거나 리밸런싱이 일어나면, 브로커는 마지막으로 커밋된 offset부터 메시지를 다시 내려준다. offset 커밋이 없으면 컨슈머 그룹은 어디서부터 읽어야 할지 모른다.

## 파일 시스템에서의 Offset

파일을 읽을 때도 offset이 쓰인다. 파일의 어느 바이트 위치부터 읽을지를 나타낸다. `read()` 시스템 콜이 호출되면 파일 디스크립터가 현재 offset을 기억하고, 읽은 만큼 자동으로 앞으로 이동한다.
