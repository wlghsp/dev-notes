# compiler-basics (컴파일러 기초)

컴파일러는 고수준 언어로 쓴 소스 코드를 기계어로 변환하는 프로그램이다. 어셈블러보다 훨씬 복잡하다. 어셈블러는 니모닉과 기계어가 1:1이지만, 컴파일러는 고수준 언어 문장 하나를 여러 기계어 명령으로 바꾼다.

## 고수준 언어가 필요한 이유

`A × Sin(2 × PI + B) / C` 같은 수식을 어셈블리로 표현하려면 수십 줄이 필요하다. 고수준 언어에서는 이 수식 그대로 쓰면 된다. 컴파일러가 나머지를 한다.

고수준 언어의 장점은 두 가지다. 가독성(어셈블리보다 훨씬 이해하기 쉽다)과 이식성(다른 프로세서용 컴파일러만 있으면 같은 소스 코드로 여러 플랫폼에서 실행할 수 있다).

단점도 있다. 능숙한 어셈블리 프로그래머가 직접 최적화한 코드보다 컴파일러 출력 코드가 더 크고 느리다. 다만 현대 컴파일러는 최적화 수준이 높아져 이 차이가 줄었다.

## 주요 고수준 언어의 흐름

FORTRAN(1950년대 중반, IBM) — 과학·공학용. 부동소수점 연산에 강했다.

ALGOL(1957~1960) — 블록 구조, 변수 선언, for 루프, if-else, 배열을 체계적으로 정의했다. 이후 등장한 대부분의 언어가 ALGOL 계열이다.

COBOL(1959) — 비즈니스 데이터 처리. 레코드와 보고서에 특화됐다. Y2K 버그의 근원이 된 2자리 연도 관행도 여기서 비롯됐다.

BASIC(1964) — 초보자도 쉽게 배울 수 있도록 설계됐다. 인터프리터 방식이 많았다. Bill Gates와 Paul Allen이 Altair 8800용 BASIC 인터프리터로 Microsoft를 시작했다.

C(1969~1973, Bell Labs) — UNIX 운영체제와 함께 성장했다. 포인터를 지원해 하드웨어에 가깝게 다룰 수 있어 "고수준 어셈블리"라고도 불린다. 이식성과 성능을 동시에 잡았다.

## 컴파일러와 인터프리터의 차이

컴파일러는 소스 파일 전체를 읽어 실행 파일을 만든다. 실행은 나중에 한다.

인터프리터는 소스 코드를 읽으면서 즉시 실행한다. 실행 파일을 만들지 않는다. 인터프리터가 더 쉽게 만들 수 있지만, 실행 속도가 컴파일러 출력보다 느리다.

## 객체 지향 언어

1970년대 Xerox PARC에서 Smalltalk가 만들어지면서 객체 지향 프로그래밍(OOP) 개념이 등장했다. C++는 C에 객체 지향을 추가한 언어다. 데이터와 코드를 객체 하나로 묶고, 객체끼리 메시지를 주고받는 방식으로 프로그램을 구성한다. GUI 프로그래밍에 특히 잘 맞는다.
