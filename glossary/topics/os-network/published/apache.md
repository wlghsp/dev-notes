# apache

가장 오래된 오픈소스 웹 서버 중 하나. 정식 명칭은 Apache HTTP Server.

## 기본 동작 방식

요청마다 프로세스(또는 스레드)를 하나 배정해서 처리한다. 요청이 끝날 때까지 그 프로세스/스레드가 전담한다. 구현이 단순하고 직관적이지만, 동시 연결이 많아지면 프로세스/스레드 수가 그만큼 늘어난다.

## MPM(Multi-Processing Module)

Apache는 요청을 어떻게 처리할지를 MPM이라는 모듈로 선택할 수 있다.

prefork MPM — 요청마다 독립적인 프로세스를 쓴다. 프로세스 간 완전한 격리가 보장된다. 하나가 죽어도 다른 요청에 영향이 없다. 메모리 사용량이 많고 동시 처리 수가 제한된다. PHP처럼 스레드 안전하지 않은 모듈과 함께 쓸 때 선택한다.

worker MPM — 프로세스 안에 여러 스레드를 만들어 요청을 처리한다. prefork보다 메모리 효율이 좋다. 스레드가 주소 공간을 공유하므로 스레드 안전한 코드가 필요하다.

event MPM — worker MPM을 개선한 방식. Keep-Alive 연결처럼 대기 상태인 연결을 별도 스레드가 관리하고, 실제 요청이 들어올 때만 워커 스레드에 할당한다. NGINX의 이벤트 루프 방식에 영향을 받아 도입되었다.

## C10K 문제와 한계

prefork/worker MPM은 동시 연결 수만큼 프로세스/스레드가 필요하다. 연결 1만 개 = 프로세스/스레드 1만 개. 생성 비용과 메모리 사용량이 선형으로 증가한다. 이것이 NGINX가 등장한 배경이다.

## Apache가 여전히 쓰이는 이유

.htaccess — 디렉토리별로 설정 파일을 두어 서버 재시작 없이 설정을 바꿀 수 있다. 공유 호스팅 환경에서 유용하다.

모듈 생태계 — mod_php, mod_rewrite 등 오랜 시간 쌓인 모듈이 많다.

PHP와의 궁합 — mod_php로 PHP를 프로세스 안에서 직접 실행한다. 설정이 단순하다.

## NGINX와의 관계

실제 운영 환경에서는 NGINX와 Apache를 함께 쓰는 경우가 많다. NGINX가 앞단에서 정적 파일과 SSL을 처리하고, 동적 요청만 뒤의 Apache로 넘기는 구조다.
