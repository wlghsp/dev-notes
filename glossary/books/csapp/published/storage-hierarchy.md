# storage-hierarchy

컴퓨터 시스템에서 저장소는 속도와 용량이 반비례하는 계층으로 구성된다.

| 계층 | 용량 | 접근 시간 |
|---|---|---|
| 레지스터 | 수십 byte | ~1 cycle |
| L1 캐시 | 수 KB | ~4 cycles |
| L2 캐시 | 수백 KB | ~10 cycles |
| L3 캐시 | 수 MB | ~30 cycles |
| 메인 메모리 (DRAM) | 수 GB | ~100 cycles |
| SSD | 수백 GB | ~수천 cycles |
| HDD | 수 TB | ~수십만 cycles |

위로 갈수록 빠르고 작고 비싸다. 아래로 갈수록 느리고 크고 싸다.

## 핵심 원칙

상위 레벨은 하위 레벨의 부분 집합이다. L1 캐시에 있는 데이터는 L2에도, L3에도, 메인 메모리에도 복사본이 있다. 어느 한 곳에서 데이터를 수정하면 하위 레벨과의 일관성을 맞춰야 한다.

프로그램이 실행되면 CPU는 항상 레지스터에서 데이터를 읽는다. 레지스터에 없으면 L1 캐시를 보고, L1에 없으면 L2, L2에 없으면 L3, L3에도 없으면 DRAM, DRAM에도 없으면 디스크에서 읽어온다. 이 과정을 "캐시 미스가 연쇄적으로 발생한다"고 표현한다.

## 왜 계층이 필요한가

이상적으로는 모든 데이터를 레지스터 속도로 접근하고 싶지만, SRAM(캐시 소재)은 비싸고 전력 소모가 크다. 반대로 DRAM은 싸지만 느리다. 계층 구조는 이 트레이드오프를 실용적으로 해결한다 — 자주 쓰는 데이터는 빠른 곳에, 나머지는 느린 곳에.
