# recurrence-relation (재귀 관계)

재귀 알고리즘의 실행 시간을 더 작은 입력에서의 실행 시간으로 표현한 식. 분할 정복 알고리즘은 문제를 작은 부분 문제로 나눠서 재귀적으로 풀기 때문에, 그 실행 시간도 자연스럽게 재귀식으로 표현된다.

가장 흔한 형태는 다음과 같다.

`T(n) = aT(n/b) + f(n)`

- a: 한 번 나눌 때 생기는 부분 문제의 개수
- n/b: 각 부분 문제의 크기 (원래 크기를 b로 나눈 것)
- f(n): 나누고(divide) 합치는(combine) 데 걸리는 시간

예를 들어 병합 정렬은 배열을 반으로 나눠서(a=2, b=2) 두 부분을 재귀로 정렬하고, 합치는 데 선형 시간이 걸리므로(f(n)=Θ(n)) `T(n) = 2T(n/2) + Θ(n)`이 된다.

## 왜 재귀식 자체로는 답이 안 보이는가

`T(n) = 2T(n/2) + Θ(n)`이라는 식만 봐서는 이게 얼마나 빠른지 바로 알 수 없다. 재귀 호출이 재귀 호출을 부르고, 그게 또 재귀 호출을 불러서 나오는 전체 비용의 합을 구해야 한다. 이 합을 실제 O/Θ 표기로 풀어내는 게 substitution-method.md, recursion-tree-method.md, master-theorem.md 세 가지 방법이다.

## 세 가지 풀이법의 관계

- 재귀 트리 방법은 정답의 "형태를 추측"하는 데 쓰고
- 추측한 형태를 치환법으로 induction.md(귀납법)를 이용해 "증명"하고
- 마스터 정리는 특정 형태의 재귀식에 대해 이 과정을 생략하고 바로 답을 주는 공식이다

셋 다 별개의 도구가 아니라, 같은 문제(재귀식을 닫힌 형태로 풀기)를 다루는 서로 다른 접근이다.

## 기억할 것 한 가지

재귀식을 세울 때는 f(n)이 "나누고 합치는 데 드는 비용"만 포함해야 하고, 재귀 호출 자체의 비용은 aT(n/b) 항이 이미 감당한다는 걸 헷갈리면 안 된다.
