# Argo CD

## 한 줄 요약

gitops.md에서 정리한 GitOps 방식을 쿠버네티스 위에서 실제로 구현하는 도구. Git 저장소를 보고 클러스터를 거기에 맞춘다.

---

## 클러스터가 Git을 당긴다(pull)

Argo CD는 쿠버네티스 클러스터 안에 컨트롤러로 떠 있다.
이 컨트롤러가 지정된 Git 저장소(보통 매니페스트나 Helm 차트가 담긴)를 주기적으로 확인한다.

여기서 방향이 중요하다.
CI 파이프라인이 클러스터를 향해 명령을 쏘는 게 아니라, 클러스터 안의 Argo CD가 바깥의 Git을 당겨온다(pull).
그래서 CI 시스템이 클러스터에 접근할 자격 증명을 가질 필요가 없다 — Argo CD만 클러스터 안에서 Git 저장소를 읽을 권한을 가지면 된다.

---

## 선언과 실제를 비교해서 교정한다

Argo CD의 핵심 루프는 세 단계다.

Git 저장소에 적힌 "원하는 상태"(Desired State)를 읽는다.
클러스터에 지금 떠 있는 "실제 상태"(Live State)를 조회한다.
두 상태를 비교(diff)해서 다르면 실제 상태를 원하는 상태로 맞춘다(sync).

이 비교는 한 번만 하고 끝나는 게 아니라 계속 반복된다.
그래서 누군가 `kubectl edit`으로 클러스터를 수동으로 고쳐도, Argo CD가 다음 확인 주기에 Git에 적힌 원래 상태로 되돌려버린다.
이게 "Git이 유일한 진실"이라는 원칙이 실제로 강제되는 방식이다.

---

## 배포 기록이 곧 Git 히스토리인 이유

Argo CD를 쓰면 "배포"라는 별도 행위가 사라진다.
매니페스트를 담은 Git 저장소에 커밋을 merge하는 순간, Argo CD가 다음 sync 주기에 그 변경을 감지하고 반영한다.
문제가 생기면 그 커밋을 revert하면 Argo CD가 이전 상태로 되돌린다.

그래서 "언제 어떤 버전이 배포됐는가"를 알려면 배포 시스템의 별도 로그를 뒤질 필요 없이 Git 커밋 히스토리를 보면 된다.
Argo CD UI에서도 각 애플리케이션이 지금 어떤 커밋 상태와 동기화되어 있는지, 과거에 어떤 커밋들을 거쳐왔는지를 그대로 보여준다.
