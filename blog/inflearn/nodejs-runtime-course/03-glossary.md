# 3강 핵심 용어 상세 해설 (Glossary in Context)

본문: 03-async-non-blocking-architecture.md

이론과 실무를 연결하는 컴퓨터 공학(CS) 핵심 용어 사전입니다. 각 개념이 Node.js 아키텍처 내부에서 어떻게 맞물려 돌아가는지 완벽히 숙지하시기 바랍니다.

### 동기 (Synchronous) vs 비동기 (Asynchronous)
- **정의**: '작업의 순서와 시점'을 맞추는 방식의 차이입니다. 동기식은 앞선 작업이 완전히 종료되어야만 다음 줄의 코드를 실행하며(순차적 보장), 비동기식은 작업의 완료를 기다리지 않고 곧바로 다음 코드를 강제 실행합니다.
- **CS 실무 맥락**: 자바스크립트는 본질적으로 하나의 메인 스레드만 갖습니다. 따라서 데이터베이스를 조회하는 fs.readFileSync(동기)를 사용하면 응답이 올 때까지 전체 서버가 굳어버립니다. 이를 방지하기 위해 작업 완료 후 실행될 함수(콜백)를 예약해두고 다음 로직으로 넘어가는 비동기 방식을 Node.js의 기본 표준으로 채택하고 있습니다.

### 블로킹 (Blocking) vs 논블로킹 (Non-blocking)
- **정의**: '제어권(실행 권한)'을 어떻게 돌려주는지에 대한 운영체제 레벨의 개념입니다. 블로킹은 호출된 함수가 자신의 모든 작업을 마칠 때까지 제어권을 꽉 쥐고 놓지 않는 것이며, 논블로킹은 작업을 백그라운드에 넘긴 직후 즉시 제어권을 돌려주어 호출한 쪽이 다른 일을 할 수 있게 해줍니다.
- **비유적 이해**: 블로킹은 웨이터가 주방 안까지 들어가서 요리가 끝날 때까지 멍하니 서 있는 것이고, 논블로킹은 주방에 주문서만 찔러 넣고 즉시 홀로 튕겨져 나와 다른 손님을 받는 것입니다. Node.js는 이 '비동기 + 논블로킹'의 조합을 통해 V8 엔진이 단 1밀리초도 쉬지 않고 연산하게 만듭니다.

### 이벤트 루프 (Event Loop)와 이벤트 큐 (Event Queue)
- **정의**: 이벤트 루프는 Node.js의 심장으로, 콜백 함수들을 순서대로 메인 스레드에 올려주는 '무한 회전 감시자'입니다. 이벤트 큐는 완료된 작업(콜백)들이 대기하는 '컨베이어 벨트'입니다.
- **CS 실무 맥락**: 비동기로 던져둔 무거운 I/O 작업들이 OS에서 완료되면, 그 결과(콜백)가 이벤트 큐에 쌓입니다. 이벤트 루프는 홀(콜 스택)이 비어있을 때마다 이 큐를 확인하여 대기 중인 콜백을 순서대로 실행시킵니다. 이 루프가 멈추는 순간(블로킹 발생), 서버의 심장이 멎는 것과 같습니다.

### 스레드 (Thread)와 컨텍스트 스위칭 (Context Switching)
- **정의**: 스레드는 프로세스 내에서 실제로 코드를 실행하는 흐름의 최소 단위입니다. 컨텍스트 스위칭은 CPU가 여러 스레드를 동시에 처리하는 것처럼 보이기 위해, 현재 스레드의 상태를 저장하고 다음 스레드의 상태를 메모리에서 불러오는 교체 작업입니다.
- **CS 실무 맥락**: Java의 Spring이나 Tomcat 같은 전통적 서버는 접속자마다 스레드를 만듭니다. 1만 명이 접속하면 1만 번의 컨텍스트 스위칭이 초당 수천 번 발생하며, CPU는 실제 연산보다 '자리 바꾸는 작업'에 리소스를 다 써버려 서버가 다운됩니다(Thrashing). Node.js는 싱글 스레드로 이 교체 비용을 '0'으로 수렴시켰습니다.

### I/O 집약적 (I/O Bound) vs CPU 집약적 (CPU Bound)
- **정의**: 애플리케이션 성능의 병목(발목을 잡는 요소)이 어디서 발생하는지를 나타냅니다. 네트워크 통신, DB 쿼리, 파일 읽기 등 외부 장치의 응답 대기 시간이 대부분을 차지하면 I/O Bound이며, 복잡한 수학 연산이나 이미지 처리 등 CPU의 연산력 자체가 한계에 달하면 CPU Bound입니다.
- **CS 실무 맥락**: Node.js는 논블로킹 I/O를 통해 I/O 집약적인 서비스(채팅 서버, 스트리밍, 실시간 대시보드)에서 세계 최고 수준의 가성비와 성능을 냅니다. 하지만 딥러닝 연산 같은 CPU 집약적 서비스에서는 단일 스레드가 막혀버리므로 절대 메인 서버에서 직접 처리하면 안 됩니다.

### 시스템 콜 (System Call) 및 OS I/O 다중화 (Multiplexing)
- **정의**: 사용자 공간에서 도는 프로그램(Node.js)이 하드웨어를 직접 제어할 수 없으므로, 운영체제(커널)의 권한을 빌리기 위해 호출하는 인터페이스입니다.
- **CS 실무 맥락**: 단일 스레드가 수만 개의 네트워크 연결을 동시에 감당하는 마법의 정체는 epoll(Linux)이나 kqueue(macOS) 같은 커널 레벨의 I/O 다중화 시스템 콜입니다. Node.js는 수만 명의 소켓 상태를 직접 확인하는 대신, OS에게 "누구든 데이터가 도착하면 나한테 알려줘(Notify)"라고 위임해 버림으로써 극단적인 효율을 달성합니다.
