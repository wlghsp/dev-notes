# assembly-language (어셈블리 언어)

기계어 명령어 하나하나에 사람이 읽을 수 있는 이름(니모닉)을 붙인 언어다. 기계어와 1:1로 대응한다.

## 기계어의 문제

프로세서는 바이트 열만 이해한다. Intel 8080에서 46h는 "HL 레지스터 쌍이 가리키는 메모리 주소의 값을 B 레지스터에 이동"이라는 뜻이다. 이걸 기억하며 프로그램을 짜는 것은 극도로 노동집약적이다.

## 니모닉과 어셈블러

어셈블리 언어는 같은 명령을 `MOV B,[HL]`로 쓴다. 더 읽기 쉽다. 어셈블러(assembler)라는 프로그램이 이 텍스트 파일을 읽어 기계어 바이트 열로 변환한다.

CP/M 환경에서 어셈블리 프로그램 작성 흐름은 다음과 같다.

```
PROGRAM1.ASM 작성 (텍스트 파일)
   ↓ ASM.COM 실행
PROGRAM1.COM 생성 (기계어 바이트 열)
   ↓ 직접 실행
결과 확인
```

어셈블러는 레이블(label)을 지원한다. `Text: DB 'Hello!$'`처럼 이름을 붙이면, 어셈블러가 그 주소를 계산해 참조하는 명령에 넣어준다. 프로그래머가 실제 주소를 직접 계산하지 않아도 된다.

## 어셈블리 언어의 한계

두 가지 문제가 있다.

첫째, 지루하다. 아주 사소한 연산도 여러 줄의 명령이 필요하다. 덧셈 하나에도 값을 레지스터에 올리고, 더하고, 결과를 저장하는 과정을 직접 써야 한다.

둘째, 이식성이 없다. Intel 8080용 어셈블리 코드는 Motorola 6800에서 실행되지 않는다. 프로세서가 바뀌면 프로그램을 처음부터 다시 써야 한다.

이 두 문제를 해결하기 위해 고수준 언어(high-level language)가 등장했다.
