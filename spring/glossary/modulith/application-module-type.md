# ApplicationModule Type (OPEN vs CLOSED)

Spring Modulith에서 `@ApplicationModule` 어노테이션이 가질 수 있는 두 가지 캡슐화 수준이다.
`type` 속성으로 지정하며, 모듈이 자신의 내부 패키지를 얼마나 엄격하게 숨길지를 결정한다.

## Type.CLOSED (기본값)

모듈 루트 패키지의 public 타입만 외부에 노출되고, 내부 패키지는 다른 모듈에서 접근하면 `verify()`가 실패한다.
가장 엄격한 캡슐화 수준이라, 처음부터 모듈 내부 구현을 완전히 숨기고 싶을 때 쓴다.
루트 패키지 바깥에 있지만 예외적으로 공개하고 싶은 패키지가 있으면 named-interface.md에서 다루는 `@NamedInterface`로 선택적으로 열어준다.

## Type.OPEN

모듈 내부 패키지까지 외부에 모두 노출된다.
의존성 방향(어떤 모듈이 어떤 모듈을 참조할 수 있는가)만 강제할 뿐, 캡슐화 자체는 강제하지 않는다.
즉 `allowedDependencies`에 명시되지 않은 모듈을 참조하면 여전히 검증에 실패하지만, 허용된 모듈이라면 그 모듈의 `internal` 패키지까지 자유롭게 접근할 수 있다.

## 언제 어느 쪽을 쓰는가

CLOSED가 이상적인 목표지만, 처음부터 모든 모듈을 CLOSED로 강제하면 기존 코드베이스를 이관할 때 위반이 대량으로 쏟아질 수 있다.
그래서 도입 초기에는 OPEN으로 시작해서 의존성 방향(순환 참조, 잘못된 계층 참조)부터 잡고, 모듈별로 정리가 끝나는 대로 CLOSED로 좁혀가는 점진적 접근이 실무에서 쓰인다.
즉 OPEN은 최종 목표가 아니라 기존 모놀리스를 모듈러 모놀리스로 전환하는 과도기 단계에 적합한 설정이다.
