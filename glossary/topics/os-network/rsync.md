# rsync

파일을 원격지로 복사할 때 `scp`처럼 쓸 수 있지만, 본질적으로 다르다.

`scp`는 파일 전체를 그냥 전송한다. `rsync`는 송신 측과 수신 측이 서로 파일 상태를 비교한 뒤, **변경된 부분만** 전송한다. 이 차이점 계산 알고리즘을 rsync 알고리즘(rolling checksum 기반)이라고 부른다.

## 핵심 동작 원리

1. 수신 측이 보유한 파일을 고정 크기 블록으로 나눈다
2. 각 블록의 체크섬을 계산해서 송신 측에 보낸다
3. 송신 측이 자신의 파일과 비교해 달라진 블록만 골라낸다
4. 달라진 블록만 전송하고, 수신 측이 재조립한다

파일이 클수록, 변경이 적을수록 효율이 극적으로 좋아진다.

## scp와 비교

- `scp` — 파일 전체 복사. 단순하고 빠른 일회성 전송에 적합
- `rsync` — 차이점만 전송. 반복 동기화, 대용량 파일 업데이트, 백업에 적합

파일 하나를 처음 보낼 때는 `scp`와 속도 차이가 없다. 이미 보낸 파일을 일부 수정하고 다시 보낼 때부터 `rsync`가 빛난다.

## 자주 쓰는 옵션

```bash
rsync -avz ./local-dir/ user@host:/remote-dir/
```

- `-a` (archive) — 권한, 타임스탬프, 심볼릭 링크 등 메타데이터 포함
- `-v` (verbose) — 전송 내역 출력
- `-z` (compress) — 전송 중 압축
- `--delete` — 수신 측에 있지만 송신 측에 없는 파일을 삭제 (완전 미러링)
- `--partial` — 전송 중단 시 부분 파일 유지 → 재개 가능

## 주의: trailing slash

```bash
rsync -av ./dir/  user@host:/remote/   # dir 내부 내용을 /remote/ 아래에 복사
rsync -av ./dir   user@host:/remote/   # dir 자체를 /remote/dir 로 복사
```

`/`가 있냐 없냐로 결과가 완전히 달라진다. 실수로 경로가 중첩되기 쉽다.

## 실전 사용 예

배포 스크립트, 서버 백업, `.git/`처럼 파일 수가 많고 자주 변경되는 디렉토리 동기화에 주로 쓴다. 특히 대용량 로그 파일이나 ML 모델 파일을 반복적으로 업데이트할 때 `scp`보다 압도적으로 빠르다.
