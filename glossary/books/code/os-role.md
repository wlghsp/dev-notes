# os-role (운영체제의 역할)

운영체제는 하드웨어와 응용 프로그램 사이에 위치하는 소프트웨어 계층이다. 프로그램이 키보드, 화면, 디스크를 직접 다루지 않아도 되도록 추상화된 인터페이스를 제공한다.

## 운영체제가 해결하는 문제

마이크로프로세서가 처음 켜지면 RAM에는 무작위 바이트만 가득하다. 프로세서는 이 바이트들을 명령어로 해석해 실행하기 시작하지만, 아무 의미 없는 동작만 일어난다. 소프트웨어가 없으면 하드웨어는 쓸모가 없다.

이 문제를 해결하는 첫 번째 장치가 ROM에 저장된 초기화 코드다. 전원이 들어오면 프로세서는 정해진 주소(Intel 8080 기준 0000h)에서 실행을 시작한다. 그 주소에 초기화 코드가 있어야 한다.

## 운영체제의 세 가지 역할

첫째, 명령 처리기(command processor). 사용자가 키보드로 입력한 명령을 해석하고 실행한다. CP/M의 콘솔 명령 처리기(CCP)가 대표적이다. `DIR`, `ERA`, `REN`, `TYPE` 같은 명령이 여기에 속한다.

둘째, 파일 시스템 관리. 디스크의 어느 섹터에 무엇이 저장되어 있는지를 운영체제가 추적한다. 프로그램은 섹터 번호를 몰라도 파일 이름만으로 읽고 쓸 수 있다. CP/M은 디렉터리 영역에 각 파일의 이름, 위치, 크기를 기록해 관리한다.

셋째, 응용 프로그래밍 인터페이스(API). 프로그램이 하드웨어에 접근하는 표준 방법을 제공한다. CP/M에서는 레지스터 C에 함수 번호를 설정하고 `CALL 5`를 실행하면 운영체제가 대신 키보드를 읽거나 화면에 출력하거나 파일을 생성한다. 프로그램은 하드웨어가 어떻게 연결되어 있는지 알 필요가 없다. 이것이 장치 독립성(device independence)이다.

## 부팅

운영체제 자체도 디스크에 저장되어 있으므로 메모리에 올려야 실행된다. 이 과정을 부팅(booting)이라 한다. ROM에는 최소한의 코드인 부트스트랩 로더(bootstrap loader)만 있으면 된다. 부트스트랩 로더가 디스크의 첫 128바이트 섹터를 읽고, 그 섹터에 있는 코드가 나머지 운영체제를 메모리에 올린다.

## CP/M의 메모리 구조

CP/M이 올라온 후 메모리는 낮은 주소부터 이렇게 배치된다.

- 0000h: 시스템 파라미터 영역
- 0100h: 임시 프로그램 영역(TPA) — 사용자 프로그램이 여기 로드됨
- 상위 주소: CCP → BDOS → BIOS 순서로 CP/M 구성 요소

BIOS(Basic Input/Output System)가 실제 하드웨어에 접근하는 유일한 부분이다. BDOS는 파일 시스템을 관리하며 BIOS를 통해 하드웨어를 다룬다. CCP는 BDOS 함수만 사용한다.

## 역사적 흐름

CP/M은 8비트 마이크로프로세서 시대의 대표 운영체제였다. MS-DOS는 CP/M의 영향을 받아 만들어졌고, 16비트 IBM PC에서 표준이 됐다. UNIX는 이식성(portability)을 목표로 설계됐고 계층적 파일 시스템, 멀티태스킹, 가상 메모리를 지원한다. 이후 GUI 기반 운영체제(Mac OS, Windows)가 등장하면서 그래픽 API가 운영체제의 핵심 역할로 추가됐다.
