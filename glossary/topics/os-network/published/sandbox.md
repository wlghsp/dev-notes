# 샌드박스 (Sandbox)

외부의 접근이나 영향을 차단하여, 그 안에서 실행되는 코드가 바깥 시스템에 임의로 손대지 못하게 격리한 실행 공간.

핵심은 "격리 경계를 누가, 어떻게 긋는가"다. 브라우저는 자바스크립트 엔진 레벨에서 이 경계를 긋는다. 웹 페이지의 자바스크립트는 파일 시스템이나 네트워크 포트에 직접 접근할 수 없고, 브라우저가 허용한 API(DOM 조작, fetch 등)를 통해서만 바깥 세상과 통신한다. 무심코 접속한 악성 사이트의 코드가 로컬 하드디스크를 건드릴 수 없는 이유가 이것이다.

Node.js는 이 브라우저 샌드박스를 벗어나 자바스크립트에 OS 제어권(fs, http 등)을 통째로 넘긴 런타임이다. 즉 브라우저의 자바스크립트는 "샌드박스 안"이고, Node.js의 자바스크립트는 "샌드박스 밖"이다. 참고: runtime.md

컨테이너 기반 격리는 같은 문제를 커널 레벨에서 푼다. Docker 컨테이너는 언어 자체의 실행 권한을 제한하는 게 아니라, 리눅스 커널의 namespace(프로세스가 보는 파일시스템/네트워크/PID 목록을 격리)와 cgroup(CPU/메모리 자원 사용량을 제한)을 이용해 "이 프로세스가 볼 수 있는 시스템 범위"를 통째로 좁힌다. 터미널 실습 플랫폼에서 사용자가 입력한 임의의 셸 명령을 실행할 때, 컨테이너가 곧 샌드박스가 된다 — 사용자가 `rm -rf /`를 쳐도 그 컨테이너 안의 파일시스템만 날아갈 뿐, 호스트나 다른 사용자의 컨테이너에는 영향이 없다.

이때 실무적으로 중요한 경계는 두 가지다.
- **컨테이너 탈출(Container Escape)**: 커널 취약점이나 잘못된 설정(예: `--privileged`, 호스트 소켓/디렉토리 마운트)으로 격리가 깨지고 호스트를 건드리는 상황. 실습 플랫폼처럼 신뢰할 수 없는 코드를 실행시키는 서비스에서는 가장 먼저 막아야 하는 시나리오다.
- **자원 고갈(Resource Exhaustion)**: 한 사용자의 컨테이너가 CPU/메모리를 무한정 먹어서 같은 호스트의 다른 컨테이너에 영향을 주는 상황. cgroup으로 자원 상한을 걸어야 막을 수 있다.

즉 브라우저의 샌드박스가 "언어 차원의 신뢰 경계"라면, 컨테이너의 샌드박스는 "OS 차원의 신뢰 경계"다. 둘 다 "이 코드는 내가 통제한 범위 밖으로 나갈 수 없다"는 동일한 목표를 다른 레이어에서 구현한 것이다.
