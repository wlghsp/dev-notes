# dingco 챌린지 공통 가이드

dingco에서 진행하는 챌린지들(algorithm-challenge, backend-resume-challenge, jpa-challenge, challenge-ai-native 등)을 모아둔 폴더. 각 챌린지의 실제 코드/설정 작업은 별도 대상 저장소(`study/` 아래)에서 하고, 여기 dev-notes에는 학습 준비와 진행 기록만 남긴다.

## 폴더 구조 패턴

챌린지마다 `<챌린지이름>/week<N>/` 아래에 다음 파일들을 쌓는다. 모든 챌린지가 전부 다 갖추는 건 아니고, 필요한 것만 만든다.

- `prep-questions.md` — 실제 작업 전에 먼저 답해야 하는 질문들. 정답을 미리 안 주고, 대상 저장소 코드를 근거로 지호님이 직접 채운다.
- `execution-guide.md` — prep-questions에 답한 뒤 실제로 진행하는 순서. 단계별로 무엇을 확인하고 무엇을 기록해야 하는지.
- `evidence-draft.md` — 대상 저장소의 `evidence/<브랜치명>.md`에 옮겨 적을 초안. 대상 저장소 evidence 틀(변경/검증/선택 근거/근거형 질문/리뷰 반영)에 맞춘다.
- `review-notes.md` — PR 자동 리뷰 결과 분석. 잘한 점(유지할 것)과 보완할 점(다음 주차 적용)을 구분해서 기록.
- `concepts.md`, `summary.md`, `<주제>-issue.md` 등 — 그 주차에서 깊게 파야 하는 개념이나 실전에서 겪은 문제를 별도 파일로 정리 (JPA 챌린지처럼 개념 학습 비중이 큰 경우).

## 진행 순서

1. **prep-questions 작성** — 대상 저장소를 실제로 열어보고, 코드/설정/로그를 근거로 질문에 답한다. 정답을 외워 쓰는 게 아니라 저장소에서 직접 확인한 내용만 쓴다.
2. **execution-guide 작성** — prep-questions 답변을 바탕으로 실제 작업 순서를 정리한다. 측정/실험이 필요하면 명령어와 실제 실행 결과를 그대로 기록해둔다.
3. **대상 저장소에서 실제 작업** — 코드 변경, 테스트 작성, 문서 작성은 dev-notes가 아니라 대상 저장소(예: challenge-backend-resume-2026-08-wlghsp-r17, challenge-ai-native-2026-08-wlghsp-r18)에서 지호님이 직접 진행한다.
4. **evidence-draft 작성 → 대상 저장소 evidence로 옮김** — dev-notes에서 초안을 잡고, 최종본은 대상 저장소의 `evidence/<브랜치명>.md`에 작성한다.
5. **PR 생성 및 자동 검사/리뷰 확인**
6. **review-notes 작성** — 리뷰 결과와 점수, 잘한 점/보완할 점을 dev-notes에 기록해서 다음 주차에 반영한다.

## 공통 규칙 (여러 챌린지에서 반복 확인된 것)

- **"같은 입력/조건" 고정** — 측정이나 실험이 들어가는 챌린지는 재현 가능하도록 조건(표본 수, 환경, 시드 데이터 규모 등)을 반드시 함께 기록한다. 조건 없이 결과값만 적으면 재현 불가로 지적받는다.
- **확인 불가는 확인 불가로** — 아직 측정/검증하지 못한 값은 추정치를 쓰지 않고 "확인 불가"로 명시하고, 다음 주차 보완 계획을 남긴다.
- **근거형 질문은 3단계로 답변** — 최초 판단 → 연결한 저장소 안 코드/테스트/로그 → 검증 후 답변. 판단만 쓰고 근거를 안 붙이면 "간접 확인"이라는 지적을 받는다.
- **"## 리뷰 반영" 섹션을 마지막까지 비워두지 않기** — 여러 챌린지에서 반복 지적된 항목. PR에 자동 리뷰나 self-check 결과가 달리면 그 즉시 evidence의 "## 리뷰 반영"에 지적 유무와 무관하게 기록한다 (지적 없으면 "지적 없음").
- **테스트가 검증하는 대상 로직을 소스 경로로 같이 제시** — 테스트 코드만 추가하지 말고, 그 테스트가 검증하려는 실제 로직이 소스 어디에 있는지 파일 경로 + 코드 스니펫으로 evidence에 함께 적는다.
- **self-check 실패 시 원인을 로그로 직접 확인** — `gh run view <run-id> --job <job-id> --log`로 실패 원인을 본다. "채점 Workflow/challenge.json 변경 금지" 에러라면 대개 `main`이 워크플로를 업데이트했는데 제출 브랜치가 그 이전에 갈라져서 생긴 문제이므로 `git merge origin/main`으로 최신화 후 재push한다.
- **PR의 "Files changed"에서 diff 누락 여부 직접 확인** — evidence 요약만으로 판단하지 않도록, 새로 추가한 파일이 실제로 PR diff에 전부 잡히는지 눈으로 확인한다.
- **이전 주차 "확인 불가" 항목은 다음 주차에 실측값으로 갱신** — 측정 도구가 늘어나거나(예: k6) 검증 수단이 생기면, 이전 문서의 확인 불가 항목을 실측값 + 근거 경로로 바꾼다.

## 커밋 대상 저장소가 dev-notes와 다른 챌린지

challenge-ai-native처럼 실제 코드/설정(claude.md, .claude/skills, Hook 등) 변경이 dev-notes가 아닌 별도 저장소에서 일어나는 챌린지는, dev-notes에는 학습 준비(prep-questions)와 진행 기록만 남기고 실제 구현은 지호님이 대상 저장소에서 직접 한다.
