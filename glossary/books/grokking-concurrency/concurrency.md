# concurrency

**"하나의 시스템이 동시에 여러 작업을 다룰 수 있는 능력"**

동시성은 작업이 물리적으로 같은 순간에 실행되는 것을 의미하지 않는다. 여러 작업이 진행 중인 상태를 유지하면서, 서로 번갈아가며 처리될 수 있다는 것이다. 실제로 동시에 실행되는지 여부는 하드웨어에 달려 있다.

---

## 왜 필요한가

현실 세계는 순차적이지 않다. 슈퍼마켓의 계산대, 교차로의 신호등, 서버가 처리하는 수천 개의 요청 — 이 모든 것이 동시에 일어난다. 이를 소프트웨어로 모델링하려면 동시성이 필요하다.

성능 개선 측면에서 동시성은 세 가지 방식으로 기여한다.

1. latency를 줄인다 — 큰 작업을 쪼개서 병렬 처리하면 전체 완료 시간이 줄어든다
2. latency를 숨긴다 — I/O 대기 중에 다른 작업을 처리해 유휴 시간을 없앤다
3. throughput을 높인다 — 단위 시간당 더 많은 작업을 처리할 수 있다

---

## 동시성의 세 레이어

```
Application Layer  — 코루틴, 동시성 제어, 디자인 패턴
Runtime Layer      — 프로세스, 스레드, 스케줄러, IPC
Hardware Layer     — CPU, 캐시, 명령어 수준 병렬성
```

각 레이어는 같은 현상을 다른 추상화 수준에서 본다. 레이어가 다르면 동작 방식도, 제약 조건도 달라진다.
