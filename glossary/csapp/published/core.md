# core

CPU 안에서 실제로 연산을 처리하는 독립적인 처리 단위.

## 왜 멀티코어가 생겼는가

초기에는 클럭을 높여서 CPU 성능을 끌어올렸다. 그런데 클럭이 높아질수록 발열이 기하급수적으로 올라가는 물리적 한계에 부딪혔다. 2000년대 중반부터 클럭을 올리는 대신 코어를 여러 개 넣는 방향으로 전환됐다.

```
싱글코어: [코어 1개] — 한 번에 하나의 흐름만 처리

멀티코어: [코어1] [코어2] [코어3] [코어4] — 4개의 흐름을 진짜로 동시에 처리
```

## 코어가 각자 가지는 것 vs 공유하는 것

- **각자 가지는 것** — 레지스터, L1 캐시, L2 캐시, ALU(연산 장치)
- **공유하는 것** — L3 캐시, 메인 메모리(DRAM)

L3를 공유하기 때문에 여러 코어가 같은 데이터를 동시에 수정하려 할 때 일관성 문제가 생긴다. 이를 캐시 일관성(cache coherence) 문제라고 한다.

## 코어와 스레드의 관계

thread.md에서 본 스레드들이 실제로 실행될 때 OS가 각 코어에 분배한다. 코어가 4개면 최대 4개의 스레드가 진짜로 동시에 실행된다. 코어보다 스레드가 많으면 context-switch로 번갈아 실행한다.

## 관련 개념

- 코어를 활용한 병렬 처리 한계는 amdahls-law.md 참고 (concurrency/)
- 코어에 분배되는 실행 단위는 thread.md 참고
- 코어별 캐시 구조는 cache.md, storage-hierarchy.md 참고
