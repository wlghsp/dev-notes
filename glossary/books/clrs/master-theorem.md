# master-theorem (마스터 정리)

`T(n) = aT(n/b) + f(n)` 형태의 recurrence-relation.md(재귀 관계)에 대해, substitution-method.md나 recursion-tree-method.md를 거치지 않고 바로 답을 주는 공식. a ≥ 1, b > 1인 상수이고 f(n)은 점근적으로 양수인 함수여야 적용할 수 있다.

핵심은 두 함수를 비교하는 것이다.
- n^(log_b a) — 재귀 호출 자체가 만들어내는 비용의 "이론적 크기"
- f(n) — 나누고 합치는 데 드는 비용

이 둘 중 어느 쪽이 더 큰지에 따라 세 가지 경우로 나뉜다.

## 세 가지 경우

**경우 1**: 어떤 상수 `ε > 0`에 대해 `f(n) = O(n^(log_b a - ε))`이면(다항식만큼 더 작으면), 재귀 호출 비용이 압도적이므로 `T(n) = Θ(n^(log_b a))`

**경우 2**: `f(n) = Θ(n^(log_b a))`이면(같은 크기라면), 둘이 동률이므로 로그 인자를 하나 곱해서 `T(n) = Θ(n^(log_b a) · lg n)`

**경우 3**: 어떤 상수 `ε > 0`에 대해 `f(n) = Ω(n^(log_b a + ε))`이면(다항식만큼 더 크면), 그리고 정규성 조건 `af(n/b) ≤ cf(n)`(어떤 상수 `c < 1`, 충분히 큰 n에서)까지 만족하면, 나누고 합치는 비용이 압도적이므로 `T(n) = Θ(f(n))`

recursion-tree-method.md에서 봤던 "루트가 지배하는지, 잎이 지배하는지, 모든 레벨이 고르게 기여하는지"가 바로 이 세 경우와 같은 이야기다. 경우 3은 루트(f(n)) 지배, 경우 1은 잎(재귀 호출) 지배, 경우 2는 모든 레벨이 동률이라 로그 배수가 붙는다.

## "다항식만큼 크다/작다"가 중요한 이유

단순히 f(n)이 n^(log_b a)보다 "크다" 또는 "작다"만으로는 부족하다. 반드시 n^ε 배 차이가 나야(다항식 차이) 각 경우가 적용된다. 예를 들어 `T(n) = 2T(n/2) + n lg n`은 f(n) = n lg n이 n^(log_2 2) = n보다 lg n배 더 크지만, 이건 다항식 차이가 아니라 로그 차이라서 경우 2와 경우 3 사이의 "틈"에 빠진다. 이럴 때는 마스터 정리를 못 쓰고 다른 방법(치환법 등)을 써야 한다.

## 예시로 감 잡기

- `T(n) = 9T(n/3) + n` → a=9, b=3, n^(log_3 9) = n². f(n)=n은 n²보다 다항식만큼 작으므로 경우 1 → T(n) = Θ(n²)
- `T(n) = T(2n/3) + 1` → a=1, b=3/2, n^(log_1.5 1) = n⁰ = 1. f(n)=1로 크기가 같으므로 경우 2 → T(n) = Θ(lg n)
- `T(n) = 3T(n/4) + n lg n` → a=3, b=4, n^(log_4 3) ≈ n^0.793. f(n) = n lg n이 다항식만큼 크고 정규성 조건도 만족하므로 경우 3 → T(n) = Θ(n lg n)

## 정규성 조건 (경우 3 전용)

경우 3의 정규성 조건 `af(n/b) ≤ cf(n)`은 "나누고 합치는 비용이 재귀적으로도 안정적으로 크다"는 걸 보장하는 기술적 조건이다. 다항식으로 유계인 함수 대부분은 이 조건을 자동으로 만족한다.

## 실전에서 쓰는 법

Strassen 알고리즘의 재귀식 `T(n) = 7T(n/2) + Θ(n²)`을 보면 a=7, b=2, n^(log_2 7) ≈ n^2.81이고 f(n)=n²은 이보다 다항식만큼 작으므로 경우 1이 적용되어 T(n) = Θ(n^(lg 7))이 바로 나온다. 일반 행렬 곱셈(a=8)의 T(n) = Θ(n³)과 비교하면, 재귀 호출 하나를 줄인 게 왜 점근적으로 더 빠른 알고리즘을 만드는지 마스터 정리가 즉시 설명해준다.

## 왜 이 세 경우가 성립하는가 (증명 개요)

마스터 정리의 증명은 recursion-tree-method.md에서 봤던 등비수열 감각을 그대로 엄밀하게 전개한 것이다. 재귀 트리의 레벨 j에서 나오는 항은 a^j · f(n/b^j) 형태인데, 이 항들을 다 더한 합이

- f(n)이 n^(log_b a)보다 다항식만큼 작으면(경우 1), 이 항들이 증가하는 등비수열을 이뤄서 마지막 레벨(잎)의 비용 Θ(n^(log_b a))이 합 전체를 지배한다
- f(n)이 n^(log_b a)와 크기가 같으면(경우 2), 모든 레벨의 항이 똑같은 값이라 그냥 "레벨 수 × 항 값" = Θ(n^(log_b a) lg n)이 된다
- f(n)이 다항식만큼 크고 정규성 조건까지 만족하면(경우 3), 항들이 감소하는 등비수열을 이뤄서 첫 항(루트)의 비용 Θ(f(n))이 합 전체를 지배한다

바닥/천장(⌊⌋, ⌈⌉) 때문에 n이 b의 정확한 거듭제곱이 아닐 때도 이 결론이 달라지지 않는다는 걸 보이는 게 증명의 나머지 절반인데, 이는 재귀가 진행되며 나오는 부분 문제 크기가 정확한 n/b^j에서 상수만큼만 벗어난다는 걸 보여서 처리한다.

## 마스터 정리로 안 풀리는 경우 — Akra-Bazzi 방법

마스터 정리는 모든 부분 문제 크기가 똑같이 n/b일 때만 적용된다. `T(n) = T(n/3) + T(2n/3) + O(n)`처럼 부분 문제 크기가 서로 다르면 마스터 정리 자체를 쓸 수 없다(이런 경우는 recursion-tree-method.md처럼 재귀 트리를 직접 그려서 풀어야 한다). 이렇게 부분 문제 크기가 불균등한 재귀식 전반을 다루는 더 일반적인 방법으로 Akra-Bazzi 방법이 있는데, 마스터 정리보다 다루기 어려운 대신 훨씬 넓은 범위의 재귀식에 적용된다.

## 기억할 것 한 가지

마스터 정리는 "세 경우 중 하나에 깔끔하게 들어맞을 때만" 쓸 수 있는 지름길이다. 틈에 빠지는 재귀식(로그 차이 등)이나 부분 문제 크기가 불균등한 재귀식을 만나면 치환법이나 재귀 트리로 직접 풀어야 한다.
