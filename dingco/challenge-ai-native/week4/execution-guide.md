## 1단계: docs/prd.md 작성

태그/카테고리 기능의 PRD를 채운다. 아래는 초안 방향이며, 실제 작성은 지호님이 직접 한다 — 성공 기준 수치와 비범위는 지호님 판단이 들어가야 하는 부분이다.

- **사용자 문제**: 글이 늘어나면 원하는 주제의 글만 모아 보기 어렵다. 현재는 시간순 목록과 이전/다음 글 이동만 있고, 주제로 묶어보는 방법이 없다.
- **성공 기준(측정 가능하게)**: 예) "태그가 붙은 글에서 태그를 클릭하면 같은 태그를 가진 글 목록으로 이동한다", "태그가 없는 글은 기존 목록/상세 페이지 동작이 그대로 유지된다(회귀 없음)"
- **사용자 스토리**: "글을 읽는 사람으로서, 관심 있는 주제(예: JVM)의 글만 모아보고 싶다"
- **기능 요구사항**: frontmatter에 `tags` 필드 추가, 상세 페이지에 태그 표시, 태그별 목록 페이지(`/blog/tags/[tag]`) 신설
- **비기능 요구사항**: 기존 글(태그 없는 글 3개)이 깨지지 않아야 함 — `tags` 필드는 optional
- **비범위**: 태그 자동 추천, 태그 검색 UI, 태그 관리 화면은 이번 주 범위 밖

## 2단계: 이슈 쪼개기

PRD를 실행 단위로 쪼개 GitHub 이슈로 만들었다:

1. **#5 frontmatter에 `tags` 필드 추가 + 파싱** — `posts.ts`의 `Post` 타입과 `parsePost`에 `tags?: string[]` 반영. 인수 조건: 기존 태그 없는 글 3개가 여전히 정상 파싱됨, 태그 있는 글은 배열로 파싱됨
2. **#6 글 상세 페이지에 태그 표시** — `page.tsx`에 태그 목록 렌더링, 각 태그는 태그별 페이지로 링크. 인수 조건: 태그 있는 글은 태그가 보이고 클릭 가능, 태그 없는 글은 이 영역이 안 보임 (#5 완료 후 진행)
3. **#7 태그별 목록 페이지** — `/blog/tags/[tag]/page.tsx` 신설, `generateStaticParams`로 정적 생성. 인수 조건: 존재하는 태그로 접근하면 해당 태그의 글만 나열, 존재하지 않는 태그는 `notFound()` (#5, #6 완료 후 진행)

PR 본문에서 이 세 이슈 번호와 각 인수 조건 체크박스를 참조해 추적한다.

## 3단계: 구현 (선택한 에이전트로)

2단계 이슈 순서대로 구현한다. 각 이슈 완료 시:

- `tests/` 아래에 인수 조건을 고정하는 시나리오 추가 (예: `tests/tag-filtering.spec.ts`)
- `npm test`, `npm run e2e` 통과 확인

기존 3개 글에는 태그가 없으므로, 태그 기능을 눈으로 확인하려면 최소 1~2개 글에 `tags`를 추가하거나 테스트용 글을 하나 추가해야 한다. 어느 쪽으로 할지는 구현 단계에서 정한다.
