# 객체 하나 만드는 데 실제로 비용이 얼마나 드는가

원문: "JVM Anatomy Quark #7: Initialization Costs" — Aleksey Shipilëv (shipilev.net)

## Why

객체를 생성할 때 드는 비용은 크게 두 가지로 나뉜다. 헤더 등 메타데이터를 쓰는 비용과, 필드/배열 내용을 초기화(zeroing)하는 비용이다. 이 둘이 객체 크기에 따라 어떻게 다르게 지배적인 역할을 하는지 다룬다.

## 측정 결과

배열 크기를 늘려가며 할당 시간을 측정하면, 1바이트짜리 배열은 약 20나노초, 10만 개짜리 배열은 약 44마이크로초가 걸린다. 경합이 있는 상황에서 할당 처리량은 초당 약 12GB에서 정체된다.

## 초기화 비용이 지배적인 이유

작은 객체는 메타데이터(Mark Word, Class Word) 쓰기 비용이 상대적으로 크게 느껴지지만, 객체가 커질수록 실제 내용물을 0으로 채우는(zeroing) 비용이 전체 시간을 지배하게 된다. 어셈블리 수준에서 보면, x86에서 큰 배열은 `rep stos` 명령어로 메모리를 대량으로 0으로 채우고, 작은 배열은 더 짧은 반복 루프를 사용한다.

## 초기화를 건너뛰면 얼마나 빨라지는가

`Unsafe.allocateUninitializedArray()`로 초기화 과정을 생략하면 속도가 극적으로 빨라진다. 10만 개짜리 배열 기준으로 초당 약 1.6테라바이트까지 처리량이 올라간다. 이 차이는 메모리를 0으로 채우는 작업에 실제로 얼마나 많은 연산이 들어가는지를 보여준다.

## 가장 뜨거운 코드 경로

객체 생성 과정에서 가장 많은 시간이 쓰이는 부분은 다음과 같다.

- 객체 메타데이터(Mark Word, Class Word) 저장
- 배열 길이 기록
- 메모리 위치 프리페치(prefetch)
- 반복적인 store 연산을 통한 대량 초기화

극단적으로 빠른 할당 속도(초당 1.6TB)에서도 GC 정지 시간은 평균 1밀리초 이하, 최대 세이프포인트 정지 시간도 약 12밀리초 수준으로 크게 문제되지 않았다.

## 결론

객체 생성 속도는 크기에 따라 지배 요인이 다르다. 작은 객체는 메타데이터 쓰기 비용이, 큰 객체는 내용물 초기화 비용이 전체 시간을 좌우한다.
