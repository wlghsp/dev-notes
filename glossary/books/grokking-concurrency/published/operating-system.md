# Operating System

OS. 하드웨어와 애플리케이션 사이의 저수준 시스템 인터페이스. 런타임 시스템(runtime-system.md)의 가장 대표적인 예다.

## 역할

프로그램이 디스크에 파일을 쓰거나, 네트워크로 데이터를 보내거나, 화면에 출력할 때 — 모두 OS를 통해 요청한다. 프로그램은 디스크 종류나 하드웨어 동작 방식을 알 필요가 없다. OS가 세부 사항을 처리하고, 하드웨어와 다른 자원을 부적절한 사용으로부터 보호한다.

## 시스템 콜(System Call)

OS가 애플리케이션에 제공하는 인터페이스. 프로그램이 하드웨어 자원에 접근하거나 OS 기능을 사용할 때 시스템 콜을 통해 요청한다.

시스템 콜을 쓰면 OS를 거치는 오버헤드가 생긴다. 이 오버헤드가 부담스러운 경우, 애플리케이션 레벨에서 직접 처리하는 방식을 택하기도 한다. 이후 챕터에서 구체적인 사례를 다룬다.

## User Space vs Kernel Space

컴퓨터 시스템은 두 영역으로 나뉜다.

- **User space** — 사용자 애플리케이션이 실행되는 영역. 하드웨어에 직접 접근하거나 시스템을 수정할 수 없다.
- **Kernel space** — OS 핵심 기능과 시스템 콜이 실행되는 영역. 하드웨어와 모든 자원에 대한 완전한 제어권을 가진다.

이 구분은 애플리케이션이 의도치 않게 하드웨어를 건드리지 못하도록 보호한다.
