# Context Rot

## 한 줄 요약

LLM의 컨텍스트가 길어질수록 출력 품질이 저하되는 현상. 컨텍스트 창이 꽉 차지 않아도 발생한다.

---

## 뭐가 문제인가

AI 코딩 세션을 길게 이어가다 보면 처음보다 나중에 생성된 코드가 더 이상한 경우가 있다. 단순히 AI가 피곤한 게 아니라, 컨텍스트가 쌓이면서 실제로 품질이 떨어지는 게 측정된다.

Chroma의 2025년 연구에서 GPT-4.1, Claude Opus 4, Gemini 2.5 포함 18개 주요 모델을 테스트했고, **모든 모델이 컨텍스트 길이가 늘어날수록 성능이 하락**했다.

Databricks 연구에서는 32,000 토큰 근처에서 정확도가 눈에 띄게 떨어지기 시작했다. 최대 컨텍스트 한계(100만 토큰)와는 한참 거리가 있는 시점이다.

---

## 왜 발생하는가: Lost in the Middle

근본 원인은 트랜스포머의 어텐션 메커니즘이다.

모델은 컨텍스트의 **앞부분과 뒷부분에 강하게 집중**하고, **중간에 있는 내용을 잘 놓친다.** U자 형태의 어텐션 분포.

```
어텐션 강도
  ↑
높음 |█                              █
     |█                              █
낮음 |    █  █  █  █  █  █  █  █
     +--------------------------------→
     앞                            뒤
                 컨텍스트 위치
```

20개 문서 중 답이 1번 문서에 있을 때와 10번 문서에 있을 때를 비교하면 정확도가 30% 이상 차이 난다.

대부분의 현대 LLM이 쓰는 RoPE(Rotary Position Embedding)가 이 효과를 강화한다. 시작과 끝 토큰에 어텐션이 쏠리도록 설계됐기 때문이다.

---

## 컨텍스트에 쌓이는 노이즈

긴 코딩 세션에서 컨텍스트를 오염시키는 것들:

- 실패한 시도의 코드와 에러 메시지
- 여러 번 수정된 같은 파일의 중복 내용
- "이거 해줘", "아 그게 아니라" 같은 교정 대화
- 더 이상 유효하지 않은 이전 설계 논의

이런 내용이 쌓이면 AI가 현재 요청에 집중하지 못하고 오래된 맥락에 끌려간다.

---

## 해결 전략: Context Engineering

Context Rot에 대응하는 방법론을 **Context Engineering**이라고 부른다. Anthropic Applied AI팀이 2025년 9월에 공식화한 용어로, "LLM 추론 중 최적의 토큰 집합을 선별하고 유지하는 전략의 집합"으로 정의된다.

실용적인 대응법들:

**1. 세션 주기적 리셋**
긴 대화를 이어가는 것보다 핵심 컨텍스트만 정리해서 새 세션으로 시작하는 게 낫다. 오염된 컨텍스트를 들고 가느니 깨끗한 상태로 재시작.

**2. 중요한 정보는 앞이나 뒤에**
어텐션이 강한 위치(시작/끝)에 핵심 지시사항과 중요한 코드를 배치한다. 중간에 묻히면 무시될 가능성이 높다.

**3. 컨텍스트 압축**
긴 대화 내용을 AI에게 요약시킨 후, 그 요약만 들고 새 세션을 시작하는 방법. 노이즈를 제거하고 핵심만 남긴다.

**4. CLAUDE.md / Steering Files 활용**
반복적으로 설명하는 프로젝트 컨벤션, 아키텍처 결정은 파일로 분리한다. 컨텍스트에 직접 쌓지 않고, 참조 파일로 두면 항상 앞부분에 올라와 어텐션을 받는다.

**5. 태스크 단위 분리**
하나의 긴 세션에서 여러 기능을 만드는 것보다, 기능 단위로 독립된 세션을 가져가는 게 품질 유지에 유리하다.

---

## AI 코딩 도구와의 연결

Claude Code, Cursor, Kiro 같은 도구들이 Context Rot을 각자 다르게 다룬다.

- Claude Code: `/compact` 명령으로 대화를 요약 압축한 뒤 이어서 진행 가능
- Kiro: Steering Files로 핵심 컨텍스트를 파일로 분리해 항상 선두에 올림
- AI-DLC 방법론: 단계마다 컨텍스트를 정제해서 다음 단계로 넘기는 구조가 Context Rot 완화에 기여

참고: ai_dlc.md, kiro_ide.md

## 요약

- 컨텍스트가 길어지면 LLM 품질이 떨어진다 — 컨텍스트 창 한계와 무관하게
- 원인: 트랜스포머가 중간 내용을 잘 못 보는 구조 (Lost in the Middle)
- 긴 코딩 세션일수록 실패 시도, 중복 내용, 오래된 논의가 쌓여 노이즈가 됨
- 대응: 세션 리셋, 중요 정보 앞/뒤 배치, 컨텍스트 압축, 파일로 분리
- 이를 다루는 방법론 전체를 Context Engineering이라 부름
